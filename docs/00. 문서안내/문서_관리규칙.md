# 문서 관리 규칙

이 문서는 `docs/` 폴더의 구조와 현행 MVP 단일 기준 문서 작성 원칙을 정의합니다.

---

## 1. 단일 MVP 기준 원칙

1. **현행 규칙만 기록**: 모든 문서는 현재 MVP에서 적용 중인 단일 규칙과 명세만 작성합니다.
2. **과거 이력 배제**: 날짜별 변경 이력(`> 2026-10-...`), 이전 백엔드(Supabase 등) 비교 설명, 폐기된 시안 대조표를 현행 문서 안에 누적하지 않습니다.
3. **폐기 문서 분리**: 기준 설정에 방해되는 구버전 문서·초안·과거 검수 보고서는 모두 `docs/999. deletefile/`로 이관하며, 현행 문서에서 `999. deletefile` 내부 경로를 링크하지 않습니다.

---

## 2. 폴더 및 파일 이름 규칙

1. `docs/` 아래 현행 폴더는 `NN. 폴더명` 두 자리 번호(`00`~`04`)를 사용하며 같은 부모 폴더 안에서 번호를 중복하지 않습니다.
2. 파일 이름은 역할이 드러나는 한글 제목(`주제_역할.md`, `DB_객체사전.txt`) 또는 코드가 직접 참조하는 고정 식별자(`design-tokens.json`, `README.md`)를 사용합니다.
3. 파일 이름에 작성 날짜나 임시 버전 번호를 붙이지 않습니다.

사용자가 지정한 `docs/998. 일일 업무 보고서/YY.MM.DD/`는 일일 작업 결과를 보관하는 예외 경로입니다. 날짜는 실제 달력에 있는 날만 허용하며, 보고서 파일 이름은 작업 내용으로 정합니다. 이 예외는 다른 이름·위치의 3자리 번호 폴더나 일반 문서의 날짜 폴더로 넓히지 않습니다. 보고서도 인코딩·프로젝트 경계·링크 검사를 동일하게 받으며 현행 기능·디자인의 단일 기준은 기존 규격 문서에 둡니다.

---

## 3. 검증 규칙

- 문서를 추가·수정·이동한 뒤에는 반드시 `npm run check:docs`를 실행해 폴더 번호, 인코딩, 로컬 마크다운 링크 무결성을 확인합니다.
- 디자인 토큰(`design-tokens.json`)을 수정한 경우 `npm run check:design`으로 WCAG AA 명도 대비(52개 항목)를 함께 검증합니다.
