# 문서 관리 규칙

이 문서는 `docs/` 폴더의 구조와 현행 MVP 단일 기준 문서 작성 원칙을 정의합니다.

---

## 1. 단일 MVP 기준 원칙

1. **현행 규칙만 기록**: 모든 문서는 현재 MVP에서 적용 중인 단일 규칙과 명세만 작성합니다.
2. **과거 이력 배제**: 날짜별 변경 이력(`> 2026-10-...`), 이전 백엔드(Supabase 등) 비교 설명, 폐기된 시안 대조표를 현행 문서 안에 누적하지 않습니다.
3. **폐기 문서 분리**: 기준 설정에 방해되는 구버전 문서·초안·과거 검수 보고서는 모두 `docs/999. deletefile/`로 이관하며, 현행 문서에서 `999. deletefile` 내부 경로를 링크하지 않습니다.

---

## 2. 폴더 및 파일 이름 규칙

1. `docs/` 아래 현행 폴더는 `NN. 폴더명` 두 자리 번호(`00`~`04`)를 사용하며 같은 부모 폴더 안에서 번호를 중복하지 않습니다.
2. 파일 이름은 역할이 드러나는 한글 제목(`주제_역할.md`, `DB_객체사전.txt`) 또는 코드가 직접 참조하는 고정 식별자(`design-tokens.json`, `README.md`)를 사용합니다.
3. 파일 이름에 작성 날짜나 임시 버전 번호를 붙이지 않습니다.

사용자가 지정한 `docs/998. 일일 업무 보고서/YY.MM.DD/`는 일일 작업 결과를 보관하는 예외 경로입니다. 날짜는 실제 달력에 있는 날만 허용하며, 보고서 파일 이름은 작업 내용으로 정합니다. 이 예외는 다른 이름·위치의 3자리 번호 폴더나 일반 문서의 날짜 폴더로 넓히지 않습니다. 보고서도 인코딩·프로젝트 경계·링크 검사를 동일하게 받으며 현행 기능·디자인의 단일 기준은 기존 규격 문서에 둡니다.

일일 보고서 폴더의 `index.html`은 날짜·요일별로 읽고 작성하는 문서 사이트입니다. 날짜 폴더마다 원본 Markdown 보고서 한 개를 두고 `npm run reports:build`로 HTML을 다시 생성합니다. 생성본을 직접 편집하지 않습니다. 사이트에서 작성한 일지는 해당 브라우저에 보관되므로 파일 백업·가져오기로 옮깁니다. 화면에서 저장한 내용을 저장소의 원본에 자동 반영한 것으로 취급하지 않습니다.

## 작업 완료 때의 누적 순서

1. 한국 시간 기준 완료 날짜의 `YY.MM.DD/일일_통합_작업보고서.md`를 열거나 새로 만듭니다. 날짜와 요일을 확인하고 그날 핵심 작업을 제목에 적습니다. 같은 날의 기존 내용과 검증 이력은 보존합니다.
2. 작업 목적·변경 영역·개선 전후·실행한 검수와 결과·미실행 사유·남은 작업을 이어서 적습니다. 로컬 검사, 실제 외부 연동, 실기기, Git 반영, 운영 배포를 구분하고 수행하지 않은 내용을 완료로 기록하지 않습니다.
3. 사이트 요약에 쓰는 표도 갱신합니다. `완료 내용과 남은 범위`에는 `구분 / 완료한 내용 / 남은 항목·판정 범위`, 개선 표에는 `개선 전 / 개선 후`, `검증 환경·결과·증거`에는 `검사 / 결과 / 증거`, `남은 작업과 적용 순서`에는 `우선 항목 / 다음 확인·작업 / 현재 판정`을 사용합니다. 상세 설명은 그 아래에 누적합니다.
4. `npm run reports:build`를 실행하고 생성된 HTML에 날짜·요일·작업·개선·검수·후속 항목이 반영됐는지 확인합니다. `npm run check:docs`와 변경 문서·HTML의 서식도 검사합니다. 코드 변경은 프로젝트의 추가 필수 검사를 따릅니다.

에이전트가 남기는 공식 작업 기록은 프로젝트의 Markdown 파일과 생성 HTML입니다. 사이트에서 사용자가 직접 작성한 일지는 `tripprint.daily-journal.v1`이라는 이름으로 현재 브라우저 저장소(localStorage)에 보관합니다. 이 값은 프로젝트 폴더에 별도 파일로 자동 저장되지 않으며, `file://`로 연 페이지와 로컬 미리보기 주소의 저장 공간도 서로 다릅니다. 브라우저 기록은 백업 버튼으로 JSON 파일을 내려받아 보관하거나 다른 창에서 가져올 수 있습니다.

---

## 3. 검증 규칙

- 문서를 추가·수정·이동한 뒤에는 반드시 `npm run check:docs`를 실행해 폴더 번호, 인코딩, 로컬 마크다운 링크 무결성을 확인합니다.
- 디자인 토큰(`design-tokens.json`)을 수정한 경우 `npm run check:design`으로 WCAG AA 명도 대비(52개 항목)를 함께 검증합니다.
