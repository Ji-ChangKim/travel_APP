# 문서 관리 규칙

기준일: 2026-10-22 / 상태: 사용자 확정 규칙 적용 / 범위: docs 전체

## 폴더

- 모든 하위 폴더는 `NN. 폴더명`으로 작성합니다. NN은 두 자리 숫자이며 같은 부모 안에서 중복하지 않습니다.
- 번호는 위치와 정렬 순서입니다. 화면 번호나 문서 버전으로 사용하지 않습니다. 새 폴더를 만들 때 기존 번호를 다시 매기지 않습니다.
- `99. 아카이브`는 이전 기준과 이력을 보존합니다. `99`를 다른 일반 폴더에 사용하지 않습니다.
- 아카이브 바로 아래의 `99. 삭제필요`에 삭제 후보를 보관합니다. 사유·대체 문서를 기록하고 실제 삭제는 별도 사용자 지시 후 진행합니다.
- `98. keys`는 기존 비공개 설정 영역입니다. 내용은 일반 문서 검사·색인·정리 백업에서 제외하고 Git·빌드 제외 설정을 유지합니다.

## 파일 이름

| 종류               | 규칙                            | 예시                            |
| ------------------ | ------------------------------- | ------------------------------- |
| 계속 갱신하는 기준 | 주제_문서종류.확장자            | 여행일정_화면규격.md            |
| 날짜가 고정된 보고 | YYYY-MM-DD_주제_보고종류.확장자 | 2026-10-21_전체UI_폴리싱검수.md |
| 출시 안내          | v버전_문서종류.확장자           | v11_출시안내.md                 |
| 화면 문서·이미지   | 기존 Num_페이지명 유지          | 100_홈.html                     |
| 폴더 색인          | README.md                       | README.md                       |

날짜는 YYYY-MM-DD, 버전은 v11처럼 표기합니다. 최종·최신·사본2 등의 이름을 만들지 않습니다. 보존 원본과 과거 기록은 출처 식별을 위해 기존 이름을 유지할 수 있습니다. 디자인 토큰·콘텐츠 JSON·CSV·HTML·스크립트의 기술 식별자는 임의 번역하지 않습니다.

## 현행·이전·삭제 후보 구분

같은 주제의 현행 기준은 하나만 두고 다른 문서에서 연결합니다. 검토안은 승인된 기준과 분리합니다. 날짜가 오래됐다는 이유만으로 아카이브나 삭제 후보로 보내지 않습니다. 기능 계약·출처·이용 조건·실제 데이터·검수 근거는 용도를 먼저 확인합니다.

문서 첫머리에 상태·검토일·적용 범위를 기록합니다. 담당자가 확정되지 않았다면 임의로 사람 이름을 넣지 않습니다. 앱의 DB·API·UI 계약을 바꾸는 작업에서는 해당 기준 문서도 함께 수정합니다.

## 이동·검증

파일 이동 시 문서 링크, 코드 import, 생성 도구, 자산 매니페스트, Git·서식·빌드 제외 경로와 AGENTS.md를 함께 수정합니다. 경로에 공백이 있는 Markdown 링크는 꺾쇠로 감쌉니다. 외부 원본·이미지·바이너리는 바이트와 출처 해시를 보존합니다.

`npm run check:docs`는 번호 누락·중복, 99 폴더 용도, 비공개 영역을 제외한 Markdown의 로컬 파일 연결을 검사합니다. 링크의 본문 의미·앵커·외부 사이트 응답·HTML의 모든 실행 동작까지 보증하지 않습니다. 관련 코드 변경 후 `npm run check`와 필요한 회귀 검사를 통과해야 합니다.

검수 출력과 로컬 백업은 outputs에 두며 Git·배포에서 제외합니다. 필요한 검수 결과는 보고서에 요약합니다. 로컬 출력이 모든 개발 환경에 존재한다고 가정하지 않습니다.
