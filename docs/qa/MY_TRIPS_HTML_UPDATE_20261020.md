# 내 여행 있음·없음 HTML 적용

기준일: 2026-10-20. 사용자가 첨부한 두 HTML을 `/plans`의 등록 있음·없음 상태에 적용했다. 개인 여행과 공개 추천 모두 기존 조회 결과만 사용하며 예시 여행을 서비스에 등록하지 않았다.

## 적용

조회 성공한 개인 목록이 비어 있으면 가방·노트 모티프, 첫 여행 안내, 새 여행 계획 만들기, 실제 공개 일정 최대2개, 여행 시작 도움말을 표시한다. 실제 공개 목록도 비면 추천 카드는0개다. 검색 불일치·초기 로딩·조회 실패·인증 없음은 등록 없음과 구분한다.

여행이 있으면 My Trips 헤더, 내 여행 아카이브·새 여행, 네 상태 필터와 정렬, 실제 여행 카드, 새 여행 안내를 표시한다. 카드 표지는 일반 사진만 선택하고 영수증·가상의 도시 사진을 넣지 않는다. 사진이 없으면 단색 표지와 지도 아이콘을 표시한다. 날짜·D-day·진행 일차·기간 진행률·항공·숙소·장소 수·사진/영수증 수·다음 일정·준비물·공개 상태는 같은 여행 원본에서 읽거나 계산한다.

일정·다이어리·비용·공개 관리는 기존 실제 경로로 연결했다. 더보기에서 새 삭제·복제 기능을 만들지 않는다. 필터·정렬은 원본을 수정하지 않고 계정 변경 시 선택과 카드 수명을 초기화한다. 목록은 FlatList로 보이는 주변 카드만 렌더링하며 개인 상세와 같은 계정별 캐시·취소·권한 검사를 사용한다.

## 변경 범위

`MyTripsScreen.tsx`를 실제 조회·상태 선택의 연결 화면으로 추가하고 `/plans` 진입을 연결했다. `MyTripsControls.tsx`, `MyTripsEmpty.tsx`, `MyTripCard.tsx`, `MyTripsButton.tsx`, `myTripsModel.ts`, `myTripsStyles.ts`, `useMyTripDetails.ts`로 표현·동작·조회 책임을 분리했다. 화면 전용 파생 모델을 `docs/DB_DICTIONARY.txt`에 기록했으며 DB 테이블·컬럼·서버 계약은 바꾸지 않았다. `tests/auth/myTripsModel.test.ts`, `tests/web/myTrips.spec.ts`에서 새 계약을 검증한다. 병행 작업의 기존 변경은 보존했고 커밋·푸시·Android 빌드는 실행하지 않았다.

첫 배포 후 소스 대조에서 `TravelPlansScreen.tsx`가 이전 내용으로 바뀐 것을 발견했다. 기존 파일을 다시 덮는 대신 새 화면을 `MyTripsScreen.tsx`로 분리해 `/plans`에서 직접 연결하고 기존 파일은 보존했다. 분리 뒤의 최종 코드 검사·브라우저 결과는 `check-delivery.log`, `browser-isolated.log`로 구분한다. 중간 `check-isolated.log`, `check-source-final.log`의 서식 실패는 이후 공개 발자국 진입 파일의 서식을 바로잡아 재검사했다. 기존 공개 발자국 진입도 최신 요청의 `PublicFootprintsScreen` 연결을 유지한다.
