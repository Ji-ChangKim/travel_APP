1. 결과
불필요한 파일 8,339개를 정리했다. 파일 크기 합계는 4,689,176,828바이트, 약 4.37GiB다. 새 검수 출력과 복원용 압축본을 제외하기 전의 정리 대상 합계이며, 운영체제에서 측정한 실제 디스크 회수량은 아니다.
활성 앱은 apps/mobile/src이며 루트 src는 실행·타입 검사 경로에서 쓰이지 않았다. 루트의 예전 초기 스토어에는 제주·도쿄 여행, 일정·비용·멤버와 user-me 데모가 실제로 남아 있었다. 이 프로토타입과 기본 Expo 이미지를 제거하고 복원본을 보관했다.
메모리 누수 없음으로 판정하지 않았다. 요청 취소, 구독 종료, 캐시 제거, 반복 시트 진입의 DOM 수명을 검사했다. Android 힙·PSS·GPU·네이티브 이미지 메모리는 이번에 직접 측정하지 않았다.

- 기존 APK/AAB·디버그 keystore 5개는 최초 목록과 같은 파일 크기로 보존했다. 최종 app-release.aab와 APK의 메타데이터도 유지했다.
- 소스·기본 이미지 24개는 원래 상대 경로로 복원할 수 있는 ZIP을 만들고 삭제 전 SHA-256과 일치함을 확인했다.
- 디자인 원본, 승인 로고·하루, 사용자 사진·영수증, 로컬 DB·환경 변수·키·실제 여행 데이터, 기존 검수 자료는 보존했다. 테스트 fixture와 과거 백엔드 스키마도 검수·참고 자료로 남겼다.
- README의 과거 실행 경로·백엔드·기본 아이콘 안내를 현행 구조로 정리했다. EAS 업로드에서는 보고서·화면 제작 자료를 제외하고 런타임 토큰은 유지한다.

3. 요청·사진 자원 관리
- 여행 목록·여행 원본·사진 주소·공개 피드 조회에 TanStack 취소 신호를 연결했다. 홈 브리핑·표지·발자국·기록·내 여행·장소 가져오기·알림도 같은 읽기 계약을 사용한다.
- 마지막 조회 구독이 해제되면 전송을 취소한다. 다른 화면이 같은 여행을 읽고 있으면 연결을 유지한다. 화면 취소 신호를 추가해도 15초 통신 제한 시간이 사라지지 않게 했다.
- 저장 요청에는 화면의 조회 취소를 연결하지 않았다. 저장 중 화면 이탈을 이유로 쓰기를 취소하거나 자동 재전송하지 않는다.
- 개인/공개 일반 사진은 화면 초점과 전경 상태에 맞춰 주소 자동 갱신을 켜고 끈다. 60초짜리 서명 URL에 맞춰 활성 화면의 45초 갱신은 유지하고, 비활성 캐시는 60초 후 정리한다. 이미 시작한 공유 요청은 다른 구독과의 충돌을 피하며 15초 제한 시간을 따른다.
- Google 장소 사진과 공개 계획 조회에도 15초 제한 시간을 적용했다. Google 사진 재조회 실패 시 이전 주소를 정상 사진처럼 계속 표시하지 않는다.
- 일반 사진·공개 사진·장소 썸네일은 Android의 resizeMethod="resize"를 사용한다. 화면 크기·비율과 원본 파일은 바꾸지 않았다. 실제 Android 디코딩 메모리 절감량은 아직 측정하지 않았다.
- 기존 이미지 업로드는 큰 원본 전체 복사 전 헤더 검사, 압축본·렌더 객체·파일 핸들·blob URL 정리를 이미 수행하고 있었다. 위치 조회·접근성 이벤트·시트 이벤트·시작 영상 구독과 게스트 저장 큐에도 정리 코드가 있었다. 누수라고 단정해 중복 정리를 추가하지 않았다.

4. 목록 최적화와 더미 방지
- 발견 목록의 ScrollView 전체 렌더링을 FlatList로 바꿨다. 초기 4개·배치당 4개·주변 5화면 범위로 렌더링한다. 행 높이는 고정하지 않고 기존 카드·필터·간격·글자·버튼을 유지한다. 신고 초안은 화면 상태에 보관한다.
- 피드 캐시에 카드용 값만 보관한다. 긴 body·DAY 소개·장소 설명/팁·비용·일정 배열은 원본을 참조하지 않고 상세 진입 시 재조회한다. 서버 응답과 저장·공개 계약은 유지한다. 비영속 읽기 모델은 DB_DICTIONARY.txt에 기록했다.
- 실제 공개 3건에서 캐시 값의 JSON UTF-8 크기는 37,546바이트에서 714바이트로 줄었다(98.10%). 실제 힙 사용량이나 서버 전송량 감소율은 아니다. 수천 건의 실제 피드 스크롤 부하는 이번에 측정하지 않았다.
- 호출처가 없는 이전 공유·OCR API 도우미와 과거 기본 서버 주소를 제거했다. 현재의 실제 공유·OCR 기능은 기존 서비스 경로를 유지한다.
- 배포 산출물 검사는 예전 trip-demo-1/2가 다시 유입되는 경우도 거부한다. 새 웹 출력의 JavaScript 2개에서 검사 대상 더미·비밀 값 0건을 확인했다. 전역 소스 문자열만으로 모든 종류의 더미 부재를 증명하는 검사는 아니다.
- staging에 이미 저장된 QA 게시물과 사용자 오사카 원본은 수정·삭제하지 않았다. 이 기록은 제품 코드에 내장된 더미와 구분했다.
