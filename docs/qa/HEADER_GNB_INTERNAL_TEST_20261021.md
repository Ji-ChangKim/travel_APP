# 헤더·GNB 커밋 및 내부 테스트 인계

기준일: 2026-10-21. 사용자 요청에 따라 헤더·GNB와 필수 연결 코드만 커밋·푸시한다. Android 빌드·Play 업로드·서버 배포는 실행하지 않는다.

## 커밋 범위

- 공통 헤더·제목·행동·브랜드·GNB, 로딩·인증 복구 오류와 화면별 복귀 연결.
- /plans 탭 수명, 공개 발자국과 개인 보관함 구분, 해당 화면을 구성하는 내 여행·공개 목록의 필수 연결 모듈.
- 기존 목록의 일정 담기 연결에 필요한 클라이언트·입력 검증 의존성. 이번 커밋에서 API 서버 구현은 변경하지 않는다.
- 규격 우회 자동 검사, 관련 검수와 디자인 문서. 현재 작업 파일을 한꺼번에 추가하지 않고, 일부 파일은 헤더 관련 변경만 선택한다.

다른 채팅의 홈 본문 개편, 새 타임라인·추천/개인 계획 상세 화면, 계정·서버·저장 구조 정리, Android workflow·릴리스 메타데이터 변경은 이번 범위에서 제외한다. 원래 작업 폴더의 변경은 보존한다. 커밋 후보는 HEAD에 선택 변경만 적용한 별도 복사본으로 검증한다. 기존 작업 폴더에서 통과한 결과와 이 후보의 결과는 구분한다.

헤더용 미사용 스타일을 제거하면서 HEAD의 홈 ‘전체 보기’가 참조하던 배치는 본문 전용 exploreLink로 분리했다. 기존 홈 본문의 배치·값을 유지한다. 목록에 이미 연결된 일정 담기가 기기 게스트에서도 동작하도록 클라이언트·기기 모델의 필수 연결을 함께 포함한다. Expo가 만드는 무시 파일 없이도 새 체크아웃에서 타입 검사가 되도록 tsconfig의 expo/types도 명시했다.

커밋·후보 검증 결과는 작업 완료 후 이 문서의 마지막 기록과 최종 보고에서 확인한다. 빌드할 소스는 최종 보고의 커밋이 포함된 원격 main이며 해당 커밋의 필수 CI 통과를 먼저 확인한다.

## 빌드 준비 상태

**판정: 헤더 변경은 검증 후 반영하되 Android 빌드 착수는 보류한다.** 부분 화면 검수만으로 앱 전체 CI나 Play 설치본 인수를 완료했다고 판단하지 않는다.

| 항목                  | 상태·조건                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 앱 버전               | ver.text의 versionCode 9 / versionName 0.1.0 유지. Play에서 9를 이미 사용했다면 다음 업로드 전에 더 큰 번호 필요 |
| 앱 식별자             | com.tripprint.app, 앱 복귀 scheme은 travelapp                                                                    |
| 빌드 경로             | GitHub Actions의 Android Play Internal, main에서 사용자가 수동 실행                                              |
| 필수 코드 검사        | npm run check에 디자인·코드 경계·헤더/GNB·타입·린트·포맷 포함                                                    |
| 전체 회귀             | 이전 작업 기록에 미통과 항목이 남아 있음. 이번 헤더 부분 검사와 구분하고 대상 커밋의 전체 CI를 확인해야 함       |
| 서명·지도 설정        | 기존 업로드 키와 GitHub Secrets의 존재·유효성, Play 앱 서명 인증서 SHA-1 제한은 빌드 계정에서 확인 필요          |
| 서버                  | 기존 staging 사용. 앱 빌드에 서버 비밀 값을 넣거나 서버를 다시 배포할 필요 없음                                  |
| 실제 로그인·기기 검수 | 새 Play 설치본에서 사용자 직접 확인. 이 인계에서는 Google 로그인·OS 권한·TalkBack을 통과로 기록하지 않음         |
| 실행 여부             | Android 컴파일·서명·AAB 생성·Play 등록 모두 미실행                                                               |

기존 전체 회귀 보류는 [빌드 안내](../ANDROID_GITHUB_BUILD.md)와 작업 폴더의 PREBUILD_V9_20261021 기록을 참고한다. 이 과거 기록의 실패 수를 이번 선택 커밋의 현재 실패 수로 옮겨 쓰지 않는다. 새 커밋의 CI가 모두 통과한 뒤 빌드를 시작한다. 필수 검사를 삭제하거나 생략하지 않는다.

R8 mapping.txt의 필수 확인·다운로드 포함을 추가한 Android workflow 변경은 다른 작업의 미커밋 파일이므로 이번 범위에 넣지 않는다. 원격 main의 기존 workflow에서 매핑 파일이 함께 내려온다고 안내하지 않는다. 빌드 담당자가 해당 인계 변경을 별도 반영하거나 매핑 파일을 확보하는 절차를 정리해야 한다.

## 사용자가 빌드를 시작할 순서

1. 원격 main에 최종 보고의 커밋이 포함됐는지 확인한다. 해당 소스의 전체 CI가 통과하기 전에는 빌드를 시작하지 않는다.
2. Play에서 versionCode 9 사용 여부와 기존 업로드 키를 확인한다. GOOGLE_MAPS_ANDROID_API_KEY, ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS, ANDROID_KEY_PASSWORD를 GitHub Secrets에서 확인한다.
3. Android Play Internal → Run workflow → main → artifact_type=aab, submit_play=false, release_status=draft로 사용자가 실행한다.
4. 성공한 실행의 Artifacts에서 AAB를 받아 버전·커밋·서명·SHA-256과 mapping.txt를 기록한다. 실제 산출물의 존재·유효성은 빌드 후 확인한다.
5. Play Console 내부 테스트에 수동 등록하고 같은 테스터 계정으로 업데이트한다. 위 점검표를 실행한다.

AUTH_SECRET·GOOGLE_CLIENT_SECRET·GOOGLE_PLACES_API_KEY는 서버 전용이며 앱 빌드에 복사하지 않는다. Stitch MCP 키도 배포 대상이 아니다. 이번 작업에서 workflow를 실행하거나 빌드를 시작하지 않는다.
