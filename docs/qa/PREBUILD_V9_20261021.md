## 이번 보완

정적 공개 메타데이터의 이전 v5 표기를 현재 v9와 일치시켰다. `versionCode`를 추가하고 날짜·후보 식별자를 갱신했다. 버전·공개 메타데이터 일치 검사를 추가했으며 빌드 입력 해시에 공개 파일과 workflow·EAS 설정도 포함한다.

검수 서버가 `/public/community/:id`를 앱 상세 주소로 잘못 해석해 종료되는 문제를 고쳤다. 앱 최상위 상세 경로만 실제 존재하는 템플릿에 연결하고, 없는 파일 요청 뒤에도 서버가 계속 응답하는 회귀 검사를 추가했다.

예전 회귀 검사의 신고 메뉴·내 여행 문구·초안 이탈 경로를 현재 화면 계약에 맞췄다. 저장 중 잠금, 명시적인 삭제 확인, 입력 보존, 공개 범위와 원본 보존 검증은 유지한다. 이전 검수 서버 중단·검사 기대값 실패 기록은 삭제하지 않고 별도 로그로 보존한다.

GitHub AAB workflow에 비어 있지 않은 `mapping.txt` 확인과 같은 다운로드 자료에 보관하는 단계를 추가했다. 이번에는 mapping.txt나 AAB를 생성하지 않았다. 이전 빌드의 가독화 파일을 새 후보의 결과물로 사용하지 않는다.

## 빌드 입력과 인계

`TripPrint_261021_Ver09_PrebuildInputs.json`에 JDK 21·Android SDK·기존 업로드 키 파일의 존재, Git 제외, R8·리소스 축소·최적화 ProGuard와 매핑 인계를 기록했다. 서명 비밀 원문은 읽거나 로그에 남기지 않았다. 파일 존재 확인은 실제 서명 성공이나 GitHub Secrets 유효성 검증을 대신하지 않는다.

사용자가 직접 진행하는 경로는 `docs/ANDROID_GITHUB_BUILD.md`다. GitHub에서는 최신 변경분이 원격 main에 반영되고 필수 CI가 통과한 커밋으로 Android Play Internal을 실행한다. 선택값은 aab, submit_play=false, draft다. 이번 작업에서는 커밋·푸시·workflow 실행·원격 배포를 하지 않았다.

Play에서 9번을 이미 사용했는지, 기존 업로드 서명과 지도 키의 GitHub Secrets가 준비됐는지, Android 지도 키가 Play 앱 서명 인증서로 제한됐는지는 빌드 계정에서 확인해야 한다. 실제 Google 로그인·앱 복귀·지도·카메라·권한 복귀·게스트 기록 보존은 새 Play 내부 테스트 설치본에서 별도 인수한다. USB 검수는 요청하지 않는다.

OCR·항공의 과거 오류는 `OCR_FLIGHT_REPAIR_20261016.md`에서 수정·실제 검수한 이력과 구분한다. 이번 로컬 후보 검사만으로 외부 공급자의 현재 서비스 상태를 다시 승인하거나 과거 오류가 남아 있다고 단정하지 않는다.

## 전체 화면 검사와 남은 수정

전체 225건은 3개 격리 브라우저로 끝까지 실행했다. 결과는 **170건 통과·55건 실패·건너뛴 검사 0건**이다. 근거는 `workspace-final.log`, `workspace-final-results.json`과 `TripPrint_261021_Ver09_WorkspaceFailures.json`이다. 실패 지점의 실제 화면과 검사 기대값을 먼저 대조해야 하며, 모든 실패를 제품 결함이나 단순한 검사 오류로 일괄 분류하지 않는다.

후속으로 공개 탐색·빈 공개 목록의 홈 이동·상세/작성 화면의 GNB 숨김 및 목록 복귀·세션 15초 제한을 순차 재확인해 **4/4 통과**했다(`workspace-repaired.log`). 앞의 170건에 더해 전체 174건 통과로 표시하지 않는다. 전체 실행 중 검수 코드의 일부 문구·목록 이름을 보완했으므로 최종 검수 소스로 다시 전체 회귀를 통과해야 한다.

남은 검토 범위:

- 공유: 이전 ‘공개 내용 작성’·한 화면 미리보기 기대값과 현재 선택→미리보기→확인의 단계 대조. 공개 항목·개인 메모·영수증 제외·응답 유실·충돌 보호를 유지하며 검사 갱신과 제품 수정을 구분한다.
- 개인 기록: 공개 발자국 `/footprints`와 개인 보관함 `/my-footprints`, 현재 다이어리의 제목·비용·기록 행동을 기준으로 이전 경로·문구 검사 재정리.
- 내 여행·권한: 네 필터·각 카드의 현재 행동, 자정 상태 갱신, 보기 전용에서 숨기는 작성 행동을 실제 화면과 대조. 일부 접근성 이름만 갱신했으며 전체 검수는 미완료다.
- 달력·헤더: 390 이하에서 날짜 입력 필드로 바뀌는 반응형 동작, 26/36 공통 제목, 출처 시트의 글자 확대, 공개 발자국 브랜드 헤더 예외를 현행 문서와 대조.
- 배치: 빈 일정의 두 안내 버튼과 고정 행동 바 경계에서 자동 검사가 2px 겹침을 관측했다. 실제 화면·스크롤·터치 범위의 추가 대조가 필요하다. 허용 오차만 늘려 성공 처리하지 않았다.
- 기타: 사진/금액 요소 범위, DAY 편집·직접 공개 링크·공개 이미지 복구, BI 시간 검사 등 나머지 실패도 위 실패 목록을 기준으로 재현·분류 후 수정한다.

위 범위를 통과시키기 위해 제품을 예전 시안으로 되돌리거나 필수 workflow 검사를 삭제·생략하지 않았다. 현재 검수 소스와 화면이 일치하는지 확인한 뒤 수정→관련 검사→전체 회귀 순서로 검증해야 한다.
