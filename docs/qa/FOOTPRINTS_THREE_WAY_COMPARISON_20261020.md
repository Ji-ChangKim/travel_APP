## 데이터·촬영 조건 때문에 생긴 차이

- 초안은 오사카·교토·제주 예시 카드3개이며 구현 캡처는 실제 ‘북큐슈’ 검색 결과1개다. 하단 빈 공간만으로 목록 누락이나 과도한 카드 간격이라고 판단할 수 없다.
- 온천 사진·가이드 하루·2026년12월·긴 북큐슈 제목은 실제 공개 일정의 값이다. 제목 두 줄에는 실제 문장 길이와 구현 행간이 함께 영향을 준다.
- 검색 화살표의 빨간 원은 클릭 후 남은 포커스 표시다. 기본 상태의 장식으로 설계된 원형 버튼과 구분해야 한다.
- 알림·프로필과 로그인, 하단 메뉴 개수는 계정 조건이 다르다. 동일한 계정 상태로 다시 비교해야 한다. 시안에 있는 알림 점이나 작성자 사진을 실제 값 없이 생성해서는 안 된다.

## 작업과 검수에서 잘못된 점

기존 읽기·터치 기준을 적용하면서 보이는 칩·행동 영역까지 일괄 확대했다. 터치 영역 확보와 보이는 요소의 크기를 나눠 검토했어야 한다. 넓힌 터치 영역이 인접 버튼과 겹치지 않는지도 함께 확인해야 한다.

현재 서버가 지원하지 않는 동행·월 조건을 기존 공개 유형으로 바꾸고 이를 디자인 차이로만 처리했다. 필터의 의미가 달라지는 기능 변경이므로 필요한 데이터와 조회 계약을 별도 정리했어야 한다.

`FOOTPRINTS_PUBLIC_FEED_SPEC.md`와 이전 검수 보고서에 이 변경을 기록했지만 문서화 자체가 사용자 확인을 대신하지는 않는다. 원본과 다른 선택을 구현자가 문서에 반영하고 그 문서를 기준으로 완료 판정을 내린 문제가 있다.

기존 브라우저12건·실제 DB 조회1건은 기능 동작의 근거다. 동일한 화면 폭·계정·검색·카드 데이터에서 원본과 비교한 시각 일치 근거로 사용할 수 없다. 현재 결과의 디자인 승인은 보류하는 것이 맞다.

## 수정할 때의 기준

1. 너비390·글자100%·동일 계정·검색 초기 상태·동일한 카드 데이터로 비교한다. 실데이터 검색 검수는 별도 유지한다.
2. 최신 HTML의 상단 밀도·작은 칩·공유 안내·보조 배지·사진 명암·푸터를 우선 재현한다. 글꼴·공식 로고·계정 메뉴에서 유지할 공통 규격과 차이는 명시한다.
3. HTML에 빠진 검색 input은 작동하도록 보완하되 큰 검색창과 추가 버튼의 필요성을 다시 검토한다. 원본 결함을 이유로 전체 높이를 임의로 확대하지 않는다.
4. 여행지·기간·동행·월 조건의 데이터와 동작을 정하고, 지원하지 않는 조건을 다른 의미의 필터로 대체하지 않는다.
5. 작은 화면·큰 글자·긴 제목·빈 목록·오류 상태를 확인한 뒤 원본과 실제 캡처를 다시 대조한다. 기능 통과와 디자인 판정을 각각 기록한다.
