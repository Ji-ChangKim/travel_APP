# TripPrint Git 통합 및 빌드 준비

최신 Git 정리: codex/release-integration-20261016에 코드·테스트·DB 명세102파일을 a376450로 커밋했습니다. 문서·캡처는 후속 커밋으로 보관합니다. main과 기존 헤더 브랜치는 유지하며 푸시하지 않았습니다. [Git 통합 기록](GIT_INTEGRATION_20261016.md)을 따릅니다.

OCR·항공은 실제 staging 핵심5/5가 통과했습니다. Play 버전8·Android 지도 키 제한 및 새 설치본 인수는 별도 확인입니다. 빌드 결과물은 아직 생성하지 않았습니다.

## 이전 준비 기록

아래의 미커밋·서비스 실패·이전 소스 해시는 과거 준비 단계의 이력입니다. 현재 소스와 Git 반영 상태는 위 통합 기록을 기준으로 봅니다.

기준일: 2026-10-16 / Asia/Seoul

기획·UI/UX의 마지막 작업 종료 후 최종 점검을 마쳤다. Google 사진19/19와 인증 Places 검색은 실제 성공했으며, 현재 남은 주요 서비스 조건은 OCR·항공 조회다. R8 재생성 설정을 보완한506파일 후보와 모델207/207·D1/R220/20·릴리스49/49·전체 코드 품질 통과를 고정했다. 전체 서비스·AAB 실행은 HOLD다. 최신 판정은 [최종 검토](FINAL_RELEASE_REVIEW_20261016.md)를 따른다. 아래14/19·16/19와 미등록 Places 기록은 이전 단계의 이력이다.

원문 6,080자는 DAY·장소별 계획으로 보존하도록 보완했다. 게시 본문 2,000자 제한은 유지하며 일차 테마·19장소 설명·선택/대체 관계를 별도로 저장·공개한다. 현재 원문 지원 선택을 기다리는 상태가 아니다. 추가 보완 이후의 계약·검수·소스 해시는 여행계획 공유 계약 문서를 따른다.

## Git 반영 준비

현재 체크아웃은 main, HEAD는 b74926fc69437a7bb2fe031f922848006198bc7c다. 로컬 참조 기준 origin/main도 같은 커밋이다. 이번 확인에서 fetch는 실행하지 않았으므로 원격의 최신 상태를 보증하지 않는다.

헤더 전용 브랜치 codex/haru-header-standard-20261016와 해당 origin 추적 참조는 c221824를 가리킨다. 담당 보고상 업로드가 끝났으며, main에는 아직 포함되지 않았다. 현재 작업 폴더에는 헤더 변경과 고객 흐름·지도·공유 계약·테스트 변경이 함께 남아 있다. 헤더 커밋 하나를 전체 기능 승인본으로 쓰지 않는다.

Git에 넣을 변경 목록과 파일별 SHA-256은 다음 로컬 자료에 보관한다.

- .release/git-update-preparation/TripPrint_261016_Ver08_GitReadiness.json
- .release/git-update-preparation/TripPrint_261016_Ver08_MobileSource.json

목록은 Git이 추적하는 수정·삭제 파일과 Git 제외 대상이 아닌 신규 파일을 포함한다. 전체 빌드 입력 목록과는 범위가 다르다. 모바일·공유 모델·에셋·네이티브·빌드 도구 500파일 해시는 기존 승인값 cbb78cc7fd368b850c982417aea5e8a1d6d8e141ee55e339fa34b6531af5a10f와 일치했다.

반영 순서:

1. 기획의 추가 게시 확인에서 코드나 계약 수정이 생겼는지 확인하고 변경 목록·검수 해시를 다시 고정한다.
2. 현재 변경을 보존한 codex/ 접두사의 통합 브랜치에서 최종 내용을 검토한다. 변경이 남은 main에서 헤더 브랜치를 즉시 병합하거나 파일을 덮어쓰지 않는다.
3. 헤더·캡처 정리와 고객 흐름·공유 계약·지도·빌드 도구를 구분해 검토한다. PlanEditor·FlightTicketEditor·TripPlanningFlow·workspace.spec.ts의 양쪽 변경이 함께 보존되는지 확인한다.
4. .env·.dev.vars·docs/98. keys·서명 파일·outputs·scratch·.release는 Git 반영에서 제외한다. 필요한 코드·테스트·DB_DICTIONARY·규격·검수 문서는 포함한다.
5. 통합 후보의 npm run check 및 변경 범위 검사를 확인한 뒤 커밋·푸시를 진행한다. 실제 반영 시 먼저 원격 변경을 확인한다.

커밋 메시지 초안:

`feat: 여행 기록 고객 흐름 및 지도 검색 통합 : 항공권 입력 복구·영수증 동일 ID 수정·기록 정리와 선택 공개 연결, 공통 헤더·회귀 검사·실제 staging 실패 인계 반영`

이미 업로드된 헤더 커밋을 통합하는 방식을 선택하면 해당 커밋을 보존하고, 후속 커밋 설명은 남은 변경만 기준으로 다시 작성한다. main에서만 실행되는 Android Play Internal workflow는 workflow_dispatch 방식이다. Git 반영과 실제 빌드 실행을 각각 관리한다.

현재 저장소의 CI는 main push·pull_request에서 검사한다. 웹·Worker 배포 workflow와 Android 빌드는 workflow_dispatch 방식이므로 Git 업데이트만으로 해당 배포 workflow를 실행하지 않는다. 원격 저장소 설정은 이번 확인 범위에 포함하지 않았다.

## 이번 작업 기록

Git 상태·브랜치·변경 파일 목록·모바일 승인 해시·Git 제외 규칙을 읽어 대조했다. 변경 후보에 민감 경로 및 네 가지 고신뢰 비밀 패턴을 검사했다. 이 제한된 검사는 전체 보안 감사를 대신하지 않는다. 검사 결과와 파일별 해시는 로컬 JSON에 기록했다.

현재 후보의 전체 코드 품질 검사는 scratch/git-readiness-check-20261016.log에 기록한다. 완료 결과는 이 문서의 마지막 기록을 따른다. 과거 검수 숫자를 새 실행 결과로 재사용하지 않는다.

이번 실행 결과: npm run check 종료코드 0. WCAG AA 토큰 46/46, TypeScript·ESLint·Prettier 모두 통과했다. 이후 수정한 이 보고서는 별도 포맷 검사로 확인한다. git diff --check도 통과했다. 변경 후보의 제한된 비밀 패턴 검사 발견 건수는 0이며, 환경·키·서명·QA 증거 경로의 Git 제외를 확인했다. 이는 Git 준비 점검 결과이며 실제 서버의 5개 실패를 해소한 결과는 아니다.

이 작업에서 앱·서버 코드, DB, 키, Git 인덱스, 브랜치를 변경하지 않았다. AAB/APK 생성·원격 배포·Play 업로드·커밋·푸시는 실행하지 않았다. 보고서와 로컬 준비 자료만 추가했다.

## 추가 여행계획 보완 이후

위 Git 목록과 500파일 해시 일치 기록은 추가 여행계획 공유 구현 전의 점검이다. 사용자는 원문을 여행계획으로 보존하도록 정정했고, 이에 따라 DAY 테마·장소별 설명·선택/대체 관계·명시 계획 공유·단건 공개 조회를 보완했다. 기존 목록을 새 최종 후보로 쓰지 않는다.

서버·공통 모델의 채택 계약과 검사 결과는 [여행계획 공유 계약](COMMUNITY_PLAN_CONTRACT_20261016.txt)을 따른다. 모델·인증 206/206, 관련 API 11/11, 로컬 D1/R2 18/18, 릴리스 48/48 및 npm run check가 통과했다. 기획 담당의 병행 UI와 실제 게시 검수는 따로 인수해야 한다. 원격 staging 반영·AAB 생성·커밋·푸시는 실행하지 않았다.
