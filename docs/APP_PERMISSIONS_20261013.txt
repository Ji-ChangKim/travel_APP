TripPrint 시작 권한 안내 변경 보고서 — 2026-10-13

1. 사용자 동작
- 시작 인트로 이후 로그인 화면 또는 복원된 여행 화면에서 알림·위치 안내를 모달로 표시한다.
- 두 권한은 선택 사항이며 각각 허용 버튼을 눌렀을 때만 운영체제 권한 창을 연다.
- 허용됨 / 다시 요청 가능 / 기기 설정 필요 상태를 운영체제 응답으로 구분한다.
- 거절해도 '이대로 시작하기'로 계속 이용한다. 안내를 닫은 기록을 이 기기에 보관하여 실행마다 반복하지 않는다.
- 홈 > 여행 도구 > 앱 권한 설정에서 안내를 다시 연다. 설정에서 돌아오면 실제 상태를 다시 조회한다.
- 타이틀은 한 줄로 표시한다. 작은 화면·큰 글자에서는 내용 영역을 스크롤할 수 있다.

2. 실제 기능 연결
- 알림: 기존 여행 출발일 오전 9시 기기 알림 예약에 허용 결과를 연결한다.
- 서버 공지 푸시 발송·개별 일정별 알람은 이번 권한 추가만으로 구현된 기능이 아니다. 관련 화면에서 작동한다고 안내하지 않는다.
- 위치: 홈 > 여행 도구 > 현재 위치 지도에서 보기에서 사용 중 위치를 읽어 실제 좌표로 외부 Google Maps를 연다.
- 위치 허용 없이 버튼을 누르면 권한 안내로 연결한다. 위치 허용 후 지도 버튼을 다시 누른다.
- 한 번의 위치 결과, 오류, 12초 시간 초과, 화면 종료, 앱 이탈 시 위치 구독과 타이머를 정리한다. 지연된 구독 생성 응답도 정리한다.
- 좌표는 이번 지도 열기의 메모리에서만 사용하며 서버·기기에 저장하지 않는다. 지도 링크에는 선택한 현재 좌표가 포함된다.
- Google Maps가 자체적으로 사용하는 위치 권한은 해당 앱에서 관리한다. 유료 Places API 활성화나 키 반영은 수행하지 않았다.
- 카메라·사진 선택 권한은 해당 기능 사용 시점의 기존 요청을 유지한다. 백그라운드 위치·마이크·동작 인식 권한을 추가 요청하지 않는다.

3. 변경 파일
- features/notifications/NotificationPermission.tsx: 기존 알림 토스트를 통합 모달 연결로 변경.
- features/permissions/PermissionModal.tsx: 두 선택 권한의 모달 UI.
- features/permissions/usePermissions.ts: 최초 안내·설정 복귀·중복 클릭·늦은 응답·닫기 처리.
- features/permissions/permissionService.ts: 실제 권한 조회·요청·Android 알림 채널·안내 확인 저장·다시 열기 상태.
- features/permissions/permissionModel.ts, permissionFlow.ts: 상태별 요청/설정 동작 및 지도 좌표 검증.
- features/permissions/oneShotLocation.ts: 한 번의 위치 조회와 구독 수명 정리.
- features/permissions/PermissionTools.tsx, workspace/HomeTools.tsx: 실제 현재 위치 지도와 권한 다시 열기 도구.
- app/_layout.tsx: 시작 인트로 이후 안내를 연결.
- app.config.ts: expo-location 설정. 사용 중 위치만 설정하고 상시·백그라운드·동작 인식은 제외.
- package.json / package-lock.json: npx expo install expo-location로 SDK 57 호환 모듈 추가.
- 현재 AndroidManifest.xml: POST_NOTIFICATIONS, ACCESS_COARSE_LOCATION, ACCESS_FINE_LOCATION 등록. 네이티브 폴더는 기존 정책대로 Git 제외.
- tests/auth/permissions.test.ts: 권한 요청 분기와 위치 수명 검증 10개.
- docs/DB_DICTIONARY.txt: 기기 안내 기록과 권한 메모리 객체 명세 추가. 서버 DB 변경 없음.

5. 배포 적용
- 이번 변경은 네이티브 위치 모듈이 추가되어 Android Studio에서 Gradle Sync 후 APK/AAB를 다시 빌드해야 한다.
- 이전 final-audit Android 번들/ZIP은 이번 권한 UI 변경 전 자료다. 새 앱 배포에는 Android Studio의 현재 소스 빌드 결과를 사용한다.
- 이번 작업은 서명 APK/AAB 생성·기기 설치·Play 업로드를 수행하지 않는다. 실제 Android의 권한 허용/거절 창과 알림 수신/GPS 지도 열기는 새 빌드 기기에서 최종 확인한다.
- 웹에서는 시작 권한 모달과 위치 도구를 표시하지 않으므로 이번 변경에 서버·웹 업로드는 필요하지 않다.
- 기존 사용자 변경 파일과 서명 자료 보존. Git 커밋·푸시 없음.
