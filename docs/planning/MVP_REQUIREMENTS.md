## 제품 범위

여행 계획을 만들고 동행자와 같은 일정을 관리하는 흐름을 MVP 중심으로 둔다. 기존 PRD를 따른다.

| 단계             | 포함 기능                                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| MVP              | 회원가입/로그인, 여행 CRUD·DAY, 일정 CRUD·순서, 장소 검색/저장, 지도 마커·DAY 필터, 수동 예상/실제 비용, 체크리스트, 초대·역할, 내 여행/상세 |
| MVP 후반 또는 P1 | Realtime, 촬영/OCR, 후보 장소, Today, 사진/후기/기록, 담당자·알림                                                                            |
| P2/Future        | 동행 비용 정산, 실시간 위치 공유, 자동 동선 최적화, 예약, 공개 검색/팔로우, AI 일정 생성                                                     |

Public Trip/복제는 PRD 5장에서 P2로 분류되어 있다. 초대 진입용 웹 안내와 공개 여행 웹은 별개이며 D-03에서 출시 범위를 확정한다. 실제 경로 선 표시 시점도 공급자 선정과 함께 결정한다. 게스트는 구현되어 있으나 MVP 제품 정책은 미확정이다.

## MVP 통합 인수 시나리오

PRD 14.1을 재현한다. 빌드/환경·계정·절차·기대/실제 결과·증거를 남긴다.

1. A가 와카야마 5박 6일 여행을 생성한다. DAY1~6와 재실행/새로고침 후 보존을 확인한다.
2. DAY2에 실제 검색한 시라하마·토레토레 시장을 저장한다. 좌표/순서 보존 및 지도 ①② 마커를 확인한다.
3. 제목/시간을 수정하고 순서를 바꾼 뒤 재조회한다. DAY1에 DAY2 마커가 나오지 않아야 한다.
4. A의 EDITOR 초대를 별도 계정/기기 B가 수락하고 DAY3 일정을 추가한다. A 재조회 결과도 같아야 한다. Realtime 인수는 D-10에 따른다.
5. VIEWER C와 미참여 D의 접근을 검증한다. UI와 직접 서버/DB 요청 모두 금지 행위를 거부해야 한다.
6. 예상/실제 비용·체크리스트를 저장한다. DAY/여행 합계와 재접속·멤버 조회 일치를 확인한다.
7. 만료/중복 초대·네트워크 실패·잘못된 날짜·기간 축소·삭제를 확정 정책대로 검증한다.
8. `npm run check`, 웹 빌드와 대상 실기기 핵심 흐름 결과를 연결한다. 전 필수 요구사항 통과와 오너 인수 후 MVP 완료로 변경한다.

## 작업 분해 기준

각 작업은 요구사항 ID·담당·선행 결정·수정 대상·완료 기준·검증 결과를 가진다. 인증/저장 → 일정 → 장소/지도 → 비용/체크 → 초대/권한 → 통합 QA 순으로 의존성을 관리한다. 일정·출시일은 선행 결정과 작업량 산정 후 기록한다.
