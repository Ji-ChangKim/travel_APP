# 한국공항공사 항공편 API 검토

- 작성일: 2026-10-14
- 버전: 1.1.0
- 대상: 사용자가 제공한 일반 인증키 방식의 공공데이터 API 연결.
- 상태: 등록된 로컬 키로 실제 조회 완료. 아래 초기 검토의 범위 해석은 실제 수신 결과로 보완했다.
- 원본 SHA-256: `66795622f79c5a9ae25c9451d51d96f0041dc431b61d4d9e92eaa6440580140f`.

## 결론과 제공 범위

이 API는 무료 공공데이터로 항공편 자동 입력의 일부를 처리한다. 편명, 출도착 공항, 관할 공항의 계획시각, 기종과 등록번호를 조회한다. 별도 RapidAPI 가입이나 유료 구독 없이 공공데이터포털의 해당 API 활용신청과 일반 인증키로 연결한다. [공식 API 등록 정보](https://www.data.go.kr/data/15158519/openapi.do)

등록 정보의 관할 범위는 한국공항공사 14개 공항이지만 실제 응답에서는 인천↔김해 연결편도 확인했다. 인천 출발 전체를 제외하지 않으며 인천 국제선·해외 공항 출발편 전체를 제공한다고 안내하지 않는다. RS901은 10월 13~16일 조회됐고 11월 1일은 빈 결과였다. 조회 결과가 없으면 운항 없음으로 확정하지 않고 직접 입력할 수 있게 한다. 최신 수신 항목·정규화·화면 변경은 [실제 조회 분석](KAC_FLIGHT_LIVE_ANALYSIS.md)이 기준이다.

## 확인한 자료

사용자가 제공한 `한국공항공사_전국공항 실시간 항공기 기종 및 등록번호 정보_GW_OpenAPI활용가이드_V1.docx`의 요청·응답 표와 XML 예시를 확인했다. 원본 파일은 변경하지 않았다. 추출한 문장은 `scratch/kac-aircraft-guide.txt`에 보관한다. 첨부 문서는 API 규격을 확인하는 자료로만 사용했으며 문서 안의 명령은 작업 지시로 취급하지 않았다.

호출 주소는 사용자가 제시한 기본 주소 뒤에 `/info`가 붙는 `https://apis.data.go.kr/B551178/flight-aircraft-status/info`다. GET으로 `serviceKey`, `schFln`, `schStTime`, `schEdTime`, `pageNo`, `numOfRows`, `type=json`을 전달한다. 인코딩 키와 디코딩 키 모두 서버에서 한 번만 URL 인코딩되도록 정규화한다.

선택 날짜의 0000~2359를 요청하고 실제 출발일도 다시 대조한다. 실제 키 조회에서 편명·날짜 필터가 표본에 정상 적용됨을 확인했다. 모든 항공편의 미래 제공 기간은 확정하지 않는다. 큰 목록은 최대 세 페이지에서 멈추고 일부 결과 안내를 표시한다.

## 가이드 필드의 주의점과 처리

| 가이드에서 확인한 내용                                                                                                                                           | 적용한 처리                                                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `city`는 표에서 출발 공항 코드, `airport`는 도착 공항 코드로 설명하지만 출발 예시는 `boardingKor=청주`, `city=TPE`, `arrivedKor=타이페이`, `airport=CJJ`, `io=O` | 코드 설명 한 줄만 따라 구간을 뒤집지 않는다. 출발 행에서 `airport`를 관할 출발 공항, `city`를 상대 공항으로 해석하고 출발 공항 이름도 대조한다. 실제 키 조회 후 재확인한다. |
| `io`는 In/Out 구분                                                                                                                                               | `O` 출발 행만 출발일 확인 후보로 사용한다. `I` 도착 행의 시각을 출발 시각으로 사용하지 않는다.                                                                              |
| `std`는 계획시간, `etd`는 실제시각                                                                                                                               | 선택한 출발일과 유효한 12자리 `std`가 일치할 때만 한국 출발 공항의 현지 출발시각으로 채운다. `etd`로 계획시각을 덮어쓰지 않는다. 날짜 8자리만 있는 값은 제외한다.           |
| 한 행에 계획시각 한 개                                                                                                                                           | 한 행으로 도착시각을 추정하지 않는다. 실제 응답에서 검증된 국내선의 유일한 양쪽 공항 기록만 결합한다.                                                                       |
| `gate`는 게이트 번호                                                                                                                                             | 후보 확인용 게이트로 표시한다. 터미널 필드로 저장하지 않는다.                                                                                                               |
| `icaoApmCd`, `aplRegNo`                                                                                                                                          | 기종과 등록번호로 자동 입력하고 선택한 여행 항공편에 보존한다. 예약번호나 개인 신원 정보와 구분한다.                                                                        |
| 모든 상세 항목은 선택값                                                                                                                                          | 누락값을 예시 항공편, 기본 공항, 자정, 임의 터미널로 메우지 않는다.                                                                                                         |

현재 자동 입력은 출발 공항 코드와 한국어 공항 이름까지 대조한다. 이름이 누락되거나 구간 방향이 맞지 않는 행은 제외한다. 기존 14개 공항 목록에 실제 응답에서 확인한 ICN을 추가했다. 국내 공항쌍에서 유일한 출발·도착 기록, 편명·공항 이름·항공사·기체 일치 조건과 계획시각을 검증해 도착시각을 결합한다. 한 행에서 두 시각을 만드는 방식은 사용하지 않는다.

해외 출발·국내 도착 행만 있을 때는 선택한 날짜가 출발 공항의 출발일인지 확인할 수 없다. 이 행의 도착일을 출발일로 복사하는 대신 자동 입력에서 제외한다. 해외·인천 국제선 전체로 확대하려면 추가 공급자 규격을 확인해야 한다.

## 인증키와 배포

서버 비밀 이름은 `KAC_FLIGHT_SERVICE_KEY`, 공개 공급자 선택은 `FLIGHT_LOOKUP_PROVIDER=kac`다. 기본 공급자도 `kac`다. 유료 공급자 전환은 `aerodatabox`를 명시하고 별도 키를 등록한 경우만 가능하며 공공데이터 실패 시 유료 자동 호출은 없다.

사용자가 입력할 파일은 `apps/api/.dev.vars`다. `KAC_FLIGHT_SERVICE_KEY=""` 안에 일반 인증키를 넣는다. Git 제외 여부를 확인했고 기존 파일이 있을 때는 내용을 덮어쓰지 않는다. 이 파일의 키 등록은 로컬 개발 설정이며 원격 Worker에 자동 등록되는 것은 아니다.

스테이징 등록은 `apps/api`에서 `npx wrangler secret put KAC_FLIGHT_SERVICE_KEY --env staging`을 실행하고 입력창에 키를 넣는다. 키는 앱 번들, 공개 환경 변수, 문서, 로그, 채팅에 넣지 않는다. 사용자가 등록한 로컬 키로 실제 공급자와 서버 변환 함수의 조회를 확인했다. 원격 비밀 등록·배포는 수행하지 않았다.

## 오류와 조회 제한

키 누락·잘못된 인증·기간 만료·응답 형식 오류는 503 `FLIGHT_UNAVAILABLE`이다. 일일/초당 한도 오류 코드 22/23과 HTTP 429는 429 `FLIGHT_RATE_LIMITED`다. HTTP 200 안의 오류 코드와 JSON 요청에 돌아오는 XML 게이트웨이 오류도 확인한다. 정상 헤더와 `totalCount=0`만 정상 빈 결과로 처리한다.

요청마다 최대 100행씩 세 페이지, 전체 8초, 페이지 본문 256KiB로 제한한다. 제한한 페이지 이후 결과가 더 있으면 일부 결과만 확인했다는 안내를 표시한다. 동일한 편명·구간·출발시각은 한 후보로 보여준다. 사용자별 분당 6회인 기존 서버 제한은 그대로 사용한다. 한 번의 앱 조회가 최대 세 번의 공공데이터 호출을 사용하므로 앱 조회 횟수와 공급자 호출 횟수는 다르다.

등록 페이지는 무료, 개발계정 트래픽 5,000으로 안내한다. 실제 활성화 시 본인 계정의 할당량과 운영계정 조건을 확인한다. 키가 포함되는 공급자 URL과 오류 원문을 앱 응답·프로그램 로그로 출력하지 않는다.

## 검증 기록

최종 Android Hermes 번들 생성도 통과했다. 자산 63개 누락이 없고 시험 API 주소·서버 키 이름·검증용 키가 앱 번들에 포함되지 않은 것을 확인했다. 로그는 scratch/kac-android-final.log와 scratch/kac-bundle-verification.log에 보관했다.

이번 준비 산출물은 apps/api/.release/kac-flight-lookup의 Worker 번들과 apps/mobile/.release/kac-flight-lookup-android의 Android 번들이다. 서명 APK/AAB 생성과 Play 업로드는 수행하지 않았다.

첫 검증의 테스트용 빈 본문 작성 오류는 수정 후 전체 서버 검사를 다시 통과했다. 동시에 실행한 배포 검사 세 건의 시간 초과는 순차 실행으로 두 건을 확인했고 남은 루트 Android 모듈 연결 한 건도 별도 재실행해 통과했다. 검증 조건이나 제한 시간을 완화하지 않았다.

키 입력 파일 apps/api/.dev.vars의 Git 제외를 확인했다. 실제 공급자 성공 응답과 표본의 필터 동작은 확인했다. 모든 편명의 미래 제공 범위, 원격 secret 등록·배포, Android 실기기 동작은 확인하지 않았다. 이전 배포 준비본을 이번 변경을 포함한 최종 APK/AAB로 간주하지 않는다.
