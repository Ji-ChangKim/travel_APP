# WHEREGO 제품 정책과 결정 기록

> 2026-10-03 사용자 직접 결정: 카카오·구글·애플 소셜 로그인부터 완성한다. 영수증 QR이 아닌 촬영/스캔·OCR을 사용한다. 종료 여행의 커뮤니티 공유와 사진·비용·지역은 완성 필수 기능이다. [최신 범위](APP_COMPLETION_SCOPE.md)가 관련 기존 후순위 분류보다 우선하며 나머지 미결정 정책을 일괄 승인한 것으로 보지 않는다.

- 버전: v0.1 / 작성일: 2026-10-02 / 상태: **권장안 검토 중, 오너 승인 전**
- 관련: MVP-01~10, [기능](FEATURE_SPEC.md), [저장](DATA_STORAGE_SPEC.md)
- 아래 내용은 구현 가능한 상세 권장안이다. 제품 오너 승인자/승인일은 모두 미정이다.
- 개발 갱신: M0/M1 지시에 따라 원본 DB·권한·90일 기간·기본 제목·통화·버전/재시도·게스트 쓰기 차단을 개발 기준으로 반영했다. 제품 승인/외부 결정과 구분하며 [실행 범위](M0_M1_EXECUTION.md)를 참조한다.

## 1. 권한 표 — D-07/D-11

viewer가 공동 비용을 볼 수 있다는 점을 초대 역할 선택에 안내한다. 공개 여행의 외부 열람 범위와 다르다. 동행자 전용 개인 메모는 MVP 미지원이며 모든 일정 메모는 여행 멤버에게 보인다는 안내가 필요하다. 연락처·접속기기·Auth 정보는 동행자 프로필에 포함하지 않는다.

앱에서 버튼을 숨기는 것과 별개로 모든 서버·DB 쓰기에 같은 역할을 검사한다. 리소스의 부모 여행을 서버에서 조회하고 client의 tripId만으로 권한을 판정하지 않는다.

## 3. D-15 입력 규격 권장 초깃값

| 입력                       | 권장값                                                 | 실패 처리                                           |
| -------------------------- | ------------------------------------------------------ | --------------------------------------------------- |
| 여행 제목                  | 선택, 입력 1~50자                                      | 공백 제거 후 빈 값이면 자동 제목                    |
| 국가/도시                  | 각 1~50자                                              | 필드 오류                                           |
| 여행 기간                  | 1~90일, 시작≤종료                                      | 실제 달력·날짜 범위 검증                            |
| 시간대                     | 유효한 IANA 이름                                       | 기기 제안값 확인, 유효하지 않은 값 거부             |
| 일정 제목/준비물/비용 제목 | 각 1~100자                                             | 공백만 입력 거부                                    |
| 일정 메모                  | 최대 300자                                             | 초과 위치 안내, 자동 잘라 저장 금지                 |
| 닉네임/자기소개            | 1~50자 / 최대 200자                                    | 서버 동일 제약                                      |
| 시각                       | HH:MM 또는 null                                        | 존재하는 00:00~23:59                                |
| 좌표                       | 위도 -90~90, 경도 -180~180; 쌍으로 입력                | 한쪽 누락/범위 오류                                 |
| 비용                       | 양수, NUMERIC(12,2) 범위, KRW/JPY 소수 0자리·USD 2자리 | 소수 초과/음수/NaN 거부, 문자열 정밀 검증           |
| 검색                       | 2~100자, 300ms 지연 후보, 직접 실행 가능               | 2자 미만은 검색 안내, 0건은 직접 등록 CTA           |
| 목록                       | 기본 20건, 최대 100건                                  | 유효 범위 외 요청 거부                              |
| DAY당 일정                 | 초기 상한 100개                                        | 상한 시 추가 차단, 사용자 안내                      |
| 요청 중복키 보존           | 24시간 권장                                            | 만료된 요청은 결과 조회 후 새 작업 여부 사용자 확인 |

날짜·금액·순서·권한은 client 검증만으로 확정하지 않는다. 서버와 DB에 필수 제약을 둔다. 예상 0원은 비용 없음, 실제 0원은 지출 생성 거부가 권장안이다.

## 4. 결정 승인 형식

각 결정에 `상태 / 선택안 / 승인자 / 승인일 / 이유 / 영향 요구사항·화면·API·DB / 검증 케이스 / 재검토 조건`을 기록한다. 현재는 전부 검토 중이다. 승인된 변경은 기능·화면·데이터·API·QA에 함께 반영하고 기존 PRD 범위와 다르면 변경 이력을 남긴다.
