# WHEREGO 앱 완성 기준

- 기준일: 2026-10-03 (Asia/Seoul)
- 권한: 사용자가 직접 요청한 7개 기능과 후속 답변을 제품 범위 기준으로 반영한다.
- 로그인: **카카오·구글·애플 소셜 인증부터 완성**한다. 최초 인증 시 가입과 기본 프로필 생성을 연결한다.
- 영수증: **QR이 아닌 영수증 사진 촬영·스캔과 OCR**이다.
- 상태: 요구사항 기준 확정, 구현 진행 중. 실제 로그인·원격 저장·OCR·게시 검증 완료를 의미하지 않는다.

## 사용자가 완주하는 흐름

소셜 로그인/가입 → 여행 국가·지역·기간 설정 → 날짜별 일정 작성 → 공유 링크로 동행 초대 → 여행 중 사진·지출·영수증 기록 → 종료 확인 → 공개할 내용을 검토 → 커뮤니티 게시 → 웹에서도 같은 계정과 여행 조회.

하나의 서버 여행을 계획·일정·비용·사진·영수증·초대의 공통 원본으로 사용한다. 기존 발자취 `device-draft`는 독립된 기기 초안이며 자동으로 공유하거나 공개하지 않는다. 계정 저장으로 전환할 때 사용자 확인을 받고 원본 보존과 중복 방지를 검증한다.

카카오톡·메시지는 설치된 앱의 OS 공유 시트로 사용자가 직접 발송한다. 카카오 메시지 API로 대신 자동 발송하는 기능은 요구하지 않았다. 별도 카카오 공유 템플릿이 필요해지면 플랫폼 SDK 설정을 추가한다.

웹 사이트 전체 디자인과 독립 웹 플래너의 출시 시점은 후속 결정이다. 이번 범위에서 앱과 웹의 공통 서버 계약 및 초대·인증 복귀 경로를 먼저 완성한다.

## 영수증·사진의 저장과 비용 처리

1. 사진 원본을 비공개 저장소에 업로드한다. 카메라 거절 시 이미지 선택·수동 입력을 제공한다.
2. 서버에서 멤버 권한과 파일 소유를 검사한 뒤 OCR 작업을 요청한다. 공급자 비밀 키는 앱에 넣지 않는다.
3. OCR 추출값은 확인 전 초안이며 일정/가계부에 자동 확정하지 않는다. 신뢰도 낮은 필드는 수정 대상으로 표시한다.
4. 사용자가 여행과 DAY/일정을 고르고 실제 결제 날짜·통화·금액을 확인한다. 기존 계획 시각을 결제 시각으로 덮어쓰지 않는다.
5. 확인 저장은 영수증·일정 기록·실제 지출을 하나의 거래와 멱등 키로 연결한다. 같은 영수증을 다시 열거나 저장해도 지출 합계가 두 번 증가하지 않는다.
6. 삭제·재인식·응답 유실·동시 편집에서도 파일 참조와 지출 버전을 검사한다. 외부 공급자 실패는 수동 입력으로 이어진다.

OCR 어댑터는 Google Cloud Vision으로 구현했다. JPG/PNG 4MiB, 비공개 Storage, 확인 전 자동 저장 금지를 적용한다. 한국어/일본어/영어 정확도·처리 비용·보존 조건은 실제 샘플 평가가 남아 있다. HTTP fixture 검증을 실제 인식 성공으로 간주하지 않는다.

## 초대와 커뮤니티를 구분하는 기본 설계

초대는 비공개 여행의 참여 권한을 부여한다. 커뮤니티 게시물은 사용자가 선택한 정보의 별도 공개 스냅샷이다. 여행 종료만으로 자동 공개하지 않는다.

공개 기본값은 제목·지역·선택 일정·선택 사진이다. 금액 공개는 선택 사항이다. 원본 영수증, 결제 식별정보, 동행 연락처, 초대 링크·토큰, 비공개 메모는 게시 원본에서 제외한다. 공개 선택·명시적 게시·철회와 실제 SQL 테이블을 구현했다. 로컬 구현과 원격 적용은 별도 상태다.

게시물·신고·차단 테이블, 공개 사진 정책, 20개 페이지 피드, SQL·도메인·DB 사전·API 계약을 함께 추가했다. 좋아요·댓글·팔로우·추천 알고리즘은 이번 요청의 최소 완료 기준에 추가하지 않는다.

## 기존 기획과의 관계

- 기존 MVP-01~10과 owner/editor/viewer, 서버 저장·버전/재시도 규칙은 유지한다.
- 기존 문서에서 후순위로 분류한 **영수증 OCR·사진과 커뮤니티 게시는 이번 완성 범위의 필수 조건**으로 변경한다.
- GPS 인증, Realtime, Today, 자동 항공 조회, 여행 복제는 여전히 별도 범위다.
- 40+5일 기존 일정은 이 추가 범위를 포함하지 않는다. 그대로 전체 앱 완성일로 사용하지 않으며 OCR/Storage/커뮤니티와 실기기 QA 작업량을 추가 산정한다.

## 실행 순서

1. **인증**: 임시 소셜 ID 제거, 실제 OAuth·PKCE·세션 연결. 공급자 콘솔 및 Supabase 테스트 환경의 실제 로그인을 검증한다.
2. **여행 보존**: 앱 화면을 기존 생성/list/snapshot API와 연결하고 앱 재실행·계정 분리를 인수한다.
3. **일정과 기록**: 일정 CRUD·기간·사진·지역·통화별 비용을 서버에 저장한다.
4. **초대**: 서버 초대 발급/수락·HTTPS 링크·OS 공유·다른 기기와 역할을 연결한다.
5. **영수증 스캔**: 카메라/파일·비공개 Storage·실제 OCR·확인 폼·원자적 기록/지출 저장을 연결한다.
6. **커뮤니티**: 종료·공개 미리보기·게시/철회·공개 피드와 사진 투영을 연결한다.
7. **전체 인수**: Android/iOS 실기기와 웹에서 전체 흐름, 실패 복구·접근권한·데이터 보존을 검증한다.

## 2026-10-03 첫 구현의 실제 범위

소셜 버튼의 임시 사용자를 제거하고 Supabase OAuth URL 발급, 모바일 인증 브라우저, 웹 전체창 인증, PKCE 교환 및 공통 `/auth/callback`, Auth 상태 구독과 계정 데이터 초기화를 구현했다. Google은 iOS에서도 접근할 수 있으며 Apple은 기존 iOS/웹 버튼을 유지한다.

첫 인증 구현 당시 여행 화면은 서버 연결 전이었다. 이후 사용자 “다 진행해” 요청에 따라 아래 후속 서버 구현을 추가했다. 실제 인증 환경이 없어 제공자 로그인·회원가입·실기기 복귀는 여전히 미검증이다.

검증 명령과 공급자 준비는 [소셜 로그인 설정](../SOCIAL_AUTH_SETUP.md)에 기록한다. 모든 APP-01~07이 실제 인수된 후 전체 앱 완성으로 표시한다.

## 2026-10-03 후속 서버 앱 구현

- 기본 내 여행/상세를 실제 API로 연결했다. 계정별 조회, 생성·DAY, 일정 CRUD/시간/순서/주소, 수동 비용/예상·실제/통화별 합계, 준비물을 제공한다.
- 소유자 기간 변경은 DAY UUID·순서를 보존한다. 기록 있는 DAY 축소와 확정 영수증 결제일 범위 제외를 차단한다. 날짜 이동은 DAY별 계획 날짜를 함께 이동하므로 폼에서 안내한다.
- 초대 발급·7일 만료·역할·OS 공유·로그인 후 수락·철회·멤버 관리와 HTTPS 랜딩을 연결했다.
- 카메라/사진 선택·비공개 원본·일정 사진 연결·Vision OCR 후보·실패 시 수동 입력·원자 확인/지출·삭제를 구현했다.
- 종료 여행의 공개 선택·게시·수정·철회·공개 피드·선택 사진·신고·차단을 연결했다.
- 앱과 웹은 같은 명령/스냅샷/Auth 계약을 쓴다. 별도 웹 디자인·스토어 출시 인수는 남아 있다.

현재 확인 폼은 상호·결제 날짜·금액·통화·구매 내역을 받는다. 결제 시각 필드, 사진에서 같은 결제를 자동 판별, 영수증 내역 상세 품목 구조화는 아직 구현하지 않았다. 기존 발자취의 결제 시각/경험 필드는 기기 초안으로 별도 유지한다. 운영 외부 환경 인수와 추가 UX 항목을 숨기지 않고 추적한다. 상세 설정·남은 인수는 [서비스 연결 절차](../APP_SERVICES_SETUP.md), 최신 결과는 [현황 보고서](../PROJECT_PROGRESS_REPORT.md)를 따른다.
