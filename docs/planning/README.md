## 무엇을 만드는가

추가 요청인 항공 기준·장소 계획·영수증 연결 콘텐츠는 [발자취 기능 명세](TRAIL_CONTENT_SPEC.md)에서 구현 범위와 기기 저장 정책을 확인한다. 기존 M0/M1 서버 기반과 별도로 동작하는 기기 초안이다.

사용자가 여행을 만들고 날짜별 일정을 작성하면 같은 장소·일정 데이터를 지도와 비용에서 활용하고, 초대한 동행자도 같은 여행을 조회·편집한다. 데이터는 서버 저장 성공 후 확정되며 재접속·다른 기기에서도 유지되어야 한다.

MVP는 인증·기본 프로필, 여행/DAY, 일정, 검색 및 직접 장소 등록, 지도, 수동 비용, 체크리스트, 초대·역할, 목록/상세다. 사진·후기·GPS·OCR·Realtime·Today는 P1, 공개 여행·복제는 PRD 5장 기준 P2다. PRD 후반의 웹 범위 미결정 사항은 정책 문서에서 유지한다.

## 문서 간 계약

`MVP-01~10`을 공통 추적 ID로 사용한다. PRD 5장의 프로필·직접 장소 등록은 MVP-01/05의 상세로 보완했다. `D-01~10`은 초기 결정 목록, `D-11~15`는 상세 작성 중 발견한 추가 결정이다. 결정은 [정책 문서](POLICY_DECISIONS.md)가 상세 원본이며 MVP 추적표는 인수 범위를 요약한다.

기획 문서의 API·필드·저장 제약은 전체 목표다. 실제 구현된 부분은 [M0·M1 실행 기록](M0_M1_EXECUTION.md)과 [DB 사전 v1.5](../DB_DICTIONARY.txt)의 5절을 기준으로 구분한다. 나머지 목표를 현행 코드에 이미 존재한다고 해석하지 않는다.

모든 문서의 역할은 제품 오너/기획/디자인/개발/QA로 표기한다. 담당 실명·승인일·공개 출시 일정은 미정이다. [일자별 계획](DAILY_MILESTONES.md)은 1인 전일제 기준 2026-10-06 착수·12-01 내부 MVP 인수·12-08 예비 재검토를 제안하며 실제 완료를 의미하지 않는다. 미확정 숫자나 정책은 권장 초깃값으로 표시한다.

## 구현 순서와 작업 단위

1. D-01/06/08/11~15 검토, 인증·원본 저장·필드 계약 확정.
2. 실제 로그인 → 여행/DAY 원자적 생성 → 재조회·재실행 보존.
3. 일정 CRUD/순서/기간 변경 → 장소 검색·직접 등록 → 지도.
4. 수동 비용·통화별 집계 → 체크리스트 → 초대 수락·서버 권한.
5. 실패/충돌/다른 기기/실기기 QA → MVP 인수.

작업 하나는 `요구사항 ID / 선행 결정 / 화면 / API / 저장 대상 / 인수 케이스 / 검사 결과`로 관리한다. 예: `MVP-02 여행 생성`은 화면만 완성하는 작업이 아니라 생성 트랜잭션·멤버/DAY·중복 재시도·재접속까지 포함한다.

상세 기획 작성 후 M0/M1 기반 개발에 착수했다. SQL·API·공통 모듈·환경/CI·테스트의 현재 구현 범위는 [실행 기록](M0_M1_EXECUTION.md)에 정리했다. 승인·운영 배포·실서비스 검증은 수행하지 않았다.
