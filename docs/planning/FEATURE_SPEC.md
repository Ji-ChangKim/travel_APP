# WHEREGO 필수 기능 상세 명세

- 버전: v0.1 / 작성일: 2026-10-02 / 상태: 상세 설계 초안
- 근거: PRD v0.3 5·9·13·14장. 관련 ID: MVP-01~10
- 권장 정책은 [결정 문서](POLICY_DECISIONS.md), 저장 필드는 [데이터 설계](DATA_STORAGE_SPEC.md) 참조

## 1. MVP 제품 경험

첫 방문자는 서비스를 이해하고 로그인한 뒤 목적지·기간만 입력해 여행을 만든다. DAY 목록에서 장소·이동·메모 등을 추가하며 지도와 예상비용이 같은 데이터를 사용한다. 동행자는 초대를 수락하고 부여된 역할에 따라 편집한다. 사용자가 다시 앱을 열어도 서버에서 같은 여행을 복원한다.

MVP 성공은 “화면이 보임”이 아니라 이 전체 경험의 완료다. 여행 전·후 어느 시점에도 기존 계획을 볼 수 있지만 Today·방문 인증·사진 앨범은 P1에서 추가한다.

MVP 프로필은 닉네임·자기소개와 본인 정보 조회/수정이다. 아바타 업로드·전화번호·스타일 확장은 P1 후보로 두고 필수 가입 필드로 요구하지 않는 권장안이다(D-11). 전화번호는 동행 목록이나 공개 응답에 포함하지 않는다.

게스트 권장안은 서버 여행 생성 없이 체험 화면만 제공한다(D-01). 실제 계정이 필요한 생성/초대 수락 시 로그인 후 원래 행동으로 복귀한다. 현재 로컬 게스트 여행 허용 코드는 확정 정책에 맞춰 변경해야 한다.

완료 기준: 실제 계정 로그인·취소·만료 복원·로그아웃·프로필 수정·다른 계정 전환을 검증한다.

## 3. 내 여행과 상세 — MVP-10

- 목록은 소유 또는 참여한 여행만 서버에서 조회한다. 각 카드는 제목·국가/도시·기간·현재 상태·내 역할·D-Day를 표시한다.
- 필터는 전체/예정/여행 중/완료다. 보관은 별도 필터 또는 마이의 보관 목록으로 제공한다. 정렬은 권장안으로 진행 중 우선, 나머지는 시작일 가까운 순, 완료는 최근 종료일 순이다.
- 여행 생성 및 초대 진입을 빈 상태에서도 제공한다. 실패 시 빈 목록으로 가장하지 않고 재시도와 마지막 갱신 정보를 보여준다.
- 상세는 일정/지도/비용/준비/멤버 5개 탭이다. 선택 DAY는 일정/지도에서 공유하되 다른 여행 이동 시 이전 여행의 DAY를 적용하지 않는다.
- 없는 여행·삭제·멤버 탈퇴·접근 불가 시 편집을 중지하고 목록으로 돌아갈 수 있게 한다. 서버는 리소스 존재 여부를 불필요하게 노출하지 않는다.

완료 기준: 신규 계정 빈 상태, 멤버 여행 표시, 타인 여행 차단, 생성/삭제 후 목록 갱신, 상세 재접속을 검증한다.

## 4. 여행 생성·수정·삭제와 DAY — MVP-02/03

### 4.1 생성 입력

| 필드        | 필수         | 권장 검증·기본값                                                                        |
| ----------- | ------------ | --------------------------------------------------------------------------------------- |
| 국가        | O            | 공백 제거 후 1~50자; MVP 자유 입력, 정규 국가 코드 확장은 후속                          |
| 대표 도시   | O            | 1~50자; 도시 검색 없이 입력 가능                                                        |
| 시작/종료일 | O            | 실제 달력 날짜 YYYY-MM-DD, 시작≤종료. 기간 최대 90일 권장(D-15)                         |
| 제목        | 선택         | 생략 시 `시작연도 + 도시 + 여행`, 입력 시 1~50자(D-06)                                  |
| 여행 시간대 | O(기본 제공) | 기기 시간대 자동 제안, 국가/도시 입력만으로 추정 확정 금지. 필요시 수정 가능            |
| 대표색      | 선택         | 디자인 시스템 팔레트의 허용 색상, 기본 테마색                                           |
| 기본 통화   | 선택         | 현재 입력 편의를 위한 통화. 국가만으로 자동 확정하지 않음; 변경해도 기존 비용 변환 없음 |

저장 버튼 → 클라이언트 검증 → 서버 인증/입력 검증 → 여행+owner 멤버+DAY1~N을 한 DB 트랜잭션으로 생성 → 확정 ID/버전 반환 → 목록과 상세 캐시 갱신 → DAY1 일정 화면 이동.

버튼 중복 클릭은 막는다. 응답 유실 후 재시도는 같은 요청 키로 처리해 여행이 두 개 생기지 않도록 한다. DB 일부 저장 시 전체 롤백하고 성공 메시지를 표시하지 않는다.

### 4.2 수정과 기간 변경

제목·목적지·색상·기본 통화·시간대·기간은 owner만 수정하는 권장안이다. 일정을 공동 편집하는 editor의 권한과 여행 관리 권한을 분리한다.

기간 변경은 먼저 영향 미리보기를 요청한다. 동일 날짜의 DAY ID는 유지하고 번호만 재계산한다. 늘어난 날짜에는 빈 DAY를 만든다. 범위를 벗어난 날짜에 일정 또는 DAY 비용이 있으면 자동 삭제하지 않고 변경을 차단해 이동/연결 해제·명시적 삭제 후 다시 시도하도록 권장한다(D-04). 날짜 이동은 “같은 달력 날짜 보존” 기준이며 사용자가 모든 일정을 새 날짜로 일괄 이동하는 기능은 후속이다.

미리보기 후 다른 멤버가 데이터를 수정했으면 버전 충돌을 반환한다. 날짜·DAY·순서와 비용 연결 변경은 트랜잭션 처리한다.

### 4.3 삭제·상태

삭제는 owner만 수행한다. 여행명·영향(일정/비용/멤버/링크)을 확인하고 명시적 확인 후 서버에서 삭제한다. 다른 여행에서도 사용하는 전역 provider 장소는 유지하고 해당 여행의 사적 manual 장소는 일정 제거 후 정리한다. 개인 기록/P1 미디어가 존재할 때 삭제 정책은 D-14를 재확정한다.

권장 MVP는 날짜와 여행 시간대 기준으로 예정/여행 중/완료 표시 상태를 계산한다. `DRAFT/ARCHIVED`는 명시적 관리 상태다. PRD Planning/Upcoming은 DB 상태를 추가하기보다 PLANNED의 UI 강조로 매핑한다(D-12). 자동 완료 판정이 여행 삭제나 방문 인증을 뜻하지 않는다.

완료 기준: 제목 생략, 1일/월말/윤일, 유효하지 않은 날짜, 생성 실패 롤백·재시도, 기간 변경 차단/성공, owner 삭제·editor 거부를 검증한다.

## 5. 일정 CRUD·순서 — MVP-04

### 5.1 유형별 입력

| 유형        | 표시/입력                                         | 장소·지도 처리                                                                 |
| ----------- | ------------------------------------------------- | ------------------------------------------------------------------------------ |
| PLACE       | 검색 선택 또는 직접 등록, 제목·시각·메모·예상비용 | 연결 장소의 유효 좌표가 있으면 마커                                            |
| TRANSPORT   | 제목, 출발/도착 설명, 교통수단, 시각·메모         | MVP 설명은 메모로 저장; 선택 장소가 있으면 단일 마커. 두 지점 경로 계산은 후속 |
| STAY        | 숙소 제목/장소, 체크인 시각·메모                  | 장소 연결 선택, 좌표 있으면 마커                                               |
| RESERVATION | 예약명·시각·메모                                  | 예약 참조번호는 개인 메모로 취급, 선택 장소만 지도 표시                        |
| TODO        | 할 일 제목·시각 선택·메모                         | 장소 연결 선택, MVP 방문/완료 상태는 P1                                        |
| MEMO        | 제목·본문                                         | 장소 불필요, 지도에서 제외                                                     |

공통 권장 제약: 제목 1~100자, 메모 최대 300자, 시각 HH:MM 또는 null, DAY 필수. 예상비용 입력 시 양수 금액·통화가 필요하고 생략 시 비용 행을 만들지 않는다. 0원은 비용 없음 표시로 처리한다. 시간 미정과 00:00을 구분한다.

### 5.2 저장·수정·이동

owner/editor가 DAY 선택 → 유형 → 내용 → 저장하면 일정 ID·순서·버전을 서버가 반환한다. 장소 선택은 장소를 저장하고 일정 FK로 연결한다. 비용 입력은 비용 행과 함께 트랜잭션 저장한다. 일정과 비용을 독립 요청으로 저장해 일부 성공 상태를 만들지 않는다.

수정은 조회 당시 버전을 보낸다. 최신 버전과 다르면 입력을 유지하고 최신 내용 비교·다시 적용을 제공한다. 서버가 마지막 저장으로 무조건 덮어쓰지 않는다.

다른 DAY로 이동 시 기존 일정 ID와 장소를 유지하고 목적 DAY 마지막에 배치한다. 연결된 비용의 DAY도 함께 이동한다. 별도로 DAY만 지정한 비용은 자동 이동하지 않는다.

### 5.3 순서·삭제

시간과 순서는 독립이다. 시각 변경만으로 순서를 바꾸지 않는다. 전체 ID 목록을 서버에 보내 현재 DAY의 모든 일정이 중복 없이 포함되는지 확인하고 sort_order를 일괄 갱신한다. 다른 사용자의 추가로 목록이 달라졌으면 충돌을 알린다.

삭제 확인은 연결 비용 개수를 보여준다. 권장안은 일정 예상비용만 제거하고 실제 지출은 보존해 schedule 연결을 null로 변경하는 것이다(D-13). 같은 DAY는 유지한다. 지도 마커·합계·목록을 서버 결과로 갱신한다.

완료 기준: 6유형과 장소 없는 메모 저장, 수정/삭제/이동/순서 재접속 보존, 비용 일관성, 동시 편집 충돌을 검증한다.

## 6. 장소 검색·직접 등록·지도 — MVP-05/06

검색어 입력 → 검색 → 결과 이름/주소 확인 → 선택 → 상세/좌표 확인 → 일정에 저장한다. 검색 결과를 확인 없이 곧바로 영구 등록하지 않는다. 같은 provider/external ID는 장소 마스터 하나를 재사용하되 개인 메모는 일정에 저장한다.

직접 등록은 이름 필수, 주소/위도/경도 선택이다. 좌표는 둘 다 입력하거나 둘 다 비워야 하고 위도 -90~90·경도 -180~180을 검증한다. 직접 등록한 사적 장소는 작성 여행 멤버만 조회하는 권장안이다. 이름만 있는 장소는 일정에 저장할 수 있으며 “좌표 없음”으로 표시한다. 임의 좌표를 채워 실제 위치처럼 표시하지 않는다.

지도는 선택 DAY의 일정과 저장 좌표를 읽는다. 전체 일정 순서 번호를 유지하므로 좌표 없는 ②를 제외하면 ①③ 마커가 나타날 수 있다. 겹친 좌표는 목록 선택/확대 등으로 각 일정을 식별한다. 마커 선택은 일정 카드, 카드 선택은 해당 마커 강조로 연결한다.

실제 이동 경로·소요시간은 공급자 호출을 별도로 확정하기 전 표시하지 않는다. 선을 그릴 경우 직선 연결이라는 표시가 필요하며 도보/교통 안내로 오인시키지 않는다. 위치 권한은 저장 장소 지도 보기의 전제 조건이 아니다.

공급자 오류 시 직접 등록으로 전환할 수 있다. 지도 타일 오류 시 주소·일정 목록은 유지한다. provider 데이터 저장 가능 범위·보관 기간은 D-02 확정 전 조건으로 둔다.

## 7. 비용 — MVP-08

예상/실제 구분, 제목, 양수 금액, 통화, 카테고리는 필수다. DAY·일정·결제자는 선택이며 선택 일정은 반드시 같은 여행에 속해야 한다. 금액 입력은 서버에서 소수 정밀도를 검증하고 초과 자리수를 자동 반올림해 숨기지 않는다.

예상비용 원본은 `expenses(is_actual=false)`로 통일하는 권장안이다. 일정 입력의 예상비용은 같은 행을 수정하며 일정을 다시 합산하지 않는다. 실제비용은 별도 `is_actual=true` 행을 만든다. 예상→실제 전환은 복사된 새 행을 생성하고 원 예상값을 유지해 차이를 보여준다.

합계는 통화별·예상/실제별로 나눈다. KRW와 JPY를 숫자만 더하지 않는다. DAY 미연결 항목은 여행 공통 비용으로 표시하고 여행 합계에는 한 번 포함한다. 사용자별 비용 정산·환율 환산은 P2다.

owner/editor는 항목 생성/수정/삭제 가능, viewer는 열람만 가능하다. 결제자 이름은 선택 정보이며 owner만의 숨겨진 개인 지출을 이 공동 가계부에 저장하는 정책은 MVP에 포함하지 않는다.

완료 기준: 일정 비용 자동 반영이 한 번만 집계되는지, 복수 통화·DAY/여행 합계·연결 변경·실제비용 보존·재접속을 검증한다.

## 8. 준비물 — MVP-09

항목명 1~100자와 완료 여부만 MVP로 제공한다. owner/editor가 추가·이름 수정·삭제·완료 설정을 수행한다. 공백만 입력한 항목은 거부하고 같은 이름은 경고 없이 허용하되 다른 항목 ID를 갖는다.

완료 요청은 “토글” 명령 대신 원하는 상태 true/false와 버전을 보낸다. 응답 재시도가 두 번 상태를 뒤집지 않도록 한다. 완료율은 완료 개수/전체 개수이며 빈 목록은 0/0과 안내 문구로 표시한다. 담당자 지정은 P1이다.

## 9. 동행 초대·역할 — MVP-07

owner가 멤버 탭에서 editor/viewer 선택 → 초대 생성 → 링크 공유 → B의 초대 안내 → 필요시 로그인 → 서버 수락 → 멤버 추가 → 여행 상세 이동 순으로 진행한다.

초대는 여행 멤버십 권한을 부여한다. 공개 열람 링크는 부여하지 않는다. owner는 초대 역할/만료/철회를 관리하며 client가 전달한 역할을 수락 API가 신뢰하지 않는다. 권장안은 고강도 불투명 난수, 서버 해시 보관, 7일 유효·1회 사용(D-07). 현재 6자리 코드만으로 참여를 허용하지 않는다.

기존 멤버의 재수락은 기존 역할 유지·동일 여행 이동이며 초대를 소비하지 않는다. 서로 다른 사용자의 동시 수락은 한 명만 성공한다. 로그아웃 후 링크를 열었을 때 초대 경로는 유지하되 원문 토큰을 로그/분석에 남기지 않는다.

owner는 역할 변경·멤버 제거 가능. editor/viewer는 본인 탈퇴 가능. 마지막 owner 탈퇴는 차단하고 MVP 소유권 이전은 제외하는 권장안이다. 제거된 멤버의 다음 조회/쓰기와 저장된 링크 접근은 즉시 권한을 다시 검사한다.

## 10. P1/P2 연결 설계

| 후속 기능    | 사용자 흐름                                     | 데이터 연결 원칙                                    |
| ------------ | ----------------------------------------------- | --------------------------------------------------- |
| Today/P1     | 여행 중 진입→오늘 일정→다음 목적지              | 같은 DAY/일정 원본 조회                             |
| GPS 방문/P1  | 권한 요청→현재 좌표/정확도→서버 검증→방문 기록  | 일정 연결 visits, 수동은 인증되지 않은 기록         |
| 사진/후기/P1 | 기존 일정/방문→업로드/후기→확정                 | private 파일 경로와 visits/reviews 연결             |
| OCR/P1       | 촬영→업로드→추출 후보→사용자 수정/확정→실제비용 | receipt 확정당 비용 1개, 원문 보관 정책 별도        |
| Realtime/P1  | 서버 확정 변경 이벤트→해당 조회 재갱신          | 이벤트만으로 무검증 덮어쓰기 금지                   |
| 공개 여행/P2 | 공개 범위 설정→별도 링크→읽기 화면              | 멤버 초대와 분리, 비용/메모/연락처/원본 미디어 제외 |

현재 후속 기능 UI가 존재하더라도 저장·검증이 없으면 출시 기능으로 안내하지 않는다. 미제공 탭에는 서비스 가치와 제공 예정 상태를 표시한다.
