- 버전: v0.1 / 작성일: 2026-10-02 / 상태: **검증 계획, 아래 케이스 실행 미완료**
- 기준: [필수 기능](FEATURE_SPEC.md), [화면](UX_SCREEN_SPEC.md), [API](API_CONTRACT.md), [저장](DATA_STORAGE_SPEC.md)
- 담당: QA·개발, 제품 인수: 제품 오너. 실명·실행일·빌드는 미정이다.

## 1. 검증 환경과 기록

실제 테스트용 Auth 계정 A(owner), B(editor), C(viewer), D(비참여)를 준비한다. 별도 앱 설치/브라우저 세션으로 사용하고 세션/캐시를 공유하지 않는다. X/Y 두 여행, DAY 여러 개, 장소 연결/좌표 없음 일정, JPY/KRW/USD 비용을 만든다.

테스트 DB에 마이그레이션 적용 결과, API 배포 버전, 앱 빌드 ID·플랫폼·시간대를 기록한다. 운영 데이터로 파괴적 삭제·권한 테스트를 수행하지 않는다.

각 케이스 결과는 아래 양식으로 기록한다.

| 항목                    | 기록값                                              |
| ----------------------- | --------------------------------------------------- |
| 케이스/요구사항/결정 ID | 예: Q-07 / MVP-02·03 / D-04                         |
| 환경·빌드·계정·실행일   | 미정                                                |
| 사전 데이터             | 여행/DAY ID, 초기 버전, 금액·통화                   |
| 실행 절차               | 실제 입력·행동/요청·재실행                          |
| 기대 결과               | 아래 계약에 따름                                    |
| 실제 결과·판정          | 미실행/통과/실패/차단                               |
| 증거                    | 화면·응답 requestId·DB 확인, 개인정보/토큰은 마스킹 |
| 결함·재검증             | 이슈 ID/원인/수정 버전/재실행 결과                  |

정적 검사·목업 API 호출·개발자 동일 세션만으로 기능 인수 완료를 판정하지 않는다.

## 4. PRD 기반 통합 시나리오

1. A 실제 로그인 → 5박 6일 여행 생성 → 재실행으로 DAY1~6 복원.
2. DAY2 실제 장소 2개 검색/저장 → 시각/순서 수정 → 지도 ①② 확인.
3. A가 editor 초대 → 별도 기기 B 로그인/수락 → B DAY3 추가 → A 재조회 일치.
4. viewer C 읽기·쓰기 거부, 비참여 D 비노출을 검증한다.
5. 일정 예상비용·실제 지출·공통 비용·복수 통화·준비물을 저장하고 양 계정에서 재조회한다.
6. 기간 변경 차단·일정 이동·예상/실제 정리·삭제와 재접속을 수행한다.
7. 위 작업 중 응답 유실·동시 수정·세션 만료를 실행해 손실/중복 여부를 확인한다.

통합 시나리오는 정적 검사 통과 후 실제 서비스 연결 환경에서 수행한다. Realtime이 P1이면 A의 재조회로 일치 확인하며 실시간 자동 반영을 MVP 필수로 오인하지 않는다.

## 5. 플랫폼·접근성 검증

Android/iOS 대상 실기기와 초대 웹에서 로그인·초대 복귀·재실행·키보드 입력·뒤로 가기를 검증한다. 실제 지원 플랫폼은 출시 결정과 연결한다. Windows의 웹 미리보기만으로 iOS 인수를 대체하지 않는다.

스크린리더의 버튼명/탭/DAY/체크 상태, 큰 글꼴의 제목/금액, 키보드만으로 폼/순서 변경, 저장 중 이탈·오류 초점 이동을 확인한다. 좁은 화면에서도 필수 입력과 저장 버튼이 가리지 않아야 한다.

## 6. 인수 조건과 후속 범위

- 필수 기능 및 저장/권한 케이스의 실제 결과와 증거를 남긴다. 미실행·차단을 통과로 계산하지 않는다.
- `npm run check`와 대상 빌드 결과를 기록한다. 타입·lint·format은 사용자 기능 테스트와 별도로 관리한다.
- 데이터 손실·권한 노출·중복 저장·핵심 사용자 흐름 차단 결함은 해결/재검증 후 인수한다.
- 미결정 정책은 승인 기록과 문서 갱신 후 검증한다. 통과 기능만 제품 오너가 인수 완료로 바꾼다.
- GPS/OCR/사진/후기/Today/Realtime의 P1 검증은 별도 확장한다. 현재 UI에 있어도 무조건 GPS 인증·Alert 후기 저장을 통과로 인정하지 않는다.

운영 배포 승인·스토어 제출·법적 문구 검토는 이번 상세 기획 작성에서 수행하지 않았다. 출시 전 계정 삭제·백업/미디어 보관·지원 범위는 릴리스 기준에 추가해야 한다.
