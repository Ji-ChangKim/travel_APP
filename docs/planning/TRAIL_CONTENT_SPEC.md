# 발자취 콘텐츠 — 항공 기준·장소 계획·영수증 기록

> 2026-10-03 사용자 요청: 영수증은 QR이 아니라 사진 촬영/스캔과 OCR로 일정 기록에 추가한다. [앱 완성 범위](APP_COMPLETION_SCOPE.md)에 필수로 반영했다. 아래 내용은 현재 기기 초안·수동 등록 기능의 구현 상태이며 OCR/서버 저장 완료가 아니다.

- 작성일: 2026-10-02
- 목표: 계획한 장소의 실제 구매·방문 상세를 영수증으로 구체화하고, 편명별 출발·귀국 시각을 여행의 기준표로 사용한다.
- 현재 제공: **앱의 발자취 탭에서 작성·첨부·재조회 가능한 기기 초안**. 기존 서버 여행을 원격 변경하거나 새 인증 완료를 가장하지 않는다.

## 1. 사용자 흐름

1. **여행 만들기**: 제목·도시·출발일·귀국일로 콘텐츠를 만든다. 이미 작성한 ‘내 여행’은 현재 사용자 소유의 여행/장소 계획을 복사해 가져올 수 있다.
2. **항공편 기준 세우기**: 가는 편/오는 편을 선택하고 편명+운항일 웹 검색을 연다. 항공사 정보에서 확인한 공항·현지 출발/도착 날짜·시각·시간대를 입력한다.
3. **계획 작성**: 여행 기간 안에 날짜·시각·장소·주소·메모를 추가한다. 기존 계획 수정도 같은 ID를 유지한다.
4. **영수증 등록**: 장소 계획의 ‘영수증 등록’에서 JPG/PNG/PDF 원본을 선택한다. 상호·실제 결제 날짜/시각·총액/통화·메뉴/수량/구매 상세·경험 메모를 확인해 작성한다.
5. **계획과 실제 비교**: 장소 카드에는 원래 계획이, 하단에는 각각의 영수증과 실제 구매 상세가 표시된다. 여러 영수증을 한 계획에 연결할 수 있다.
6. **다시 보기**: 같은 기기/브라우저에서 다시 열면 콘텐츠와 원본 첨부를 읽는다. 기존 체크인 기록은 별도 목록으로 유지한다.

예: ‘11/10 12:00 도쿄 식당 — 라멘 예약’ 계획에 ‘11/11 12:30, 2500 JPY, 라멘 2그릇·각 1250 JPY, 현금 결제’ 영수증을 연결한다. 계획 날짜를 실제 결제 날짜로 덮어쓰지 않는다.

## 2. 항공권/항공편 범위

이 기능은 **편명 기반 운항 정보 확인·기준표 작성**이다. 운임 비교·발권·예약 확정은 제공하지 않는다. 편명만으로 날짜가 결정되지 않으므로 검색에는 운항일을 반드시 포함한다. 같은 편명이라도 날짜별 스케줄은 달라질 수 있어 검색을 등록과 구분한다.

현재 검색은 편명+운항일의 실제 웹 검색을 새 창으로 연다. 실시간 항공 데이터 공급자 API, 자동 스케줄 추출, 예약번호 조회는 연결하지 않았다. 임의 스케줄을 응답하지 않는다. 자동 조회는 공급자 선정·접근 키·정확한 날짜 조회 범위가 준비된 뒤 별도 연동한다.

항공 기준은 현재 가는 편/오는 편 각 한 구간이다. 같은 방향 수정은 기존 기준을 교체한다. 경유 여러 구간·멀티시티·취소/변경 알림은 후속 확장이다.

| 기준      | 규칙                                                                  |
| --------- | --------------------------------------------------------------------- |
| 출발일    | 가는 편의 출발 공항 현지 날짜                                         |
| 귀국일    | 오는 편의 도착 공항 현지 날짜                                         |
| 현지 시각 | 날짜/HH:mm/UTC 오프셋을 각각 입력, 저장은 오프셋 포함 ISO 시각        |
| 왕복 순서 | 실제 UTC 도착/출발 순서로 비교. 날짜 변경선을 넘는 시각도 처리        |
| 기간 변경 | 기존 계획·영수증 실제 날짜가 새 기간 밖이면 차단, 자동 이동/삭제 없음 |
| 최대 기간 | 시작일 포함 1~90일                                                    |

한국/일본 기본 오프셋은 +09:00으로 제시한다. 다른 공항과 서머타임은 확인한 운항 날짜의 실제 오프셋으로 바꿔 입력해야 한다. 공항 코드만으로 시간대를 자동 추정하지 않는다.

## 3. 영수증의 역할

원본 파일과 사용자 확인 데이터를 함께 저장한다. 영수증 등록은 GPS 방문 인증이나 자동 OCR 인증이 아니다. 사진·PDF만 첨부하면 완료하지 않고 최소 상호·결제 날짜/시각·양수 총액·지원 통화·구매 상세를 함께 입력한다.

- 허용 파일: JPG/PNG/PDF, 파일당 2MB 이하. 사진은 카드 미리보기, 원본은 웹 다운로드 또는 네이티브 공유로 제공한다.
- 금액: decimal 문자열. KRW/JPY 정수, USD 소수 두 자리까지. 환산·서로 다른 통화의 합산 없음.
- 연결: 같은 콘텐츠의 기존 planId에만 연결. 여행 밖 결제 날짜 거부. 계획과 실제 날짜는 별도 보존.
- 중복: 같은 영수증 ID는 교체하며 새 ID는 별도 기록. 동일 사진/같은 결제의 자동 중복 탐지는 미제공.
- 삭제: 영수증 있는 계획의 삭제는 차단. 영수증 기록 삭제 후 다른 기록이 참조하지 않는 관리 파일을 정리한다.

수량·단가·메뉴는 현재 상세 텍스트로 기록한다. 자동 품목 추출·부가세/팁·품목별 합계 검사·expenses 자동 반영은 후속이다. 기존 여행 비용과 영수증 총액을 동시에 합산해 중복 집계하지 않는다.

## 4. 기기 저장 및 기존 서비스와의 관계

기기 초안은 현재 로그인 계정과 연결하지 않는 `device-draft` 영역이다. 기존 프로토타입의 임시 로그인 ID가 재발급돼도 기기 초안이 사라지지 않도록 분리했다. 같은 기기를 사용하는 사람은 이 초안을 볼 수 있으며, 다른 계정/다른 기기와의 서버 공유 기능은 없다. 화면에서 계정 미연동·기기 초안임을 안내한다.

| 플랫폼      | 콘텐츠                                                                  | 첨부                                                                |
| ----------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 웹          | localStorage `wherego-trail-device-draft`, `{version:1,journeys:[...]}` | base64 data URI. 임시 blob URI는 저장하지 않음                      |
| Android/iOS | 앱 문서 `wherego-trail-device-draft.json`                               | 앱 문서 `trail-receipt-<uuid>.jpg/png/pdf`로 실제 복사 완료 후 연결 |

파일/문서 저장 완료 뒤에만 화면 결과를 확정한다. 웹 용량 부족이나 파일 쓰기 실패는 입력을 유지하고 오류로 표시한다. 읽기/버전 오류 때 빈 문서로 자동 덮어쓰지 않는다. 앱 문서 경로 변경 시 관리 파일명을 현재 문서 경로로 다시 연결한다.

웹 브라우저 데이터 삭제·시크릿 창 종료·앱 삭제·기기 분실은 로컬 기록 소실을 일으킨다. 현재 외부 백업/복구·원격 동기화는 없다. 네이티브 저장은 단일 JSON 파일로 전원 중단까지 보장하는 DB 트랜잭션과 다르다. 저장 중 입력/중복 저장을 막는다.

가져오기는 기존 여행/일정의 **복사**이며 sourceTripId로 중복 가져오기를 막는다. 이후 변경을 원본 여행에 자동 전파하지 않는다. 기존 DB `receipts`, `expenses`, `visits`, `itinerary_items`를 직접 변경하지 않는다. 이번 요구에 한해 기기 초안 작성 범위를 추가했으며 기존 MVP의 서버 원본/오프라인 저장 큐 정책을 일반적으로 변경하지 않는다.

| 실제 브라우저 흐름                    | `tests/web/trail.spec.ts`, `playwright.config.ts`, `scripts/preview-trail.mjs` |

Expo SDK 57 호환 document-picker/file-system/crypto/sharing을 `npx expo install`로 추가했다. 규칙 테스트는 기존 기반 테스트와 함께 실행한다. 브라우저 테스트는 자체 새 Chrome 프로필에서 폼·파일 선택기로 작성하고 새로고침 후 보존을 확인한다. 실제 사용자 프로필·브라우저 저장소를 테스트에 사용하지 않는다.

```powershell
npm run check
npm run test:foundation
npm run build:web
npm run test:trail:web
```

웹 테스트에는 설치된 Chrome이 필요하다. 웹 검토는 `npm run build:web` 후 `npm run preview:trail`, `http://127.0.0.1:8788/footprints`에서 수행한다. 프리뷰 서버는 빌드 폴더만 제공하고 로컬 PC에만 바인딩한다.

확인된 브라우저 흐름: 여행→장소 계획→PNG 원본/상세 등록→재조회, 왕복 항공 기준 입력→재조회. Android/iOS 실기기 파일 선택·복사·공유·앱 재실행과 실제 항공사 정보 정확성은 별도 검증이 필요하다.

2026-10-02 검증 결과: 기반/발자취 규칙 테스트 총 28개 통과, 실제 브라우저 흐름 3개 통과(편명·운항일 검색 요청 URL 포함), Expo 웹 정적 export 성공. 최종 타입/lint/format은 `npm run check`로 검증한다.

현재 의존성 audit은 17개(높음 4/중간 13), 기존 Expo 의존성 경로 및 sharing의 config-plugins 전이 보고다. 기존 호환 패치 과제를 유지하며 주요 버전 자동 변경은 하지 않았다.

기술 근거: [Expo DocumentPicker](https://docs.expo.dev/versions/latest/sdk/document-picker/), [FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/), [Sharing](https://docs.expo.dev/versions/v57.0.0/sdk/sharing/). 실제 설치 버전의 비동기 파일 API와 웹 picker base64 필드를 확인해 구현했다.
