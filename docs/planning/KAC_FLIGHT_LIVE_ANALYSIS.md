- 작성일: 2026-10-14
- 버전: 1.0.0
- 실제 조회: 등록된 로컬 인증키로 공급자 HTTP 10회, 서버 변환 함수 경유 3회. 모두 정상 응답.

## 실제로 넘어온 값

응답은 `response.header`와 `response.body`로 나뉜다. HTTP 200, `resultCode=00`, `resultMsg=NORMAL SERVICE.`를 확인했다. 본문은 `numOfRows/pageNo/totalCount/items.item[]` 구조다. 편명 필터를 넣은 RS901은 출발·도착 두 행을 반환했다. 전체 공항 조회는 총 1,901건 중 첫 100건을 확인했다. 전체 데이터 품질을 100건 표본으로 일반화하지 않는다.

## 국내선 출발·도착 결합 조건

출발행의 날짜·편명·공항 코드·공항 이름을 먼저 검증한다. 출발과 도착이 모두 확인한 한국 공항인 경우에만 같은 편명, 같은 방향의 공항쌍, 같은 항공사, 올바른 공항 이름을 가진 도착행을 찾는다. 등록번호·기종이 양쪽에 있으면 일치해야 한다. 없는 등록번호는 추정하지 않는다.

동일 날짜·구간의 출발행이 하나이고 조건을 만족하는 도착행도 하나이며, 계획시각 차이가 양수이고 6시간 이내일 때만 결합한다. 모호한 반복 운항·중복행·다른 기체·다른 항공사·역전 시각·잘못된 날짜는 결합하지 않는다. 같은 한국 시간대의 계획시각 차이만 소요시간으로 계산한다. 해외 구간은 시차를 추정해 계산하지 않는다. 날짜 범위 밖의 다음 날 도착행을 추가 요청하지 않으므로 해당 경우에는 도착시각이 비어 있을 수 있다.

## 화면 설계와 구현

편명 입력 → 찾기 → 항공권과 같은 구간 확인 → 선택 요약 → 저장 순서다. 공통 `FlightLookupCandidateCard`와 `FlightRoutePreview`를 여행 생성·일정 추가에서 함께 사용한다.

- 후보 상단: 편명·항공사·조회 당시 상태. 날짜와 현지 시각 안내.
- 후보 중앙: 출발/도착 예정 라벨, 큰 시각, 공항 코드, 공항 이름. 없는 도착시각은 ‘항공권 확인’과 다음 행동 안내.
- 후보 하단: 출발 게이트·실제 출발이 있으면 예정시각과 구분하고 ‘조회 당시 · 변경될 수 있어요’ 표시. 주요 선택 버튼은 기체 정보 앞에 둔다.
- 기종·등록번호: ‘기체 정보’를 누르면 펼침. 첫 화면의 선택 동작을 밀어내지 않음.
- 선택 후: 공항·예정시각 요약을 동일한 모양으로 표시. ‘항공편 정보 수정’에서 누락된 도착·터미널·예약 조건을 보완. 기체 입력은 상세 입력 끝으로 이동.
- 저장 카드: 예정 라벨과 누락 안내를 유지. 기종·등록번호는 기존 ‘항공편 정보 보기’ 안에 표시. 조회 당시 상태·실제 출발·게이트는 실시간 정보처럼 저장하거나 재표시하지 않음.
- 출처와 제공 범위: 후보 아래 표시. 결과 없음·실패·재시도·직접 입력·기존 작성 내용 보존 동작 유지.

기존 UI TOOL KIT의 아이보리·흰 카드·코랄 강조·네이비 글자·16 모서리를 적용한다. 원본 SVG `flight-outline`을 공항 사이에 사용한다. 44 이상 터치 영역을 유지하고 360/390/430 폭을 검수한다. 색상만으로 선택·운항 상태를 전달하지 않는다.
