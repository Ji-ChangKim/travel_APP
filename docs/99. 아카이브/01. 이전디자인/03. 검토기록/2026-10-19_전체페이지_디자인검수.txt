docs/02. 디자인/01. 화면설계/01. 페이지시안/PAGE_MANIFEST.json이 화면 번호·이름·상위 화면·분류·파일의 목록이다. 각 화면은 Num_페이지명.html, 캡처는 같은 이름의 PNG로 정리했다. ALL_PAGES.html에서 번호순 축소판을 누르면 전체 내용을 읽고 이동할 수 있다. PNG는 첫 화면이며 HTML에는 스크롤 아래 내용도 포함한다.
큰 페이지와 작은 페이지는 parent로 연결했다. 예외와 팝업도 발생한 화면으로 연결한다. 같은 장소라도 개인 원본·검색 후보·공개 읽기는 별도 화면이다.

4. 브라우저 화면 검사
106개 × 화면 폭320/390/430px × 글자100/200% =636조합을 실제 브라우저에서 검사했다. 본문·헤더·팝업 가로 넘침0, 보이는 버튼의44px 미만 터치 영역0, 깨진 이미지0. DAY 목록의 의도한 가로 스크롤은 본문 넘침과 구분했다. 이미지가 없는 기본 슬롯은 정상 대체 상태로 검사했다.
기본390px/100%의106개 최종 캡처: outputs/page-design/captures/.
상세 기록: baseline-final.json(106개), wide-final.json(430px의212조합). 집계: matrix-summary.json. 320/390px의424조합은 도구 실행 결과로 확인했으나 브라우저 제어 세션 초기화로 전체 상세 배열을 보존하지 못했다. 보존한 상세 기록과 실행 집계를 구분한다.
320px·글자200%·긴 제목을 추가 확인했다. 여행 제목은 줄바꿈하고 세로로 스크롤한다. DAY1→DAY2 선택 전후 각 버튼의 너비·높이가 같았고 가로 넘침이 없었다. 증거: long-title-320-large.png. 큰 글자에서 긴 제목이 첫 화면의 많은 높이를 차지하는 점은 실제 앱 적용 때도 사용자 검토 대상이다.
공개 확정·도시 출처 팝업은 애니메이션 종료 프레임으로 다시 촬영했다. 흰 패널·제목·닫기·본문·버튼을 대조했고 중간 프레임의 겹침을 제거했다. 캡처 모드만 애니메이션을 생략하며 실제 시안에는 열기200ms·닫기150ms와 동작 줄이기 처리가 남아 있다.

5. 실제 조작 검사
브라우저의 입력과 버튼으로 DAY 소개 수정→장소 설명 수정→선택 공개 미리보기→공개 사본 읽기를 확인했다. 수정한 소개·설명은 유지되고 개인 메모와 선택을 해제한 장소는 빠졌다. 공개 장소 읽기에는 수정 행동이 없다. 기록: outputs/page-design/selection-flow.json.
보기 전용에서 쓰기 행동 숨김, DAY2 지도와 같은 DAY 장소 목록 일치, 나라 변경 뒤 도시 초기화, 생일 없이 온보딩 복귀를 확인했다.
팝업은 안전한 닫기 버튼에 처음 초점을 둔다. 마지막 조작에서 닫은 뒤 검토 목록의 중복 버튼을 찾던 문제를 고쳤다. 실제 화면 안의 진입 버튼과 검토 목록을 구분해 선택하고, Escape 종료 후 ‘여행 관리 메뉴’로 초점이 돌아오는 것을 재확인했다. 기록: outputs/page-design/interaction-summary.json. 이 수정은 초점 대상 선택만 바꾸며 화면 모양과636조합의 크기 조건에는 영향을 주지 않는다.
이 흐름은 로컬 메모리의 상호작용이다. 새로고침 후 서버 재조회·실제 게시·계정 권한 인수로 보고하지 않는다. 실제로 연결하지 않은 카메라·인증·결제·설정 행동은 바깥 검토 안내에서 범위를 구분한다.

6. 실제 장소 사진 확인
검토 도구에서 실제 Google 사진 옵션을 켜고 기존 공개 장소 사진 API를 읽기 전용으로 조회했다. DAY1의8개 사진이 로드됐고 오류0·깨진 이미지0을 확인했다. 증거: outputs/page-design/google-photo-review.png.
기존 공개 데이터나 게시물을 수정하지 않았다. 키·사진 원본·사진 URL을 별도 데이터 파일로 저장하지 않았다. 기본 시안은 대체 슬롯이며 전체19개 사진·모든 예외·공급자 비용·권한을 이번 결과로 승인하지 않는다. 지도는 DAY별 상대 위치 도식으로, 실제 Google 지도 타일이나 경로 검증이 아니다.

7. 독립 UI 검토
UI 팀장 역할의 AI 검토가 소스와 최신 대표12개 캡처를 직접 대조했다. 초기 공개0건·공개 사본·철회 재진입·보기 전용 복귀 오류를 고쳤고 새 P0 디자인 오류는 발견되지 않았다. 판정은 디자인 제작본 조건부 승인이다. 직접 검토 범위와 제작 담당의 자동·조작 검사 보고는 PAGE_UI_LEAD_REVIEW.txt에서 구분했다. 실제 사람인 UI 팀장의 승인으로 표현하지 않는다.
제작 담당도 일정·공개계획·공개 확정·320px 큰 글자 긴 제목과 전체 보드를 직접 열어 확인했다. 전체106개를 모두 육안으로 완전 승인했다고 보고하지 않는다.

8. 남은 차이와 실제 앱 적용 조건
최종 디자인 선택은 사용자 검토가 필요하다. 현재 결과는 전체 화면 디자인과 로컬 상호작용 제작본이다. 실제 앱 코드·API·DB·버전코드·Android 빌드·배포는 이번 작업에서 변경하지 않았다. 기존의 다른 작업 변경은 보존했다.
실제 적용 후 작은 기기·큰 글자·키보드·TalkBack·시스템 뒤로·안전 영역·위치 및 카메라 권한·통신 복귀를 확인해야 한다. 공개 사본·권한·서버 저장/재조회, Google 지도와 검색, 촬영/업로드는 실제 API와 내부테스트 설치본으로 별도 검증한다.
