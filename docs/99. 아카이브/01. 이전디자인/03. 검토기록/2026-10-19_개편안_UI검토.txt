TripPrint 전체 개편 UI 독립 검토
검토일: 2026-10-19
검토 역할: UI 경력 10년 차 팀장 관점의 AI 독립 검토자
판정: 개편 방향은 조건부 승인. 현재 시안의 일괄 개발 착수·출시 디자인 확정은 보류.
이 문서는 실제 인간 UI팀장의 승인이나 사용자의 최종 승인을 대신하지 않는다.

1. 판정 근거

여행 원본에서 일정·사진·비용을 쌓고 선택한 내용만 공유하는 방향은 유지한다. 네이비·코랄·아이보리, Pretendard, 왼쪽 제목, DAY 배경 채움도 적절하다. 블로그 본문을 별도로 쓰지 않는 공개 계획 구조를 승인한다.
다만 예쁜 카드 배치와 고객 작업의 완결성 사이에 차이가 남아 있다. 홈에서 다음 일정 브리핑이 사라졌고, 공개 장소 읽기가 개인 일정 추가로 연결된다. 공유 선택이 미리보기에 반영되지 않으며 정상 지도·사진 기록·동행·공개 확정 화면을 검토할 수 없다. 이 상태를 전체 디자인 컴펌 완료로 보고 개발에 넘기면 안 된다.
P0는 고객 데이터·공개 범위·권한·저장에 영향을 주는 출시 차단 조건이다. 시안에 서버가 없다는 이유만으로 결함이라고 판정한 것은 아니다. 현재 시안으로 해당 계약을 확인할 수 없으므로 아래 사례를 보완한 뒤 승인한다. P1은 개발 전달 전 고칠 설계·규격, P2는 후속 제안이다.

3. 화면별 수정 요청과 승인 조건

홈 / P1
사진 표지와 주요 행동 하나는 유지한다. 그러나 기존 홈의 다음 일정 장소·DAY·시간 정보가 일반 문구로 바뀌었다. 큰 여행 표지 아래에 같은 여행의 다음 일정 한 건과 예약 확인 행동을 넣는다. 여행 중에는 오늘 일정, 준비 중에는 다음 준비 행동, 완료 여행만 있으면 기록 열기로 바꾼다. 상태·설명·버튼은 같은 판별 결과를 사용한다. 추천은 여행 작업보다 아래에 둔다.

내 여행 / P1
검색과 상태별 원본 보관은 승인한다. 현재 시안의 필터는 전체/예정/완료만 있고 여행 중·날짜 미정의 처리와 검색 결과 수가 보이지 않는다. 상태 머신과 필터 대응을 명시하고 결과 없음과 여행 없음도 구분한다. 첫 여행 열기와 새 여행 만들기의 버튼 위계는 사용자 검토로 확정한다.

여행 만들기 / P0
날짜 나중에 정하기는 선택할 수 있지만 기간 입력과 DAY 생성의 관계를 확인할 수 없다. 나라 변경 시 도시 초기화, 날짜 미정·과거 여행·기간 축소를 각각 보여준다. 기존 여행ID와 DAY ID, 연결 지출·사진을 보존하는 현재 계약과 새 배치를 맞춘 후 승인한다. 항공권은 필수로 만들지 않는다.

DAY 일정 / P1
체크 없는 네이비 채움과 같은 크기의 DAY는 승인한다. 다만 화면에 실제 방문 시간·미정 상태·순서 편집·장소 관리 진입이 없다. 시간은 등록된 값만 표시하고 미정은 작게 안내한다. 상세 헤더 오른쪽의 더보기가 항공 아이콘 하나로 대체돼 공유·사진·동행 진입이 보이지 않는다. 예약 바로가기와 전체 관리 진입을 구분한다.

지도 / P0
오류 안내만으로 정상 지도 설계를 승인할 수 없다. 동일 DAY의 실제 핀·선택 장소 카드·장소 목록 복귀, 위치 권한 거부·서비스 꺼짐·정확도·설정 복귀를 제시한다. 연결선과 실제 도로 길찾기를 구분한다. 내부테스트 설치본의 타일·검색 성공은 출시 전 필수 인수다.

장소 검색 / P0
도시·DAY 맥락 유지와 직접 입력은 승인한다. 후보 선택→추가→저장→같은 DAY 복귀에서 실제 장소ID·주소·좌표가 함께 보존돼야 한다. 늦은 응답·0건·사진 실패·할당량 초과를 구분한다. 검색한 것처럼 고정 예시 후보가 뜨는 시안을 실제 검색 성공으로 인수하지 않는다.

장소 설명·팁 / P0
현재 place()는 공개 계획과 개인 검색에서 같은 화면을 열고 footer()가 모두 ‘이 장소 추가’를 표시한다. 공개 읽기는 읽기 전용으로 돌아가고, 검색 후보만 추가, 개인 기존 일정은 권한이 있을 때 편집으로 나눈다. 제목·선택 DAY·원래 목록 스크롤을 유지한다. 우→좌 200ms 진입·150ms 닫기 및 동작 줄이기 계약은 기존 컴포넌트로 보존한다.

장소 편집 / P0
공개 설명과 개인 메모를 나눈 점은 승인한다. 선택 DAY·시간·일정 유형·장소 연결·선택 후보/대체 장소·순서 필드가 시안에서 빠져 있다. 기존 입력을 삭제하는 개편으로 해석되지 않게 상세 폼을 보완한다. 원문 임의 절삭 금지, 저장 실패·409 충돌·중복 제출·이탈 후 입력 보존을 인수한다. 설명을 쓰지 않아도 일정 저장이 가능해야 한다.

이날 소개 편집 / P1
이날 제목과 소개의 분리는 승인한다. DAY2 이후 소개가 편집/개인 일정/공개 읽기에서 다른 예시 문구로 표시된다. 동일 DAY 원본이 선택 공유 후 같은 내용으로 나오는 연결을 시안에서도 보여준다. 소개를 쓰지 않으면 빈 장문 영역을 남기지 않는다.

항공·예약 / P0
공항·현지 시각 우선 배치는 승인한다. ‘숙소 추가’가 장소 편집으로 연결되는 오류와 항공 조회 진입 부재를 수정한다. 예약번호·첨부 공개 제외, 날짜 경계·취소·조회 실패·수동 입력을 확인한다. 제공하지 않는 운항 변경 알림이나 예약 자동 수집을 약속하지 않는다.

항공권 직접 입력 / P1
출도착 현지 날짜·시각 안내는 유지한다. 현재 고정 텍스트 입력을 실제 날짜·시각 선택과 공항 선택으로 바꿀 규격을 지정한다. 키보드와 하단 저장이 겹치지 않고 국제선 날짜가 달라도 입력할 수 있어야 한다.

비용 / P1
통화별 합계와 실제/예상 분리는 승인한다. 두 개 탭과 등록 항목이 실제로 바뀌는 상태, 항목 상세·수정·삭제, 연결 일정이 없는 비용을 보완한다. 서로 다른 통화의 합계나 가짜 환율을 만들지 않는다. ‘지출 추가’가 바로 영수증 확인으로 가는 흐름보다 촬영/앨범/직접 입력 선택을 먼저 제시한다.

지출 직접 입력 / P0
금액·통화·일정은 적절하다. 실제/예상 구분과 현재 지원 통화를 누락하지 않는다. 소수·0·상한·미지원 통화·중복 저장을 구분하고 서버 재조회 합계와 일치해야 한다.

영수증 확인 / P0
사진 보기 버튼이 자기 화면으로 돌아가 원본을 대조할 수 없다. 촬영/앨범→원본 확대→인식 초안→품목 합계/총액 차이→사용자 확정→한 건의 지출 연결을 완성한다. 사진·총액·통화의 추출 실패 상태와 수정 후 재시도를 각각 설계한다. 인식 결과를 확정 지출처럼 표시하지 않는다.

발자국 / P1
완료 여행 원본을 읽는 역할은 승인한다. 현재 같은 제목의 여행이 홈에서는 11월 예정, 발자국에서는 10월 완료로 바뀌는데 같은 일정 화면으로 연결된다. 서로 다른 예시 여행임을 데이터로 나누고 해당 여행의 날짜·일정·비용이 유지되게 한다. 사진 추가·기록 더하기가 일반 장소 편집으로만 가는 흐름도 수정한다.

선택 공유·미리보기 / P0
선택 공유와 영수증·예약번호·개인 메모 기본 제외는 승인한다. 현재 체크를 해제해도 publicPlan()은 고정 DAY/장소를 읽는다. 공개될 DAY·일정·일반 사진만 미리보기에 표시하고 선택 0건은 게시하지 못하게 한다. 미리보기→공개 확정→공개 사본→수정/재게시·철회를 검토할 수 있게 추가한다. 개인 원본 편집과 공개 사본 갱신은 구분한다.

발견 / P1
공개 계획을 여행 조건으로 찾는 방향은 승인한다. 보고서의 도시·일수·관심사 필터와 시안의 단순 계획/기록/오사카 버튼이 다르다. 첫 적용 범위를 확정하고 필터 조합·결과 없음·철회 게시물·작성자/원본 출처를 보여준다. 출처 없는 인기·평점·좋아요 수는 넣지 않는다.

공개 여행계획 / P0
여행 제목 헤더와 DAY 소개·장소·설명 구조는 승인한다. 실제 Google 장소 사진 필수는 유지한다. 지금 대부분 자리 표시이고 작성자·Google 출처·사진 실패 상태가 없으므로 이미지 규격 최종 승인은 보류한다. 기존 PlacePhoto의 88×88·원본 접근·간결한 출처·재시도 계약을 그대로 연결한다. 반복되는 긴 저작자 텍스트 줄을 다시 만들지 않는다. 공개된 내용은 원래 여행계획에서 작성·선택한 범위와 일치해야 한다.

MY / P1
계정 중심 역할은 적절하다. 프로필 편집이 장소 편집으로, 알림/계정 설정이 같은 MY로 연결되는 임시 이동은 개발 전달 전에 제거한다. 공개 관리에는 실제 공개 사본 목록·철회·소유자 확인이 필요하다. 재인증·로그아웃·탈퇴·이탈 보호와 기존 회원 유지 계약을 보존한다.

누락 화면 / P1
사진·영수증 보관, 동행 역할·초대, 준비물, 인증/온보딩, 정상 지도와 공유 확정은 문서만 있고 대표 시안이 충분하지 않다. 일곱 고객 작업을 끝까지 확인할 대표 상태를 추가해야 전체 컴펌 범위가 된다. 기존 기능을 숨기거나 없애는 변경은 별도 사용자 결정이 필요하다.

4. 시각 규격 판정

유지 확인: 기본 제목 26/36·700, 섹션22/30, 장소18/26·600, 본문16/26, 보조14/22, 하단13/20, 좌우20·카드16·섹션24, 최소터치44·주요버튼52, 네이비/코랄/아이보리와 DAY 네이비 채움. 캡처의 왼쪽 설명 행동과 사진/제목 묶음은 이전 중앙 링크보다 훑어보기 좋다.
P1 아이콘: 시안 icon()은 임의 SVG path와 stroke-width 1.7을 사용하지만 현행 토큰은 기본24·선2와 원본 예외2.5다. 기존 53개 아이콘을 연결하고 없는 아이콘만 같은 체계로 요청한다. 하단 활성 상태는 기존 filled 자산을 우선 비교한다.
P1 표지 모서리: 시안 cover-card는 radius16을 사용하지만 표지 기준은20이다. 일반 카드16과 여행 표지20을 구분하거나 바꾸려는 근거를 명시해 사용자 결정을 받는다.
P1 헤더: 개인 상세의 같은 행 여행 제목은 현행 별도 제목과 다른 제안이다. 사용자 승인 전 전 화면에 확장하지 않는다. 긴 제목52/72가 본문을 밀 때 최소 본문·스크롤을 실제 캡처로 재확인한다.
P1 확대: .number가32×32에 글자200%를 담고 있어 순서10 이상·날짜가 긴 경우를 별도 확인해야 한다. 큰 글자 여부를 CSS :has(검토 체크박스)에만 의존하지 말고 앱의 실제 글자 배율과 가용 너비로 전환한다.
P1 접근성: 시안의 일반 button에 aria-selected만 붙인 것은 전체 탭 패턴 검증을 뜻하지 않는다. 개발 시 탭/버튼 의미와 초점·선택 상태를 맞추고 키보드 이동·TalkBack 읽기·우측 상세 복귀 초점을 인수한다. 자동 검사 통과를 WCAG 전체 적합성으로 보고하지 않는다.

5. UI팀장에게 전달할 자산 활용 요청서

요청 A / 앱 아이콘·브랜드
TripPrint_app-icon_1024x1024, Play512, Android foreground/monochrome, 가로 로고 자산을 유지한다. 스토어용·런처용·앱 안 브랜드용을 구분해 전달한다. 하루를 작은 런처 아이콘 안에 추가하지 않는다. 실제 Android 원형/둥근 사각/테마 아이콘과 흰 시작 화면 중앙 심볼을 비교한다. 원본 SVG/PNG·manifest·해시와 글꼴 라이선스를 보존한다.

요청 B / 하루 적용 화면
첫 여행 만들기, 여행이 없는 홈/발자국, 재시도 가능한 오류에 각각 기존 empty/error를 배치한 안을 요청한다. 로딩은 기존 loading과 실제 진행 표시를 함께 쓰되 고정 대기시간을 만들지 않는다. 기본 조합은 세로 흐름 안에서 캐릭터→짧은 안내→주요 행동 하나다. 크기는 기존 브랜드 컴포넌트 규격으로 제시하고 새 임의 고정값을 제품 토큰에 넣지 않는다.
빈 화면과 오류에서도 버튼·입력·지도·장소 사진을 가리지 않게 한다. 일정이 많은 화면, 비용 숫자, 영수증 확인과 키보드 위에 캐릭터를 띄우지 않는다. 320px·200%에서 글과 행동이 먼저 보이도록 장식 크기를 줄이거나 생략하는 안도 함께 제시한다. 원본의 얼굴·색·옷·자세·투명 배경을 보존한다. 실제 확인한 empty 이미지는 RGBA1024×1536, 알파0~254다. 아이보리 합성에서 테두리·번짐은 별도 확대 검수한다.

요청 C / 접근성과 신규 제작 조건
장식 캐릭터는 화면 읽기에서 제외하고 상태는 텍스트로 전달한다. 실제 로딩·오류를 이미지 하나로만 구분하지 않는다. 움직임은 기본 정적 자산을 우선하고 추가 애니메이션은 동작 줄이기·백그라운드 정책을 제시한 뒤 검토한다.
기존 자산으로 설명할 수 없는 상태가 확인될 때만 새 포즈를 요청한다. 요청에는 화면·사용자 문제·기존 자산으로 부족한 이유·참조 원본·종횡비·투명도·파생 파일·접근성·승인자를 함께 적는다. 하루 신규 제작은 원본 참조 편집으로 진행하고 원본 파일을 덮어쓰지 않는다.

자산 권리 기록
아이콘 LICENSE는 사용자 지정 Stitch 원본의 All rights reserved와 별도 오픈소스 허가 미기재를 명시한다. 이를 MIT/Apache 자산으로 다시 표시하거나 외부에 독립 배포하지 않는다. 브랜드/하루 manifest는 생성·참조·파일 이력을 기록하지만 별도의 포괄 라이선스 문서는 아니다. 기존 프로젝트 사용 이력은 보존하며 외부 배포물에 포함할 원본 권리 확인은 출시 담당자가 기록한다. Pretendard/Poppins 라이선스는 해당 fonts 폴더를 유지한다. 경쟁사 아이콘·사진·캐릭터·문장을 그대로 제품 자산으로 복사하지 않는다.

6. 수정 후 승인 절차

첫 재검토: 홈의 다음 행동, 정상 지도/검색, 개인·공개 장소 상세의 분기, DAY/장소 작성→선택 미리보기의 일치, 사진·예약·동행 진입, 공식 아이콘과 하루 적용안을 제출한다. P0 계약과 누락 화면을 확인한 뒤 화면 묶음별 개발 전달을 승인한다.
구현 검수: 320/390/430, 글자100/200%, 긴 여행/장소명·순서10 이상·여행0건·일정0건·사진 실패·권한 거부·느린 응답·오프라인·재시작을 실제 앱 캡처로 확인한다. Android 안전 영역·시스템 뒤로·키보드·TalkBack·동작 줄이기도 포함한다.
기능 인수: 분리된 검수 계정으로 여행→항공→DAY/장소→영수증→지출 합계→발자국→선택 공개를 완주하고 서버 저장·재조회·권한·공개 사본을 대조한다. 버전코드·서명·키 제한을 확인한 Play 내부테스트 설치본 결과를 최종 제출한다.
P2 ‘내 여행에 담기’는 신규 계약 확정 전 주 행동으로 출시하지 않는다. 초기 공개 화면은 실제 지원하는 읽기·외부 지도·공유 행동만 사용하고 신규 복제는 별도 승인한다.
100만 다운로드는 사업 목표이며 이 디자인 판정으로 달성을 보증하지 않는다. 첫 장소 저장 성공·복귀·재방문·공개 조회·오류·비용을 실제로 측정해 개선 순서를 결정한다.
