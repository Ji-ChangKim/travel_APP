TripPrint 전체 페이지 제작본 UI 독립 재검토
기준일: 2026-10-19 / 검토 대상: page-design-1
검토 역할: UI 경력 10년 차 팀장 관점의 AI 독립 검토자
최종 독립 판정: 디자인 제작본 조건부 승인. 제품 적용·출시 승인은 포함하지 않는다.
승인 범위: 기존 브랜드·공통 디자인 시스템·핵심 작업의 화면 구조와 대표12개390×844 제작 캡처. 조건: 세부 상태·접근성·제품 적용 인수와 사용자 최종 검토를 완료한다. 전체 확대 행렬은 제작 담당 보고로 완료됐으며 독립 검토자의 직접 실행 범위와 구분한다.
실제 인간 UI팀장이나 사용자의 최종 승인으로 표현하지 않는다. 이 문서는 앱·API 구현이나 출시 인수 결과가 아니다.

1. 검토 범위와 확인 방법

전체페이지_디자인규격.txt·팝업_규격.txt·pages/PAGE_MANIFEST.json과 catalog.mjs·model.mjs·components.mjs·screens.mjs·states.mjs·review.js·review.css·design-system.mjs를 읽었다. 현행 디자인시스템.md·design-tokens.json3.0.2·헤더GNB_규격.md·공개여행계획_화면규격.md·일정 규격·이전 UI_LEAD_REVIEW.txt를 대조했다.
pages의 HTML106개와 captures의 PNG106개 존재를 확인했다. 기본390×844 캡처 중100·210·211·221·311·420·421·701·801·802·805·812를 직접 열어 제목·문구·사진·아이콘·하루·DAY·행동·팝업 배치를 확인했다. baseline.json의 가로 넘침·44px 미만 버튼·깨진 이미지0 기록도 읽었다. 해당 자동 검사를 이 검토자가 재실행한 것은 아니다.
106개 캡처 전부를 육안으로 검토했다고 보고하지 않는다. 320/200%·Android 키보드/TalkBack·실제 Google 타일·서버 저장·Play 설치본은 별도 인수 대상이다.

2. 이전 필수 요청에서 보완된 점

홈100에 다음 일정의 DAY·날짜·시각 미정·장소·예약 확인을 복원했다. 큰 표지 반복 대신 작은 여행 요약과 주요 행동 하나를 사용했다.
개인 장소221의 하단은 일정 수정, 공개 장소311은 보던 일정으로 복귀, 검색 후보222는 이 장소 추가로 분리했다. 공개 읽기에서 바로 개인 장소를 추가하던 기본 분기는 고쳤다.
DAY는 체크와 체크 공간 없이 흰색→네이비 채움·밑줄·aria-pressed를 사용한다. 개인 상세는 이동 바와 큰 제목을 분리하고 공개 상세만 제목을 뒤로가기 옆에 둔다.
일정 개별 체크가 previewSnapshot에 투영되고 선택0건은 미리보기/공개 버튼을 잠근다. 확정 시 structuredClone으로 공개 사본을 만들어 이후 원본 편집을 자동 반영하지 않는다. 공개 허용 필드를 명시하고 개인 메모·예약·동행·영수증은 제외한다.
사진/영수증·준비물·동행·예약·숙소·계정·인증·예외·확인/선택 시트가 번호별 파일로 추가됐다. 영수증 원본 화면도 확인 폼과 분리했다.
공식53개 아이콘 자산과 하루 empty/error/loading을 재사용했다. 여행 표지20·일반 카드16·버튼12·팝업24를 구분했다.701의 하루는 행동을 가리지 않고 빈 상태 설명을 돕는다.
원문은 plan-source.mjs의4DAY·19장소로 관리하고 별도 블로그 본문을 만들지 않는다. 원문에 포함된 영업·평점 문구를 실시간 Google 조회 결과로 새로 생성하지 않는다는 문서 경계도 확인했다.

3. P0 필수 수정 — 공개 범위·권한의 디자인 계약

P0-1 공개 읽기에서 작성자용 선택 안내 노출
screens.mjs publicPlan()은 현재DAY에 공개 항목이 없으면 public/preview 모두 ‘공개할 일정을 먼저 골라주세요’와 share 이동을 표시한다. navigate()는 preview에서만 선택DAY를 정규화한다. 공개 사본에DAY2만 남긴 뒤 개인DAY1에서 공개 화면을 열면 읽기 목적과 맞지 않는 작성 행동이 나타날 수 있다.
수락 기준: 공개 목록·직접 파일·뒤로 복귀 모두 공개 가능한 첫DAY로 맞춘다. 공개0건은 다른 여행 탐색/이전 목록 복귀만 보여준다. 작성자 미리보기0건만 공개 선택으로 돌아간다.

P0-2 공개기록이 사본을 우회
publicRecord()가 publicSnapshot 대신 state.places[8] 개인 원본을 직접 읽는다. 공개기록의 선택·철회·사본 고정을 확인할 수 없다.
수락 기준: 공개계획과 공개기록이 동일한 허용 필드 투영을 사용한다. 선택에서 뺀 장소·사진·비용은 나오지 않고 게시 후 개인 설명 변경도 공개본을 바꾸지 않는다. 공개기록의DAY·제목·장소가 같은 사본에 속해야 한다.

P0-3 철회 후 공개 내용 재진입
withdrawPreview()는 publicationWithdrawn만 바꾸고 publicPlan/publicSnapshot은 이를 검사하지 않는다. 공개 관리 버튼은 철회 예외로 가지만 카탈로그·직접 공개 화면·뒤로 복귀는 계속 내용을 읽을 수 있다.
수락 기준: 로컬 철회 후 공개계획·공개기록·공개장소의 모든 진입에서 철회 안내를 보여준다. 개인 원본은 그대로 읽고 편집할 수 있어야 한다. 이는 디자인 모델의 요구이며 실제 API 철회 검증을 완료했다는 뜻은 아니다.

P0-4 보기 전용 일정 복귀
718 편집권한없음의 ‘일정 읽기’가 일반 schedule로 연결돼 일정 추가·소개 편집·순서 편집·관리 수정이 다시 보인다. 보기 전용 맥락을 유지하는 상태가 없다.
수락 기준: viewer의 일정/장소/더보기에는 쓰기 행동을 숨기고 장소 읽기와 목록 복귀만 제공한다. 같은 화면에서 owner/editor 상태는 기존 편집 동작을 유지한다. 서버 권한 회귀는 구현 인수에서 별도로 검증한다.

4. P1 필수 수정 — 맥락·문구·복구·전환

지도211: DAY2~4로 바꿔도 핀이p1/p2/p4/p5로 고정된다. 도식이라도 선택DAY의 장소 집합과 선택 카드가 같아야 한다. 모든19곳을 같은 좌표에 가짜로 채우지 말고 해당DAY 목록·핀·카드를 같은 데이터로 구성한다.

작성중이탈802: discardDraft가 back()만 호출해 작성 화면으로 돌아간다. ‘계속 작성’과 ‘나가기’의 결과가 같다. 안전한 이전 목적지로 실제로 이탈하고, 계속 작성은 입력·DAY·장소·스크롤을 유지하는 로컬 동작을 보여준다.

제품 밖 식별자:701에 ‘예외·첫여행’,420에 ‘공개항목선택’,211 등 번호명에서 가져온 붙여쓴 제목이 노출된다. 제품 제목은 ‘홈’/‘공개할 항목 선택’처럼 고객 언어로 정의하고 번호·예외명은 검토 도구에만 둔다. 일정 종류PLACE/TRANSPORT/STAY/RESERVATION/TODO/MEMO는 저장값과 한글 표시 이름을 나눈다.421의day1-cafe 같은 선택 묶음 키는 숨기고 원문의 선택지 안내를 표시한다.

원문221/311: ‘4.3 stars rating4.3’·‘Open’도 원문에 속하므로 임의 삭제/윤문하지 않는다. 다만 본문을 ‘여행자가 적은 설명’으로 구분해 현재 영업정보·새 Google 평점처럼 읽히지 않게 한다. 실제 Google 사진 출처는 별도로 유지한다.

사진 상태: placePhoto는 항상 ‘사진 없음’ 대체 슬롯이고 hydratePhotos는 정상응답만 교체한다. 조회 전/사진 없음/조회 실패·한도/이미지 실패가 같게 남고 재시도도 없다. 사진은 필수 요구다. 라이브 옵션으로 실제 한 장을 확인하는 것만으로 상태 디자인을 승인하지 않는다. 같은 장소의 정상 사진·없음·한도/통신·이미지 실패에 각각 안내·복구를 제공하고 잘못된 다른 장소 사진으로 채우지 않는다.

전환: CSS는 열기200ms만 있고 닫기는 즉시render로 제거된다. POPUP_SPEC와000의 닫기150ms 문구를 충족하지 않는다. 오른쪽 상세·팝업 닫기의 실제 동작을 맞추고 동작 줄이기/백그라운드는 즉시 닫는다. 앱 구현에서 화면 읽기와 접근성 미확인 시 즉시 전환할 계약도 유지한다.

팝업 캡처805/812: 첫 검토 캡처는 애니메이션 도중 저장돼 패널과 글자가 반투명하고 배경 글이 겹쳤다. 최종 CSS가 투명하다고 단정하지 않는다. 종료 프레임에서 흰 패널·읽기 대비를 확인한 새 캡처가 필요하다.801/802는 불투명 패널과 안전한 닫기·세로 행동 배치가 확인됐다.

폼 맥락: 생성확인114·항공/비용·기록·나라/도시 등 일부는 고정 예시다. 로컬에서 저장을 보여주기로 한DAY 소개·장소 설명과 서버 처리가 없는 폼을 외부 범위 안내에서 계속 구분한다. 현행 수정 화면의 필드를 삭제하는 개편으로 전달하지 않는다. 특히 recordEditor·currentTrip별 원본은 단일 state.days/places를 함께 쓰므로 서로 다른 여행을 독립 저장한 결과로 보고하면 안 된다.

5. 규격·자산 판정과 남은 차이

유지: Pretendard 제목26/36·700, 섹션22/30, 장소18/26, 본문16/26, 보조14/22, 하단13/20, 좌우20·카드16·섹션24, 터치44·주요52·입력48. 기존 코랄/네이비/아이보리와 원본 아이콘·캐릭터를 유지한다.
반영 확인: 임의1.7px SVG 아이콘을 버리고 공식 매니페스트를 연결했다. 다만 뒤로/닫기/더보기는 글자기호로 표현한 디자인 대체물이며 실제 앱의 플랫폼 아이콘 적용 결과와 구분한다. 작은 화살표의 광학 중심·24px 규격은 제품 컴포넌트 캡처로 최종 확인한다.
브랜드 추가 제작: 새 앱 아이콘이나 하루 그림은 현재 필요하지 않다. 기존 원본 재사용을 우선한다. 하루는 첫 시작·빈 화면·오류에만 보조로 두고 일정·비용·사진·지도를 가리지 않는다. 장식 alt빈값과 aria-hidden을 유지한다. 새 포즈가 필요하면 기존 원본으로 해결되지 않는 화면과 이유를 명시한 뒤 요청한다.
큰 글자: .large-text에서 카드/사진/번호를 세로로 바꾸고 숫자공간을 확장한 점은 개선이다. 전체106화면의320/200% 결과와 긴 제목·긴원문·팝업 행동 접근 가능성을 별도로 대조해야 한다. 고정844 높이 안에 큰 제목만 들어가는지보다 본문/주행동을 실제로 사용할 수 있는지 확인한다.
팝업: 중앙/하단/전체읽기 구분·초점·inert·Escape 코드는 확인했다. 네이티브 배경 읽기/터치와 Android 뒤로는 실제 앱 검수로 남긴다.브라우저 코드 존재만으로 TalkBack 통과를 선언하지 않는다.

6. 재검토 요청과 승인 경계

우선 재검토: publicRecord·공개0건·철회 재진입·viewer 복귀의P0 네 항목. 이어서DAY2~4 지도·802 나가기·701/420 및enum/선택키 문구·사진 예외·닫기 전환·805/812 종료 캡처를 확인한다.
다음 결과가 있어야 디자인 조건부 컴펌을 결정한다: 선택1건/0건→미리보기→확정→개인원본편집→공개사본불변→철회→공개재진입, 개인/후보/공개/보기전용 장소 행동 분기, DAY별 지도/목록 일치, 작은화면 큰글자 팝업 종료/복귀.
사용자는 전체 페이지 디자인 제작을 요청했다. 이번106개HTML은 제작본이고 서버/API/실제 앱 반영은 범위 밖이다. 서버 저장·재조회·외부 공급자·실제 사진·권한·Android 설치본 인수는 REDESIGN_TECH_API_BUILD.txt와 기능 작업에서 완료해야 한다. 디자인 검수 통과를 기능 구현 완료나100만 다운로드 달성 근거로 사용하지 않는다.

변경 범위: 이 재검토 보고서 한 파일만 작성했다. 코드·시안·앱·API·DB·버전코드·빌드·배포는 변경하지 않았다.

7. 1차 수정 후 소스 재검토

아래는 초기 발견 사항의 조치 확인이다. 위3~4절은 발견 당시 이력이며7~8절의 최신 상태를 우선한다. 새 종료 프레임 캡처 대조 결과는8절에 기록했다.

P0-1 수정 확인: publicPlan의 공개0건 안내를 발견 복귀로 분리했고, navigate가 preview/public/publicRecord의 선택DAY를 공개 사본 기준으로 정규화한다. 공개 읽기에 작성자용 선택 버튼을 남기지 않는다.
P0-2 수정 확인: publicRecord가 publicPlan으로 위임해 같은 publicSnapshot을 읽는다. 개인 state.places[8] 직접 참조를 제거했다.
P0-3 수정 확인: publicSnapshot에서 철회 사본을 비우고, 공개계획·기록·장소 읽기도 철회 안내로 분기한다. 원본은 지우지 않는다.
P0-4 수정 확인: forbidden 진입의 viewer 상태를 유지하고 applyReadOnly로 일정/장소/관리의 쓰기 진입과 입력을 숨기거나 잠근다. 다른 여행을 열거나 검토 카탈로그에서 독립 화면을 여는 경우 owner 예시로 초기화되는 경계도 확인했다.
