TripPrint 전체 개편 검토안
기준일: 2026-10-19 / 결정 상태: 사용자 검토 전 / 서비스 화면·API·DB 미반영

1. 이번에 결정할 것

여행 앱을 예쁘게 꾸미는 작업에 앞서 ‘만들기→여행 중 확인→기록→선택 공유’가 한 여행 안에서 이어지도록 설계한다. 첫 이용자는 한국어로 해외 자유여행을 준비하거나 다녀온 여행을 정리하는 개인·동행 여행자로 가정했다. 이는 검토용 타깃 가설이며 고객 조사 결과가 아니다.
Google Play 100만 다운로드는 사업 목표다. 경쟁 앱의 다운로드 구간을 디자인의 인과적 성공 근거로 사용하지 않는다. 획득 채널·콘텐츠 공급·여행 시기별 재방문·안정성·운영비를 함께 검증해야 한다. 달성 시점이나 전환율을 현재 실적처럼 제시하지 않는다.
검토 결과를 받은 뒤 공통 규격과 화면을 순차 수정한다. 이번 산출물은 역기획 보고서와 클릭 가능한 디자인 검토안이다. 로그인 후 경쟁 앱을 실기기로 완주하거나 TripPrint 새 기능을 서버에 구현한 결과가 아니다.

2. 조사 근거와 한계

2026-10-19 조회한 Google Play 공식 등록 페이지의 다운로드 표시, 기능 설명, 개발자가 제공한 홍보 스크린샷을 사용했다. 스크린샷의 홍보 프레임과 실제 UI를 구분했다. 앱 버전·기기·실험군에 따라 설치 앱은 다를 수 있다. 스토어에 보이는 소수 리뷰는 대표 표본으로 쓰지 않았다.
관찰: 공개 자료에 직접 드러난 기능·화면. 해석: 그 배치가 해결하려는 사용자 문제. 제안: TripPrint에 적용할 설계. 각 단계는 아래에서 구분한다. 경쟁 앱의 색·글꼴 수치를 스크린샷에서 추정해 규격으로 삼지 않는다. 문구는 의도·길이·행동 표현을 참고하고 TripPrint용으로 새로 작성한다.

5. 제안하는 정보 구조

하단: 홈 / 내 여행 / 발견 / 발자국 / MY. 기존5개 역할을 유지하되 ‘커뮤니티’를 ‘발견’으로 이름을 바꾸고 발자국과 순서를 조정하는 안이다. 확정이 아니라 이번 검토 대상이다.
홈: 진행 중/가장 가까운 여행1건의 다음 행동. 해당 여행이 없으면 새 여행 시작과 지난 여행 기록 진입. 여행 팁/추천은 아래.
내 여행: 전체 원본의 검색·상태별 보관. 일정이 없는 계획도 저장 가능한 작업 공간.
발견: 공개 계획·여행 기록·장소를 탐색. 긴 게시글 작성 진입 없음. 개인 여행에서 선택 공유한 결과를 읽는다.
발자국: 완료 여행의 사진·장소·비용·내 메모를 다시 보는 개인 여행기록. 달력 종료와 기록 정리 완료는 별개로 유지한다.
MY: 프로필·계정·알림·공개 관리·설정. 여행의 핵심 작업을 여기에 숨기지 않는다.
여행 상세: 여행 제목 헤더→일정/지도/비용→선택한 작업. 예약 정보·사진/영수증·동행·공유는 개요/더보기로 접근한다. 상세에서는 전역 하단 메뉴를 숨긴다.

6. 일곱 고객 작업의 화면 계약

항공권: 여행 상세의 예약 정보→항공편 추가→조회 또는 직접 입력→내용 확인→같은 여행에 저장. 조회0건/오류/과거 여행에서도 직접 입력 가능. 시각·공항을 만들어 넣지 않는다.
일정: DAY 선택→장소 검색/직접 입력→장소 확인→시간 선택(선택 항목)→저장→해당 DAY로 복귀. 검색 문구·후보·스크롤을 뒤로가기 후 보존한다.
여행 계획: DAY 소개는 그날 일정 위 ‘이날 소개 편집’, 장소 설명·팁은 장소 편집의 별도 공개용 입력. 개인 메모는 구분한다. 필수 글쓰기 없이도 계획을 완성할 수 있다.
영수증: 비용→영수증 촬영/앨범→인식 내용 수정→통화/총액/일정 확인→지출 저장. 취소·권한 거부·인식 실패·합계 차이·미지원 통화의 복구 경로를 제공한다.
경비 요약: 실제/예상과 통화를 구분한다. 합계는 등록 지출로 계산한다. 환산은 환율 출처·기준 시각·원래 통화가 확인될 때만 추가한다. 지원 전에는 통화별 합계.
커뮤니티 노출: 개인 여행의 공유→계획/기록 선택→공개할 일정·사진 선택→미리보기→확인 후 게시. 개인 메모·영수증·예약번호·동행 개인정보는 기본 제외. 철회는 원본 삭제와 별개.
내 여행기록: 완료 여행의 같은 여행ID/DAY/지출/사진을 발자국에서 재조회한다. 전체 여행을 다시 작성하거나 블로그 본문을 붙여 넣게 하지 않는다.

새 제안인 ‘내 여행에 담기’는 공개 계획을 개인 원본으로 가져오는 기능이다. 현재 게시 읽기·공유 API에서 복제 계약을 확인하지 못했으므로 P2 신규 기능으로 표시한다. 공개ID→새 개인ID, 선택 일정·DAY 재매핑, 저작자/원본 출처, 비공개 항목 제외·중복 제출 방지·철회 후 처리 규칙을 먼저 정하고 DB 사전을 갱신해야 한다. 디자인 시안의 버튼은 실제 복제 성공을 뜻하지 않는다.

8. 디자인 규격 대조

유지: Pretendard, 네이비#203247·코랄#FF6B57·아이보리#FFF9F3·흰 카드, 제목26/36·섹션22/30·장소18/26·본문16/26·보조14/22·탭13/20, 좌우20·카드16·섹션24, 카드radius16·버튼12, 최소터치44, 주요버튼52, 2px 초점선. DAY는 체크 없이 배경 채움·크기 고정.
제안 차이: 하단 이름/순서, 개인 상세의 여행 제목을 공유 상세처럼 뒤로가기와 같은 헤더에 배치, 예약·기록 진입의 노출, 검색 중심 일정 추가, 장소 카드의 가로 정보 묶음. 승인을 받기 전에는 현재 헤더 규격·제품 토큰을 바꾸지 않는다.
시안은 현재 수치로 재배치했다. 지도는 연결된 척 그리지 않고 오류/목록 복귀 배치를 보여준다. 여행지 이미지는 저장소의 기존 오사카 사진이며, 실제 Google 장소 사진·개인 업로드 사진으로 주장하지 않는다. 숫자·날짜·항공편·비용은 시안의 예시 데이터다.
Google 장소 썸네일 필수 요구는 유지한다. 시안의 장소 카드에는88×88 사진 영역을 두고 준비되지 않은 사진은 중립 아이콘으로 구분한다. 실제 구현에서는 기존 PlacePhoto를 연결해 해당 장소의 실제 사진·원본 접근·출처·실패/재시도·한도 계약을 유지해야 한다. 대체 아이콘을 정상 사진 조회 성공으로 인수하지 않는다.
화면 폭320/390/430, 글자100/200%, 긴 제목, 빈 상태, 오류 상태를 검토 컨트롤로 볼 수 있다. 기본 상태만으로 승인하지 않는다. Android TalkBack·실제 키보드·설치본 지도·네트워크·저장 재조회 검증은 구현 후 별도 필요하다.

9. 수정 순서와 인수 조건

P0 기능 신뢰: Play 지도/검색·위치 권한, 항공 수동 입력, 영수증 인식 실패 복구, 서버 저장/재실행 재조회, 공개 범위·권한·중복 제출. 실제 계정·분리된 검수 데이터로 서버/DB 대조. 화면 성공 표시만으로 통과 처리하지 않는다.
P1 핵심 화면: 공통 헤더/문구/정보 밀도→홈·내 여행→일정/검색/장소→항공/비용/영수증→발자국/공유/발견. 화면마다 현재 기능·새 설계·승인한 차이와 구현 가능 범위를 고정한다.
P2 성장: 공개 계획 담기·저장한 장소 재사용·공유 링크 설치 복귀·도시 콘텐츠 공급·검색 유입. 원본 출처·철회·복제·새ID 계약을 먼저 확정한다.
보류: 예약 판매, 상시 추적, AI 자동 완성·자동 최적화, 환율·자동 정산. 고객 효용·공급자 비용·보호·인수 범위가 정해진 뒤 검토한다.

릴리스 완료 조건: 모든 변경에서 npm run check 통과. 관련 모델·권한·저장·공개 회귀 통과. 작은 화면·큰 글자·빈/오류·권한 거부·느린 응답·배경 복귀·초점/화면 읽기 확인. 마지막에 버전코드와 서명·지도 키 제한을 확인하고 Play 내부테스트 설치본으로 검수한다.

10. 100만 다운로드를 위한 측정 설계

획득: 스토어 방문→설치, 유입 채널별 비용, 공유 링크→설치→원래 공개 계획 복귀. 설치 수와 가입 수·활성 이용자를 구분한다.
활성화: 여행 생성→첫 장소 저장→두 번째 날짜 사용까지의 완료율·시간, 실패·중도 이탈 사유. 첫 일정 완료 시간을 먼저 측정하고 수치 목표를 정한다.
여행 중 이용: 일정 열기·지도/검색 성공·영수증 등록→지출 확인·오프라인/복귀 실패. 여행 주기 때문에 일반 앱의 일일 재방문율만으로 판단하지 않는다.
회고·성장: 다녀온 여행 재열기→사진/기록 추가→선택 공유→공개 링크 열기→새 여행 작성. 개인정보 없는 집계 이벤트를 검토하고 동의·보관 정책을 먼저 정한다.
신뢰: 저장 성공률·중복 생성·재조회 불일치·충돌·크래시·공급자 오류/비용. 다운로드 목표 때문에 잘못된 성공 메시지나 콘텐츠 수치를 만들지 않는다.
위 지표는 신규 측정 제안이며 이번에 수집하거나 SDK를 추가하지 않았다. 기준값·실험 기간·예산·운영 목표는 미확정이다.

UI 경력10년 차 팀장 관점의 별도 AI 검토 결과는 UI_LEAD_REVIEW.txt에 기록했다. 실제 인간 팀장이나 사용자 최종 승인과 구분한다. 개편 방향은 조건부 승인, 현재 시안의 일괄 개발 착수·출시 디자인 확정은 보류다.
필수 수정은 공개 읽기/개인 장소 추가 분기, 선택 공유와 미리보기 일치, 홈 다음 일정 브리핑, 정상 지도와 사진·동행·공개 확정 화면, 원본 아이콘 규격이다. 현재 시안은 이 수정 전 상태이며 기존 레이아웃 자동 검사 통과가 고객 작업의 완결성을 뜻하지 않는다.
사용자가 요청한 앱 아이콘·하루 활용을 검토자에게 전달했다. 새로 그리기보다 기존 공식 아이콘과 하루 empty/error/loading을 실제 적용한 안을 재검토한다. 구체적인 자산 경로·화면별 수락 기준·수정 후 검토 절차는 독립 검토서에 있다.

사용자의 후속 지시에 따라 전체 페이지와 디자인 시스템을 제작했다. 최신 원본은 전체페이지_디자인규격.txt·팝업_규격.txt·pages/PAGE_MANIFEST.json·pages/PAGE_INDEX.txt이며 번호별 HTML과 캡처를 Num_페이지명으로 관리한다. 기본62개(디자인 시스템 포함)·예외24개·팝업20개로 총106개다.
