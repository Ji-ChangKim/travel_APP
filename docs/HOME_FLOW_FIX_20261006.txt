TripPrint 첫 진입 홈 개선 기록
기준일: 2026-10-06

확인한 문제
게스트가 공개 글이 없는 커뮤니티로 진입했다.
로그인 후에는 내 여행 목록과 도구 버튼이 먼저 나와 여행 없는 사용자가 시작 목적을 이해하기 어려웠다.
첫 진입에 로그인부터 요구하고 시작 화면에서도 인증을 중복 조회했다.

첫 화면의 목적
여행이 없는 사용자는 목적지 선택과 일정·기록 사용 예시로 여행 계획을 시작한다.
기존 여행이 있는 사용자는 진행 중·예정 여행부터 재개한다.
공개 게시물이 없어도 홈에서 첫 행동을 제공한다.

변경 내역
1. 앱 시작: 인증 여부와 관계없이 공개 홈을 제공한다. 초대·지도 공유 대기 경로는 유지한다.
2. 탭: 첫 탭을 홈으로 바꾼다. 공개 화면 진입과 서버 쓰기 권한을 분리하며 실제 비공개 조회·쓰기는 기존 계정 인증을 유지한다.
3. 홈: 브랜드 헤더, 목적지 선택, 여행 시작 버튼, 하루 일정·사진·비용 기록 예시를 보여준다. 예시는 실제 후기나 인기 순위로 표시하지 않는다.
4. 생성 연결: 선택 목적지를 로그인 경유 후 새 여행 폼의 국가·도시·시간대·통화 기본값으로 전달한다. 날짜는 직접 선택한다. 외부 복귀 주소를 받지 않는다.
5. 재방문: 진행 중인 여행을 우선 표시하고 예정 여행을 시작 날짜순으로 표시한다. 완료한 여행과 보관한 여행도 별도 영역에서 접근할 수 있다.
6. 오류: 서버 조회 실패를 빈 여행 목록으로 표시하지 않고 시작 도구와 재조회 경로를 함께 유지한다.
7. 커뮤니티: 글이 없는 상태에도 홈으로 돌아가 여행을 시작하는 설명과 버튼을 제공한다.
8. 로그인: 게스트 둘러보기 후 공개 홈으로 이동한다. 여행 생성에서 온 경우 로그인 이유와 복귀할 목적지를 안내한다.
9. 명세: DB_DICTIONARY.txt에 화면 전용 목적지 객체와 고정 복귀 규칙을 기록했다. DB/API 스키마 변경 없음.
10. 마이페이지: 탭 경로를 유지하며 인증 복원 후 개인 화면을 표시해 웹 초기 렌더링 불일치를 방지한다.

검증 결과

신규 검증: 첫 진입·새로고침 → 목적지 선택 → 로그인 → 국가/도시/시간대 유지 → 기간 입력 → 저장 → 홈 재개.
신규 검증: 내 여행 서버 조회 실패 시 시작 도구 유지·재조회 복구, 공개 글 없는 커뮤니티에서 홈 복귀.
기존 검증: DAY 일정·비용·영수증·종료·선택 공개·프로필·초대 읽기 권한·공유 장소 인증 복귀 유지.
테스트 인증 응답에 실제 서버와 동일한 set-auth-token 노출 헤더를 반영해 공개 설정 번들도 검증했다.
로컬 공개 번들 인수: 첫 방문 홈·목적지 전달·마이페이지 직접 진입·새로고침·파일 SHA256 일치 통과. 화면 실행 오류 0, 익명 개인 여행 API 요청 0.
