1. 데이터베이스 개요 및 공통 Enum 타입
================================================================================

* 기본 데이터베이스명: postgres (wherego_travel)
* 문자셋: UTF-8
* 고유 식별자(PK): UUID v4 (uuid_generate_v4())
* 시간 표준: TIMESTAMPTZ (UTC 기준)

[ Enum 타입 정의 ]

1) trip_status (여행 진행 상태)
   - 'DRAFT'       : 작성 중인 임시 여행
   - 'PLANNED'     : 여행 예정 (출발 전 D-Day)
   - 'IN_PROGRESS' : 여행 중 (실시간 Travel Mode / Today 화면 대상)
   - 'COMPLETED'   : 여행 완료 (발자국 스크랩북 전환 및 정산 대상)
   - 'ARCHIVED'    : 보관된 여행

2) place_category (장소 분류)
   - 'stay'        : 숙소 (호텔, 리조트, 펜션, 게스트하우스 등)
   - 'food'        : 식당/음식점
   - 'cafe'        : 카페/디저트
   - 'sightseeing' : 관광지/자연명소/유적지
   - 'activity'    : 액티비티/체험/레저
   - 'etc'         : 기타

3) member_role (동행 멤버 권한)
   - 'owner'       : 방장 (여행 생성자, 모든 편집/삭제/멤버관리 권한)
   - 'editor'      : 편집자 (일정/가계부/체크리스트 추가 및 수정 권한)
   - 'viewer'      : 뷰어 (읽기 전용 조회 권한)

4) verification_method (발자국 방문 인증 방식)
   - 'gps'         : 현재 위치 위경도 기반 반경 200m 자동 인증
   - 'manual'      : 사용자 수동 방문 완료 체크인
   - 'receipt'     : 영수증 촬영/OCR 결제 내역 매칭 인증

5) schedule_type (일정 항목 성격)
   - 'PLACE'       : 방문 명소 및 식당
   - 'TRANSPORT'   : 항공/기차/버스/렌터카 등 이동 수단
   - 'STAY'        : 숙박 시설 및 체크인/아웃
   - 'RESERVATION' : 사전 티켓/투어 예약
   - 'TODO'        : 여행 중 챙겨야 할 할 일
   - 'MEMO'        : 참고 메모 및 꿀팁

6) expense_category (가계부 지출 카테고리)
   - 'food'        : 식비/카페
   - 'transport'   : 항공/대중교통/주유/택시비
   - 'stay'        : 숙박비
   - 'activity'    : 입장료/티켓/체험비
   - 'shopping'    : 쇼핑/기념품
   - 'etc'         : 여행자보험/기타 잡비

5. M0/M1 실제 마이그레이션·도메인 변경 명세 (2026-10-02)
================================================================================

[적용 상태 및 원본]
DB명: postgres (Supabase 테스트 프로젝트명 미정), schema: public / wherego_private.
이 절은 v1.4 본문과 충돌할 때 우선한다. 기존 미변경 컬럼은 2절을 참조한다.
실제 SQL: supabase/migrations/20261002000001_foundation_schema.sql,
          supabase/migrations/20261002000002_foundation_commands.sql.
기존 3개+신규 2개 전체 체인을 격리 PostgreSQL(PGlite)에서 적용·실행했다.
원격 Supabase 적용은 미실행. public 테이블은 기존 13개+신규 2개=15개.
wherego_private는 함수만 보관하며 사용자 데이터 테이블은 없다.

[기존 테이블의 추가·변경 컬럼]
1) public.profiles
- version: BIGINT, NOT NULL, DEFAULT 1, CHECK >0. 프로필 낙관적 충돌용 버전.
- 본인 SELECT만 허용. 일반 사용자 INSERT/UPDATE/DELETE 차단, 수정 RPC는 후속.
- Auth 가입 트리거: id=auth.users.id, nickname은 metadata.nickname/name/email 앞부분/
  여행자 순으로 공백 제거 및 50자 제한. auth_provider는 raw_app_meta_data.provider.
- v1.4의 app_metadata 접근과 달리 실제 Auth 컬럼 raw_app_meta_data를 사용한다.

2) public.trips
- timezone: TEXT, NOT NULL, DEFAULT 'UTC'. RPC에서 pg_timezone_names 검증.
  DB 컬럼 자체의 시간대 CHECK는 없으며 직접 사용자 쓰기는 차단한다.
- default_currency: VARCHAR(3), NOT NULL, DEFAULT 'KRW', CHECK KRW/JPY/USD.
- version: BIGINT, NOT NULL, DEFAULT 1, CHECK >0. 여행 aggregate 쓰기 버전.
- 기간 제약: end_date-start_date BETWEEN 0 AND 89, 포함 1~90일.
- owner 참조: (id,user_id) -> trip_members(trip_id,user_id), DEFERRABLE INITIALLY DEFERRED.
  생성 명령에서 여행과 owner 멤버를 같은 트랜잭션에 만들기 위한 참조.
- 생성 RPC: title 선택, 공백/미입력은 YYYY 도시 여행. title 입력 최대 50자.
- snapshot의 status는 저장된 trip_status이며 날짜 기반 displayStatus는 후속.

3) public.trip_members
- updated_at: TIMESTAMPTZ, NOT NULL, DEFAULT NOW(). 향후 역할 수정 명령에서 갱신.
- UNIQUE(trip_id,user_id)는 기존 유지. role='owner' 부분 유일 인덱스(trip_id).
- BEFORE INSERT/UPDATE 트리거: trips.user_id와 owner 역할의 일치 검증.
- 기존 소유자를 owner로 백필. 소유자 아닌 owner가 남아 있으면 적용 실패.

4) public.trip_days
- updated_at: TIMESTAMPTZ, NOT NULL, DEFAULT NOW(). 향후 기간 변경 명령에서 갱신.
- day_number CHECK >0, UNIQUE(trip_id,trip_date). 기존 UNIQUE(trip_id,day_number) 유지.
- 생성 RPC에서 start_date~end_date 전체 달력 날짜를 generate_series로 저장.

5) public.places
- provider: VARCHAR(30), NOT NULL, DEFAULT 'legacy'. 기존 데이터 공급자 미확정 표시.
- external_place_id: TEXT, NULL 허용. 외부 공급자 장소 식별자.
- scope_trip_id: UUID, NULL 허용, FK trips.id ON DELETE CASCADE. 사적 장소 소속.
- fetched_at: TIMESTAMPTZ, NULL 허용. 공급자 조회 시각, 현재 외부 검색 미연결.
- updated_at: TIMESTAMPTZ, NOT NULL, DEFAULT NOW().
- 좌표: 둘 다 NULL 또는 둘 다 값. latitude[-90,90], longitude[-180,180].
- provider='manual'이면 scope_trip_id 필수. 외부 ID가 있으면 provider+ID 부분 UNIQUE.
- 멤버 소속 장소 또는 해당 여행 일정에 연결한 장소만 SELECT.

6) public.itinerary_items
- place_id: 기존 UUID를 NULL 허용으로 변경, FK places.id ON DELETE RESTRICT.
  장소 없는 TRANSPORT/MEMO 등 지원. master 장소 삭제로 일정 삭제하지 않는다.
- type: VARCHAR(20), NOT NULL, DEFAULT 'PLACE', CHECK PLACE/TRANSPORT/STAY/
  RESERVATION/TODO/MEMO.
- title: VARCHAR(100), NOT NULL, CHECK btrim 길이 1~100. 기존 places.name에서 백필.
- created_by: UUID, NOT NULL, FK profiles.id. 기존 부모 여행 owner로 백필.
- updated_by: UUID, NOT NULL, FK profiles.id. 기존 부모 여행 owner로 백필.
- updated_at: TIMESTAMPTZ, NOT NULL, DEFAULT NOW().
- memo: 기존 컬럼, NULL 허용, CHECK length<=300.
- time_slot: 기존 컬럼, NULL 허용, CHECK HH:mm(00:00~23:59).
- sort_order: 기존 정수 컬럼, CHECK >0.
- 트리거: 사적 place.scope_trip_id와 trip_day의 trip_id 일치 검증.
- estimatedCost 등 기존 도메인 표시 필드는 물리 컬럼이 아니다. 비용 원본 expenses.
  자동 예상비용 생성/수정/삭제 명령은 후속 M3 작업이다.

7) public.expenses
- source: VARCHAR(20), NOT NULL, DEFAULT 'manual', CHECK manual/schedule/receipt.
- created_by/updated_by: UUID 각각 NOT NULL, FK profiles.id. 기존 owner로 백필.
- updated_at: TIMESTAMPTZ, NOT NULL, DEFAULT NOW().
- amount: 기존 NUMERIC(12,2), 추가 CHECK >0. API 금액은 문자열로 직렬화.
- currency: 기존 VARCHAR(3), CHECK KRW/JPY/USD. KRW/JPY amount=trunc(amount).
- category: 기존 컬럼, CHECK food/transport/stay/activity/shopping/etc.
- title: 기존 컬럼, CHECK btrim 길이 1~100.
- source='schedule'이면 schedule_id 필수, is_actual=false.
- schedule_id+currency 부분 UNIQUE WHERE source='schedule' AND is_actual=false.
- 트리거: trip_day_id 소속 여행, schedule_id의 DAY/여행 일치, 결제자의 여행 멤버십.
- USD 초과 소수 입력의 NUMERIC 자동 반올림은 PostgreSQL 특성이다.
  사용자 입력 원문 소수 제한은 공통 Zod 및 향후 비용 명령에서 검증해야 한다.
- 비용 CRUD·합계·일정 삭제 시 실제 비용 유지 처리는 후속, 현재 제약/조회만 제공.

8) public.checklists

[DB RPC·권한·함수]
공개 사용자 RPC(모두 SECURITY DEFINER, search_path='', authenticated만 EXECUTE):

- wherego_list_trips() -> JSONB: 현재 여행 멤버 목록, 정렬 start_date/id.
- wherego_trip_snapshot(p_trip UUID) -> JSONB: 동일 statement snapshot.
- wherego_create_trip(p_input JSONB,p_key UUID) -> JSONB: 여행/owner/DAY 원자 생성.
- wherego_add_checklist(p_trip UUID,p_title TEXT,p_version BIGINT,p_key UUID) -> JSONB.
- wherego_set_checklist(p_item UUID,p_trip UUID,p_completed BOOLEAN,p_version BIGINT,
  p_key UUID) -> JSONB: 실제 부모와 헤더 여행 대조.

공개 handle_new_user() trigger 함수 EXECUTE도 사용자에게 회수.

및 멤버 trips/members/days/places/itinerary/expenses/checklists의 RLS 정책에 한정.

6. 발자취 기기 저장·도메인 객체 명세 (2026-10-02)

물리 위치: 웹 localStorage wherego-trail-device-draft;

apps/mobile/src/features/trail/{model,storage,store,TrailScreen}.

[논리 객체 TrailJourney / journeys]
- id: string(UUID), 필수, 앱 crypto UUID, 기기 콘텐츠 식별자.
- sourceTripId: string, 선택, 기존 여행 복사 원본 ID, 같은 여행 재가져오기 차단.
- title: string, 필수, trim 1~100자, 콘텐츠 제목.
- city: string, 필수, trim 1~100자, 여행 도시.
- startDate/endDate: string YYYY-MM-DD, 필수, 실제 날짜 및 포함 1~90일.
- flights: TrailFlight[], 필수, 가는 편/오는 편 각 한 구간, 같은 방향은 교체.
- plans: TrailPlan[], 필수, 날짜별 장소 계획.
- receipts: TrailReceipt[], 필수, 계획과 연결한 실제 구매·경험 기록.

[논리 객체 TrailFlight / flights]
- id: string(UUID), 필수, 항공 기준표 항목 식별자.
- direction: 'outbound'|'return', 필수, 가는 편/오는 편.
- flightNumber: string, 필수, trim/대문자, 항공편명 형식 검증.
- departureAirport/arrivalAirport: string 각각 필수, 대문자 IATA 3자.
- departureAt/arrivalAt: string ISO(datetime + offset), 필수, 실제 도착>출발.
  UI는 공항 현지 날짜/HH:mm/UTC 오프셋으로 분리 입력.
- source: 'user-confirmed', 필수, 사용자가 확인한 정보. 공급자 자동 조회 아님.
- 왕복 실제 시각 비교 및 기존 계획·영수증 기간 축소 차단.
- 가는 편 출발 현지 날짜 -> startDate, 오는 편 도착 현지 날짜 -> endDate.

[논리 객체 TrailPlan / plans]
- id: string(UUID), 필수, 계획 생성/수정 시 동일 ID 유지.
- date: string YYYY-MM-DD, 필수, 여행 기간 안 실제 날짜.
- time: string HH:mm, 필수, 00:00~23:59, 현지 계획 시각.
- title: string, 필수, trim 1~100자, 장소·일정명.
- address: string, 필수(빈 값 허용), trim 최대 200자, 장소 주소.
- memo: string, 필수(빈 값 허용), trim 최대 1000자, 예약/방문 계획.
- 정렬 date/time/id. 영수증 연결된 계획 삭제 거부.

[논리 객체 TrailReceipt / receipts]
- id: string(UUID), 필수, 같은 ID 저장은 교체. 자동 결제 중복 탐지 없음.
- planId: string, 필수, 동일 journey.plans에 존재해야 함. 다른 콘텐츠 부모 거부.
- merchant: string, 필수, trim 1~100자, 영수증 상호.
- date: string YYYY-MM-DD, 필수, 실제 결제 날짜, 여행 범위 내.
- time: string HH:mm, 필수, 실제 결제 현지 시각. 계획 시각 덮어쓰기 없음.
- amount: string(decimal), 필수, 양수, 정수부 최대 10자리.
- currency: 'KRW'|'JPY'|'USD', 필수, KRW/JPY 정수 및 USD 소수 2자리.
- details: string, 필수, trim 1~1000자, 메뉴/수량/단가/이용 내용.
- note: string, 필수(빈 값 허용), trim 최대 1000자, 실제 경험·다음 방문 팁.
- attachment: {name:string,uri:string,mimeType:string}, 필수, 원본 파일 메타데이터.
  name: 사용자 원본 파일명. mimeType: image/jpeg,image/png,application/pdf만 허용.
  uri: 웹 data URI, 네이티브 앱 문서 원본 URI. 파일당 2MB 이하.
  네이티브 원본 파일명: trail-receipt-<uuid>.jpg/png/pdf.
  실제 파일 복사 완료 후에만 연결, 앱 문서 경로 변경 시 관리 파일명 재연결.
  닫기/교체/기록 삭제 시 참조 없는 관리 원본만 정리. 외부 경로 삭제 금지.
- createdAt: string ISO UTC, 필수, 영수증 콘텐츠 등록 시각.
- OCR/GPS 인증 플래그 없음. 기존 expenses/visits/receipts 테이블 자동 기록 없음.

[화면 저장 상태 TrailState / Zustand]

- journeys: TrailJourney[], 필수, 저장이 확인된 콘텐츠 스냅샷.
- loading/saving: boolean, 필수, 읽기 완료/중복 저장 차단.
- error: string, 필수, 저장소 오류 안내. 읽기 실패 시 빈 파일로 덮어쓰지 않음.

[테이블 profiles / 본인 상세 프로필]
user_id TEXT PK FK user(id) ON DELETE CASCADE.
details TEXT NOT NULL DEFAULT '{}' CHECK json_valid: {bio,travelStyles}.
bio: string|null, 최대 300자. travelStyles: string[], 최대20개, 각 최대50자.
닉네임은 user.name에 저장하고 details는 같은 D1.batch에서 확정한다.
프로필 API는 본인만 접근. 클라이언트는 서버 확정 뒤 저장 완료를 표시한다.
