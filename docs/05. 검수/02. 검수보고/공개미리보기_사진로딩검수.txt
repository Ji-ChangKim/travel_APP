TripPrint 공개 전 장소 사진·로딩 후속 작업
기준일:2026-10-19 / Android 빌드 금지 유지
현재 판정:최신 staging API·웹 반영과 실제 Google 공개 전/후 사진6/6, 신규 UI 저장/재조회/공유8/8을 확인했다. 실제 미리보기 사진과 공개 사진·출처·저작자가 일치하며 검수 공개본 철회 후 원본은 보존했다. 최신 배포·실제 화면·한계는 P0_STITCH_ACCEPTANCE.txt를 따른다. 아래 초기 승인 검토 차단 기록은 당시 과정이며 현재 미완료 판정이 아니다. 신규 UI의 넓은 화면 규격은 ../design/STITCH_CURRENT_INTEGRATION.txt가 우선한다.

1. 공개 전 사진
공개 미리보기의 CommunityPlanView에 현재 tripId/userId를 전달한다. PLACE 일정만 PlacePhoto로 표시하고 공개 상세와 같은88×88 공간·Google Maps 표기·원본 열기·사진 없음/오류/재시도 규칙을 사용한다.
새 인증 GET /api/v1/trips/:tripId/places/:scheduleId/photo는 서버가 세션과 현재 멤버십, 실제 일정의 소속/종류를 먼저 확인한다. 공개본을 먼저 만들거나 기존 공개본에서 다른 장소 사진을 빌리지 않는다. 글/메모/예약번호를 공급자에 보내지 않는다.
공개·비공개 경로는 같은 findPhotoPlace/photoDisplay/respondPhoto를 사용한다. 저장된 Google place ID가 우선이며 없으면 나라·도시·장소명 검색이다. 공급자 대표 사진은 현재 응답에 따라 바뀔 수 있다. 사진 URL/이름을 D1/R2/공개 사본에 고정 저장하지 않는다. 기존 분당·월 한도를 공유하고 Cache-Control:no-store다.
사진을 보는 요청은 여행 버전·일정·DAY·공개 상태를 바꾸지 않는다. 비공개 조회 키는 계정/여행/일정을 구분하며 DAY 변경/해제의 취소 신호와 배경 취소를 유지한다.

2. 로딩 연출
사용자 요청에 따라 트리플 공식 소개 https://triple.guide/intro를 참고했다. 공식 페이지로 설치본의 실제 로딩 모션을 확인한 것은 아니며 동일 모션을 복제했다고 설명하지 않는다. TripPrint 로고/현재 색상/글꼴을 사용한다.
시작·인증 복원의 대기는 흰 배경 중앙 로고164×52, 작은 코랄 세 점, 짧은 실제 상태 문구다. 일반 콘텐츠 대기도 큰 캐릭터 카드 대신 세 점과 상태 문구를 사용한다. 빈 상태·오류의 하루는 유지한다.
점은8·간격6·고정24 높이,900ms 밝기 변화다. 실제 진행률/가짜 완료 수치는 없다. 진입은 로고180ms·문구120ms로 기존1초씩/80px 상승을 없앴다. 현재 시작 점검의 성공·실패·복구·인증 복귀 조건은 유지한다. 동작 줄이기·화면 읽기·접근성 미확인은 정적, 배경·해제에서는 반복을 멈춘다. BI 미제작 시 흰 바탕 중앙 심볼 대체는 그대로다.

3. 화면 폭·해상도 대응
디자인 원본 단위는 logical-pixel이다. Android/iOS는 React Native의 논리 크기, 웹은 CSS 화면 폭을 사용한다. 물리1080/1440px에 맞춰 화면 전체를 확대/축소하지 않는다. 폰트·터치·여백은 공통 토큰으로 유지하고 실제 가용 폭에 맞춰 배치한다.
헤더/본문은 width100%·최대640·가운데 정렬, 좌우20. 주요 버튼52, 일반/아이콘/칩 터치48 이상이다. 제목26/36·장소18/26·본문16/26·보조14/22를 사용한다. 사진 썸네일88×88·contain/cover의 역할을 구분한다.
제목과 본문은 줄바꿈/세로 스크롤을 사용하며 글자를 자동 축소하거나 제목을 고정 높이로 자르지 않는다. 큰 글자는 OS fontScale, 웹 루트 글자 배율을 따른다. 200% 제목은52/72다. 배율1.3 이상에서는 일정의 시간/장소를 세로 배치한다. 폭400 미만 또는 배율1.3 초과의 달력은7열을 축소하지 않고 날짜 입력/플랫폼 선택기를 쓴다.
DAY는 의도한 한 줄 가로 탐색이며 본문 가로 넘침과 구분한다. 체크 공간 없이 선택 전후 같은 버튼 크기를 유지한다. 다중 선택만 체크 공간을 미리 확보한다. 공개 폼 웹 스크롤바 공간도 고정한다. 안전 영역은 최상위에서 한 번 적용하고 폼은 키보드와 세로 스크롤을 처리한다.
현재 대조:신규 공개 화면의320/390/430·100/200%와 태블릿, 실제 미리보기 사진을 P0_STITCH_ACCEPTANCE.txt에 기록했다.200%는 같은 웹 실행본의 글꼴 배율 QA다. 신규 UI는1024 이상에서 화면별2열을 사용하며 큰 글꼴은 한 열로 읽는다. Play 실기기의 OS 글꼴·노치·가로 회전·접힘 기기 인수는 별도다.
