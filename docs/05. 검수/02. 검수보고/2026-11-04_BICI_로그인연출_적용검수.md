# BI/CI → 로그인 연출 적용 검수

대상: `d1698b2` 이후 이번 시작·로그인 변경 작업 트리. 환경: Windows, Expo 웹 export, 설치된 Google Chrome. 검수일: 2026-11-04.

## 요청과 변경 범위

승인한 목업처럼 중앙 심볼이 상단으로 올라가고, Google·게스트 버튼이 각자 제자리 아래에서 나타나게 했다. 정상 시작의 중간 로딩 화면을 없애고 실제 시작 점검·오류 복구·업데이트·인증 경계를 유지했다. 전용 Google 버튼과 한·영·일 글꼴, 실제 앱 버전을 연결했다. DB·OAuth 공급자 설정·배포는 변경하지 않았다.

시작 경로는 `app/index.tsx`, `LaunchIntro.tsx`, `launchSession.ts`, `useStartupController.ts`에서 연결한다. 로그인 배치는 `WelcomeScreen.tsx`·`welcomeStyles.ts`, 움직임은 `useWelcomeMotion.ts`·`welcomeMotion.ts`, Google 버튼은 `GoogleBrandButton.tsx`·`GoogleLogin.tsx`가 맡는다. `PageTransition.tsx`는 전용 등장 연출이 있는 welcome 화면에서만 공통 효과를 중복 적용하지 않는다. 다른 화면의 시간·헤더·GNB는 유지한다.

진행 중이던 일정 화면·업데이트 갱신 작업의 변경은 보존했다. 같은 `useStartupController.ts`에 추가된 `refreshPlayAndPolicy` 연결도 유지했다. 이 보고의 구현 범위와 다른 작업의 변경을 구분한다.

## 규격 대조

참조 문서는 시작화면_규격.md, 디자인시스템.md, design-tokens.json, 헤더GNB_규격.md, Google로그인_버튼규격.md다. 원본 심볼·영문 로고, 132·200 너비와 비율, 좌우 20·버튼 간격 12·최소 높이 52, LINE Seed·Google 전용 글꼴과 색을 대조한다. 게스트 버튼은 공통 DesignButton의 테두리를 유지하므로 목업의 코럴 경계와 차이가 있다. 실제 캡처와 구조 설명용 목업을 구분한다.

## 자동 검사와 남은 검증

인증 회귀 `npm run test:auth` 316개, `npm run test:headers:web`의 헤더·GNB·뒤로가기·이탈 보호 21개, `npx playwright test --config tests/config/playwright.startup-motion.config.ts`의 실제 앱 웹 화면 10개가 통과했다. 화면 검사에는 중앙 심볼의 첫 위치 연속성·위쪽 이동·버튼 순서, 백그라운드 중단·복귀, 직접 링크·움직임 줄이기, 영어·일본어 표시, 점검·인증 실패 복구, 작은 화면·글자 200%를 포함했다.

최종 Expo 웹 export는 `apps/mobile/.release/startup-motion-web`에 생성했다. 실제 실행 청크의 API 주소가 로컬 검수 주소이며 staging 주소가 남지 않은 것도 확인했다. 최종 화면 검사 로그는 `outputs/startup-motion-app/browser-check.log`, 빌드 로그는 `build-web.log`, 중앙 심볼 프레임 기록은 Playwright 첨부 JSON에 보관했다. `login-390.png`, `login-320-200.png`, `login-430-200.png`, `login-en.png`, `login-ja.png`를 직접 열어 원본 로고·규격·줄바꿈을 대조했다.

필수 전체 검사 `npm run check`는 `outputs/startup-motion-app/check.log`에 기록하며 최종 종료 결과를 추가한다.

Android·iOS 설치본, 실제 Google 계정 로그인 성공·앱 전환과 복귀는 미검증이다. 네이티브 빌드 설치나 운영 배포를 이번 요청에서 실행하지 않았다. 데이터 저장 계약 변경이 없어 서버 저장·재조회 검증은 해당 없음이다. 후속 실기기 검수에서는 안전 영역·큰 글자·백그라운드 중단과 복귀·Google 브라우저 복귀를 확인한다.
