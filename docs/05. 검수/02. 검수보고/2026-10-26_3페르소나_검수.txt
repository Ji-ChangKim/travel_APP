1. 목적과 경계
사용자가 지정한 총3개 페르소나만 사용한다. 이름·나이·통계·성공률을 임의로 부여하지 않는다.
P1은 검색·앱스토어에서 발견했다고 가정하되 검사는 앱 첫 진입부터 시작한다. 검색 노출·설치 전환은 미검증이다.
P2는 친구의 공개 여행계획 링크를 받은 사용자다. 공개본 열람·내 사본 담기이며 원래 여행에 편집 권한을 주는 동행 초대와 다르다.
P3은 준비 중인 계획 또는 다녀온 기록을 다른 사용자에게 공개하려는 사람이다. 공개 저장과 기기 공유·실제 메시지 전달을 별도로 판단한다.
테스트 계정과 데이터는 격리된 로컬 Worker/D1/R2에만 존재한다. 이전 검증 번들은 현재 앱 코드와 동일하며 이번 변경은 테스트·검수 문서다. 운영 계정·배포·원격 DB·메시지 전송은 수행하지 않았다.

2. P1 — 여행 계획을 만들러 온 신규 사용자
목표: 가입부터 첫 여행·일정 저장까지 끝내고 재접속해서 확인한다.
예상 행동: 공개 여행을 먼저 살펴보거나 회원가입/게스트를 선택 → 날짜·국가·도시 → 항공권 또는 항공편 없이 시작 → DAY별 일정 추가·수정·순서 변경·삭제 → 내 여행 → 재접속.
P1-01 실제 UI 이메일 회원가입 → 선택 프로필 설정 → 홈: journey.test.mjs에서 이전 API 준비를 UI 가입·온보딩으로 대체했다. 세션은 메모리에만 보관하고 로그에 남기지 않는다.
P1-02 여행 생성 → 항공권·DAY → 일정 CRUD → 새로고침: 실제 D1 행·버전과 화면 일치 확인.
P1-03 같은 저장소 새 페이지·탭 왕복·새 브라우저 로그인·로그아웃 취소/확정·재로그인: 기록 유지와 서버의 폐기 세션 거절 확인.
P1-04 둘러보기·항공편 없는 생성·저장 응답 유실·저장 후 조회 실패: 기존 웹 회귀로 확인. HTTP 응답 통제 검사이며 실제 외부 검색/OAuth/항공 공급자 검사는 아니다.
예상 마찰: 가입 전 탐색 여부, 항공권 필수라는 오해, 날짜/도시 선택 부담, 실패 후 입력 유실 우려. 실제 사용자 행동률이나 이탈률은 측정하지 않았다.

3. P2 — 친구에게 공개 여행계획을 받은 사용자
목표: 로그인 없이 먼저 읽고, 내 계정으로 담아 내 출발일에 맞게 수정한다.
P2-01 비로그인 공개 URL → DAY·장소·설명 확인: 공개본만 조회한다.
P2-02 내 여행으로 일정 담기 → 별도 수신 계정 로그인 → 같은 공개 URL 자동 복귀: 로그인 뒤 주소를 테스트가 직접 바꾸는 기존 우회를 제거했다.
P2-03 출발일·제목 확인 → 내 여행 저장: 원본과 다른 여행/소유자, 항공권·사진·지출·영수증·개인 메모 미복사 확인.
P2-04 내 사본 일정 제목 수정 → 새로고침 → D1 확인: 일정 ID로 대조하며 친구의 원본과 공개본은 불변이다.
P2-05 원본 비공개 여행 요청은404, 공개 링크를 열거나 담아도 원본 멤버 수는1명으로 유지한다. 초대 없이 동행 권한이 생기지 않는다.
P2-06 공유자가 공개 중단 → 이전 공개 URL은 안내 표시, 이미 담은 내 사본은 계속 조회 가능.
예상 마찰: 공개본 열람과 함께 편집을 혼동함, 로그인 후 원래 링크를 잃음, 담기와 원본 수정의 차이를 모름. 앱 안내와 권한 경계를 검사하며 설명을 실제 사용자가 이해하는지는 후속 관찰 과제다.

4. P3 — 내 여행을 다른 사용자에게 공유하려는 사람
목표: 원하는 일정·사진·비용만 공개하고 나중에 수정하거나 공개를 중단한다.
P3-01 여행 더보기 → 여행 공유 → DAY 전체 선택 → 소개 → 미리보기 → 공개 범위 확인 → 공개: 실제 UI·D1 공개 사본 일치.
P3-02 비공개 메모 제외, 원본 수정은 공개본에 자동 반영하지 않음, 명시적 재공개는 같은 공개 ID로 반영.
P3-03 별도 비로그인/수신 계정에서 공개 결과 확인 → 공개 중단 후 공개 API404와 화면 안내 확인.
P3-04 로컬 HTTP 환경에서 공유 링크 보내기는 HTTPS 검증에 의해 거절된다. 복구 안내가 표시되고 공개본이 유지되는지 확인했다. 이를 실제 링크 전달 성공으로 계산하지 않는다.
P3-05 기록 공유·선택 사진·통화별 실제 비용·영수증 후 선택 게시·미리보기 왕복·응답 유실·동행 충돌: 기존 웹 회귀를 실행했다. 공유 정보 선택과 실패 동작의 통제 응답 검사다.
예상 마찰: 공개 범위가 무엇인지 불안함, 원본 수정이 자동 반영될 것으로 기대함, 링크 전송 실패를 공개 실패로 오인함. 공개본과 원본·전송 상태를 분리하여 검사한다.

7. 남은 사용자·실기기 검수
검색/앱스토어 유입, 설치, 실제 Google 로그인, 메신저 인앱 브라우저에서 공개 URL·앱 링크 복귀는 미실행.
HTTPS 배포 환경에서 링크 복사·OS 공유 시트·공유 취소·클립보드 거절·다른 기기 수신을 확인해야 한다. 새 운영 배포는 이번 요청에 포함하지 않았다.
실제 Android의 강제 종료·SecureStore·시스템 뒤로가기·키보드·안전 영역·TalkBack·촬영 권한·네트워크 전환은 별도 인수다. 실제 영수증 표본의 OCR 정확도는 별도 검수다.
가설 검증을 위한 사용자 관찰 질문: P1은 가입 전 가치를 이해하는가, P2는 원본과 내 사본을 구분하는가, P3는 무엇을 공개했는지 설명할 수 있는가. 완료 시간·되돌아감·도움 요청·이탈 원인은 실제 관찰 후에만 기록한다.
