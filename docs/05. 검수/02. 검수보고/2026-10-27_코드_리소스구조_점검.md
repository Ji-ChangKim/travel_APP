## 리소스 구조 정리

1. 이전 시안용 Pretendard 3종과 라이선스·명세, 총 5개 파일을 `apps/mobile/assets/fonts/pretendard/`로 이동했습니다. 파일명과 내용은 보존했습니다.
2. 이전 헤더 시안의 CSS·서버와 시안 렌더러의 참조를 갱신했습니다. 이전 시안의 디자인 토큰 전체를 재생성하지 않았습니다.
3. Pretendard 명세에 빠져 있던 Semibold의 크기·해시를 등록했습니다. 원본 다운로드 주소는 미확인으로 남겼습니다.
4. 공개 타이베이 사진에 별도 명세를 추가했습니다. 앱 사진과 같은 원본이라고 가정하지 않습니다.
5. 현행 LINE Seed와 이전 시안 글꼴을 문서에서 구분했습니다. 아이콘 전면 교체가 완료됐다는 오해를 줄이도록 보유 자산과 적용 후보를 구분했습니다.
6. `check:resources`를 전체 `check`에 추가했습니다. 검사 자체의 회귀 시나리오도 4개 추가했습니다.

브랜드 이미지·하루·현행 글꼴·공통 아이콘의 바이트와 디자인은 바꾸지 않았습니다. 런처 파생본, 이전 자료, 검수 산출물도 삭제하지 않았습니다.

실제 동작 검사는 로컬 Worker·D1·브라우저를 사용합니다. 초안 PUT를 잠시 보류한 뒤 원 서버로 보내고 저장 중 뒤로가기를 확인합니다. 서버 초안 첫 조회 실패 후 재시도, 편집 뒤 포커스 복귀 시 입력 유지도 확인합니다. 서버 성공 응답을 가짜 결과로 바꾸지 않습니다.

이번 첫 헤더 검사에서는 만들기 단계 안내의 대비 문제로 9개가 실패했습니다. 위 글자색 보완 후 21개 모두 통과했습니다. 과거 DEV-01 보고서의 홈 대비·이전 버튼 이름 실패와는 구분합니다. 전체 정적 검사 중 Windows 임시 폴더 연결 권한으로 한 번 중단된 검사는 허용된 로컬 실행 권한으로 다시 진행했습니다. 검사를 제외하거나 기준을 낮추지 않았습니다.

여행 흐름 검사는 과거 홈 버튼 이름과 직접 입력형 날짜 필드를 찾던 부분에서 중단됐습니다. 현재 보이는 ‘새 여행 만들기’ 버튼과 달력의 월·날짜 버튼을 누르도록 검사를 고쳤습니다. 실제 입력·저장·DB 대조 조건은 유지했습니다. 전체 실행에서 초안·여행 검사가 통과한 뒤, 선택자를 고친 공유 검사와 다도시 검사를 각각 다시 실행해 통과했습니다. 마지막 문구 정정 후 번역 검사 4개도 다시 통과했습니다(`outputs/resource-architecture-localization.log`).

그 뒤 연속 뒤로가기 사례를 추가한 최신 journey는 실패했습니다. 따라서 현재 전체 여행 흐름 검사를 통과했다고 표시하지 않습니다. 도중 로컬 검수 서버 시작이 약 4초 대기를 넘겨 중단된 경우도 있어, `runtime.mjs`의 준비 대기 한도를 30초로 늘렸습니다. 실제 HTTP 성공 확인과 제품 동작의 단언은 유지했습니다.

디자인 대조 기준은 디자인시스템.md, design-tokens.json, 헤더GNB_규격.md, 여행일정_화면규격.md입니다. `ui-ux-pro-max`의 일반 글자 대비 4.5:1 기준을 함께 확인했습니다. 실제 `outputs/header-standard/create-320-200.png`에서 큰 글꼴의 제목·안내 줄바꿈과 색을, `outputs/planning-v11/06-draft-editing-retained-390.png`에서 편집 중 입력 유지와 공통 헤더를 확인했습니다. 이번 의도한 시각 변경은 단계 안내 글자색뿐입니다.

### 가장 먼저 고칠 항목: CODE-ARCH-05

재현 순서: 로그인한 웹에서 홈 → MY → 커뮤니티 → 내 여행 → 새 여행 계획 만들기 → 제목 입력 → 상단 뒤로 → 계속 작성 → 브라우저 뒤로가기.

상단 뒤로에서는 확인창이 열리지만, 마지막 브라우저 뒤로에서는 확인 없이 `/plans`로 이동하고 제목 입력란이 사라집니다. 브라우저 기록은 현재 2번, 한 칸 전 `/plans`, 두 칸 전 `/`였습니다. 기록이나 앱 데이터를 인위적으로 넣지 않고 재현했습니다. 영향은 저장하지 않은 입력의 유실입니다. 이 문제는 원인이 확정되지 않았으므로 이번 변경이 새로 만든 문제인지도 아직 단정하지 않습니다.

근거: `outputs/planning-v11/history-destination-fixture.json`, `history-destination-result.json`, `08-history-destination-result-390.png`, `outputs/resource-architecture-history-attempt-05.log`. 입력값 확인과 상단 확인창 검사는 통과했으므로, 입력이 처음부터 없었던 경우와 구분합니다. 첫 브라우저 뒤로부터 실패해 두 번째 뒤로 이후 최초 목적지 유지 검증은 아직 도달하지 못했습니다.

권장 방향은 웹 기록 이동 처리와 폼의 보호 상태가 바뀌는 순서를 먼저 추적한 뒤, 같은 화면의 쿼리 변경과 다른 화면으로의 이동을 하나의 확인 절차로 연결하는 것입니다. 필요하면 화면이 바뀌어도 유지되는 공통 위치에 웹 이탈 처리를 둘 수 있습니다. 다른 선택지는 두 종류의 이동 보호를 분리하고 각각의 실패·취소·계속 작성·버리기 시나리오를 유지하는 것입니다. 어느 방식을 택하든 자동 저장을 추가해 문제를 감추거나 이탈 검사를 지우지 않습니다.

재개 시 위 한 경로부터 재현하고, 해결 후 `journey.test.mjs`의 연속 뒤로가기까지 통과하는지 확인합니다. 이후 공통 헤더·GNB 검사와 `npm run check`를 실행합니다. 검토 횟수 상한 이후 발견한 미해결 쟁점으로 사용자에게 전달하며, 이번 결과를 전체 검수 완료로 표시하지 않습니다.
