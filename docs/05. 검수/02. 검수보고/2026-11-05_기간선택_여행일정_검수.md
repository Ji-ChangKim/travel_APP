# 여행 기간 선택과 DAY 일정 화면 검수

상태: 로컬 웹 구현·검수 완료 / Android·회원 실서버 미검증 / 기준일: 2026-11-05 / 대상: `main` · `61b6cd7` 이후 이번 작업의 미커밋 변경

세 기획서에 따라 여행 기간 선택, 선택 DAY의 일정 없음, 일정 등록 후 화면을 제작했다. 기간을 적용하면 여행 만들기 폼으로 돌아오고, 저장된 여행에서는 날짜별 장소를 추가·조회·정리한다. 실패한 요청은 입력을 남기며 사용자가 다시 저장하거나 최신 내용을 불러오도록 한다.

`planning`에 기간 임시 선택·달력 계산·30일 검증을, `schedule`에 일정 카드·상세·임시 순서 편집을 추가했다. `hub`에서 하단 행동·공유·DAY 이동·오프라인 제한을 연결했다. `expo-network`는 Expo 설치 명령으로 추가했고, 네이티브 연결 이벤트를 쿼리의 연결 상태에 연결했다. 기존 물리 테이블과 저장 명령 형식은 바꾸지 않았다. 화면 임시 객체는 [DB 객체사전](<../../03. 개발/02. 데이터정의/DB_객체사전.txt>)에 기록했다.

기존 사용자 변경 중 앱 설정·브랜드 이미지·로고·홈 헤더 배치를 유지했다. 전체 린트가 지적한 홈 헤더의 사용하지 않는 import 한 줄만 제거했다. `workspace.spec.ts`의 기존 사용자 변경도 보존하며 새 기간 선택창·공유 키보드 순서·장소 추가 문구에 맞춰 관련 검수 도우미와 선택자를 갱신했다.

## 남은 계약 차이와 인계

영수증 연결 일정의 이동·삭제 제한과 일정에서 만든 예상 비용 삭제는 기존 공통 계약을 유지했다. 새 기획의 모든 연결 기록 보존·분리 정책까지 반영하려면 영수증의 부모 관계와 API·DB 계약을 함께 바꿔야 한다. 기존 자료를 삭제하거나 이 보호를 임의로 해제하지 않았다.

회원 오프라인 자료는 현재 실행에서 조회한 메모리 캐시만 제공한다. 영구 오프라인 보관, DAY 메모 새 정책, 날씨, 드래그 순서 조작은 이번에 추가하지 않았다. 운영 배포와 Android 설치본 제작은 수행하지 않았다. 후속 담당자는 최종 검사 기록과 실제 파일을 대조하고 남은 네이티브·실서버 검수부터 진행한다.
