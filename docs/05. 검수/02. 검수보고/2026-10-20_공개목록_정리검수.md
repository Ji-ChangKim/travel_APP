# 공개 목록의 검수 자료 정리

기준일: 2026-10-20. 사용자가 홈·발자국의 더미 노출을 지적해 실제 공개 응답과 생성 기록을 대조했다.

## 원인

이전 검수에서 생성한 글 두 건을 공개 상태로 남긴 것이 원인이다. 그중 한 건은 앱 로고를 일반 사진으로 업로드해 공개했다. 홈과 발자국은 실제 서버의 공개 목록을 공통으로 읽으므로 이 검수 자료까지 여행 카드로 표시됐다. 직전 배포 검수에서도 검수 글을 발견하고 정상으로 처리한 판단이 잘못됐다.

`HomeExplore.tsx`, `communityService.ts`, `useDiscoveryController.ts`, `CommunityPhoto.tsx`를 확인했다. 조회 결과가 비면 예제 여행을 삽입하는 로직은 이 경로에 없었다. 데이터가 없으면 홈은 공개 여행 없음 안내, 발자국은 조건에 맞는 여행 없음 안내를 표시한다. 사진 조회 실패도 다른 사진으로 대체하지 않는다. 앱 로고는 대체 이미지가 아니라 검수자가 실제 업로드한 파일이었다.

## 조치

이름 접두사를 화면에서 숨기는 방식 대신, 생성 기록과 소유권을 확인한 두 글에 정상 `community.withdraw` 명령을 실행했다. 검수 계정으로 로그인해 해당 여행의 소유자·게시 ID·제목·버전을 확인하고 공개 사본만 철회했다. 제목이 비슷하다는 이유로 다른 글을 정리하지 않았다.

## 검증 근거

최종 실제 staging 검수3/3건이 통과했다. 공개 응답·정상 목록·실제 빈 검색 결과·홈 노출을 확인했다. 홈은 최초 실행 주소의 로그인 선택 화면과 구분해 발자국의 ‘홈’ 탭으로 이동했다. 첫 검사에서 이 진입 조건을 잘못 잡은 실패 기록은 보존하고 최종 로그는 `live-browser-final.log`로 구분했다. 제품의 인증 흐름은 변경하지 않았다.

- `outputs/public-feed-cleanup-20261020/withdraw-result.json`: 정상 철회·개인 원본 보존·사용자 공개본 불변 판정.
- `public-before.json`, `public-after.json`: 실제 공개 목록의 전후 게시 ID·제목·사진 경로.
- `live-results.json`, `live-browser-final.log`: 실제 staging의 목록·홈·빈 검색 결과 검수.
- `footprints-clean-390.png`: 검수 글과 로고 사진이 사라진 실제 공개 목록.
- `footprints-real-empty-390.png`: 실제 서버가 빈 배열을 반환한 검색에서 여행 카드0개와 빈 안내.
- `home-clean-390.png`: 실제 홈 공개 일정 영역.

파일명만 적은 검증 자료는 모두 `outputs/public-feed-cleanup-20261020/` 아래다. 브라우저 검수는 응답 대체 없이 기존 staging 기본 주소를 사용했다. 공개 상태를 바로잡는 작업이므로 웹·API 재배포나 제품 코드 변경은 하지 않았다. 직전의 검색창 삭제·GNB 다섯 메뉴를 유지한다.

## 이후 검수 기준

검수용 공개 글은 생성 ID·소유자·공개 ID를 기록하고 검사가 끝나면 정상 철회한다. 검수 실패나 중단도 정리 대상이며 재실행에서 기존 기록을 먼저 확인한다. 홈·발자국 검수는 실제 DB 응답이라는 이유만으로 승인하지 않고 게시물 출처와 검수 자료의 잔존 여부까지 확인한다. 데이터를 채우려고 가상 여행·가짜 사진·사용자를 추가하지 않는다. 일부러 보존할 공개 콘텐츠는 사용자의 명시된 등록 요청이 있어야 한다.

제품 코드·DB 구조·API 계약을 변경하지 않았으므로 이번 작업에서 전체 코드 검사를 새로 실행하지 않았다. 실제 공개 상태 변경과 브라우저 검수 결과를 완료 근거로 삼는다. Android 빌드·Git 커밋·푸시는 실행하지 않았다.
