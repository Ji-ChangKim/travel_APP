계획을 만들고, 받고, 나누는 세 가지 여정

예상 행동을 앱의 현재 기능과 연결한 흐름입니다. 페르소나는 사용 가설이며 실제 이용자 인터뷰나 사용성 실험 결과가 아닙니다.

화살표는 행동 순서입니다. 점선은 앱 밖의 검증 경계, 연한 초록색은 각 사용자가 얻으려는 결과입니다. 이 문서는 앱 화면 시안이 아닙니다.

P1 · 처음 계획하는 사람

“여행 일정을 만들고 싶어요.”

여행 계획 앱을 찾다가 방문. 복잡한 준비 없이 첫 일정을 저장하고 다시 보고 싶다.

  1. 검색·앱스토어에서 발견유입 가설. 검색 순위·설치 전환은 미검증.
  2. 앱 첫 진입로그인 선택 또는 공개 여행 둘러보기
    계정 부담이 크면 게스트로 시작 → 기기 기록
  3. 회원가입 → 프로필 설정이메일·닉네임·비밀번호, 선택 정보 확인
    입력 오류는 수정 / 기존 회원은 로그인
  4. 여행 만들기날짜 → 국가·도시 → 항공권 또는 항공편 없이 시작
  5. DAY별 일정 관리장소·시간·설명 추가 → 수정·순서 변경·삭제
    작성 취소는 확인 / 저장 실패는 재시도
  6. 내 여행에서 다시 확인새로고침·새 페이지·재로그인 후 같은 기록
예상 망설임과 검사
  • 가입 전에 앱을 살펴볼 수 있는가?
  • 항공권이 없어도 계획을 만들 수 있는가?
  • 저장 실패를 빈 목록이나 성공으로 잘못 안내하지 않는가?

주검사: journey.test.mjs. 실제 UI 회원가입·온보딩과 로컬 DB 저장을 연결.

P2 · 친구의 계획을 받은 사람

“이 일정, 나도 쓰고 싶어요.”

공유자가 아닌 별도 계정. 친구가 보낸 공개 계획을 먼저 읽고 내 날짜에 맞게 수정하고 싶다.

  1. 친구에게 링크 받기실제 메신저 전달은 별도 검수.
  2. 로그인 없이 공개 일정 열기DAY·장소·공개 설명 확인
    철회된 링크 → 찾을 수 없음 안내·복귀
  3. 내 여행에 담기미로그인 → 로그인 → 같은 공개 계획으로 복귀
  4. 내 이름·출발일로 사본 저장내 계정이 소유한 별도 여행 생성
    항공권·사진·지출·개인 메모는 복사하지 않음
  5. 내 사본 수정 → 재조회친구의 원본·공개본이 바뀌지 않는지 대조
  6. 내 계획으로 계속 사용친구가 공개를 중단해도 이미 담은 내 사본은 유지
권한 경계
  • 공개 링크 열람·담기는 동행자 권한을 주지 않는다.
  • 수신자는 공유자의 비공개 여행에 접근할 수 없다.
  • 함께 편집하려면 별도의 동행 초대가 필요하다.

주검사: triple-flow.test.mjs. 발행자 A와 수신자 B를 분리해 저장·권한·사본을 대조.

P3 · 내 여행을 공유하는 사람

“필요한 내용만 나누고 싶어요.”

준비한 계획이나 다녀온 기록을 보여주고 싶다. 개인 메모와 영수증 원본은 공개하지 않는다.

  1. 내 여행 → 여행 공유준비 중이면 계획, 정리한 여행은 기록 공유
  2. 공개 범위 선택DAY·일정·사진·비용·소개를 명시적으로 선택
  3. 미리보기 → 공개 범위 확인선택한 내용과 비공개 정보 제외 여부 확인
    돌아가서 수정해도 선택·소개 보존
  4. 공개 저장 → 링크 보내기공개본 생성과 기기 공유의 성공은 별개
    기대: 공유 취소·실패가 공개본을 삭제하지 않음. 실제 공유 시트 취소는 미검증
  5. 공개 내용 바꾸기 / 공개 중단원본 수정은 자동 공개하지 않음. 명시적 재공개로 반영
  6. 수신자 화면으로 결과 확인선택 내용만 보임. 공개 중단 후 이전 링크는 열리지 않음
개인정보·실패 검사
  • 개인 메모·원본 여행 권한을 공개 링크에 포함하지 않는다.
  • 응답 유실은 같은 요청으로 확인하고 충돌은 재선택한다.
  • 로컬 HTTP의 링크 보내기는 거절 안내와 공개본 보존을 검사한다. 실제 HTTPS 공유 성공은 미검증.

계획 공개는 실제 DB, 기록·사진·비용·실패 분기는 통제한 HTTP 응답으로 검사.
