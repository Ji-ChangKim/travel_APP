영수증 P0 개발·검수 기록
기준일: 2026-10-26
상태: 로컬 P0 구현 및 자동 검수. 실기기·실물 영수증 인수 전.
작업 위치: travel_APP / main. 커밋·푸시·배포·원격 DB 변경 없음.

1. 적용 기준
승인 정책 RCP-D01~D14, 영수증_P0_개발인계_검토안.md, 영수증_화면상세_모바일스케치_검토안.md, 영수증_모바일스케치_검토안.html을 따른다.
디자인시스템.md, design-tokens.json, 헤더GNB_규격.md와 기존 Ledger 공통 컴포넌트를 사용한다. 공통 색·폰트·헤더·GNB 토큰 및 라우트는 변경하지 않았다.

2. 변경 범위
RCP-P0-01: ReceiptMenuEditor와 receiptChecks/receiptFlow/formCommands에서 메뉴 추가·수정·삭제, 빈 목록, 최대50개, 고유 행 키와 삭제 후 초점을 구현했다. 잘못된 수량 문자열을 보존하고 빈 값만 null로 변환한다. 통화 자릿수 오류를 해당 메뉴 필드에 연결하며 행 변경 후 오래된 행 번호 오류를 제거한다.
RCP-P0-02: workspaceModel의 receipt.update가 일정 없는 DAY에도 새 장소를 만들 수 있다. 영수증·실제 지출 ID를 유지하고 보관 사진을 재연결하며 이전 계획은 남긴다. 날짜 변경 후에는 연결을 다시 선택한다.
RCP-P0-03: receiptDuplicates/ReceiptDuplicates가 같은 여행의 영수증과 직접 입력한 실제 지출을 비교한다. 상호는 NFKC·공백 제거·소문자로 비교하되 원문은 보존한다. 같은 원본은 기존 서버 제한을 유지하고, 유사 후보는 확인 후 별도 저장한다. 후보·입력·여행 버전이 달라지면 동의는 무효다. 충돌 후 입력을 보존하면서 내용·합계·중복 확인을 초기화한다.
RCP-P0-04: ReceiptOriginal에서 원본 확대·접기와 원본 미보관 상태를 구분한다. ReceiptDetails는 ‘영수증으로 기록’과 보관 여부를 표시한다. 원본·메뉴가 공개 여행에 자동 포함되지 않는 기존 투영을 유지한다.
원본 삭제 실패: cloudStore가 영수증 저장과 같은 CAS 트랜잭션에 receipt_cleanup_jobs를 남긴다. DB 저장 후 파일 삭제 실패는 RECEIPT_CLEANUP_PENDING으로 구분하고 같은 요청으로 재시도한다. 앱 종료 후에도 기존 서버 예약 실행이 미완료 작업 최대50건을 다시 처리한다. 이전 확정 결과와 업로드 삭제 표식이 모두 일치하는 원본도 마이그레이션에서 등록한다.
화면 종료·계정/여행 전환: workspaceMediaActions는 이전 화면의 늦은 OCR 결과가 현재 폼에 반영되지 않도록 요청 당시 수명을 확인한다.
계약 문서: DB_객체사전.txt와 API_기본계약.md에 입력·검증·오류·정리 테이블 및 배포 순서를 기록했다.

3. 인계 시나리오 대조
M01~M05: 메뉴0/50/51개, 빈 이름·수량·금액 자릿수, 중간 삭제·초점, 합계 차이 확인, 저장·재조회 자동 검사. M06은 긴 일본어 입력과 웹 큰 글자 검사를 수행하되 실제 키보드 검수는 남는다.
D01~D03: 완료 여행의 과거 날짜 저장과 빈 DAY로 수정, 원래 계획·ID·미디어 연결 보존을 모델/화면에서 검사한다. D04·D06은 기존 날짜·권한·교차 여행 회귀를 유지한다. D05의 실제 기기 시간대 변경은 미실행이다.
F01~F05: 기존 응답 유실/멱등·같은 원본 제한 회귀, 신규 후보 비교·별도 결제 동의, 충돌 후 입력 보존 검사를 사용한다. F06·F08은 합성 OCR 응답/오류/통화 회귀이며 실제 OCR 정확도 검사가 아니다. F07은 등록한 미확정 사진의 기존 목록·명시 삭제와 확정 미보관 원본의 서버 재시도를 구분한다.
P01~P04: 출처 문구, 공개 투영, 편집 권한, 삭제 연결 관계를 기존 모델/API 회귀와 화면 검사로 확인한다. P05는 실제 로컬 D1/R2에 삭제 실패를 주입해 DB 보존·같은 요청 재생·예약 재시도·이전 데이터 보완을 검사한다.
Q01~Q05 및 A01~A10: 자동 회귀는 일부 근거이며 전체 인수 통과로 표시하지 않는다. 실제 촬영/앨범 권한·시스템 글자 확대·TalkBack·키보드·안전 영역·백그라운드/종료·실물 표본은 별도 인수한다.

4. 자동 검사와 증거
- npm run test:auth: 286개 통과. 이후 영수증 충돌 재조회 회귀를 추가해 해당 저장 세션 검사와 원본 정리 검사 합계8개도 통과했다.
- npm run test:foundation: 131개 통과. 이후 이전 데이터 정리 보완은 별도 원본 정리 검사로 재검증했다.
- npm run test:cloud: 37개 통과. 격리된 로컬 Worker/D1/R2 검사이며 배포가 아니다.
- npm run test:headers:web: 21개 통과. 320/390/430px·100/200% 제목·GNB·이탈 보호 회귀 포함.
- npm run check: 문서·디자인 대비·아키텍처·헤더 경계·TypeScript·ESLint·Prettier 모두 통과. 임시 연결 생성 검사는 Windows 실행 제한 때문에 허용된 로컬 권한으로 재실행했다.
- 영수증 및 관련 이탈/삭제 브라우저 회귀: 22개 통과. 메뉴 편집·날짜 수정·합계 차이·통화 정정·320/390/430px 중복 비교와200% 글자 포함.
- 이후 메뉴 정상·오류·저장 중 캡처와 저장 잠금 검사를 보완하고 해당1개를 재실행해 통과했다. 웹 TextInput은 disabled 속성 대신 readonly로 잠기므로 편집 불가 상태를 검사한다. p0-states-final.log에 기록했다.
로컬 로그: outputs/receipt-screen-review/p0-auth-final.log, p0-foundation.log, p0-cloud.log, p0-recovery-final.log, p0-headers.log, p0-check-final.log, p0-web-final.log.
초기 브라우저 검사에서 합계 동의 전에 새 장소를 고르는 테스트 순서와 오류 텍스트 선택자를 수정했다. 제품 검증 기준은 낮추지 않았다. 초기 린트에서 발견한 행 초점 콜백과 화면 수명 관리 오류를 수정했다.

5. 화면 대조와 차이
공통 ScreenHeader, 한 열 입력, Ledger 카드·입력·버튼, 기존 글꼴·색·터치 규격을 재사용한다. 결제 정보 → 방문 연결 → 메뉴 → 확인·원본 보관·저장 순서를 따른다. 새 독립 헤더나 GNB를 만들지 않았다.
원본 확대(S4)와 후보 비교(S7)는 기존 확인 폼 안에서 열고 접도록 구현했다. 별도 라우트/모달 이동이 없어 입력 수명과 이탈 보호가 유지된다. 확대는2배 이미지와 스크롤이며 자유로운 핀치 확대는 제공하지 않는다. 원본 확대 중 제자리 복귀·네이티브 화면 읽기 초점은 실기기에서 확인해야 한다.
검수용 웹 화면은 실제 앱 코드와 합성 응답으로 생성했다. 구조 설명 HTML을 실행 화면 증거로 사용하지 않았다. 웹 캡처와 실기기 캡처는 구분한다.
실제 웹 캡처: outputs/receipt-screen-review/p0-menu-390.png, p0-menu-error-390.png, p0-saving-390.png, p0-duplicate-320-200.png(390/430도 동일 이름 패턴). 320px·200%에서 제목·본문·버튼이 줄바꿈하며 가로 넘침 없이 저장에 접근했다. 화면별 명세와 공통 Ledger의 카드·폰트·버튼을 대조했다. 화면 읽기 도구·네이티브 안전 영역은 아직 검수하지 않았다.

6. 배포·최종 인수 전에 할 일
1) 승인된 대상 DB의 백업·마이그레이션 이력을 확인하고0009를 먼저 적용한 뒤 Worker를 배포한다. 이번 작업에서는 실행하지 않았다.
2) 현재 예약 실행 설정은 staging에 있다. 운영 환경 배포 시 해당 환경의 예약 설정을 확인하고 실제 미완료 작업 처리·경보 운영을 검수한다. 예약 주기 이전의 대기는 삭제 완료로 안내하지 않는다.
3) 실제 Android에서 카메라·앨범·권한 거절·키보드·뒤로가기·안전 영역·TalkBack·큰 글자를 확인한다. iOS가 출시 대상이면 iOS도 별도 검사한다. Android 설치본은 이번 요청에서 만들지 않았다.
4) 사용 권한이 있는 KRW·JPY 실제 영수증30장 이상(통화별 최소10장 권장)과 USD 회귀 표본을 준비한다. OCR 필드별 분모·실패/수정률을 기록하고 개인정보는 검수 자료에서 가린다.
5) 사용자가 위 인수 결과와 화면을 확인한 뒤 출시 여부를 결정한다. 앱 초안의 종료 후 복원·오프라인 큐·자동 병합은 P0 신규 범위가 아니다.

7. 검토 이력
읽기 전용 분석 담당의 범위 확인, 검토 담당의 최초 검토와 재검토1회를 수행했다. 최초 지적2건(메뉴 오류 행 이동, 원본 정리 내구성)을 수정했다. 재검토1회에서 추가 결함은 발견되지 않았으며 운영 예약 설정 확인 사항을 인계했다. 같은 내용의 재검토 한도는 최초 이후 최대2회다.
