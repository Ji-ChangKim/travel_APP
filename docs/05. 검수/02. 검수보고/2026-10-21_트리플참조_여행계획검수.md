# 여행 생성·편집·공유 보완 검수

기준일: 2026-10-21. 트리플 공식 안내를 참조해 실제 TripPrint 코드를 보완했다. 원격 배포·커밋·Android 빌드는 실행하지 않았다. 변경 전부터 있던 다른 채팅의 미커밋 코드는 보존했다.

## 기능 변경

- 일정 관리에 복사를 추가했다. 새 ID의 작성 초안에서 날짜·시간을 확인한 뒤 기존 `schedule.save`로 저장한다. 실제 지출·사진·영수증을 복사하지 않는다. 예상 비용은 새 일정에 별도 생성한다.
- 추가·수정·복사의 공통 제목을 구분하고 DAY 전체 공개 선택·해제를 추가했다. 개별 항목 선택과 비공개·권한 검증은 유지한다.
- 공개본 링크 전달을 기기 공유 또는 웹 클립보드에 연결했다. 전달 URL에는 공개 게시 ID만 들어간다. 공유 실패·취소는 원본이나 공개 상태를 바꾸지 않는다.
- 공개 화면의 담기 버튼을 기존 날짜 입력·확인 시트와 실제 저장 API에 연결했다. 새 여행이 저장된 뒤 그 여행을 연다. 실제 동작이 없는 인쇄·스크랩 버튼은 노출하지 않는다.
- 미리보기와 공개 화면을 같은 타임라인·사진·통화별 비용 표시로 연결했다. 장소 설명·팁 보기의 기존 슬라이드 상세와 Google 사진 조회 경로를 유지한다.
- 일정 개수에서 임의로 만든 이동 거리·소요시간, 입력하지 않은 체크인·검증·추천 문구를 제거했다. 공개 여행계획을 다녀온 후기라고 안내하지 않는다.

## 코드 역할

순수 변환: `scheduleCopy.ts`, `publicPlanLink.ts`, `publication.ts`, `timelinePlanAdapters.ts`.

기능·수명: `publicPlanShare.ts`, `usePublishedPlanShare.ts`, 기존 `workspaceScreenActions.ts`, `useCommunityImport.ts`.

표시: `PublishedPlanActions.tsx`, `PublicPlanExecution.tsx`, `PlanAttachments.tsx`, 기존 일정·공개·미리보기 컴포넌트. 공통 헤더·GNB 컴포넌트와 토큰은 변경하지 않았다.

DB 스키마는 바꾸지 않았다. 화면 전용 `PlanForm.copySourceTitle?: string`과 공개 타임라인의 선택 속성은 DB 사전에 기록했다. 복사·공개·담기는 기존 저장 명령과 서버 API를 재사용한다.

로컬 인증 세션·실제 Worker·실제 별도 D1을 사용했다. 저장 응답이나 DB를 성공하는 것처럼 대체하지 않았다. 테스트 회원·공개본은 로컬 검사 환경에서만 만들며 원격 고객 자료를 사용하지 않았다.

Android 시스템 공유, 실제 Google 로그인, 실기기 키보드·TalkBack과 staging의 실제 Google 사진 응답을 이번 로컬 검사 성공으로 보고하지 않는다. 로컬 사진 공급자 설정이 없는 경우의 실패·재시도 화면은 확인했다. 새 코드를 웹 배포나 내부 테스트 설치본에 반영한 상태는 아니다.
