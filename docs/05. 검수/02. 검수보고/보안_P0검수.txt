TripPrint P0 보안 검수·수정 결과
검수일: 2026-10-20 (한국 시간)
범위: SECURITY_RELEASE_GATE.txt의 S01 계정별 권한, S02 인증·세션, S03 비공개 정보·공개 파일.
판정: 이번 반례 검사에서 발견한 공개 파일 정보 노출 1건을 수정하고 staging에서 재검증했다. 전체 보안 출시 승인을 뜻하지 않는다.

1. 발견 사항과 수정
P0-01: 공개 사진의 부가 메타정보 노출. 공개 JSON에서는 개인 메모·영수증을 제외하지만, 공개 파일은 저장 원본 바이트를 그대로 응답하고 있었다. 따라서 GPS·촬영자 등을 담은 EXIF/PNG 텍스트가 있으면 내려받을 수 있는 경로였다.
재현 자료는 실제 개인정보 대신 GPS_PRIVATE_OWNER_P0 표식을 넣은 1픽셀 소유 검수 PNG다. 직접 업로드·등록·선택 공개 후 내려받은 108바이트에 표식이 남았다. 격리 Worker/D1/R2와 실제 staging 양쪽에서 재현했다.
수정은 apps/api/src/publicImage.ts와 cloudMedia.ts에 적용했다. 현재 공개 선택과 서명을 통과한 파일에만 공개 응답 변환을 적용한다. JPEG EXIF/XMP/IPTC/주석, PNG 텍스트·EXIF 등 부가 정보를 제거하고 압축 픽셀·색상 정보는 유지한다. 방향은 1~8 범위의 태그 하나만 새로 기록한다.
비공개 R2 원본·미디어 ID·경로·등록 데이터는 변경하지 않았다. 공개 시점에 변환하므로 수정 전에 저장한 파일에도 적용된다. 최대 4MiB이며 손상된 세그먼트 경계는 거부한다. 새 패키지·DB 마이그레이션·별도 저장본은 추가하지 않았다.
수정 후 같은 검수 자료의 공개 응답은 68바이트이며 표식이 없다. 수정 전 저장한 동일 파일을 다시 공개해도 제거됐다. 비공개 응답은 수정 전후 모두 원래 108바이트와 동일 SHA-256을 유지했다.
이 처리는 완전한 이미지 디코더·악성 파일 검사나 사진 픽셀에 보이는 개인정보 제거를 대신하지 않는다. 색상 프로필 등 렌더링 정보는 보존한다.

2. S01 계정별 권한 결과
격리 환경에서는 실제 인증 API로 회원 4명을 만들고, 실제 초대 발급·수락으로 소유자·편집자·조회자·비멤버 역할을 구성했다. staging에서는 기존 QA 소유 회원과 신규 검수 이메일 회원 3명을 사용했다. 클라이언트 표시 역할이나 DB 직접 삽입으로 권한 검사를 대체하지 않았다.
- 소유자·편집자·조회자는 서버에서 각자의 myRole을 받았다. 비멤버는 여행 조회 404, 익명은 401이다.
- 편집자의 허용 일정/DAY 저장은 성공하고, 초대 발급·역할 변경·공개 명령은 403이다.
- 조회자의 일정 쓰기·파일 업로드·OCR 요청은 403, 비멤버의 같은 요청은 404이다. OCR은 권한 검사에서 차단돼 실제 공급자 인식을 실행하지 않았다.
- ownerId/role을 입력 본문에 추가한 요청은 strict 계약에서 422로 차단됐다. 차단된 쓰기 묶음 전후 서버 원본 전체를 비교해 변경이 없음을 확인했다.
- 다른 여행의 DAY·파일 경로, 다른 동행이 올린 파일 등록은 격리 서버에서 422로 차단됐다.
- 제거 전 편집자의 사진 URL은 200이었다. 동행 제거 직후 동일 URL과 원본 여행 조회는 404다. 만료 대기 없이 현재 멤버십을 적용했다.

3. S02 인증·세션 결과
- 변조된 세션·임의 토큰은 격리 및 staging에서 401이다.
- 실제 로그아웃한 세션으로 여행 목록을 다시 요청하면 401이다. 별도의 정상 회원 세션은 유지됐다.
- 세션 만료는 격리 D1의 만료 시각을 조정해 401을 확인했다. 운영 DB 시계나 회원 세션을 임의로 수정하지 않았다.
- 일회용 인증 교환은 잘못된 검증자 401, 동일 코드 동시 교환 200/401, 만료 코드·유효하지 않은 세션 401이다. 이 시험은 격리 D1에서 교환 경계를 검증하며 Google 인증 성공을 가장하지 않는다.
- Google 설정이 실제로 있는 staging에서 허용하지 않은 복귀 주소 5종은 422, 외부 Origin은 403, 임의 일회용 코드는 401이다. 제3자 주소로 이동하거나 Google 사용자 로그인을 수행하지 않았다.
- 기존 게스트 연결·이전 토큰 철회·탈퇴 유예·재로그인 복구·90일 정리 검사는 격리 통합 회귀 검사에서 통과했다. 실사용 계정 영구 삭제는 실행하지 않았다.

4. S03 공개 정보 결과
- 공개 JSON에는 선택한 장소 설명과 선택 사진 1장만 남았다. 개인 메모, 비선택 사진, 영수증 원본 경로·상호·상세 메모·품목, QA 이메일이 포함되지 않았다.
- 비선택 일반 사진·영수증의 공개 URL 발급은 404이다. 회원에게만 허용된 URL 발급을 비멤버로 우회할 수 없었다.
- 새로 발급받아 200을 확인한 공개 사진 URL을 사용했다. 사진 선택 해제 직후 동일 URL은 404였다. 만료된 링크의 오류를 공개 중단 성공으로 오인하지 않도록 갱신 직후 검사했다.
- 공개 중단 뒤 단건 공개 조회와 공개 URL 발급은 404이다. 이번 검수로 만든 공개 글은 모두 공개 중단했다. 이미 외부에 내려받은 사본까지 회수된다고 주장하지 않는다.
- 수정 전후 QA 파일의 비공개 원본 보존과 기존 파일에 대한 공개 메타정보 제거를 별도 재검증했다.

7. 남은 범위와 최종 판단
아래는 최초 검수 시점의 남은 범위다. 이후 Google 시작·취소·외부 요청·키 검사의 실행 결과와 미완료 조건은 SECURITY_P0_FOLLOWUP.txt로 갱신했다.
이번 요청의 권한·세션·공개 정보 반례에서는 수정 후 재현되는 우회가 발견되지 않았다. 이것을 모든 공격에 안전하거나 전체 P0 검수가 끝났다는 뜻으로 사용하지 않는다.
Google 사용자 계정의 실제 동의·브라우저 로그인·Android 앱 복귀, 최종 Android 설치본의 저장소·통신·권한은 미검수다. 허용 Origin·복귀 경로와 일회용 교환 경계 검증으로 이를 대신하지 않는다.
DB 관리자 직접 조회 권한 부족, S05의 전체 입력/서버 요청 위조 검사, S09의 키 폐기·재발급·Git 이력/배포 비밀 검사 및 운영 접근 통제는 이 보고서의 완료 범위가 아니다. 노출된 Stitch 키의 폐기·재발급 여부는 운영 확인이 필요하다.
웹 localStorage 세션의 XSS 위험, 업로드 파일의 완전한 디코딩·픽셀 수 제한, 비용 악용 한도 등 계획서의 P1과 운영 보완도 별도로 남는다.
기존 UI/UX 유지와 Android 빌드 보류 조건을 지켰다. 전체 출시 합격은 SECURITY_RELEASE_GATE.txt의 미검수 필수 항목까지 해결한 뒤 판정한다.
