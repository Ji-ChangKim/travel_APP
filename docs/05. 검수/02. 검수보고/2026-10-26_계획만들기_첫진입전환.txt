2026-10-26 계획 만들기 첫 진입 전환

확정 범위
사용자가 앱 첫 진입부터 계획 만들기로 변경하도록 확정했다.
시작 점검·기존 인증 복귀 경로는 유지하고 /(tabs)의 콘텐츠를 PlanningStartScreen으로 교체했다.
첫 화면에는 계획 만들기 제목, 신규 계획 생성하기, 이 계정의 기기 저장 초안만 표시한다.
추천 여행지·퀵메뉴·여행 정보·공개 기록은 첫 화면에서 제외했다. 이전 홈 구현과 검수 자료는 이력으로 보존한다.
로그인 전 신규 생성은 next=new-trip을 유지한 인증으로 연결한다.
기존 여행 목록은 내 여행, 새 계획은 날짜·여행지 → 선택 항공편 → 실제 저장 성공 → 해당 여행 일정 화면으로 연결한다.
여행 생성·일정 저장 데이터 계약과 DB는 변경하지 않았다.

변경 파일
apps/mobile/src/features/workspace/PlanningStartScreen.tsx: 계획 시작 화면.
apps/mobile/src/app/(tabs)/index.tsx, _layout.tsx: 첫 화면 연결·탭 이름.
apps/mobile/src/components/navigationModel.ts, screenNavigationPolicy.json: 첫 메뉴 이름·달력 아이콘·일반 제목 헤더 정책.
apps/mobile/src/features/workspace/WorkspaceScreen.tsx: 초안 복원 실패 시 복귀 문구.
apps/mobile/src/features/localization/messages.json: 한국어·영어·일본어 문구.
tests/web/workspace.spec.ts: 로그인 완료 기준·첫 메뉴·접근성·임시 저장·생성 이동 검사.
디자인 문서: 홈온보딩_화면규격.md, 여행일정_화면규격.md, 헤더GNB_규격.md에 최신 확정 범위를 기록했다.

검증
첫 진입 화면·320/390/430px·큰 글꼴, 여행 생성 후 DAY2 일정 저장, 임시 저장·재조회·복원·삭제, 저장 공간 오류 시 입력 보존: 4개 통과.
언어 카탈로그와 초안 단위 검사: 6개 통과.
공통 헤더·GNB·복귀 검사: 첫 실행 18개 통과, 3개는 이전 홈의 여행 카드를 찾는 검사여서 실패했다.
해당 3개의 첫 화면 기대값을 계획 만들기로 수정한 후 320/390/430px 접근성 검사 모두 통과했다.
근거 로그: outputs/planning-start-flow.log, planning-start-unit.log, planning-start-headers.log, planning-start-wcag.log.
화면 캡처: outputs/planning-start/320.png, 390.png, 430.png, 320-large.png.
공통 ScreenHeader·DesignButton·글꼴·간격·터치 규격을 재사용했다. GNB는 첫 메뉴의 이름과 아이콘만 변경했다.
320px 글자 200%에서 버튼과 메뉴 문구는 여러 줄로 확장된다. 캡처에서 잘림은 없으며 실기기 글꼴·안전 영역 검수는 남아 있다.

검증 경계
로컬 웹 앱과 격리된 HTTP 응답으로 검증했으며 실서비스 저장이나 배포를 수행하지 않았다.
실기기 시작·Google 로그인·키보드·안전 영역·앱 종료 후 초안 복원은 별도 확인 대상이다.
제거한 추천 홈을 전제로 한 과거 테스트는 이번 변경의 통과 근거로 사용하지 않는다.
커밋·푸시·배포는 수행하지 않았다.

필수 검사: npm run check 전체 통과. TypeScript·ESLint·Prettier·문서·디자인·구조·화면 이동 경계를 확인했다. 근거: outputs/planning-start-check.log.
