TripPrint V11 여행계획 등록 검수
기준일: 2026-10-21 / versionCode11 / versionName0.1.0

1. 확정한 이용 흐름
구매한 항공권을 가진 이용자가 앱을 실행하고 계획 만들기→여행 날짜→국가·도시→항공권 입력→DAY별 계획 추가·수정·삭제·순서 변경을 진행한다. 항공권을 구매·결제하는 서비스가 아니다. 아직 항공권을 입력하지 않은 기존 이용자의 건너뛰기 경로는 유지한다.
생성 화면은 여행 기간, 국가·도시, 선택 제목 순서로 바꿨다. 다음 화면은 구매한 출발편·귀국편·추가 항공편을 직접 입력하거나 기존 조회 결과로 확인한다. 항공권 조회 성공을 저장의 필수 조건으로 만들지 않는다.
공통 헤더·GNB·폰트·색·버튼·이탈 보호·저장 잠금은 유지한다. 여행 생성은 기존 API의 실제 저장 성공 뒤 받은 tripId로 상세 화면을 연다. 별도 샘플 여행이나 자동 공개를 만들지 않는다.

2. 실제 저장 경계
회원: 앱 폼→API→인증·멤버십→D1 trips.snapshot/CAS version→새 workspace 조회.
항공권: 출발일의 실제 DAY ID에 TRANSPORT 일정과 flight 상세로 저장. 출발편·귀국편의 서로 다른 DAY 배치를 확인한다.
장소: 선택 DAY UUID와 일정 UUID를 사용한다. schedule.save 편집은 같은 UUID를 유지하고, schedule.reorder는 같은 DAY의 전체 ID를 저장하며, schedule.delete는 확인한 일정만 제거한다. 기존 DAY와 다른 DAY의 항공권은 보존한다.
게스트는 같은 기기의 실제 기록이며 서버 DB 저장으로 보고하지 않는다. 이번 서버 저장 시나리오는 실제 회원 세션으로 확인했다. DB 스키마 변경은 없다.

scripts/qa/verify-planning-live.mjs는 TRIPPRINT_VERIFY_STAGING=1인 경우에만 고정 staging에 비공개 QA를 만든다. 반복할 때마다 계정·빈 여행이 남으므로 필요할 때 명시적으로 실행한다. CI에서 자동 실행하지 않는다.
다른 채팅의 홈 개편·서버·계정·타임라인·Android workflow 변경은 보존하고 이번 V11 등록 변경과 섞지 않는다. 이전 전체 화면 검사에서 확인한 화면 기대값 불일치는 별도 보류 사항이다. V10 원격 CI는 이번 확인 시점에도 진행 중이었고, V11의 부분 등록 검수를 전체 CI·Google 실제 로그인·실기기 인수·Play 업로드 성공으로 기록하지 않는다.
버전은11로 준비하며 Android 컴파일·서명·AAB·APK 생성·Play 제출은 실행하지 않는다.
