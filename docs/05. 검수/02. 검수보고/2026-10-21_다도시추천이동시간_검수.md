# 다도시·AI 장소 추천·실제 이동시간 검수

기준일: 2026-10-21. 요청한 순서대로 다도시 관리, AI 장소 추천, Google Routes 이동시간 조회를 앱·공통 저장 모델·서버에 연결했다. 공통 헤더·GNB·디자인 토큰은 유지했다. Android 빌드와 활성 웹·API 서비스 배포는 하지 않았다. 기존 미커밋 변경도 보존했다.

## 실제 외부 공급자와 원격 D1 검증

활성 서비스 대신 Worker 후보 버전 `87f1b212-ca57-45a4-90cb-ab52d22afd0e`에서 등록된 서버 Secret을 유지해 검사했다. 기존 Places 키로 Routes가 실제 응답했으므로 별도 키를 다시 입력할 필요는 없다. 별도 키를 사용할 때만 Worker Secret `GOOGLE_ROUTES_API_KEY`를 추가한다. 앱 번들에는 서버 키를 넣지 않는다.

- 실제 Workers AI와 Google Places가 추천 장소5개를 반환했다. 장소 유형 필터로 관심사와 다른 검색 결과를 줄였다. 외부 응답이 늦을 때를 확인해 AI 제한60초·앱 요청75초로 조정했다.
- 반환된 실제 장소2개를 정상 회원의 여행에 저장하고 연속 구간의 도보 수단을 저장했다. Google Routes가 실제 소요시간·거리를 반환했다.
- 같은 회원으로 다시 로그인한 새 세션에서 도시 목록, DAY 배정, 일정2개, 이동수단을 재조회했다.
- 선택 공개본과 공개 경로 API 응답을 확인하고 검수 공개본을 철회했다. 중간 검수 도구에서 공개 ID를 응답에 있다고 가정한 오류도 수정했다. 이후에는 원본 재조회로 ID를 확인하고 실패 때도 철회한다. 중간에 남은 해당 공개본1건도 ID·소유자를 확인해 정리했다.
- 실제 D1 직접 조회: 여행 `e728be33-2b2c-490b-8bcc-92f9e8f5c741`, 최종버전7, 도시2개·일정2개·구간1개, `postId=null`, 공개 행0개. 경로의 `durationSeconds` 저장 속성도 없다. 검사 계정의 비공개 여행 원본은 보존했다.

근거: `outputs/multicity-planning/live-provider-evidence.json`, `remote-db-evidence.json`. 공개 장소 원문·키·세션·공급자의 숫자 경로 콘텐츠를 검수 문서에 복제하지 않고 성공 여부와 직접 D1 대조 결과만 남긴다. 외부 조회를 사용하지 않는 대역 테스트와 위 실제 공급자 검증은 구분한다.

## 코드 구분과 반영 상태

데이터·순수 변환: domain `planning.ts`, validation `planning.ts`·`workspaceDestinations.ts`·`workspaceModelCore.ts`·`workspaceModel.ts`·`communityImport.ts`, 앱 `destinationForms.ts`·`formCommands.ts`·`timelinePlanAdapters.ts`.

통신·수명: API `planning.ts`·`planningRecommendations.ts`·`planningRoutes.ts`·`places.ts`·`googleUsage.ts`, 앱 `planningService.ts`·`usePlanningRequest.ts`. 계정·DAY·여행 버전·관심사·수단 변경과 화면 종료·백그라운드에서 이전 요청을 취소한다. 같은 요청의 연속 클릭을 막는다.

표시·기존 동선 연결: `DestinationCollection.tsx`·`DestinationEditor.tsx`·`DayRecommendations.tsx`·`TravelRoute.tsx`, 기존 생성·더보기·일정 편집·타임라인·미리보기·공개 화면. 도시 편집도 기존 충돌 복구와 이탈 보호 경로를 사용한다.

호출 상한 테이블은 staging에 추가했다. 미적용 마이그레이션 목록에는 다른 채팅의 `0007_account_retirements.sql`도 있어 전체 마이그레이션을 실행하지 않았다. 이번 테이블만 멱등 DDL로 적용했으며 추후 정식 마이그레이션 실행으로 이력을 기록할 수 있다. 활성 배포·커밋·푸시·Android 빌드는 별도로 실행하지 않았다.

게스트의 기기 여행은 추천·경로 기능 때문에 원격 서버에 자동 업로드하지 않는다. 실제 기기 Google 로그인·TalkBack·내부 테스트 설치본 검증은 웹·API 검사 결과로 대체하지 않는다. Google이 경로를 제공하지 않는 수단·지역은 실패 안내와 재조회 동작을 사용한다. 월 상한은 비용 제한이며 무료 사용을 보장하지 않는다.

전체 포맷 검사에 걸린 기존 `docs/08. 여행콘텐츠/00. 공개여행계획/huru-japan-10-curated-plans.md`는 내용 변경 없이 서식만 정리했다.
