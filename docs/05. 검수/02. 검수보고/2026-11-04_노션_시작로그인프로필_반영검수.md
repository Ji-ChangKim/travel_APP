## 요청과 적용 기준

승인한 BI/CI → 로그인 연출을 유지하고, 나머지는 사용자 지정 노션 문서에 맞춘다. [적용 규격](<../../02. 디자인/01. 화면설계/로그인_프로필생성_규격.md>)에 참조 문서·기존 규격과의 차이를 기록했다. 작업 시작 기준은 `81316e6`과 기존 공유 작업 트리이며 홈·계획 화면의 다른 변경은 보존했다. 버전은 `0.0.1 (14)`를 유지한다.

## Android Studio에서 테스트

1. 저장소 루트에서 `npm run android:api`를 실행한다. 원격 자원과 분리된 `outputs/android-studio-local`의 로컬 DB·파일 저장소만 사용한다. 재실행해도 같은 로컬 자료를 유지하며 새 migration만 적용한다.
2. 다른 터미널에서 `npm run android:metro:local`을 실행한다. 8081 개발 서버가 API `http://127.0.0.1:8787`에 연결된다. 이전 `npm run android:metro` 명령은 기존 staging용이므로 새 API를 검사할 때 혼용하지 않는다.
3. Android Studio에서 `apps/mobile/android`를 열고 Gradle JDK 21·실행 구성 TripPrint·debug·`Medium_Phone_API_37.0`을 선택한다.
4. 아래 두 포트를 연결하고 Run한다. 실제 설치·실행 결과는 아래 검증 표에 기록한다.

```powershell
& 'C:/Users/Jichang/AppData/Local/Android/Sdk/platform-tools/adb.exe' -s emulator-5554 reverse tcp:8081 tcp:8081
& 'C:/Users/Jichang/AppData/Local/Android/Sdk/platform-tools/adb.exe' -s emulator-5554 reverse tcp:8787 tcp:8787
```

로컬 기본 구성에는 Google 인증 자격이 없다. 따라서 실제 Google 인증이 필요한 검사는 별도 클라이언트·복귀 주소 설정이 필요하다. API 검사의 테스트 인증 문맥 주입과 실제 로컬 이메일 인증으로 발급한 세션을 사용한 웹 검수는 Google 로그인 성공 증거가 아니다. 사용자 화면에 가짜 계정이나 성공 응답을 넣지 않는다.

이전 독립 실행 APK `TripPrint_261104_Ver02.apk`는 이번 명세 반영 전 산출물이다. 최신 debug 컨테이너는 Metro의 현재 소스를 읽는다. 새 기능을 이전 standalone APK로 검수하지 않는다. 실기기 ARM 빌드와 Play 배포는 이번 로컬 준비에 포함하지 않는다.

## 최종 검수 보완 기록

- 공유 작업 트리의 HEAD는 작업 중 `4bdba73`으로 바뀌었다. 다른 채팅의 홈·계획 변경은 보존했다. 검사에서 발견한 홈의 버튼·추천 코스 설명 대비 두 곳과 `homeConciergeCatalog.ts`의 서식만 보완했다.
- 실제 로컬 인증·D1을 사용한 UI 검수에서 프로필 저장·재진입·재조회, 영어 320 너비·글자 200%, 일본어 430 너비, 중앙 이미지 선택 팝업, 사진 선택·JPEG 변환·인증된 사진 미리보기·저장을 확인했다. 브라우저 img의 인증 헤더 제약은 인증 응답의 임시 blob 주소로 처리했다.
- 실제 앱이 만든 기기 게스트 문맥에 동일한 도메인 엔진으로 만든 검수 여행을 보관한 뒤, 로그인 목적 DAY → 사용자 선택 연결 → 실제 서버 여행 저장 → 원래 날짜 복귀까지 통과했다. 원래 기기 문서의 여행 UUID도 그대로 남았다. 기기 여행 내용은 검수 모델 자료이며 원격 실제 사용자 여행 저장의 증거가 아니다.
- 안드로이드 API 37 x86_64 debug에서도 기존 기기 게스트를 다시 열어 홈 진입을 확인했다. native Fetch에 없는 `Response.json` 정적 함수를 생성자로 대체한 뒤 여행 목록 조회 오류가 사라졌고 기존 기기 프로필은 유지됐다. 해당 환경을 자동 검사에도 추가했다.
- Google의 명시적인 취소는 로그인 기본 화면으로 돌아온다. 서버의 세션·검증 실패는 취소로 숨기지 않는다. 실제 Google 인증은 이번 검사에 포함하지 않는다.
- 공유·공개·OCR 버튼과 게스트 로그인에 현재 여행·DAY를 인계하고, 공개 폼·선택 사진 확인·초대 영역을 다시 표시한다. 신고 본문은 URL이 아닌 기기 임시 저장소에 두며, 원래 계정 또는 명시적인 게스트 전환에서만 복원한다. 복원 후 정리하고 1시간이 지난 초안은 다음 조회에서 폐기한다. 자동 제출은 하지 않는다. 여행 작성 중 로그인은 기존 생성 초안 인계 기능을 재사용한다.
- 공통 헤더·접근성 21개는 대비 보완·취소 기대값 수정 뒤 통과했다. 최초 실행에서 통과한 14개와 수정 후 재실행한 7개의 증거를 합산한다. 320 너비의 일시적인 로딩 실패도 같은 기준으로 재실행해 통과했다. `notion-headers.log`, `notion-headers-retry.log`에 기록했다. 오류 페이지의 헤더 검수 입력은 정상 취소인 `access_denied` 대신 검증 오류 `invalid_state`로 바꿨다. 정상 취소 자체는 별도 실제 UI 검사로 확인한다.

검수 명령은 로컬 API·Metro 실행 후 `npm run test:onboarding:web`다. `outputs/android-studio-20261104/notion-ui/result.json`과 캡처를 확인한다. 기기 캡처는 `notion-native.png`, `notion-native-guest-final.png`, XML은 같은 이름의 파일이다.

로컬 Google 설정이 있으면 `TRIPPRINT_STUDIO_GOOGLE_CLIENT_ID`와 `TRIPPRINT_STUDIO_GOOGLE_CLIENT_SECRET` 환경 변수로 전달할 수 있다. 값은 소스·로그·보고서에 남기지 않는다. Google 콘솔의 실제 클라이언트·복귀 주소 등록도 맞아야 하며, 환경 변수 입력을 인증 성공으로 보고하지 않는다. 현재 기본 구성은 미설정이다.

실제 Google 계정·ARM 실기기·네이티브 프로필 사진 선택과 저장·모든 BI 전환 프레임은 미검증이다. 프로필과 사진 저장은 실제 웹 앱·로컬 D1/R2에서 검증했으며, Android에서는 시작·로그인·기존 게스트 복원과 홈 조회를 검증했다. 미사용 업로드의 정리 기간과 실제 가입 고지·지원 경로는 운영 기준을 확정할 때 함께 정해야 한다. 현재 없는 정책·링크·인증 성공을 사용자 화면에 넣지 않았다.
