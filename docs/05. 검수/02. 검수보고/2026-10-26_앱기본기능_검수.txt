앱 기본 기능 점검
기준일: 2026-10-26 / 작업: travel_APP main / 상태: 로컬 기본 기능 검수 통과, 실기기 인수 전
요청: 실행·로그인·화면 이동·여행 및 일정 관리·저장과 재조회 점검, 문제 수정, 기존 디자인 유지.

1. 검수 환경과 구분
실제 앱 소스의 웹 번들을 Chrome에서 실행했다. Android 설치본·기기 실행 결과가 아니다.
기본 UI 회귀는 HTTP 응답을 통제하여 실패·지연·게스트 오프라인 등 조건을 재현했다.
여행 통합 검수는 별도 최신 웹 번들 + 실제 로컬 Worker + 격리 D1/R2를 연결한다. 여행 저장 응답을 가짜 성공으로 바꾸지 않고 D1 행과 HTTP 재조회를 대조한다. 외부 장소·항공·OCR 공급자의 실제 응답 품질은 이 검수 범위가 아니다.
테스트 계정은 로컬에만 만들며 운영 DB·계정·Worker는 변경하지 않는다. 커밋·푸시·원격 배포도 실행하지 않는다.

2. 기본 기능 점검 범위
실행: 시작 연출, 버전·공통 자료 확인, 실패 재시도, 알 수 없는 기기 저장 형식 차단.
로그인: 이메일 로그인, 로그인 필요한 여행 직접 링크 복귀, 세션 확인 지연·통신 실패 시 토큰 보존, 같은 브라우저 저장소에서 새 페이지 시작 후 자동 복원.
로그아웃: 취소하면 계정 유지, 확정하면 로그인 화면 이동, 비공개 여행 진입 차단, 같은 계정 재로그인 후 기존 일정 복원.
이동: 홈·내 여행·발자국·MY 왕복, 목록 검색·상태 필터, 상세/작성 이동, 미저장 이탈 보호, 잘못된 복귀 주소 제한.
여행·일정: 여행 날짜·국가·도시·항공권 입력, 일정 추가·제목/시간/설명 수정·순서 변경·삭제, 일정 복사·다른 DAY 연결, 여행 도시와 DAY 배정.
저장·재조회: 새로고침, 새 브라우저 세션 로그인, 같은 저장소의 새 페이지, HTTP 조회와 실제 D1 JSON 일치, 기존 일정 ID·DAY 보존.
기기 게스트: 서버 없이 여행·일정·사진 기록을 만든 뒤 웹 재실행과 비용 저장. 회원 서버 기록과 구분한다.
기본 범위 외에 기존 여행계획 통합 스크립트가 포함하는 공유·가져오기·공개 중단도 회귀로 실행한다.

3. 이번 보완
tests/planning/journey.test.mjs: 기존 새 브라우저 재로그인 검사에 더해 같은 저장소 자동 복원, GNB 왕복, 로그아웃 취소·확정·비공개 차단·재로그인 후 D1 원본 보존을 추가했다.
docs/02. 디자인/00. 공통규격/디자인시스템.md: 문서 작성 당시의 ‘영수증 앱 적용 전’ 설명과 현재 P0 구현 상태를 구분하고 실제 검수 기록을 연결했다. 토큰·공통 컴포넌트·디자인 수치는 바꾸지 않았다.
이전 영수증 P0 변경은 그대로 보존했다. 이번 검사 범위에서는 재현된 제품 결함이 없어 앱 코드는 추가 수정하지 않았다. 여행이 있는 홈에 빈 상태의 제목을 기대하던 새 테스트 조건을 실제 여행 카드 표시로 수정했다. 제품 검증 기준이나 디자인은 낮추지 않았다.

4. 결과·증거
기본 브라우저 회귀21개 통과: outputs/basic-app-review/basic-ui.log.
실제 Worker/D1 통합3개 통과: outputs/basic-app-review/planning.log. 여행 생성·일정 관리·공유/복사·도시 관리의 연속 흐름이다. 이후 서버 세션 폐기 및 탭 표시를 보완한 기본 여정1개도 재실행 통과했다(outputs/basic-app-review/journey-final.log).
outputs/planning-v11/db-evidence.json: HTTP/D1 일치, 새 브라우저 복원, 같은 저장소 복원, 로그아웃 취소/확정/재로그인, 서버의 폐기 세션401을 확인했다. responses 배열은 최초 page의 통신만 포함하며 추가 페이지는 별도 UI/API 단언으로 검사했다. 토큰은 메모리에만 보관하고 출력하지 않았다.
전체 코드·문서 검사: npm run check 통과. 문서·디자인 대비·구조·헤더 경계·TypeScript·ESLint·Prettier를 확인했다(outputs/basic-app-review/check.log). 최종 보고서 추가 후 check:docs도 통과했다(outputs/basic-app-review/docs-final.log).
이번 UI 회귀에서 일정 기본 화면(outputs/schedule/itinerary-default-390x844.png)과 로그인320px(test-results/tripprint-login-320.png)을 직접 열어 보았다. 기존 테스트가 정한 캡처 경로이며 새 보고서에서는 다른 환경에도 필요한 결과를 본문에 남긴다.
실제 로컬 DB에 저장한 여행 목록 캡처(outputs/planning-v11/05-restored-plans-390.png)도 열어 확인했다. 제목·카드·상태 필터·날짜·계획 진입·하단 메뉴의 표시와 기존 규격을 대조했다. 제목26/36, 기존 카드 간격과 색, GNB 순서·선택 표현을 유지했다. 이번에 관찰한 캡처에서 수정이 필요한 겹침·가로 넘침은 발견하지 못했으며 모든 기기·상태의 시각 인수를 완료했다는 의미는 아니다.

읽기 전용 분석·검토는 신규 기본기능 범위에서 각각1회 수행했다. 검토 의견에 따라 주소 변화만 보던 GNB 검사를 실제 화면과 선택 상태까지 확인하도록 보완하고, 로그아웃한 브라우저의 같은 세션이 서버에서도 거절되는지 추가했다. 같은 내용의 불필요한 재검토는 실행하지 않았다.

5. 디자인 작업 방식
디자인시스템.md·design-tokens.json·헤더GNB_규격.md와 홈온보딩_화면규격.md·내여행_화면규격.md·여행일정_화면규격.md의 최신 기록을 기준으로 한다. 과거 아카이브의 베이지 바탕을 다시 적용하지 않는다.
기존 #F8F9FF 바탕, 흰 카드, Pretendard, 네이비 본문과 기존 강조색을 유지한다. 공통 ScreenHeader·GlobalNavigation·입력·버튼을 재사용한다. 화면별 시안의 차이는 해당 화면에만 적용하며 공통 제목·터치·탭 규칙을 덮어쓰지 않는다.
시안 → 앱 공통 컴포넌트 연결 → 실제 화면 캡처 → 제목 위치·글꼴·간격·터치 영역·긴 문구·오류·빈 상태 대조 순서다. 현재 열려 있는 영수증 HTML은 검토용 스케치이며 앱 실행본이 아니다.
이번에는 기본 동작 검수가 목적이므로 앱 전체 디자인을 새로 만들거나 공통 규격을 바꾸지 않았다. 자동 검사만으로 모든 디자인 상태나 국제 접근성 기준 전체 적합성을 선언하지 않는다.

6. 실기기 인수표 — 모두 별도 확인 필요
N01 새 설치/재실행: Android 스플래시·첫 프레임·글꼴, 느린 기기에서 앱 시작 및 재시도.
N02 인증: 강제 종료 후 SecureStore 세션 복원, 만료 세션, 로그아웃 뒤 다시 켜기. 웹 저장소 검사는 대체 증거가 아니다.
N03 외부 인증: Google 앱/브라우저 왕복, 취소·실패·앱 링크 복귀. 실제 OAuth 계정 연동은 이번 로컬 검사에 포함하지 않았다.
N04 이동: 시스템 뒤로가기·제스처, 작성 중 이탈/저장 중 잠금, 백그라운드와 복귀.
N05 입력/디자인: 키보드에 가려지는 입력·저장 버튼, 노치·하단 안전 영역, 작은 화면·긴 문구·시스템 글자 확대·TalkBack. iOS 출시 대상이면 VoiceOver와 iOS도 별도 확인한다.
N06 저장: 저장 중 네트워크 전환·앱 강제 종료·응답 유실 후 재접속. 기록 개수·금액·DAY를 서버 원본과 대조한다.
N07 권한/파일: 카메라·앨범·위치 거절과 설정 복귀, 사진 선택 취소, 실제 영수증 원본과 메뉴 저장·재조회.
N08 운영 연결: 실제 배포 API·DB 마이그레이션·예약 작업·외부 공급자 설정·배포한 앱 버전을 함께 확인한다. 현재 로컬 성공은 운영 설치 앱 성공을 뜻하지 않는다.

7. 인수 판단
웹 기본 기능 결과, 실제 로컬 서버 저장 결과, 실기기 인수를 따로 기록한다. 현재 문서만으로 Android/iOS 출시 인수를 완료 처리하지 않는다. 실기기에서 실패하면 재현 조건·영향·화면과 로그를 개인정보 없이 남기고 수정 후 같은 조건으로 확인한다.
