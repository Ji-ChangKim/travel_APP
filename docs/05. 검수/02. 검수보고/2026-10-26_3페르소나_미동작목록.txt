3개 페르소나별 미동작·미지원 목록
검수일: 2026-10-26 / 기준 커밋: d481938 / 상태: 추가 검수, 수정 전
범위: 로컬 웹 앱·실제 로컬 인증 서버/D1·제품 코드. 운영 배포·운영 계정·외부 메시지 전송 없음.

1. 종합 판정
세 페르소나의 기본 경로는 작동하지만 모든 상황에서 목적을 끝낼 수 있는 상태는 아니다.
P1: 이메일 가입 → 여행·일정 생성 → 저장·재조회 가능. 비밀번호를 잊으면 앱 안에서 복구할 수 없다.
P2: 비로그인 열람 → 로그인 또는 새 가입 → 내 여행으로 담기 가능. 가입 설정을 중단한 뒤 공유 링크로 다시 들어오는 경로는 목적지를 잃는다.
P3: 선택 공개 → 재공개 → 공개 중단 가능. 현재 로컬 HTTP에서는 외부 공유 링크를 만들지 못하며, 공유 API가 거절되는 브라우저에는 별도 복사 대안이 없다.
기존 보고서의 주요 경로 통과를 앱 전체 검수 통과로 확대하지 않는다. 아래 결함·지원 범위·환경 제약·미검증을 따로 관리한다.

2. 수정 또는 기능 결정이 필요한 항목

G01 / P2 / 높음 / 실제 UI 재현: 가입 설정 중 공유 링크 재진입 시 홈으로 이탈
재현: 친구의 공개 여행 → 일정 담기 → 이메일 신규 가입 → 프로필 설정을 완료하지 않은 상태에서 같은 공개 URL 다시 열기 → 선택 안 함 → 설정하고 여행 시작하기.
기대: 친구의 /community/{id}로 돌아가 일정 담기를 이어간다.
실제: /로 이동. 친구 일정으로 자동 복귀하지 않는다. 링크를 다시 열면 우회할 수 있으며 데이터 삭제 문제는 아니다.
근거: outputs/persona-gaps/interrupted-onboarding.log의 URL 기대 검사 실패, interrupted-onboarding/route.json, result.png. 로컬 실제 서버·D1 사용.
원인: apps/mobile/src/features/auth/authReturn.ts:66의 returnFromPath가 /community/{id}를 처리하지 않는다. AuthGate.tsx:86–94, gateReturn이 빈 복귀 정보를 프로필 설정에 전달한다.
완료 기준: 설정 중 재진입·새로고침 뒤에도 해당 공개 ID를 보존하고 설정 완료 후 같은 공개 여행으로 복귀. 일반 홈 진입과 허용되지 않은 외부 주소 거부도 유지.

G02 / P1·P2 / 높음 / 미구현 확인: 이메일 비밀번호 복구 없음
재현: 로그인 → 이메일 계정으로 로그인 / 회원가입 → 비밀번호를 잊은 상태에서 복구 행동 찾기.
실제: 로그인과 회원가입만 제공한다. 비밀번호 찾기·재설정 연결이 없다. 기존 여행이 삭제된 것은 아니지만 비밀번호를 모르면 계정 접근을 회복할 앱 내 방법이 없다.
근거: 실제 로그인 화면에서 복구 버튼 0개 확인(gap-probes.json, email-login.png). EmailAuth.tsx의 login/signup 모드, services/authService.ts:16–28, apps/api/src/features/auth/cloudAuth.ts:32. 재설정 메일 발송 연결도 확인되지 않는다.
완료 기준: 복구 요청 → 메일 수신 → 유효한 일회용 링크로 새 비밀번호 설정 → 로그인 → 기존 여행 조회. 만료·재사용·잘못된 링크와 발송 실패도 확인. 다른 이메일로 새 가입하는 것은 계정 복구로 인정하지 않는다.

G03 / P3 / 중간 / 통제 조건 재현: 브라우저 공유 거절 후 링크 복사 대안 없음
조건: navigator.share는 존재하지만 NotAllowedError로 거절하고 navigator.clipboard.writeText는 사용 가능.
기대: 별도 링크 복사 행동 또는 사용자가 선택할 다른 전달 방법을 제공한다. 사용자가 취소한 경우에는 자동 복사를 강요하지 않는다.
실제: 공유 오류를 반환하며 클립보드 호출은 0회. 같은 보내기 행동을 반복하면 같은 조건에서 다시 실패한다. 공개본 자체는 유지된다.
근거: publicPlanShare.ts:24–35의 제품 함수를 실행해 플랫폼 경계만 통제한 gap-probes.mjs/json. usePublishedPlanShare.ts는 다시 시도 안내를 표시한다. 실제 메신저 공유 시트에서 재현한 결과는 아니다.
완료 기준: 공유 권한 거절 시 독립적인 링크 복사 대안 제공. 공유 성공·사용자 취소·복사 허용·복사 거절 각각 검사. 공개 상태와 원본 보존.

G04 / P2 / 중간 / 연결 미구현: HTTPS 공유 링크에서 설치된 앱으로 바로 열기
조건: 친구가 받은 HTTPS /community/{id}를 눌러 설치된 앱의 해당 여행으로 진입하려는 경우.
실제 지원: 공개 웹 주소 생성. 현행 app.config.ts에는 travelapp 스킴만 있고 HTTPS 앱 연결 호스트가 없다. AndroidManifest.xml의 실행용 필터에도 HTTPS 호스트가 없다(queries의 HTTPS 선언과 다름). iOS associatedDomains도 없다.
영향: 현재 설정은 설치된 앱으로 직접 연결하는 App Links/Universal Links를 제공하지 않는다. 웹 열람 자체가 불가능하다는 뜻은 아니다. 기기별 브라우저 행동은 미검증.
완료 기준: 앱 직접 열기를 제품 범위로 채택하면 도메인 연결·앱 설정을 함께 준비하고 설치/미설치·로그인/비로그인·메신저 인앱 브라우저에서 동일 공개 여행으로 연결. 우선 웹 제공만 할지 결정 필요.

3. 현재 지원 범위의 제한

L01 / P1→P3 / 게스트의 기기 여행을 회원 여행으로 옮기기
게스트로 계획한 여행을 가입 후 계정 여행으로 이전해 공유·다른 기기에서 동기화하는 경로는 없다. 가입 후 새 여행을 계정에 저장하는 현재 안내와 일치하므로 기존 동작의 고장으로 분류하지 않는다.
login.tsx:108, workspace/service.ts:30–39, profile/MyAccountView.tsx의 이전 기기 기록 보기와 대조했다. 이전 기록 조회와 계정 이전은 다르며 기록이 사라진다고 표현하지 않는다.
제품 결정: 게스트가 만든 계획을 그대로 회원 계정에 이어갈지 확정하고, 포함한다면 중복·재시도·사진/영수증·소유권·원본 보존 기준을 정한다.

4. 환경 때문에 현재 검수에서 막힌 항목

E01 / P3→P2 / 로컬 HTTP의 외부 공유 링크 전송
공개 후 공유 링크 보내기 → '공유 링크를 만들지 못했어요. 공개 화면에서 다시 시도해 주세요.' 표시.
publicPlanLink.ts:19–27는 HTTPS만 허용한다. 이번 로컬 번들은 HTTP이므로 공개 화면에서 반복해도 해결되지 않는다. 공개 저장은 성공하며 링크 전송은 실패한다.
기존 triple-flow 검사와 이번 신규 가입 수신자 연결 검사에서 재확인했다. HTTPS 주소를 사용하는 운영 환경의 장애로 단정하지 않는다.
해결·확인: 승인된 HTTPS 웹 주소와 빌드 설정을 맞춘 뒤 다른 기기 수신까지 확인. 이번에는 배포하지 않았다.

E02 / P1·P2 / 로컬 Google 로그인 사용 불가
실제 로컬 로그인 화면에서 Google 버튼 비활성 확인(gap-probes.json). 로컬 검사 서버는 Google 공급자 설정 없이 실행한다. 이메일 가입·로그인은 가능하다.
실제 Google 계정의 로그인·동의·취소·복귀는 미검증이며 운영 Google 로그인 고장으로 집계하지 않는다.

5. 결함으로 확정하지 않은 후보와 남은 검증

C01 / P1 / 게스트 서버 세션 만료 후 외부 검색 복구
useTripStore.ts:50–54는 저장된 기기 프로필이 있으면 guestSession 호출을 건너뛴다. AuthBridge는 기기 게스트를 복원하지만 workspace/service.ts:45–61의 장소·항공 검색은 서버 인증을 요구한다.
예상 영향: 기기 여행은 열려도 장소·항공 조회가 인증 오류로 막히고 게스트 재시작으로 회복되지 않을 수 있다. 이번에 만료 세션의 실제 UI를 재현하지 않았으므로 확정 결함 수에 포함하지 않는다.
후속 시나리오: 게스트 여행 저장 → 서버 세션만 만료/철회 → 앱 재실행 → 장소·항공 조회 → 재시도/게스트 재진입 → 서버 세션 재발급과 기존 기기 기록 보존 확인.

미검증: 검색·스토어 유입/설치, 실제 Google 로그인, HTTPS의 실제 메시지 전송·공유 취소·수신, Android/iOS의 앱 링크·키보드·안전 영역·강제 종료·촬영 권한, 실제 OCR 표본. 미검증은 실패와 구분한다.
장소·항공 공급자 설정이 없는 조건의 실패는 수동 입력과 별도 판정한다. 장소 검색이나 항공 조회 전체가 미구현이라고 분류하지 않는다.

6. 이번 실행 결과와 변경 범위
기존 기본 경로: 실제 로컬 서버·DB 연속 검사 2개, 통제 화면 분기 12개, 공유 계약 6개 통과 결과 유지. 같은 코드의 동일 경로를 불필요하게 반복하지 않았다.
추가 정상 검사: 공개 링크 → 별도 신규 가입 → 프로필 설정 → 원래 공개 여행 → 담기·수정·공개 중단 뒤 사본 조회 연속 검사 1개 통과. outputs/persona-gaps/new-recipient.log.
추가 결함 재현: 설정 중 링크 재진입 검사 1개 실패(G01). 기대 URL을 홈으로 바꾸거나 제품을 수정하지 않았다.
추가 점검: 복구 버튼 부재·로컬 Google 비활성 UI 확인, 공유 거절 조건에서 복사 대안 미실행 확인. outputs/persona-gaps/gap-probes.json.
문서 검증: npm run check:docs, 변경 HTML의 Prettier 검사, git diff --check 통과. 최초 문서 검사는 임시 심볼릭 링크 생성 권한으로 실패했으며 허용된 실행 환경에서 재실행해 통과했다. 흐름도 390/1180px의 가로 넘침·문서 링크·접기 동작 검사 통과. 앱 코드·저장소 테스트를 이번에 바꾸지 않아 전체 npm run check는 직전 통과 결과를 유지하며 재실행하지 않았다.
분석·검토 담당은 신규 예외 경로를 각각 최초 1회 읽기 전용 조사. 주 에이전트가 G01과 G03을 직접 실행해 확인. 추가 재검토 없음, 동시 최대 3명 준수.
이번에는 앱 코드·디자인·공통 규격을 변경하지 않았다. 기존 테스트 수정분은 보존했고 추가 재현 스크립트·캡처는 outputs/persona-gaps에 저장했다. 문서와 흐름도에 발견 내용을 추가했다. 커밋·푸시·배포 없음.
