1. 검토 기준
파일 이름과 줄 수만 바꾸지 않고, 기능 처리·표현·예외·정책의 실제 책임을 확인했다.
검토 우선순위는 저장 결과와 요청 키 보존, 인증·계정 경계, 원문 노출, 요청 제한 시간,
미사용 코드, 조회/표현 의존성, 디자인 값의 중복 순서다.
정적 검사는 실행 import와 타입 전용 import를 구분한다. 환경 변수·키 값은 읽지 않았다.
구조 검사 위반0건은 등록한 계층 규칙을 통과했다는 뜻이다. 모든 함수의 책임·예외·성능을 자동으로 증명하는 결과는 아니다.

2. 우선 수정한 결함
P0 요청 제한 시간 회귀
  이전 자원 관리에서 기본15초 취소 신호를 합치면서, 영수증 인식에 지정한75초도15초로 짧아질 수 있었다.
  FoundationRequestInit.timeoutMs를 도입해 기본/업로드/인식을 requestPolicy의15000/30000/75000ms로 구분했다.
  timeoutMs는 fetch 옵션에서 제거하고 취소 신호와 결합한다. 실제 OCR 클라이언트의 전송 옵션을 검사해75000만 적용됨을 확인했다.
  실제75초 대기나 Vision 서버 부하 검사는 아니다. 명시적 화면 취소가 긴 작업에도 전달되는 검사도 통과했다.

P1 결과 미확인 기록의 재시도 요청 해제
  기록 편집에서 모든500 미만 응답을 저장 거부로 보고 원래 요청을 버릴 수 있었다.
  이제 확인된 입력 거부와 VERSION_CONFLICT만 새 작성으로 복구한다.408·요청 키 충돌·파손된 성공 응답·응답 유실은 기존 본문과 키를 유지한다.
  409 전체를 ‘동행이 변경했다’고 안내하던 분기도 정확한 VERSION_CONFLICT 코드로 구분했다.

P1 출처 불명의 한국어 예외 노출
  Error.message에 한글이 있다는 이유만으로 그대로 표시하던 처리를 제거했다.
  검토한 클라이언트 안내는 UserFacingError로 구분하고, 일반 오류·서버/SDK 원문은 고정된 복구 안내로 변환한다.
  로그인·인증 콜백·프로필·기기 여행기록에도 같은 userFacingMessage 정책을 적용했다. 알려진 로컬 안내와 클라이언트 Zod 입력 오류는 보존했다.
  SQL·토큰·파일 경로가 섞인 한국어 오류가 표시되지 않는 검사와 기존 안전한 사진/기기 저장 안내 보존 검사를 통과했다.
  회원 전환은 JSON 전체의 부분 문자열이 아닌 error.code의 정확한 값으로 판단한다. 순환 객체를 문자열로 펼치지도 않는다.

P1 제품 라우트에 남아 있던 미사용 프로토타입
  (tabs)/index.tsx와 trips/[id].tsx는 실제 화면을 기본 export하면서 예전 화면을 named export로 함께 보관했다.
  사용하지 않는 날짜·도시·상태 분기·색상 팔레트가 남아 있었다. 두 라우트는 실제 WorkspaceScreen 연결만 유지했다.
  두 프로토타입만 사용하던 QuickAddModal.tsx도 호출처를 확인한 뒤 제거했다. 실제 ScheduleEditor는 유지한다.
  변경 전 소스는 outputs/cto-review-20261019/before-refactor.zip에 보관했다.

4. 예외 처리 기준과 보존한 계약
저장 성공과 후속 재조회 실패를 구분하고, 실패한 저장을 성공한 것처럼 표시하지 않는다.
화면의 조회 취소를 이미 전송한 쓰기 요청의 취소로 바꾸지 않는다. 계정 변경 이후 결과 적용 보호는 유지한다.
확인되지 않은 요청의 키·본문·버전을 유지하며, 버전 충돌은 실제 코드로 판단한다.
입력 오류·로그인 만료·권한 상실·일시 통신 실패의 경계를 유지한다. 고객 화면에 내부 SQL·세션·서버 원문을 출력하지 않는다.
기록 재조회에서 동일한 캐시 값을 두 번 쓰던 중복도 제거했다. 영수증 오류 초안 생성의 불필요한 두 번째 UUID 생성도 제거했다.
기존 캐시/임시 파일 정리·로그아웃·OS 설정·위치 구독의 예외까지 일괄 재던지거나 무조건 무시하는 공통 catch를 만들지 않았다.
네이티브 파일 정리 실패와 실제 사진 재시도 전체는 실기기 인수에서 추가 확인한다.
