# 항공편 조회와 자동 입력

- 작성일: 2026-10-14
- 버전: 1.3.0
- 기본 공급자: 한국공항공사 공공데이터 API.
- 상태: 등록된 키로 실제 공급자와 서버 변환 함수 조회 확인. 실제 응답에 맞춰 화면 수정.
- 범위: 여행 생성의 출발편·도착편·추가편, 선택한 DAY의 추가 항공편. 공급자가 제공한 정보만 자동 입력.

## 사용자 흐름

2026-10-15 여행 생성은 항공편 목록과 항공권 입력으로 분리했다. 항공사를 코드로 선택한 뒤 번호와 출발일로 조회하고 완료를 눌러 목록에 반영한다. 기본 출발편·도착편과 추가 구간의 흐름, 단일 조회 결과의 임시 선택, 도시 생략과 새 저장 계약은 [여행 생성 흐름 개편](<../../01. 서비스기획/02. 사용자흐름/여행생성_사용자흐름.md>)을 따른다. 이 화면에는 별도 직접 입력하기가 없다. 아래의 상세 직접 수정 흐름은 기존 일정 추가·수정 화면에 해당한다.

기존 화면에는 운항 조회 기능이 없어 공항 코드와 시각까지 사용자가 입력해야 했다. 이제 편명을 넣고 항공편 찾기를 누르면 선택한 출발일의 구간을 확인할 수 있다. 같은 구간을 선택하면 조회값을 한 번에 채우고 요약 카드를 표시한다. 입력칸은 항공편 정보 수정을 선택할 때만 펼친다. 결과 선택과 실제 여행·일정 저장은 별개다.

여행 생성은 시작일, 일정 추가는 선택한 DAY를 출발일로 사용한다. 타이핑할 때마다 조회하지 않으며 다구간 결과의 첫 항목을 임의로 확정하지 않는다. 날짜·편명·계정이 바뀌거나 화면을 닫으면 이전 요청을 취소한다. 실패해도 작성한 내용은 유지하고 직접 입력할 수 있다. 출발 공항을 인천으로 자동 지정하지 않는다.

## 현재 기본 API에서 채우는 정보

| 항목                     | 한국공항공사 API 처리                                                                                 |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| 편명·출도착 공항         | 요청 편명과 출발일, 관할 출발 공항의 이름·코드가 일치하는 출발 행만 적용                              |
| 출발 시각                | 해당 한국 출발 공항의 예정 계획시각 std. 실제시각 etd로 대체하지 않음                                 |
| 기종·항공기 등록번호     | 제공된 경우만 입력·저장. 기종을 좌석 등급이나 수하물 조건으로 해석하지 않음                           |
| 게이트                   | 조회 후보 확인용으로 표시. 터미널로 저장하지 않음                                                     |
| 도착시각·도착일·소요시간 | 국내선의 같은 운항편 출발·도착 기록이 유일하게 확인될 때만 결합. 해외 구간·모호한 기록은 비워 둠      |
| 터미널                   | 응답에 없어 비워 둠. 게이트를 터미널로 사용하지 않음                                                  |
| 운항 상태·실제 출발      | 후보에서 조회 당시 정보로 구분 표시. 선택 후 일정의 예정시각을 덮어쓰거나 실시간 상태로 저장하지 않음 |
| 수하물·좌석 등급         | 예약 조건이므로 자동 추정하지 않음. 동일 구간의 기존 사용자 입력만 보존                               |

[공식 등록 정보](https://www.data.go.kr/data/15158519/openapi.do)의 관할 공항 안내와 별개로 실제 응답에서 인천↔김해 연결편도 확인했다. 인천 출발 전체를 제외하지 않으며 인천 국제선 전체를 제공한다고도 안내하지 않는다. 해외 출발·국내 도착 행의 도착일을 출발일로 복사하지 않는다. RS901은 10월 13~16일 조회됐고 11월 1일은 정상 빈 결과였다. 결과 없음은 운항 없음의 확정이 아니다.

가이드의 city/airport 표 설명과 실제 출발 예시가 서로 달라 출발 공항 이름까지 검증한다. 실제 키로 airport=기준 공항, city=상대 공항임을 확인했다. 필드별 결과와 국내선 결합 조건은 [실제 조회 분석](항공편_실제데이터분석.md)을 따른다.

## 사용자가 입력할 인증키

별도 RapidAPI 가입이나 유료 구독은 필요하지 않다. 공공데이터포털에서 해당 API 활용신청을 승인받고 일반 인증키를 사용한다. 서버 비밀 이름은 KAC_FLIGHT_SERVICE_KEY다. 사용자가 입력할 로컬 파일은 apps/api/.dev.vars이며 따옴표 안에 키를 입력한다. 이 파일은 Git에서 제외된다.

```dotenv
KAC_FLIGHT_SERVICE_KEY=""
FLIGHT_LOOKUP_PROVIDER="kac"
```

이 파일을 채우는 것은 로컬 개발 설정이다. 원격 Worker에 자동 등록되지는 않는다. 스테이징 키 등록은 apps/api에서 아래 명령을 실행하고 입력창에 키를 넣는다. 키를 채팅·공개 환경 변수·문서·Git에 넣지 않는다.

```powershell
npx wrangler secret put KAC_FLIGHT_SERVICE_KEY --env staging
```

사용자가 등록한 로컬 키로 실제 공급자와 서버 변환 함수의 성공 응답을 확인했다. 원격 비밀 등록·배포·원격 앱 세션 조회는 확인하지 않았다. API 주소만으로는 인증된 조회가 되지 않는다.

## 공급자 선택과 비용

기본 공급자는 kac이며 공공데이터 실패 시 유료 공급자를 자동 호출하지 않는다. 기존 AeroDataBox 어댑터는 선택형으로 유지한다. 이를 사용하려면 FLIGHT_LOOKUP_PROVIDER=aerodatabox를 명시하고 AERODATABOX_RAPIDAPI_KEY를 따로 등록해야 한다. Direct/API.Market 키와 RapidAPI 키는 호환된다고 가정하지 않는다.

공공데이터 등록 페이지는 무료와 개발계정 트래픽 5,000을 안내한다. 앱 조회 한 번은 최대 세 페이지를 읽으므로 공급자 호출 횟수와 다르다. 실제 계정의 할당량과 운영계정 조건은 활성화할 때 확인한다. 기존 유료 어댑터의 구독·사용 조건은 해당 공급자를 선택할 때만 검토한다.

## 서버와 저장 계약

앱 요청은 GET /api/v1/flights/lookup?number=ZE781A&date=2026-08-11이다. 기존 세션 인증과 사용자별 분당 6회 제한을 통과한 뒤 조회한다. 이 제한은 Cloudflare 위치별 근사 제한이며 계정 전체의 월 비용 상한은 아니다.

실제 공급자 주소는 https://apis.data.go.kr/B551178/flight-aircraft-status/info다. 일반 인증키는 URL 파라미터 serviceKey로 서버에서만 전달한다. 편명과 날짜 범위, 페이지, JSON 형식만 지정하고 사용자 토큰·예약번호·여권·여행 원본은 보내지 않는다. 인코딩/디코딩 키의 + / = 문자를 보존해 이중 인코딩을 피한다. 키가 포함되는 공급자 URL과 외부 오류 원문을 출력하지 않는다.

공공데이터 조회는 전체 8초, 한 페이지 100행과 256KiB, 최대 세 페이지로 제한한다. HTTP 200 안의 오류 헤더와 JSON 요청에 반환되는 XML 게이트웨이 오류도 확인한다. 22/23 및 HTTP 429는 FLIGHT_RATE_LIMITED, 인증·형식·본문 상한·설정 오류는 FLIGHT_UNAVAILABLE로 처리한다. 정상 빈 목록과 오류를 구분한다.

조회 응답은 후보 배열, 실제 출처, 조회시각, 선택 안내문으로 구성한다. 후보를 서버 DB나 공용 캐시에 저장하지 않는다. 사용자가 선택·저장한 항공편에만 기종과 등록번호를 추가한다. 기존 D1 trips.snapshot과 기기 guestWorkspace JSON을 사용하며 SQL 테이블이나 물리 컬럼은 추가하지 않는다. 공개 커뮤니티로 항공편 상세를 새로 노출하지 않는다. 상세 계약은 docs/03. 개발/02. 데이터정의/DB_객체사전.txt를 따른다.

## 검증과 배포 준비

실제 응답을 반영한 기획 자체 검토를 통과했다. 서버 93/93, 폼·저장 79/79, 브라우저 전체 56/56, Worker dry-run과 Android Hermes 번들 생성을 통과했다. 360/390/430 폭에서 선택 버튼 가림도 확인했다. 최신 로그·캡처와 원격 배포 미수행 범위는 [실제 조회 분석](항공편_실제데이터분석.md)을 따른다. 초기 연결 준비의 검증 이력은 [API 검토](항공편_API검토.md)에 보관한다.

검증용 항공편은 외부 HTTP 경계에서만 사용하며 운영 데이터로 넣지 않는다. 실제 인증키 성공 응답과 Android 실기기 인수는 자동 검증으로 대신하지 않는다.

이전 .release/schedule-v5와 .release/flight-lookup 산출물은 이번 공공데이터 변경 이전 파일이다. 이번 연결을 포함한다고 보고하지 않는다. 키 등록이나 코드 연결만으로 서명 APK/AAB 생성, Play 업로드, 운영 배포가 끝났다고 판단하지 않는다.
