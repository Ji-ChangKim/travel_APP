# 입력 정책 검수

프로필과 도시 검색에서 한글을 입력할 수 없는 문제를 우선 확인한다. 입력 제한은 문서의 유무, 앱·서버 적용 여부, 실제 검증 결과를 구분한다. 이 문서는 현재 진행 상태를 관리하며, 검증하지 않은 항목을 완료로 표시하지 않는다.

여기서 NFC는 분해형 한글을 같은 완성형으로 맞추는 처리다. 예를 들어 `하`는 처리 후 `하` 한 글자로 센다. 코드 포인트는 유니코드 문자값 단위이며, JavaScript의 일반 문자열 길이(UTF-16)와 다를 수 있다.

## 범위와 기준

- 기준 버전: `db0dc16`과 현재 공유 작업 트리. 다른 작업의 화면·문서·DB 이관 변경은 보존한다.
- 참조: [디자인 시스템](<../../02. 디자인/00. 공통규격/디자인시스템.md>), [로그인·프로필 규격](<../../02. 디자인/01. 화면설계/로그인_프로필생성_규격.md>), [MVP 기능 규격](<../../01. 서비스기획/01. 기능정의/MVP_기능규격.md>).
- 수정 범위: 공통 Android 입력의 한글 조합·커서 보존, 닉네임 오류 표시·재입력 복구, 웹 한글 조합 취소, 에뮬레이터 키보드 설정. 화면 배치·색상·글꼴 파일은 변경하지 않는다.
- DB 테이블·컬럼·저장 형식은 변경하지 않는다. 기존 닉네임 저장 제한과 기존 값 보존 예외도 유지한다.

## 구현과 확인 근거

- `packages/validation/src/profile.ts`: 앱·서버가 같은 오류 이유를 사용한다. 기존 닉네임과 원문이 같을 때만 예외를 유지하며 신규 가입에는 적용하지 않는다.
- `ProfileFields.tsx`, `ProfileEditor.tsx`, `profileEditorActions.ts`, `useMyAccountController.ts`: 입력 중 오류를 숨기고 초점 이동·명시적 저장 때 확인한다. 잘못된 입력을 보존하고 재입력 시 이전 제출 오류를 지운다.
- `webModalAccessibility.ts`: 조합 중 keydown을 기억해 compositionend 이후 Escape keyup도 조합 취소로 처리한다. 일반 Escape의 기존 닫기 동작은 유지한다.
- `DesignInput.tsx`, `AndroidTextInput.tsx`: Android에서는 네이티브 편집 원문을 매 입력마다 다시 덮어쓰지 않는다. 입력 중인 값은 부모 상태로 전달하고, 외부 변경·지우기·정규화처럼 실제로 다른 값만 명시적으로 적용한다. 웹·iOS는 기존 입력 경로를 사용한다. [React Native TextInput 문서](https://reactnative.dev/docs/textinput.html)의 value·defaultValue 계약과 저장소에 설치된 구현을 대조했다.
- `tests/web/workspace.spec.ts`, `tests/config/playwright.input.config.ts`: 실제 웹 앱에서 CDP IME 경로·프로필 재진입·검색 결과·글꼴 실패를 검사한다. HTTP 응답은 대역이므로 실제 서버 저장 검증과 구분한다.
- `tests/web/android-input.spec.ts`, `tests/fixtures/androidInputHarness.tsx`, `tests/fixtures/nativeInputStub.tsx`: 실제 React 렌더링에서 네이티브 어댑터의 외부 값 변경·거부·초기화·정규화 명령을 검사한다. 네이티브 명령은 대역이며 실제 IME 증거는 아래 Android 조작 결과로 구분한다.
- `apps/api/test/profile-onboarding.test.ts`: 실제 격리 D1에서 1/2/10/11자·공백·이모지·자모·NFD 저장과 기존 이름 예외를 API로 검사하고 재조회한다. 인증 공급자는 검사 경계로 대체한다.

## 검토 기록

- **INPUT-POLICY-01 / 주요 입력 계약 / 최초 0회**: 읽기 전용 분석으로 소개 80/300자, 메모 300/1,000자, 금액 0원, 검색 제한의 정책 차이를 확인했다. 수치 변경은 보류했다.
- **INPUT-IME-01 / 공통 입력·웹 모달 / 최초 0회**: 입력값을 지우는 공통 경로는 찾지 못했다. 조합 Escape 문제를 발견해 실제 웹에서 재현했다.
- **INPUT-IME-01·INPUT-NICKNAME-01 / 오류 표시 수정 / 재검토 1회**: 입력 초점을 유지한 저장에서 오류가 숨겨질 수 있음을 발견했다. 명시적 저장 오류 표시와 해당 조건의 웹 검사를 추가했다. 검토 의견만으로 실제 검증을 대체하지 않는다.
- **INPUT-NICKNAME-01 / 오류 표시 수정 / 재검토 2회**: 추가 필수 결함 없음. Android 전용 입력 어댑터는 이 검토 이후 추가된 변경이며, 주 담당이 기본 Android 입력과 비교하고 같은 조작을 재검증했다. 검토 횟수를 초기화하거나 추가 재검토를 요청하지 않았다.

로컬 Metro와 API는 에뮬레이터 확인을 위해 실행 중이다. 운영 배포·운영 DB 변경·실제 소셜 인증·유료 장소/OCR API 호출은 수행하지 않았다. iOS·실제 휴대폰과 미조사 입력의 검증은 미완료다. 전체 API 실패 20건과 미확정 수치 정책이 남아 있으므로 전체 기능 검수를 완료로 판단하지 않는다.
