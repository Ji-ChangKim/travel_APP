# 앱 기본 구조 구현 검수

## 결과와 범위

앱 실행·로그인·기본 프로필·홈·커뮤니티·MY를 하나의 이용 흐름으로 정리했다. 추가 개인정보 입력 없이 홈으로 들어가고, 커뮤니티와 MY를 오간 뒤 설정에서 로그아웃·재로그인하는 로컬 실제 서버 검수를 통과했다. 계정 관리의 옛 90일 유예 안내와 닫힌 요청도 현행 삭제 정책에 맞췄다.

여행 제작·일정 편집 화면, 게스트 서버 저장·재조회, 영수증 저장 분기는 이번 구현 범위에서 제외했다. 홈에서 기존 여행 제작으로 들어가는 진입점만 유지했다. 기본 구조의 로컬 검수 통과를 실제 Google 외부 인증·실기기 인수·운영 배포 완료로 확대하지 않는다.

- 대상: `main`, 기준 HEAD `d92abb9cfd640fd84a8aa5eb3aeceaec99ad7eb0`와 현재 변경 파일.
- 환경: Windows, Node.js 22.17.0, npm 11.5.2, Chrome, 실제 Worker·격리 D1/R2, 전용 웹 8920/API 8921.
- 문서 기준: [앱 기본 구조 화면 규격](<../../02. 디자인/01. 화면설계/앱기본구조_화면규격.md>), [디자인 시스템](<../../02. 디자인/00. 공통규격/디자인시스템.md>), [단일 토큰](<../../02. 디자인/00. 공통규격/design-tokens.json>), [헤더·GNB](<../../02. 디자인/00. 공통규격/헤더GNB_규격.md>), [앱·서버 API 계약](<../01. API계약/앱서버_API계약.md>).
- 보존: 사용자가 수정한 `사용자_탐색흐름.md`와 사용자 흐름 이미지 3개. 덮어쓰기·이동·커밋·배포하지 않았다.

게스트는 현재 기기 기록 모드라는 실제 범위를 표시한다. 사용자가 확정한 게스트 서버 저장 요구는 후속 필수 작업이며 완료 표시하지 않았다. 모든 비게스트를 Google 회원이라고 추정하지 않고 기본 프로필 및 서버가 확인한 계정 종류를 사용한다.

## 디자인 대조와 실제 캡처

기존 브랜드·LINE Seed·색상 토큰·20px 화면 여백·640px 최대 폭·48px 최소 터치 영역과 공통 버튼·헤더·4탭 GNB를 유지했다. 공통 문서에 남아 있던 이전 색상·타입 수치·탭 이름·주소는 실제 토큰과 구현에 맞췄다. 공통 코드와 토큰 값을 새 디자인으로 바꾼 작업은 아니다.

320·390·430px와 글자 200%의 실제 화면을 캡처해 대조했다. MY의 입력 버튼 제거와 기본 이미지, 계정 관리의 삭제 대상 구분, 커뮤니티의 빈 화면·오류·공개 상세를 확인했다. 320px 큰 글꼴에서 설정의 계정 표시가 지나치게 좁아진 부분은 세로 배치로 보완했다. GNB의 큰 글꼴 줄바꿈은 기존 확장 규칙을 따른다. 가로 넘침을 막으려고 공통 헤더·글꼴을 줄이지 않았다.

증거는 `outputs/app-shell/`에 있다. `index.html`에서 기본 화면 6개를 함께 볼 수 있다. 실제 화면이며 설명용 스케치가 아니다. `source-manifest.json`은 검수한 변경 파일의 해시를 기록한다.

| 검사                         | 결과       | 증거                                                                                                              |
| ---------------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------- |

| 배포                         | 해당 없음  | 로컬 구현·dry-run만 수행                                                                                          |

헤더 검사 초기 실행은 과거 버튼 경로와 프로필 편집 기대 때문에 멈췄다. 현행 조작으로 갱신하고, 탐색 이력에 숨겨진 화면을 현재 화면과 함께 찾던 선택자를 바로잡았다. 새로 추가했던 사진 배경 검사는 단색 배경을 전제로 한 도구의 적용 범위를 벗어나 기존 위치로 되돌렸다. 기존 대비·최소 터치 영역·줄바꿈·이탈 보호 기준과 22개 검사 수는 유지했다. 마지막 실행에서 22개 모두 통과했다. 전체 과거 여행 편집 검사 묶음을 실행한 결과는 아니다.

분석·검토 담당은 읽기만 수행했고 계정 구현 담당은 소유 파일만 수정했다. 주 에이전트가 합친 코드·실제 동작·검사·캡처를 확인했다. 같은 쟁점의 재검토 2회는 사용하지 않았다. 헤더 검사 갱신은 테스트 유지보수이며 제품 검토 횟수를 초기화하는 근거가 아니다.

후속 순서는 실제 Google·실기기 인수 → 게스트 서버 저장·재조회 → 여행 제작·장소·영수증 작업이다. 실제 약관·개인정보 문서 페이지는 현재 없으므로 문서와 게시 주소를 준비해야 한다. 작동하지 않는 링크는 추가하지 않았다. 외부 검수 계정·기기와 배포 환경이 준비되면 같은 기본 흐름으로 이어서 검사한다.
