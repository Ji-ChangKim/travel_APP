# 웹 개발 실행 안내

독립 웹의 개발 서버·빌드·검사 환경을 준비하는 `0.0.1` 기준이다. 소개 랜딩·공통 모듈을 포함하며 누구나 같은 명령으로 실행하고 검사할 수 있게 한다. Android·WEB 1.0.0 목표와 웹 게스트 금지는 그대로 유지한다.

## 1. 준비 범위와 다음 단계

| 구분 | 현재 범위                                                     | 다음 작업                                       |
| ---- | ------------------------------------------------------------- | ----------------------------------------------- |
| 실행 | Next.js 16.4.6 App Router, 개발·빌드·빌드 후 실행             | 실제 페이지·오류·로딩 구성                      |
| 품질 | 웹 전용 엄격 타입·ESLint, 루트 통합 검사, 직접 의존 경계 검사 | 공통 UI·이동·간접 서버 의존 검사                |
| 검수 | 개발·빌드 후 HTTP 응답 및 프로세스·포트 정리                  | 로그인·실제 API 저장·폭별 화면·실기기           |
| 배포 | 기존 배포 유지, CI에 웹 빌드·HTTP 검사 추가                   | Linux CI 실행 결과, Workers 실행 계층·배포 검증 |

소개 랜딩 `/`을 제공한다. 서비스 홈 `/home`은 화면·기능 설계까지이며 아직 구현하지 않는다. `/health`는 서버가 응답하는지만 확인한다. 이 결과로 DB 연결·회원 로그인·기기 간 동기화가 정상이라고 판단하지 않는다. 랜딩은 200, `/home`은 404로 응답한다. 가짜 로그인이나 예시 여행 데이터는 없다.

## 2. 처음 실행하기

저장소 루트 `J:\002. Project_Service\travel_APP`에서 실행한다. Node.js는 `.nvmrc`의 22.17.0, npm은 `packageManager`의 11.5.2를 따른다. React·Expo·TypeScript 버전은 기존 앱과 맞춘다. Python·Docker·WSL을 새 필수 조건으로 추가하지 않는다.

```powershell
npm ci
npm run web:dev
```

브라우저에서 `http://127.0.0.1:3000/health`를 연다. `service: tripprint-web`, `status: ok`가 나오면 개발 서버가 응답한 것이다. 종료는 실행 창에서 `Ctrl+C`를 누른다. 다른 포트가 필요하면 Windows PowerShell에서 `npm.cmd run web:dev -- --port 3001`을 사용한다.

의존성은 루트 `package-lock.json` 하나로 관리한다. `apps/web` 안에 잠금 파일을 따로 만들지 않는다. `.next`, `next-env.d.ts`, 타입 검사 캐시·로컬 검수 결과는 Git에 넣지 않는다. 생성 타입은 `web:typecheck`에서 다시 만든다. 현재 웹 실행에는 별도 키나 환경 변수 설정이 필요 없다. 랜딩은 `http://127.0.0.1:3000/`에서 연다.

## 3. 명령과 성공 기준

| 명령                       | 목적                                       | 성공 기준                                |
| -------------------------- | ------------------------------------------ | ---------------------------------------- |
| `npm run web:dev`          | 개발 서버 실행                             | 기본 127.0.0.1:3000에서 HTTP 응답        |
| `npm run web:build`        | 배포 전 로컬 빌드                          | Next 빌드 종료 코드 0                    |
| `npm run web:start`        | 위 빌드 실행                               | `/health` 200 응답                       |
| `npm run web:typecheck`    | 경로 타입 생성·웹 엄격 타입 검사           | 종료 코드 0                              |
| `npm run web:lint`         | 웹 전용 코드 규칙 검사                     | 오류·경고 0                              |
| `npm run check`            | 앱·웹·문서·전체 규칙 통합 검사             | 모든 하위 검사 통과                      |
| `npm run test:release`     | 기존 출시 설정·웹 경계·검수 실패 복구 검사 | 모든 테스트 통과                         |
| `npm run test:web:dev`     | 실제 개발 서버 자동 검사                   | HTTP 확인·서버 종료·포트 해제            |
| `npm run test:web:runtime` | 실제 빌드 후 서버 자동 검사                | 먼저 빌드, HTTP 확인·서버 종료·포트 해제 |

자동 HTTP 검사는 `GET /health` 200·정해진 JSON·캐시 금지·프레임워크 정보 헤더 제거, `POST /health` 405, `/` 200과 소개 본문, `/home` 404를 확인한다. 검사마다 빈 임시 포트를 사용한다. 결과는 `outputs/development-preparation/web-development.json`, `web-production.json`에 남긴다. 검사 실패와 서버 정리 실패는 각각 보존한다.

같은 `.next`를 사용하는 개발 서버·타입 생성·빌드는 순서대로 실행한다. 기존 `npm run web`, `mobile:web`, `build:web`은 Expo 앱용이다. 새 웹 명령과 서로 바꾸지 않는다.

## 4. 폴더와 경계

| 경로                                   | 책임                              |
| -------------------------------------- | --------------------------------- |
| `apps/web/src/app/layout.tsx`          | 웹 문서 기본 구조·검색 노출 제한  |
| `apps/web/src/app/health/route.ts`     | 서버 응답 확인 전용 GET           |
| `apps/web/tsconfig.json`               | Next 전용 타입·웹 내부 별칭 `@/*` |
| `apps/web/eslint.config.mjs`           | Next·TypeScript 코드 규칙         |
| `scripts/build/run-web.mjs`            | 루트 위치와 무관하게 웹 도구 실행 |
| `scripts/qa/verify-web-foundation.mjs` | 실제 HTTP 검사와 검사 서버 정리   |

앱의 Expo 타입·`@/*` 별칭은 유지하고, 웹은 자체 설정으로 검사한다. 루트 `typecheck`·`lint`가 웹 검사를 반드시 이어서 실행한다. `check:architecture`는 웹의 앱·API 내부 소스 참조와 클라이언트의 `src/server` 직접 참조를 차단한다. 문자열 동적 import·실행 재내보내기도 검사하고 타입 전용 참조는 제외한다. 계산된 경로와 중간 모듈까지 추적하는 보장은 없다. 실제 서버 전용 기능을 넣기 전에 `server-only` 표식 또는 의존성 추적과 빌드 실패 검증을 연결한다.

현재 랜딩·웹 공통 UI 모듈을 제공한다. 앱 공통 UI 패키지 추출과 서비스 홈 구현은 후속이다. 후속 UI 작업 전 현행 디자인 문서를 읽고 공통 헤더·GNB의 실행 호환·이동 검사를 확장한다. `apps/mobile/src` 내부 코드를 가져오거나 헤더를 복제해서 해결하지 않는다. API·DB·도메인은 변경하지 않아 객체 사전 변경은 없다.

## 5. 실행이 안 될 때

| 증상                              | 확인·다음 행동                                                                              |
| --------------------------------- | ------------------------------------------------------------------------------------------- |
| 명령을 찾지 못함                  | 저장소 루트인지, 지정된 Node·npm으로 `npm ci`를 마쳤는지 확인                               |
| 포트 사용 중                      | 기존 개발 서버를 종료하거나 `--port 3001`로 실행. 다른 작업의 프로세스를 일괄 종료하지 않음 |
| 빌드가 없다는 안내                | 개발 서버 종료 후 `npm run web:build`, 이어서 `npm run web:start` 실행                      |
| `/home` 404                       | 현재 기대 결과. 서비스 홈은 로그인·API와 함께 별도 구현                                     |
| 경로 접근·자식 프로세스 실행 거부 | 현재 실행 환경의 권한 제한 확인. 검사를 생략하거나 성공으로 기록하지 않음                   |
| 서버는 응답하나 로그인 불가       | 로그인은 후속 작업. `/health`로 로그인 상태를 판단하지 않음                                 |

CI 파일에 검사 단계를 넣은 것과 GitHub에서 실제 통과한 것은 구분한다. 이 준비 단계의 로컬 Node 실행 결과는 Cloudflare Workers·운영 배포 결과를 대신하지 않는다. 다음 단계는 [정식 출시 계획](<../../01. 서비스기획/03. 작업계획/앱웹_정식출시_계획서.md>)의 0.1 기반 확정이며 서비스 홈 구현은 공통 UI·인증·이동 조건을 확인한 뒤 진행한다.
