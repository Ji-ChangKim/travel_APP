`supabase/migrations`는 서버의 기존 PostgreSQL 계약 검사에서도 사용한다. 과거 시스템 자료라는 이유로 임의 삭제하거나 옮기지 않는다. 루트 `assets/EXPO-LICENSE.txt`와 승인된 브랜드 자산의 원래 이름도 출처 식별을 위해 유지한다.

`apps/mobile/package.json`의 `main`은 `index.ts`이며 루트 `package.json`도 같은 `apps/mobile/index.ts`를 가리킨다. 이 파일은 웹의 입력 보호 이벤트를 먼저 등록하고 마지막에 `expo-router/entry`를 불러온다. Router가 이전 화면의 상태를 먼저 적용해 미저장 입력이 사라지는 것을 막기 위한 초기화 순서다. [Expo의 사용자 지정 진입점 규칙](https://docs.expo.dev/router/installation/)을 따르며 네이티브 경로에서는 DOM 이벤트를 등록하지 않는다. 릴리스 소스 명세에도 이 진입점을 포함해 루트·모바일 빌드와 검수 해시가 같은 파일을 참조하도록 한다.

## 폴더와 파일 이름

리소스의 역할·보존 대상·등록·검사 절차는 [리소스 아키텍처](리소스_아키텍처.md)를 따른다. 리소스 경로·글꼴 명세·공개 이미지 검사는 `npm run check:resources`이며 전체 `npm run check`에도 포함한다.

| 대상                           | 규칙                                                    | 예시                                               |
| ------------------------------ | ------------------------------------------------------- | -------------------------------------------------- |
| 코드 폴더                      | 소문자 kebab-case                                       | `api-client`, `navigation-guard`                   |
| React 화면·컴포넌트            | PascalCase `.tsx`                                       | `TripTimelineView.tsx`                             |
| TypeScript 업무·통신·타입 모듈 | camelCase `.ts`                                         | `receiptAnalysis.ts`, `readBounded.ts`             |
| Hook                           | `use` + PascalCase                                      | `useWorkspaceController.ts`                        |
| Node 도구·선언·Gradle          | kebab-case                                              | `release-source-manifest.mjs`, `app-version.d.cts` |
| Expo 플러그인                  | camelCase `.cjs`                                        | `withAppVersion.cjs`, `gradleScript.cjs`           |
| 브라우저 설정                  | `playwright.시나리오.config.ts`                         | `tests/config/playwright.header.config.ts`         |
| 자동 검사                      | `기능.test.ts`, `기능.test.mjs`, `기능.spec.ts`         | `build-paths.test.mjs`                             |
| 문서                           | [문서 관리 규칙](<../../00. 문서안내/문서_관리규칙.md>) | `YYYY-MM-DD_주제_검수보고.txt`                     |

Expo Router의 `(그룹)`·`[매개변수]`·`_layout.tsx`·`+not-found.tsx`와 플랫폼별 `.web.tsx`·`.native.tsx`는 프레임워크 규칙을 따른다. 자산·SQL 이력·기존 시안의 출처 이름을 코드 이름 규칙으로 일괄 변경하지 않는다.

루트에는 패키지·워크스페이스·Expo·TypeScript·ESLint·Prettier·EAS 등 도구가 찾는 설정을 둔다. 루트 `playwright.config.ts`는 기본 진입점만 제공하며 실제 설정을 `tests/config`에서 가져온다. 화면별 설정을 루트에 추가하지 않는다. 반복 실행에 쓰는 도구는 `scripts`의 역할 폴더에, 일회성 검사 출력은 `outputs`에 둔다.

기존 `scratch`·`output`·`_workspace`는 Git에서 제외된 로컬 작업 영역으로 보존한다. 이 영역은 제품 코드의 타입·린트·서식·EAS 입력에서 제외한다. 새 검수 결과는 `outputs`에 두고, 계속 유지할 도구는 검토 후 `scripts`로 편입한다.

## 의존성 규칙

- 앱 화면은 기존 기능 폴더를 사용한다. 화면·컨트롤러·업무 모델·통신·스타일을 목적에 맞게 나누며 같은 기능을 별도 루트에 복제하지 않는다.
- API 진입점은 기능 라우트를 조립한다. 기능 코드는 해당 기능 폴더에 두고 저장소 처리와 공통 응답 읽기를 분리한다.
- `apps/api/src/shared`는 개별 기능에 의존하지 않는다. 항공·장소·발견 기능이 응답을 읽으려고 영수증 OCR을 가져오지 않게 한다.
- 기능 간 호출은 기존 업무 계약을 따른다. 이번 정리는 DB 스키마·URL·공개 API를 바꾸지 않는다.
- `scripts/shared/repository-paths.cjs`가 저장소 기준 경로와 Android 기본 출력 경로를 제공한다. 호출한 터미널 위치를 저장소 루트로 가정하지 않는다.
- `apps/mobile/plugins/gradleScript.cjs`가 루트·모바일 Expo의 상대 경로를 계산한다. `scripts/android/repository-root.gradle`이 Gradle에서 같은 저장소 기준점을 설정한다.

인증 구독을 먼저 설치하고 최초 복원을 시작하는 순서, 계정이 바뀔 때 캐시를 비우는 순서, 이전 인증 응답을 무시하는 규칙을 유지한다. 팝업은 기존 계층과 전환 모듈을 사용한다. 최상위 창만 닫기·키 입력을 처리하며, 중첩 창을 닫으면 이전 초점을 복원한다.

이 분리 작업은 DB·API·저장 형식·화면 문구·디자인 값·헤더·GNB 정책을 변경하지 않는다. 새 표현 컴포넌트와 컨트롤러도 `scripts/checks/check-code-boundaries.mjs`에서 기존 역할과 같은 경계 규칙으로 검사한다. 프로필 헤더의 부모 여백 예외는 헤더가 옮겨진 `ProfileEditor`에만 적용한다.

장소 사진은 `placePhotoService`가 인증·조회·응답 검증을 맡고, `usePlacePhoto`가 계정별 조회 캐시·취소·재시도를 관리한다. `PlacePhoto`는 사진과 출처, 오류 상태를 표시한다. 비공개 사진을 공개 주소로 대신 조회하지 않으며 취소 신호와 Google 출처 검증을 유지한다.

기기 기록의 편집 수명은 `useTrailController`가 소유한다. 파일 선택이 끝나기 전에 편집창을 닫거나 계정을 바꾸면 선택 결과를 폼에 연결하지 않고 참조 없는 임시 원본만 정리한다. 같은 기기 문서를 읽거나 저장하는 도중 재마운트돼도 `store`의 진행 중 상태를 초기화하지 않는다. 기기 공용 저장 공간 `device-draft` 정책과 저장 형식은 유지한다.

`trailAttachmentReferences`는 원본 정리의 참조 목록을 정한다. 화면에서 문서를 불러오는 중이면 빈 메모리 목록을 삭제 근거로 사용하지 않고 보존 문서를 다시 읽는다. 읽기 실패는 호출자에게 전달해 원본을 보존한다.

| 네이티브 프로젝트        | `apps/mobile/android`           | Expo 생성물, 기존 서명 설정 보존 |
| 검수 결과·경로 이동 명세 | `outputs/architecture-20261023` | 로컬 검수 전용                   |

Android 파일 이름은 기존 `TripPrint_YYMMDD_VerNN.apk`와 `.aab`를 유지한다. `VerNN`은 당일 파일 순번이며 `ver.text`의 Android versionCode와 다르다. 기존 파일을 덮어쓰지 않고, 임시 파일의 최종 이름 변경이 실패하면 파일을 보존하고 실제 오류를 표시한다.

`TRIPPRINT_BUILD_OUTPUT_DIR`가 있으면 그 경로를 사용한다. 상대 경로는 저장소 루트 기준이며 절대 경로도 지원한다. 예전 외부 `travel_APP_bulid` 폴더의 산출물은 옮기거나 삭제하지 않는다.

R8·리소스 축소·업로드 서명·매핑 생성 규칙을 유지한다. 폴더 정리 검수는 실제 AAB 서명 빌드나 Play 설치 검수를 대신하지 않는다.

## 검증과 변경 절차

1. 파일의 책임과 참조를 확인하고 기존 기능 폴더 또는 도구 역할 폴더를 선택한다.
2. 파일을 옮길 때 import·Expo 플러그인·Gradle·npm 명령·CI·문서·검사를 함께 수정한다.
3. `npm run check`로 배치·의존성·문서·타입·린트·서식을 확인한다.
4. 빌드 연결 변경은 `npm run test:release`, 서버 이동은 `npm run test:foundation`과 `npm run test:cloud`로 확인한다.
5. 브라우저 설정 이동은 시나리오 목록 로딩과 실제 로컬 화면 회귀를 확인한다. 웹과 Worker 번들은 원격 배포 없이 검증한다.

자동 검사는 배치 위반과 알려진 의존성 역전을 차단한다. 함수의 책임과 디자인 품질을 파일명이나 길이만으로 승인하지 않는다.
