# 리소스를 어디에 두고 어떻게 확인하나요?

기준일: 2026-10-27. 그림·글꼴의 이름과 내용은 유지하고 역할별 저장 위치와 확인 방법을 정리합니다.

여기서 **리소스**는 앱이 쓰는 그림·아이콘·글꼴 파일입니다. **명세(manifest)**는 파일 이름과 출처를 적은 목록입니다. **해시**는 파일 내용의 지문처럼 쓰는 값으로, 폴더를 옮긴 뒤에도 원본 내용이 같은지 확인할 때 사용합니다.

## 2. 파일을 사용할 때

앱은 기존 정적 `require()`를 유지합니다. Expo가 빌드할 때 파일을 찾을 수 있도록 문자열로 된 경로를 씁니다. 현재 폰트 등록은 `AppFontProvider` 한 곳에서 관리합니다. Bold와 Semibold가 같은 LINE Seed 파일을 읽는 것은 역할별 이름을 연결한 것이며 중복 파일이 아닙니다.

패키지가 제공하는 Ionicons 파일을 앱 폴더로 복사하지 않습니다. 로고·흰 심볼·Android 전경·단색 아이콘은 내용이 같아도 사용하는 곳이 다를 수 있습니다. 해시가 같다는 이유만으로 지우지 않습니다.

아이콘 제작은 사용자가 지정한 도구와 범위에 따릅니다. `icon-generator`는 기존 원본에서 앱 설치 아이콘을 출력합니다. 이번 구조 정리에서는 새 아이콘·이미지를 만들거나 화면 디자인을 바꾸지 않습니다.

## 3. 추가하거나 옮길 때

1. 실행용인지, 디자인 원본인지, 검수 결과인지 정합니다.
2. 출처·이용 조건·원본 이름을 기록합니다. 확인하지 못한 정보는 미확인으로 남깁니다.
3. 앱·Expo 설정·시안·생성 도구의 참조를 함께 바꿉니다.
4. 파일 내용이 그대로라면 기존 크기와 해시가 유지되는지 확인합니다.
5. `npm run check`와 관련 빌드·화면 검사를 실행합니다.

## 4. 자동 검사는 무엇을 확인하나요?

`npm run check:resources`는 앱의 정적 이미지·글꼴 import/require, 선택 영상 폴더, 루트와 모바일의 Expo 설정에 적힌 assets 경로, 글꼴 manifest의 파일·크기·해시·라이선스 존재, 공개 이미지 manifest를 확인합니다. 명세에서 빠진 같은 폴더의 글꼴도 찾습니다. 공개 이미지가 모두 사라져도 명세에 등록된 파일의 누락을 보고합니다.

원격 주소의 이용 가능 여부, 모든 문서 속 이미지, 동적으로 조합한 경로, 실제 기기의 이미지 표시까지 증명하는 검사는 아닙니다. 문서 링크는 `check:docs`, 앱 연결은 빌드와 실제 화면으로 별도 확인합니다. 사용 흔적을 못 찾은 파일을 자동으로 삭제하지 않습니다.

## 5. 이번에 보존한 확인 대상

`Google_G.png`와 `TripPrint_login-hero.png`는 실제 로그인 화면에서 사용하지만 파일별 출처 기록이 충분하지 않습니다. Pretendard Semibold는 기존 저장소 파일의 크기·해시를 등록했으며 원본 다운로드 주소는 확인이 필요합니다. 정상 사용 중인 파일을 삭제하거나 출처를 추측해 채우지 않습니다.

기존 아이콘 명세의 전면 교체 표현은 적용 후보로 정정했습니다. 실제 헤더·GNB·글꼴·화면 규격은 그대로 유지합니다.
