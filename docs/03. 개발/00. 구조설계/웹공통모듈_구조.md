# 웹 공통 모듈 구조

랜딩 `/`은 사이트를 소개하고 서비스 홈 `/home`은 회원의 여행 작업을 연결한다. 현재 구현은 랜딩과 아래 공통 모듈이다. 홈은 [홈페이지 화면 계획](<../../02. 디자인/01. 화면설계/웹홈페이지_화면계획.md>)에 따라 별도로 구현한다.

## 책임과 연결 방향

| 경로                                      | 맡는 일                                         | 의존 경계                                       |
| ----------------------------------------- | ----------------------------------------------- | ----------------------------------------------- |
| `app/page.tsx`                            | 랜딩 진입                                       | 화면 조립 모듈만 연결                           |
| `app/layout.tsx`                          | 글꼴·메타데이터·단일 디자인 변수 공급           | 로그인·여행 업무 로직 없음                      |
| `shared/design-system/designVariables.ts` | 단일 토큰을 CSS 단위로 변환                     | 현행 JSON을 읽고 색상·치수 사본을 만들지 않음   |
| `shared/design-system/primitives.css`     | 공통 컨테이너·버튼·제목·초점                    | 기능 페이지에 의존하지 않음                     |
| `shared/assets/siteAssets.ts`             | 승인한 로고·도시 사진·출처 연결                 | 공개 정적 자산만 재사용, 앱 내부 코드 참조 금지 |
| `shared/navigation/siteNavigation.ts`     | 소개 구간과 랜딩·홈 목적지 이름                 | 홈 주소 선언만으로 구현·권한 보장을 뜻하지 않음 |
| `shared/motion`                           | 스크롤 진행률 계산·읽은 위치·움직임 줄이기 구독 | 계산과 브라우저 연결 분리, 구독·프레임 정리     |
| `components/ui`                           | ActionLink·SectionHeading                       | 실제 링크·본문을 속성으로 받음                  |
| `components/layout`                       | SiteHeader·SiteFooter·좁은 화면 메뉴·출처       | 소개 공통 틀. 앱 HomeHeader·GNB 대체 금지       |
| `components/motion`                       | 사용자의 정지 선택·노출 감지·탭 비활성 처리     | 브라우저 상태만 관리, 개인 자료·저장 없음       |
| `features/landing/model`                  | 세 장면의 문구·이미지 선택                      | 통신·화면 제어 없음                             |
| `features/landing/ui`                     | 소개 장면 조립·장면 선택·랜딩 스타일            | 앱·API 내부 소스 참조 없음                      |

함수는 실제로 다른 이유로 바뀌는 책임만 나눈다. 한 번 전달만 하는 도우미, 빈 서비스·저장소 폴더, 아직 없는 기능의 성공 응답은 만들지 않는다. 공통 모듈은 기능별 화면을 역참조하지 않는다. 업무 모델·검증·API는 기존 `packages`를 재사용한다.

## 디자인과 자산의 단일 원본

색상·글꼴·제목·본문·컨트롤·반경은 현행 [디자인 토큰](<../../02. 디자인/00. 공통규격/design-tokens.json>)을 읽는다. 모션과 소개 구도는 [랜딩 규격](<../../02. 디자인/01. 화면설계/웹랜딩_화면규격.md>)에만 기록한다. 별도 `design-system` 문서 폴더나 같은 로고·사진·글꼴의 복사본을 만들지 않는다.

기존 `apps/mobile/assets`의 공개 로고·사진·글꼴을 Next 빌드에서 재사용한다. 사진 출처도 기존 `credits.json`을 읽어 표시한다. 웹 경계 검사는 공개 미디어·글꼴·메타데이터 형식만 허용하고 앱 TypeScript 코드는 계속 거부한다. 사용자 사진·영수증 원본은 정적 자산 경로에 넣지 않는다. API·DB·도메인은 이번 변경에 포함하지 않는다.

## 헤더·푸터와 홈 인계

랜딩 헤더는 로고·소개 구간, 좁은 화면의 열기·Escape 닫기·초점 복귀를 제공한다. 푸터는 같은 구간·맨 위로·사진 출처를 제공한다. 아직 없는 약관·개인정보·로그인·홈 경로를 버튼으로 노출하지 않는다.

서비스 홈 구현 때는 현행 HomeHeader·ScreenHeader·HeaderAction·GlobalNavigation의 의미와 규격을 공유하는 플랫폼 연결 계층을 먼저 준비한다. 앱의 Expo 이동·기기 상태·네이티브 표현을 Next에서 직접 읽거나 비슷한 헤더를 페이지마다 복제하지 않는다. 앱 `/`와 웹 `/home`의 목적지만 구분하며 탭의 의미·순서·선택 규칙은 유지한다. 실제로 양쪽이 사용하는 공통 계약이 생길 때 `packages/ui` 추출 범위를 확정한다.

## 검증과 운영

필수 검사는 `npm run check`, 웹 빌드·개발/빌드 후 HTTP, `test:release`다. 랜딩의 실제 조작·반응형·초점·움직임 제어는 기존 Expo 검사와 별도로 확인한다. 앱 헤더·GNB·저장·인증 구현을 변경한 것으로 설명하지 않는다. 새 웹 실행과 기존 Expo 실행 명령을 유지하며 커밋·푸시·배포는 별도 요청 범위다.
