# 계정 스키마와 API 계약

계정은 Google 인증 연결로 구분한다. 기존 내부 ID와 여행 소유권은 유지한다. 기기 게스트를 서버 회원으로 만들거나 이메일만 보고 계정을 합치지 않는다.

실행 원본은 `apps/api/migrations/0014_account_lifecycle.sql`, `0015_account_deletion_guards.sql`이다. [SQL 참조 사본](계정_목표스키마.sql)은 두 파일의 구조를 함께 보여준다. 로컬 구현과 격리 D1 검증을 마쳤으며 운영 적용 여부는 [검수 보고서](<../04. 검증/계정_데이터관리_검수.md>)에서 구분한다.

## 계정의 기준

| 구조                    | 역할과 제약                                                                                    |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| `user`                  | 기존 UUID·비공개 이메일·가입/수정 시각 유지. `lastLoginAt`은 성공한 Google 새 로그인 때만 기록 |
| `account`               | Google `sub`와 내부 ID 연결. `(providerId,accountId)` 고유, Google 연결은 내부 회원당 하나     |
| `session`               | 앱 세션. 유효성·만료·계정 삭제 상태를 요청별 검증. 새 IP·User-Agent 저장 중단                  |
| `account_retirements`   | 이미 접수된 구 90일 요청의 기한·복원·파기 상태 보존. 신규 요청 경로는 닫음                     |
| `account_deletion_jobs` | 신규 실제 삭제의 요청·정책·선점·시도 횟수. 실제 회원 삭제 후 CASCADE로 제거                    |
| `account_data_cleanup`  | 기존 추가 개인정보 정리 대상. 실패 시 남기고 성공한 계정만 제거                                |
| `account_storage_sweep` | 고아 파일·백업 복원 표식의 진행 위치와 다음 유지보수 종류                                      |

`active_google_members`는 Google 연결이 있고 서버 익명이 아니며, 구 탈퇴 요청과 새 삭제 작업이 없는 회원만 조회한다. 이 뷰는 현재 요청의 인증·권한 검사를 대신하지 않는다. 새 `members`, `guest_accounts`, `isGuest`, `isGoogleUser`는 만들지 않는다.

신규 이름은 `여행자`, 사진은 NULL이다. SDK 호환 컬럼은 유지하지만 Google 공급자 토큰·scope·만료 값은 NULL로 저장한다. 미연결 이메일 계정의 비밀번호 해시는 이행 로그인에만 유지하며 Google 연결 직후 제거한다. Google 이름·사진·응답 전체를 프로필이나 통계에 복제하지 않는다.

## 임시 인증과 사본

`oauth_handoffs`의 `session_user_id`, `guest_user_id`는 검증한 세션에서만 채우며 `user(id) ON DELETE CASCADE`로 연결한다. 기존 서명 토큰은 현재 세션의 서명 전 토큰과 대조해 소유자를 이행한다. 로그인 완료 시 이전 게스트 참조를 비운다. 만료 handoff·verification·요청 제한 자료는 예약 실행에서 정리한다.

추가 프로필 입력 API와 프로필 사진 업로드 API는 닫는다. 기존 프로필·사진·응답 사본은 재시도 작업으로 제거한다. 여행·공개본·미완료/완료 가져오기의 표시명도 정리하되 작업 ID·입력 해시·미디어 매핑·저장 요청 키는 보존한다. 호환 테이블·SDK 컬럼의 DROP은 구버전 의존을 정리한 다음 단계다.

## 이용 측정

`usage_events`와 `usage_daily`의 DB 구조는 반영한다. 수집 API와 앱 이벤트 전송은 아직 열지 않는다. 원본의 보관 기간·늦은 전송 허용 기간이 정해지지 않은 상태에서 임의의 기본값으로 수집을 시작하지 않는다.

`usage_events`는 허용된 이벤트 6종, 서버 집계 날짜, 발생/수신 시각, 회원 또는 게스트 측정 세션 참조, 필수 만료 시각만 가진다. 회원은 `member_id`만, 게스트는 `guest_session_id`만 사용한다. 게스트 측정 세션은 기기 여행 복원 UUID·설치 ID·광고 ID와 다르다. 두 식별자를 한 행에 같이 넣지 않는다.

이벤트는 `guest_started`, `member_active`, `google_login_completed`, `member_registered`, `trip_created`, `receipt_confirmed`로 제한한다. 가입 이벤트에만 `registration_source=direct|guest`가 필수다. 일자별 회원 활성·게스트 세션과 회원별 최초 가입에는 부분 고유 인덱스를 둔다. 이벤트 UUID 형식·행위 출처·인증된 회원 ID 검증은 향후 수집 API에서도 수행해야 한다.

`usage_daily`는 `(stat_date,audience,metric)`별 0 이상 정수 집계다. 회원·게스트 식별자·이메일·위치·금액·본문을 넣지 않는다. 이벤트 저장과 집계 증가는 중복 확인을 포함한 원자 처리로 연결해야 한다. 게스트 세션 수를 실제 사람 수라고 표현하지 않는다.

실제 회원 DELETE는 이용 원본을 FK로 제거한다. 구 90일 파기처럼 회원 행을 남기는 처리는 원본 이벤트를 별도 삭제한다. 식별자 없는 집계는 분리한다. 원본 만료 이후 재전송 중복 방지는 서버의 최초 Google 연결·저장 요청 키와 함께 설계해야 하며, 테이블 제약만으로 전체 통계 구현 완료라고 보지 않는다.

## 삭제와 이행

새 삭제는 본인 최근 인증·명시 확인·정책 버전을 요구한다. 공유 소유 여행은 기존 참여자에게 소유권을 넘긴 뒤 삭제한다. 개인 여행·본인 업로드·영수증 사본·인증 정보를 정리하고 마지막에 실제 회원 행을 삭제한다. 공유 자료의 유지 범위, 실패 재시도, 백업 복원 차단은 [계정 이행·삭제 서버 정책](계정_이행삭제_서버정책.md)을 따른다.

운영 DB·R2의 실제 자료를 이번 작업에서 조회·삭제하거나 배포하지 않았다. 이행 검사는 기존 구조를 적용한 격리 DB에 합성 자료를 넣고 새 마이그레이션을 실행했다. 실제 Google 공급자와 앱 화면을 조작한 검수는 별도다.
