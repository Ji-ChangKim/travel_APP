TripPrint 앱 더미 데이터 제거 기록
작성일: 2026-10-06 (Asia/Seoul)

1. 제거 대상과 결과
- 미사용 메모리 저장 모듈 travelStorage.ts의 샘플 여행 2개와 추억 기록 2개를 제거.
- 해당 여행에 포함된 가상 동행·방문 장소·가짜 초대 코드·후기·외부 샘플 이미지 URL 제거.
- currentTrips와 currentMemories는 빈 배열로 시작하며 실제 입력한 기록만 보관.
- 현재 서비스 홈과 여행 허브는 원래부터 실제 인증 API와 멤버십 검증을 거친 여행을 조회한다. 임의 여행을 자동 생성하지 않음.
- 미리보기의 검증용 여행·일정·지출 캡처를 제거하고 실제 서비스의 비로그인 상태 12개 화면으로 교체.
- 이전 PNG 캡처 49개와 실패 캡처 1개는 공개 미리보기 폴더에서 제거하고 .release/page-gallery/fixture-archive-20261006에 내부 검증용으로 분리 보관.
- 실제 사용자 기록이나 기기에서 직접 작성한 여행을 일괄 삭제하지 않음.
- 나라·도시 선택지와 공항·통화 등 실제 기준 정보는 유지. 가상 사용자 여행 데이터와 구분.

2. 서버 확인
- 실제 staging D1에서 앞서 만든 검증용 여행 UUID 3개와 미리보기 UUID 2개에 해당하는 여행: 0건.
- receipt-*@example.test, preview@example.test, home@example.test, fixture@example.test에 해당하는 계정: 0건.
- 원격 확인은 개수만 조회. 실제 사용자 정보·여행 내용·인증 비밀은 조회하지 않음.
- 조회 결과 changes 0, rows_written 0. 서버 데이터 삭제 명령은 수행하지 않음.

3. 재발 방지
- release-artifacts 검사에 과거 더미 여행 제목·초대 코드·미리보기 계정을 추가. 배포 JS에 들어가면 실패.
- 새 캡처 도구는 실제 HTTP 응답을 그대로 읽으며 더미 인증·여행·영수증 응답을 주입하지 않음.
- 새 브라우저의 비로그인 상태에서 화면을 촬영하고 서버 쓰기 요청은 차단.
- 갤러리 생성은 responseSource='service'인 실제 서비스 캡처만 허용. 화면이 없는 일정·영수증 페이지는 실제 앱으로 이동하는 안내 제공.
- 자동 테스트에 필요한 tests/fixtures 데이터는 서비스 번들과 구분하여 유지.

4. 수정 파일
- apps/mobile/src/services/travelStorage.ts: 초기 샘플 여행·추억 제거 및 빈 목록 초기화.
- apps/mobile/public/release.json: test-1-no-dummy 식별자.
- scripts/release-artifact-checks.mjs: 배포 번들의 더미 데이터 검출 기준.
- tests/release/artifacts.test.mjs: 추가 검출 기준 검증.
- scripts/capture-service-pages.mjs: 실제 서비스 응답으로만 공개 화면 촬영.
- scripts/build-page-gallery.mjs: 실제 캡처만 허용, 없는 화면을 더미로 채우지 않음.
- docs/DB_DICTIONARY.txt: 메모리 객체의 빈 초기값과 서버 기록 보존 규칙.
- 이 보고서: 제거 범위·원격 확인·검증 결과.
- outputs/TripPrint-pages: 실제 서비스 PNG 12개, manifest 및 갤러리 HTML.
- .release/page-gallery/fixture-archive-20261006: 공개 목록에서 분리한 이전 검증용 캡처. 서비스 배포에 포함하지 않음.
