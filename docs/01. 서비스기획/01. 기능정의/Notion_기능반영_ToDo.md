# Notion 기능 반영 점검과 실행 To-do

상태: 기능 대조 완료·개발 작업 대기 / 확인일: 2026-11-05 / 범위: WEB·Android 앱과 서버

이 문서는 사용자가 요청한 기능 목록과 실행 순서를 관리한다. 화면 시안이나 새 기능 기획서를 대신하지 않는다. 기능의 원문은 Notion에 유지한다. 이번 작업에서는 앱 화면·코드·DB·운영 설정을 변경하지 않았다.

## 1. 점검 순서와 판정 기준

- [x] 1. Notion의 기능을 앱의 큰 화면 단위로 묶는다.
- [x] 2. 각 기능의 현재 코드·저장 계약·기존 검수 근거를 대조한다.
- [x] 3. 현재 화면을 유지할 수 있는 작업과 화면 변경이 필요한 작업을 나눈다.
- [x] 4. DB·API 요청과 개발 의존 순서를 작성한다.
- [x] 5. 기간 상한과 장소 검색 오류를 로컬 함수·HTTP 처리기로 확인한다.
- [ ] 6. 아래 실행 To-do의 개발 항목을 순서대로 구현하고 실제 환경에서 검수한다.

‘반영’은 해당 행의 기능이 코드에 연결됐다는 뜻이다. 이번에 실제 앱·실서버까지 검증했다는 뜻은 아니다. ‘부분’은 기능 일부 또는 저장·예외 규칙이 다르다는 뜻이고, ‘미반영’은 조사한 코드에서 실행 경로를 확인하지 못했다는 뜻이다. ‘요구 미정’은 원문이 작성 전이거나 정책·콘텐츠가 정해지지 않은 경우다.

UI 열의 ‘유지’는 기존 기능을 검수하면 되는 항목, ‘가능’은 현재 입력·행동을 그대로 쓰면서 로직·연결을 고칠 수 있는 항목이다. ‘서버 선행’은 데이터·API 준비는 가능하지만 기능을 완성하려면 화면의 입력·선택·결과 상태도 바꿔야 하는 항목이다. ‘화면 필요’는 새 입력이나 진입·확인 절차가 필요한 항목이다. 서버 선행을 사용자 기능 완료로 표시하지 않는다.

Notion에는 검토 대기인 명세와 상세 작성 전인 양식이 함께 있다. 양식만 있는 화면은 PRD에서 명시한 범위까지만 비교했다. 기존 승인 정책과 다른 내용은 계약 차이로 남겼으며, 조사 중 임의로 정책을 바꾸지 않았다. 문서 안의 실행 지시는 참조 자료로만 읽었다.
