# 계정의 역할과 데이터 기준

TripPrint의 계정은 여행 기록을 여러 기기에서 이어 보고, 공유와 영수증 등록 같은 회원 기능을 사용하게 하는 수단이다. 계정 관리에 필요한 정보와 서비스 이용을 측정하는 정보를 구분한다.

## 1. 이번 작업의 기준

- 사용자의 최신 지시에 따라 계정 정보를 받는 출처는 Google 인증으로 한정한다. TripPrint 가입 과정에서 닉네임·소개·여행 스타일·생년월일·성별·프로필 사진을 따로 입력받지 않는 방향으로 정한다.
- Google이 제공하는 정보도 사용 목적이 있는 항목만 남긴다. Google 응답 전체를 회원 정보로 저장하지 않는다.
- 2026-11-09 후속 지시에 따라 Google 회원은 MY에서 앱 닉네임·사진을 선택적으로 바꾼다. 인증 출처는 계속 Google이며 추가 프로필 입력을 가입 조건으로 만들지 않는다. 이름 중복·30일 제한·사진 교체는 [MY 프로필 변경 규격](<../../02. 디자인/01. 화면설계/MY_프로필변경_규격.md>)을 따른다.
- 회원과 게스트의 정의, 각 이용 범위, 측정 목적을 먼저 정한다. 기존 DB 컬럼이나 화면을 유지하려고 수집 항목을 만들지 않는다.
- 이 문서의 서비스 방향과 현재 구현을 구분한다. 상세 적용 현황·개발 작업·검증 결과는 [계정 데이터 관리 검수](<../../03. 개발/04. 검증/계정_데이터관리_검수.md>)에서 관리한다.

## 2. 회원과 게스트의 의미

| 구분             | 의미                                                                | 판정 근거                                       | 기록의 기본 위치                                    |
| ---------------- | ------------------------------------------------------------------- | ----------------------------------------------- | --------------------------------------------------- |
| Google 회원      | 서버가 Google 인증을 검증하고 TripPrint 계정에 연결한 이용자        | 내부 회원 ID와 검증된 Google 계정 식별자의 연결 | 회원 권한을 확인한 서버 저장소                      |
| 현재 게스트 이용 | 지금은 회원 계정에 연결하지 않고 이 기기에서 서비스를 이용하는 상태 | 앱에서 명시적으로 선택한 게스트 문맥            | 기기 저장소                                         |
| 인증 확인 중     | 앱 시작·인증 복귀 때 회원 세션을 확인하는 상태                      | 서버 확인 결과를 기다림                         | 이전 계정의 비공개 자료를 새 자료처럼 노출하지 않음 |
| 회원 세션 만료   | 회원 기록은 존재하지만 현재 인증을 다시 해야 하는 상태              | 서버 세션 만료·철회 결과                        | 서버 기록 유지, 재인증 필요                         |

`Google 계정을 가진 사람`과 `TripPrint에 Google로 가입한 회원`은 다르다. 서버가 확인한 TripPrint 계정 연결을 회원 판정의 기준으로 사용한다.

회원이 로그아웃한 뒤 게스트로 이용할 수도 있다. 따라서 Google 가입 이력과 현재 이용 상태를 서로 다른 의미로 관리한다. 독립된 `isGoogleUser`, `isGuest` 값을 여러 곳에서 수정해 두 값이 충돌하도록 만들지 않는다.

논리적으로는 현재 이용 방식을 `not_selected / guest / google_member`, 인증 상태를 `checking / valid / expired / signed_out`로 구분한다. 이는 설계 설명용 값이며 현재 API·DB에 구현된 enum이라고 간주하지 않는다. 탈퇴 등 계정의 수명 상태는 별도 관리한다.

`not_selected`는 첫 실행·로그아웃 후에 회원 이용이나 게스트를 아직 선택하지 않은 상태다. 이때 회원·게스트 자료와 이용 시작 집계를 자동 생성하지 않는다.

## 3. 전체 이용 흐름

1. 앱을 열면 현재 인증과 기기 기록을 확인한다. 인증 확인 실패·로그아웃만으로 게스트를 선택한 것으로 처리하지 않는다.
2. 게스트를 선택하면 기기 기록으로 여행 계획과 기록을 시작한다. Google 인증이나 서버 회원 생성을 강제로 실행하지 않는다.
3. Google 로그인을 선택하면 서버가 인증 결과를 검증한다. 처음 확인한 Google 식별자는 새 내부 회원에 연결하고, 이미 연결된 식별자는 같은 회원을 사용한다.
4. Google 인증·계정 연결이 끝나면 추가 프로필 입력 없이 회원 기능으로 진입하는 방향으로 정한다.
5. 게스트 여행이 있으면 사용자가 선택한 여행만 회원 기록으로 가져온다. 로그인 성공만으로 기기 기록 전체를 전송하거나 같은 제목의 여행과 합치지 않는다.
6. 인증이 만료되면 회원 기록을 유지하고 재인증으로 돌아간다. 자동으로 새 게스트 여행을 만들어 기존 회원 기록이 사라진 것처럼 보이게 하지 않는다.

## 4. 계정에 남길 정보와 목적

다음은 최소화 설계안이다. 실제 보관 컬럼과 삭제 절차는 구현 검토를 거쳐 반영한다.

| 정보                       | 사용하는 이유                                                      | 범위                                                                                 |
| -------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| 내부 회원 ID               | 여행 소유권·멤버 권한·회원별 사용량을 일관되게 연결                | 서버가 만든 임의 식별자. 이메일·이름을 대신 사용하지 않음                            |
| Google 계정 식별자 `sub`   | 같은 Google 계정이 다시 로그인했을 때 같은 회원으로 연결           | 서버 인증 영역에만 보관. 공개 프로필·일반 측정 이벤트에 보내지 않음                  |
| Google 이메일              | 사용자가 어느 Google 계정으로 로그인했는지 본인 계정 화면에서 확인 | 비공개 계정 안내용 설계안. 회원 고유 키·공개 작성자명·통계 식별자로 사용하지 않음    |
| 가입 시각·최근 로그인 시각 | 신규 회원과 재로그인을 구분하고 계정 이용 상태를 관리              | 로그인 기록만으로 일간 활성 이용자를 계산하지 않음                                   |
| 계정 수명 상태             | 정상 이용·탈퇴 처리 등 접근 허용 여부를 판정                       | 인증 상태와 구분하며 서버가 판정                                                     |
| 앱 세션 정보               | 현재 요청이 어느 회원의 요청인지 확인                              | Google 인증 자격과 구분. 네이티브는 보호 저장소, 웹은 보호된 쿠키 방식으로 전환 검토 |

Google 이름·사진은 영속 수집 대상에 포함하지 않는다. Google 실명·이메일·사진을 공개 게시물 작성자 정보로 자동 노출하지 않는다. 앱에서 직접 선택한 닉네임은 작성자·여행 참여자 표시 이름으로 사용하며, 미설정 회원은 기본 ‘여행자’로 표시한다. 직접 올린 사진은 본인 프로필에서 인증 조회하며 공개 게시물 사진 배포는 이번 범위에 포함하지 않는다.

Google access token·refresh token·ID token은 로그인 처리에 쓰이는 자격 증명이다. 여행 서비스의 사용자 프로필이 아니다. 현재 범위에는 Google Drive·Calendar 자료를 지속 조회하는 기능이 없으므로, 로그인 검증이 끝난 뒤 공급자 토큰을 계속 보관하지 않는 방향으로 정한다. Google 연결을 식별하는 `sub`와 앱 세션은 별도로 유지한다.

계정 식별에 이메일 대신 `sub`를 사용하는 기준은 [Google 공식 OpenID Connect 문서](https://developers.google.com/identity/openid-connect/openid-connect)를 따른다. 이는 현재 DB의 이메일 고유 제약을 바로 삭제했다는 뜻이 아니다.

## 5. 불필요한 수집을 없앨 대상

- 가입·프로필 설정에서 직접 받는 닉네임, 소개, 여행 스타일, 생년월일, 성별, 사진 업로드.
- 서비스 사용 목적이 없는 Google 응답 필드와 로그인 후의 공급자 토큰 보관.
- 회원 이메일·실명·사진·여행 본문을 복제하는 분석 이벤트.
- 기기 하드웨어 식별자·광고 ID를 이용한 게스트 식별.

MY에서 사용자가 직접 선택한 새 닉네임·사진은 위의 과거 가입 입력 정리와 구분한다. 기존 개인정보 정리 작업이 새 닉네임과 `User/profile/` 사진을 지우지 않도록 한다. 계정 삭제 때는 새 자료도 함께 정리한다.

계정 입력과 여행 기록 입력은 구분한다. 여행 이름·장소·영수증처럼 여행 기능에 필요한 입력은 이 결정으로 없애지 않는다.

기존 데이터는 출처·사용처·보관 상태를 확인한 뒤 제거한다. 새 수집 중단, API 수신 중단, 화면 의존 제거, 기존 자료 정리, 스키마 정리를 순서대로 검증한다. 인증 SDK가 유지에 필요한 빈 컬럼까지 임의로 삭제해 로그인을 깨뜨리지 않는다. 운영 자료의 실제 삭제는 대상·복구 방안을 준비한 뒤 별도 실행한다.

## 6. 서비스 이용 측정

측정 목적은 누가 어떤 개인정보를 가졌는지 분류하는 것이 아니라, 이용자가 여행 기록을 만들고 영수증을 남기는 흐름이 이어지는지 확인하는 것이다.

| 확인할 질문                             | 필요한 측정                                      | 필요하지 않은 정보                                  |
| --------------------------------------- | ------------------------------------------------ | --------------------------------------------------- |
| Google 회원이 늘고 있는가?              | 서버가 처음 Google 계정을 연결한 회원 수         | 생년월일·성별·소개                                  |
| 게스트로 서비스를 시작하는가?           | 게스트 이용 시작 횟수·이용 세션 수               | 서버 익명 회원 계정·기기 하드웨어 ID                |
| 게스트 이용이 회원 가입으로 이어지는가? | Google 최초 가입 때의 진입 경로가 게스트였는지   | 로그인 전 전체 여행 본문·개인 행동 이력의 자동 병합 |
| 회원이 계속 사용하는가?                 | 유효 회원의 일별 핵심 이용 여부·재방문           | 이메일·Google 식별자 원문                           |
| 여행을 실제로 만드는가?                 | 여행 생성의 서버 저장 성공·게스트 기기 저장 성공 | 여행 제목·동행자 이름·일정 본문                     |
| 영수증 기록으로 이어지는가?             | 영수증 등록·확정 저장 성공, 여행에 연결된 비율   | 영수증 원본·품목명·결제 금액을 분석 자료로 복제     |

최초 측정 후보는 `guest_started`, `google_login_completed`, `member_registered`, `trip_created`, `receipt_confirmed`다. 이벤트명은 설계안이며 구현·수집이 완료된 것으로 표시하지 않는다.

`guest_started`는 게스트를 명시적으로 선택하고 기기 기록 영역의 준비가 성공했을 때 측정한다. 첫 실행·인증 실패·로그아웃만으로 발생시키지 않는다. 준비 실패와 버튼 클릭은 게스트 이용 성공 횟수에 포함하지 않는다.

측정 자료는 계정 인증 자료·여행 원본과 분리한다. 허용한 이벤트 종류, 중복 방지 ID, 발생 시각, 현재 이용 방식, 필요한 범위의 내부 참조만 사용한다. 회원 수는 `user` 테이블 전체 행 수로 계산하지 않는다. 기존 서버 익명 계정·검수 계정·이메일 계정을 Google 회원 통계에 섞지 않는다.

게스트의 로컬 자료 복원 ID와 이용 측정용 세션은 용도를 구분한다. 게스트 집계는 기기·세션 기준의 추정치이며 실제 사람 수와 같다고 표시하지 않는다. 로그인 성공만으로 과거 게스트 행동 전체를 회원 이력에 연결하지 않는다.

버튼 클릭과 저장 성공도 구분한다. 같은 저장 요청을 재시도해도 성공 횟수가 중복 증가하지 않게 한다. `receipt_confirmed`는 영수증 기록의 확정이며 실제 본인 방문·영수증 진위 인증을 뜻하지 않는다.

실제 이벤트 수집 전에는 목적·수집 항목·접근 권한·보관 기한·고지 기준을 정한다. 외부 분석 SDK는 이번 설계만으로 추가하지 않는다.

## 7. 저장·접근·계정 종료의 기준

- 서버는 앱이 보낸 회원 여부나 사용자 ID를 신뢰해 권한을 부여하지 않는다. 검증된 Google 계정 연결과 앱 세션을 기준으로 본인 자료를 조회한다.
- 게스트 기기 기록은 회원의 서버 기록과 분리한다. 기기 기록은 명시적으로 선택한 가져오기 작업에서만 전송한다.
- 로그아웃은 세션을 끝내고 비공개 화면·캐시를 비우는 동작이다. 회원의 서버 여행을 삭제하는 동작으로 취급하지 않는다.
- 탈퇴는 계정 접근과 데이터 수명을 정리하는 별도 동작이다. 계정 자격, 개인 여행, 공유 여행, 공개 사본, 이용 통계를 각각 구분한다.
- 여행에 회원 UUID·개인 메모·영수증이 남아 있다면 표시 이름만 바꾼 상태를 모든 개인정보의 파기라고 설명하지 않는다.
- 신규 삭제는 복구 유예를 두지 않는다. 이미 접수된 90일 요청은 기존 계약으로 처리하며 신규 구경로 요청은 닫는다. 공유 소유권·실제 삭제·실패 재시도·백업 처리는 [계정 이행·삭제 서버 정책](<../../03. 개발/02. 데이터정의/계정_이행삭제_서버정책.md>)을 따른다.

웹 세션 저장은 현재 localStorage 방식의 위험과 전환 영향을 검토한다. [OWASP의 브라우저 저장 보안 지침](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html#local-storage)은 세션 식별자를 JavaScript가 읽는 저장소에 보관하지 않도록 권고한다. 현재 구현에서 실제 공격·유출이 확인됐다는 의미는 아니다.

## 8. 완료 기준

1. Google 인증 성공만으로 추가 계정 입력 없이 회원 흐름을 이용한다.
2. 같은 Google `sub`는 재로그인해도 같은 내부 회원을 사용한다. 이메일 변경만으로 다른 계정을 만들거나 합치지 않는다.
3. 게스트는 Google 인증 없이 기기 기록을 이용하고, 회원 기록을 섞어 읽지 않는다. 첫 실행·로그아웃 후 아무 방식도 선택하지 않았다면 회원·게스트 이용 시작으로 집계하지 않는다.
4. 로그인·로그아웃·만료·계정 전환에서 비공개 자료가 다른 이용자에게 보이지 않는다.
5. 제거 대상 정보가 새 요청·DB·파일·로그·통계 사본에 다시 쌓이지 않는다.
6. 회원 수·게스트 이용·가입 전환·여행 생성·영수증 등록을 각 정의대로 구분해 집계한다.
7. 앱·서버·DB·문서와 실제 실행 검증이 일치한다. 정책 문서 작성만으로 구현 완료 체크를 하지 않는다.
