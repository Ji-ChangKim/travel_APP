# 앱 기본 구조 페이지별 기능 정의서

## 1. 목적과 문서 상태

사용자가 앱을 열고 이용 방식을 선택한 뒤, 내 여행과 공개 여행을 찾아보고 계정을 관리하는 흐름을 정의한다. 각 페이지의 역할을 먼저 정하고 그 역할에 맞춰 상단 타이틀과 하단 GNB를 배정한다. GNB는 앱의 주요 화면을 오가는 하단 메뉴를 뜻한다.

이 문서는 페이지 기능과 탐색 구조의 기준이다. 사용자의 구현 지시에 따라 내 여행·커뮤니티의 제목을 통일하고 페이지별 헤더·GNB를 배정한다. 기능의 수용 기준과 실제 검증 결과를 구분하며, 미구현 기능을 완료로 표시하지 않는다.

| 구분               | 적용 내용                                                                                                            |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| 확정된 범위        | 앱 실행, 로그인, 기본 프로필 확인, 홈, 커뮤니티, MY. 연결에 필요한 내 여행 목록·설정·계정 관리·공개 여행 상세도 포함 |
| 확정된 프로필 정책 | 추가 입력 없이 시작하고 기본 프로필을 표시. 별도 프로필 생성·편집 페이지를 가입 관문으로 두지 않음                   |
| 확정된 게스트 목표 | 게스트 프로필로 여행 기록을 서버 DB에 저장하고 다시 조회. 커뮤니티 공개 공유는 게스트 완료 기준에서 제외             |
| 현재 게스트 구현   | 기기 저장 방식. 서버 저장·재조회는 미구현이며 후속 작업. 화면 안내는 구현 전까지 실제 저장 범위를 따름               |
| 후속 범위          | 여행 생성·계획 편집 내부, Google 장소 검색·등록, 영수증 촬영·추출·확정 저장, 공개본 작성                             |
| 탐색 구조 기준     | 내 여행·커뮤니티의 제목 통일, 페이지별 헤더 행동, GNB 노출·복귀·상태 보존 기준                                       |

기능 범위는 이 문서에서 정의하고, 치수·색상·글꼴의 단일 기준은 [디자인 시스템](<../../02. 디자인/00. 공통규격/디자인시스템.md>), [디자인 토큰](<../../02. 디자인/00. 공통규격/design-tokens.json>), [헤더·GNB 규격](<../../02. 디자인/00. 공통규격/헤더GNB_규격.md>)에서 관리한다. 화면 구성은 [앱 기본 구조 화면 규격](<../../02. 디자인/01. 화면설계/앱기본구조_화면규격.md>)을 참조한다.

## 2. 전체 흐름과 페이지 역할

첫 실행은 시작 확인 → 로그인 선택 → 기본 프로필 확인 → 홈 순서다. 재실행은 인증과 저장 상태를 확인한 뒤 허용된 원래 목적지 또는 홈으로 복귀한다. 인증 실패를 게스트 선택으로 바꾸지 않는다.

앱의 루트 화면은 홈·내 여행·커뮤니티·MY다. 내 여행은 내 자료를 찾는 곳이고, 커뮤니티는 다른 사람이 공개한 자료를 읽는 곳이다. MY는 이용 방식과 내 기록의 요약을 확인하는 곳이다. 설정과 계정 관리는 MY 아래에 둔다.

| 페이지 ID | 페이지           | 경로·진입                                                                   | 사용자에게 보여줄 결과                                   |
| --------- | ---------------- | --------------------------------------------------------------------------- | -------------------------------------------------------- |
| P01       | 앱 실행          | 앱 시작, `src/app/index.tsx`                                                | 이용 가능한 버전과 인증 상태를 확인해 다음 화면으로 이동 |
| P02       | 로그인 선택      | 첫 선택 `/welcome`, 재로그인·계정 연결 `/login`, 인증 복귀 `/auth/callback` | 선택한 Google 계정 또는 게스트로 시작                    |
| P03       | 기본 프로필 확인 | 로그인 성공 후 내부 처리, 과거 주소 `/profile-setup`                        | 추가 입력 없이 기본 프로필 적용 후 원래 화면으로 이동    |
| P04       | 홈               | `/`, 실제 라우트 `(tabs)/index.tsx`                                         | 지금 볼 여행과 다음 행동 안내                            |
| P05       | 내 여행          | `/plans`                                                                    | 내 여행을 찾아 선택                                      |
| P06       | 커뮤니티         | `/footprints`, 호환 주소 `/community`                                       | 공개된 계획·기록의 목록                                  |
| P07       | 공개 여행 상세   | `/community/:postId`                                                        | 공개가 허용된 여행 내용                                  |
| P08       | MY               | `/my`                                                                       | 기본 프로필·이용 방식·내 여행 요약                       |
| P09       | 설정             | `/settings`                                                                 | 언어·앱 정보·로그아웃·계정 관리 진입                     |
| P10       | 계정 관리        | `/account`                                                                  | 본인 계정 확인과 계정 삭제 절차                          |

P01과 P04는 외부 주소가 `/`로 보일 수 있지만 앱 시작 분기와 홈 화면이라는 역할이 다르다. P02의 세 주소도 하나의 동일한 화면으로 취급하지 않는다. 첫 선택, 재로그인, 외부 인증 결과 확인을 나눠 검사한다.

## 3. 상단 타이틀과 GNB 배정표

홈은 브랜드 헤더를 사용하고 나머지 루트는 공통 제목 헤더를 사용한다. 사용자의 구현 지시에 따라 커뮤니티 브랜드 헤더 예외를 해제한다. 기존 공통 치수·글꼴·GNB 구성은 유지한다.

| 페이지             | 상단 역할              | 적용 제목·유형                                     | 좌측 행동                                                     | 우측 행동                        | GNB           |
| ------------------ | ---------------------- | -------------------------------------------------- | ------------------------------------------------------------- | -------------------------------- | ------------- |
| P01 앱 실행        | 시작 전용 표시         | 유지. 화면 타이틀 없이 BI·진행 상태                | 없음                                                          | 없음                             | 숨김          |
| P02 첫 로그인 선택 | 브랜드 중심 시작 화면  | 유지. 별도 공통 타이틀 없음                        | 없음                                                          | 없음                             | 숨김          |
| P02 로그인         | `로그인`               | 공통 하위 헤더 `로그인`                            | 기존 이용 문맥이 있으면 이전 화면. 없으면 뒤로가기 생략       | 없음                             | 숨김          |
| P02 인증 복귀      | `로그인 확인`          | 유지. 확인 중 상태 표시                            | 정상 처리 중에는 별도 행동 없음. 실패 시 본문에서 로그인 복귀 | 없음                             | 숨김          |
| P03 기본 프로필    | `계정 확인`            | 유지. 정상 가입의 독립 입력 화면으로 노출하지 않음 | 로그인 화면으로                                               | 없음                             | 숨김          |
| P04 홈             | `TripPrint` 브랜드     | 유지. `HomeHeader`                                 | 브랜드 표시만, 뒤로가기 없음                                  | 현재 홈은 없음                   | 홈 선택       |
| P05 내 여행        | 공통 루트 헤더         | `내 여행`                                          | 뒤로가기 없음                                                 | 검색 열기·닫기, MY 이동          | 내 여행 선택  |
| P06 커뮤니티       | 두 주소 공통 루트 헤더 | `커뮤니티`                                         | 뒤로가기 없음                                                 | 없음. 검색·조건·공유 진입은 본문 | 커뮤니티 선택 |
| P07 공개 상세      | `공유된 여행`          | 유지. 공통 하위 헤더 `공유된 여행`                 | 실제 이전 목록. 직접 링크는 커뮤니티                          | 기본 없음. 자료별 행동은 본문    | 숨김          |
| P08 MY             | `MY`                   | 유지. 공통 루트 헤더 `MY`                          | 뒤로가기 없음                                                 | 설정                             | MY 선택       |
| P09 설정           | `설정`                 | 유지. 공통 하위 헤더 `설정`                        | MY                                                            | 없음                             | 숨김          |
| P10 계정 관리      | `계정 관리`            | 유지. 공통 하위 헤더 `계정 관리`                   | 설정. 삭제 접수 후 또는 세션 없을 때 로그인                   | 없음                             | 숨김          |

홈은 브랜드를 보여주고 나머지 루트 탭은 GNB와 같은 페이지 이름을 보여준다. 커뮤니티의 소개 문장은 본문에 남기고 대표 제목은 상단에 한 번만 표시한다. 검색·조건·공유 진입은 본문에 둔다.

### 3.1 공통 상단 규칙

- 루트 탭에는 뒤로가기를 두지 않는다. 하위 화면은 `뒤로가기 → 제목 → 해당 화면 행동` 순서를 따른다. 제목은 왼쪽 정렬이며 중앙 정렬과 혼용하지 않는다.
- `ScreenHeader`, `ScreenTitle`, `HeaderAction`, `HomeHeader`를 사용한다. 제목과 본문 제목을 임의 스타일로 복제하지 않는다. 페이지는 제목·행동·복귀 목적지·잠금 상태를 지정한다.
- 현행 토큰 기준은 헤더 최소 높이 56, 수평 여백 20, 최대 폭 640, 수직 여백 6, 행동 간격 8, 터치 영역 48이다. 화면 제목은 `headlineLarge`의 26/36·굵기 700이다. 값 변경은 공통 규격 작업에서만 한다.
- 상단 안전 영역은 별도로 반영한다. 큰 글꼴·긴 번역 제목은 줄바꿈과 높이 확장을 허용한다. 글자 축소·말줄임·행동 숨김으로 해결하지 않는다.
- 로딩·빈 화면·오류에서도 페이지 제목과 복귀 위치를 유지한다. 삭제·이전 등 중복 실행이 위험한 처리 중에는 관련 행동과 이탈을 잠그고 처리 상태를 표시한다.
- 브라우저 뒤로가기·기기 뒤로가기·헤더 뒤로가기를 같은 시나리오로 검사한다. 고정 복귀와 실제 이전 화면 복귀는 위 표의 페이지별 정책을 따른다.

### 3.2 공통 GNB 규칙

| 순서 | 라벨     | 목적지        | 역할                                            |
| ---- | -------- | ------------- | ----------------------------------------------- |
| 1    | 홈       | `/`           | 여행 상태와 시작점                              |
| 2    | 내 여행  | `/plans`      | 내 여행 목록                                    |
| 3    | 커뮤니티 | `/footprints` | 공개 여행 탐색. `/community`도 같은 탭으로 선택 |
| 4    | MY       | `/my`         | 내 프로필과 기록 요약                           |

- 현재 4탭의 개수·순서·아이콘·선택 표시를 유지한다. 새 여행 만들기는 목적지 탭이 아니므로 GNB에 추가하지 않는다.
- GNB는 이 네 루트에서만 표시한다. 로그인·설정·계정·공개 상세·여행 작업 화면에서는 숨긴다. 모달에서는 배경 탭이 터치되거나 읽히지 않게 한다.
- 현행 토큰 기준은 탭 최소 높이 64, 최소 터치 영역 48, 아이콘 22, 라벨 `navigation` 13/20이다. 하단 안전 영역을 반영하고 마지막 콘텐츠를 가리지 않는다.
- 선택은 현재 주소로 계산한다. 눌렀다는 이유만으로 목적지에 도착한 것처럼 표시하지 않는다. 활성 탭 재선택은 기존 검색·스크롤을 보존한다.
- 다른 탭을 다녀오면 해당 화면의 탐색 상태를 보존하는 것을 수용 기준으로 둔다. 현재 상태 보존 범위는 실제 조작으로 별도 확인한다. 로그아웃·계정 전환에서는 이전 계정의 비공개 화면·캐시를 분리한다.
- 현행 스크롤 숨김·복귀 모션은 유지한다. 이를 항상 표시 방식으로 바꾸는 결정은 이번 기능 정의에 포함하지 않는다.

## 4. 페이지별 기능 정의

각 행의 ‘실패·완료 기준’은 앞으로 검사할 수용 기준이다. 구현 코드가 있다는 이유로 통과 처리하지 않는다.

### P01 앱 실행

**목적:** 앱을 이용할 수 있는지 확인하고 올바른 시작 화면으로 안내한다. 사용자는 앱을 열며, 앱은 확인 결과에 맞는 화면을 보여준다. 확인이 실패하면 재시도할 수 있어야 한다.

| 기능 ID  | 사용자 행동·처리            | 결과                                                           | 실패·완료 기준                                                          |
| -------- | --------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------- |
| START-01 | 앱 실행                     | 승인 BI 표시 후 시작 정책·버전 확인                            | 실패는 재시도. 임의의 정상 응답으로 대체하지 않음                       |
| START-02 | 기존 이용 상태 복원         | 유효 회원·선택한 게스트는 목적지 또는 홈, 미선택은 로그인 선택 | 통신 실패·만료를 새 게스트로 처리하지 않음. 이전 비공개 자료 노출 없음  |
| START-03 | 필수 업데이트 안내에서 이동 | 실제 스토어 이동                                               | 주소 오류·이동 실패 시 현재 상태와 재시도 제공. 필수 업데이트 우회 없음 |

### P02 로그인 선택과 인증 복귀

**목적:** Google 또는 게스트 중 이용 방식을 고른다. Google은 서버가 인증을 확인한 뒤 회원으로 시작하고, 게스트는 명시적 선택 후 기본 프로필로 시작한다.

| 기능 ID  | 사용자 행동            | 결과                                        | 실패·완료 기준                                                                  |
| -------- | ---------------------- | ------------------------------------------- | ------------------------------------------------------------------------------- |
| LOGIN-01 | Google 계정으로 계속   | 실제 인증 → 계정 확인 → 원래 목적지 또는 홈 | 취소·공급자 실패·세션 실패를 성공 처리하지 않음. 재시도와 현재 화면 복귀        |
| LOGIN-02 | 게스트로 시작          | 게스트 기록 영역 준비 후 기본 프로필로 진입 | 준비 실패 시 원본 보존·재시도. 지금은 기기 저장이며 서버 저장으로 안내하지 않음 |
| LOGIN-03 | 기존 이용 이어서 시작  | 같은 이용 문맥으로 복귀                     | 목적지·여행 선택 정보 보존. 임의 외부 복귀 주소 거부                            |
| LOGIN-04 | 다른 계정으로 로그인   | 기존 세션 종료 후 명시적 계정 선택          | 중복 요청 차단. 실패 시 계정이 바뀐 것처럼 표시하지 않음                        |
| LOGIN-05 | 외부 인증에서 돌아오기 | 일회용 결과 확인 후 기본 프로필 처리        | 새로고침·만료·중복 복귀·앱 재시작을 검사. 인증 자격을 화면·로그에 노출하지 않음 |

Google 로그인만으로 게스트 기록 전체를 전송하지 않는다. 가져오기는 사용자가 고른 여행에 한해 별도 확인하며, 실패 시 원본을 보존한다. 회원 가입용 이메일·비밀번호·닉네임 입력은 새로 추가하지 않는다.

### P03 기본 프로필 확인

**목적:** 사용자가 별도 정보를 입력하지 않고 여행 기능을 시작하게 한다. 정상 흐름에서는 확인 결과를 적용하고 자동 이동한다. 과거 주소로 들어온 경우에도 입력 폼을 열지 않는다.

| 기능 ID    | 처리·사용자 행동                | 결과                                 | 실패·완료 기준                                             |

| PROFILE-01 | 로그인 뒤 기본 프로필 확인      | 기본 이름·이미지·실제 이용 방식 적용 | 생일·성별·소개가 없어도 진입. 없는 값을 새로 입력받지 않음 |
| PROFILE-02 | 과거 `/profile-setup` 직접 진입 | 확인 후 허용된 목적지로 이동         | `next=my`는 MY 복귀. 별도 프로필 쓰기·완료 요청 없음       |
| PROFILE-03 | 다시 시도 또는 로그인 화면으로  | 같은 계정 재확인 또는 로그인 복귀    | 계정 전환 후 늦은 이전 응답 반영 금지                      |

MY에서 기본 프로필을 보여준다. 기본 이름이 비었을 때는 ‘여행자’를 사용한다. 서버가 확인하지 않은 계정을 Google 회원으로 표시하지 않는다. Google 회원의 선택적 닉네임·사진 변경은 P08에서 처리하며 시작 단계의 입력 관문으로 만들지 않는다.

기능별 판정은 통과·실패·미검증·해당 없음으로 기록한다. 대상 버전·환경·사전 조건·조작·기대 결과·실제 결과·증거 위치를 남긴다. 실제 Google 인증, 서버 저장, 실기기 검수와 대체 응답 검사를 구분한다. 추가·삭제·편집이 없는 조회 페이지에는 해당 변경 API를 억지로 만들지 않는다. 변경 행동은 저장 결과와 재진입·재조회까지 확인한다.

상단·GNB 구현을 바꿀 때는 `npm run check`, `npm run test:headers:web`와 관련 복귀·이탈 검사를 실행하고 실제 캡처를 대조한다. 인증·API가 바뀌면 관련 검사도 추가한다. 문서만 바꾸는 경우에는 `npm run check:docs`와 변경 문서 서식 검사를 적용한다. 실행하지 않은 화면 검사를 통과했다고 기록하지 않는다.
