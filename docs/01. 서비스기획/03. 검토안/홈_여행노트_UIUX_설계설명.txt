여행 노트 UI/UX 디자인 시안
상태: 검토안 / 2026-10-27 / 앱 적용 전
파일: 홈_여행노트_UIUX_시안.html

방향
큰 소개 카드·슬로건·중앙 캐릭터 중심 홈을 여행 노트 구조로 바꾼다.
도시와 날짜를 먼저 읽고, 일정 흐름을 따라 다음 행동으로 이동한다.
본문의 둥근 카드 반복을 없애고 구분선·시간축·작은 목록으로 묶는다.
사진이 없어도 완성되는 구성이며 실제 여행 데이터가 없으면 첫 여행 입력으로 전환한다.

보존과 변경
공식 로고 심볼·Poppins 브랜드명·하루 원본·LINE Seed를 보존한다.
공통 헤더의 높이·좌우20·48 터치·로고 크기·큰 글꼴 줄바꿈을 대조했다.
GNB의 홈·내 여행·커뮤니티·MY 순서, 아이콘22, 선택 면48×28,
라벨13/20, 최소48 터치를 보존한다. 웹 검토 시안이므로 아이콘은 SVG로 표현한다.
변경 제안은 홈 본문의 흰 바탕, 낮은 카드 밀도, 구분선, 도시 제목52~58,
날짜22, 본문16, 보조14, 구역24~28, 주 버튼 반경8이다.
현행 앱 토큰과 기준 문서는 변경하지 않았다. 승인 후 구현 시 본문 토큰을 별도로 반영해야 한다.

상태별 구성
처음 방문: 목적지·날짜 항목 → 첫 여행 만들기 → 작은 하루 안내.
여행 준비: 도시·D-day·기간·동행·장소 수 → 이어서 계획 → 첫날 일정 → 새 여행 생성.
여행 중: 오늘 DAY·시간축 일정 → 영수증으로 기록하기 → 내일 일정.
여행 후: 완료 여행·방문 기록 요약 → 남은 영수증 정리 → 메뉴 기록.
하루의 조언은 이 디자인에서 역할을 설명하기 위한 예시다. 운영에서는 승인된 안내 또는 서버 팁을 사용한다.

프로토타입 경계
화면의 도쿄 일정·인원·개수·메뉴·금액은 디자인 검토용 예시이며 서버 데이터가 아니다.
상태 전환, 200% 글꼴, 모달, 여행지·날짜 입력 미리보기만 동작한다.
생성·영수증 업로드·OCR·저장·계정 처리를 실제로 수행하지 않는다.
나머지 탭은 연결 목적을 보여주는 미리보기이며 해당 화면 전체 디자인은 포함하지 않는다.
구현 시 일정·동행·기록 수는 실제 조회 결과만 표시하고 실패를 0으로 바꾸지 않는다.
기록이 없는 여행 후 화면은 기록 숫자 대신 첫 기록 행동을 제공해야 한다.

설계 근거
UI UX Pro Max를 사용했다. 디자인 시스템 검색의 Aurora/스크롤 효과·Playfair 추천은
이 관리형 여행 앱과 한·영·일 글꼴 조건에 맞지 않아 채택하지 않았다.
후속 task prioritization dashboard 검색도 일치 결과가 없어, 해당 부분은 스킬의 일반 원칙과
제품 사용 흐름에 근거한 설계 판단이다. 검색 결과가 디자인 효과를 입증한 것은 아니다.
접근성·명시적 행동 이름·모바일 우선·색 역할 분리·예측 가능한 탐색을 적용했다.

검증
Chrome에서 4상태×320/390/430×일반/200%=24조합의 가로 넘침과 이미지 로드를 확인했다.
여행 입력 미리보기, Escape 닫기, 페이지 스크립트 오류를 확인했다.
캡처에서 날짜 라벨 간격과 어두운 배경 안 버튼 글자색을 보완했다.
밝은 모드 검토안이며 다크 모드, 가로 방향, 실기기 접근성 검수는 미완료다.
앱이나 서버에 배포하지 않았다.

제목 보완: 사용자 요청에 따라 첫 방문 제목은 ‘어디로 떠나볼까요?’ 한 문장으로 표시한다.
강제 줄바꿈을 제거하고 28px/1.4, 자간 -0.8px을 적용한다. 일반 모바일에서는 한 줄,
큰 글꼴에서는 내용 잘림 없이 자연스럽게 줄바꿈한다. 다른 상태 제목은 유지한다.

사용자 확정 변경: 시안의 우측 상단 프로필을 제거한다. 계정 진입은 하단 MY로 통일한다.
브랜드 위치·헤더 높이·하단 메뉴는 유지한다. 기존 앱 공통 헤더 반영은 기능 정의서의 후속 개발 단계다.
