## 1. 프로젝트 개요 (Executive Summary)

- **공식 서비스명**: TripPrint (트립프린트)
- **브랜드 슬로건**: _"떠나기 전의 설렘부터, 돌아온 뒤의 추억까지 하나의 여행으로"_
- **핵심 가치 제안 (UVP)**:
  - 기존의 5개 이상 쪼개진 여행 도구(노션, 엑셀, 카카오톡, 구글맵, 가계부 앱)를 **[계획(Plan) - 현장 길잡이/정산(In-Trip) - 기록/출판(Record & Print)]**의 단절 없는 단일 파이프라인으로 통합.
  - 가입 장벽 0%의 '무마찰 게스트 모드'와 동행자 초대 링크 기반의 오가닉 바이럴(K-Factor > 1.2)을 통해 **안드로이드 1만 다운로드 조기 돌파**.

## 2. 배경 및 문제 정의

### 2.1 해결하려는 문제

#### (1) 시장 데이터 및 사용자 관찰

한국관광공사 및 여행 트렌드 데이터에 따르면, 2030 자유여행자(FIT)의 82% 이상이 여행 준비 및 현장 진행 과정에서 **"극심한 도구 파편화에 따른 인지 과부하(App-switching Fatigue)"**를 호소하고 있습니다.

```
[ 기존 여행자의 분절된 작업 환경 ]
정보 탐색 (블로그/유튜브)
  → 일정 수립 (노션/구글 스프레드시트/메모장)
  → 동행자 공유 (카카오톡 대화방 링크 복붙)
  → 현장 길찾기 (구글맵 별도 검색)
  → 경비 계산 (영수증 보관 후 엑셀 정산)
```

#### (2) 지금 이 문제를 해결해야 하는 핵심 이유 4가지

1. **정보의 파편화 및 현장 인지 부하**:
   - 여행 현장(길거리, 공항, 기차역)에서 급하게 일정을 확인하려 할 때 데이터가 흩어져 있어 동행자 간 혼선과 피로도가 극대화됩니다.
2. **동행자 간 실시간 협업 및 다중 통화 정산 갈등**:
   - 해외 현지에서 엔화(JPY), 달러(USD), 유로(EUR) 등 이종 통화 결제 후 영수증이 구겨져 분실되고, 여행 종료 후 환율 계산 착오로 인해 정산 시 불필요한 감정 소모가 발생합니다.
3. **공들인 계획의 일회성 휘발 및 기록 단절**:
   - 여행 전 수 주간 공들여 짠 일정표는 여행이 끝남과 동시에 버려지며, 수천 장의 사진은 스마트폰 갤러리에 방치되어 "어디서 무엇을 했는지" 추억을 복원하기 어렵습니다.
4. **과도한 회원가입 장벽으로 인한 동행자 이탈**:
   - 일정표 링크 하나 보려고 해도 강제 앱 설치와 본인 인증을 요구하여, 초대받은 동행자의 42%가 첫 화면에서 이탈합니다.

### 2.2 제품 비전 및 전략적 연계

#### (1) 비전 매핑

TripPrint는 단순한 '일정표 작성기'나 '예약 대행사(OTA)'가 아닙니다. **"여행의 라이프사이클 전 과정(End-to-End)을 관통하는 올인원 스마트 트래블 컴패니언"**입니다.

#### (2) 상위 비즈니스 전략과의 부합성

- **단발성 커머스 경쟁 탈피**: 수수료 출혈 경쟁이 심한 항공/호텔 예약 중개 시장 대신, 사용자가 여행의 전 여정 동안 앱에 머무르는 **'체류 시간(Time-Spent)과 경험 데이터'를 독점**합니다.
- **LTV(고객 생애 가치) 극대화 구조**:
  - 여행 전: 계획 템플릿 탐색 및 동행 협업 유입
  - 여행 중: GPS 동선 안내 및 2단계 영수증 OCR 정산 유틸리티 제공
  - 여행 후: 감성 '여행 영수증(Trip Receipt)' 및 '발자국 포토북' 출판으로 이어지는 재방문 및 수익화 플라이휠 완성.

## 3. 목표 및 성공 지표 (KPI)

### 3.1 성공의 기준

- **목표 1 (최우선 과제):** 출시 90일 이내 **안드로이드 마켓 누적 다운로드 10,000건(1만+) 돌파** (오가닉 및 ASO 중심).
- **목표 2:** 가입 허들 없는 게스트 모드 도입으로 **초기 온보딩 이탈률(Drop-off) 15% 이하 유지**.
- **목표 3:** 동행 초대 링크 및 웹 추천 일정 발행을 통한 **오가닉 바이럴 계수(K-Factor) 1.2 이상 확보**.
- **목표 4:** 다자간 동시 편집 및 오프라인-온라인 환경 전환 시 **데이터 유실률 0.00% 달성**.

### 3.2 핵심 지표 (KPI)

| 지표명 (KPI)                            | 현재 기준값       | 목표값         | 측정 주기 및 추적 방법                           |
| :-------------------------------------- | :---------------- | :------------- | :----------------------------------------------- |
| **안드로이드 누적 설치 수 (Downloads)** | 0건 (출시 전)     | **10,000+ 건** | Google Play Console (일간/주간 집계)             |
| **초기 온보딩 이탈률 (Drop-off Rate)**  | 45% (업계 평균)   | **15% 이하**   | GA4 / Mixpanel (`first_open` → `main_view`)      |
| **첫 여행 생성 완료율 (Activation)**    | 40% (업계 평균)   | **70% 이상**   | Mixpanel (`trip_create_success` 퍼널)            |
| **D+7 리텐션 (Retention)**              | 18% (여행앱 평균) | **35% 이상**   | GA4 코호트 분석 (D-Day 대기자 대상)              |
| **바이럴 계수 (Viral K-Factor)**        | 0.8               | **1.2 이상**   | 활성 여행 1건당 생성된 초대 수락 디바이스 수     |
| **웹 일정 발행 → 앱 다운로드 전환율**   | 5%                | **20% 이상**   | Branch / Firebase Dynamic Link (웹 배너 클릭)    |
| **영수증 OCR 정산 완주율**              | 25%               | **65% 이상**   | 인앱 이벤트 (`receipt_scan` → `expense_confirm`) |
| **데이터 동시성 충돌 유실 건수**        | N/A               | **0건 (Zero)** | Sentry 및 백엔드 에러 로깅 (`TP-TRIP-CON-001`)   |

## 4. 대상 사용자 및 핵심 사용자 여정

### 4.1 대상 사용자 / 페르소나

#### [주요 페르소나 (Primary)] "완벽주의 총무 플래너" - 강민서 (29세, 직장인)

- **행동 특성**: 엑셀과 구글맵을 켜두고 분 단위로 동선을 짜야 직성이 풀리는 J형 여행자. 친구 3명과의 오사카 3박 4일 여행을 총괄 기획.
- **핵심 니즈**:
  - 일정 링크를 줬을 때 친구들이 "우리 다음 어디 가?"라고 묻지 않고 스스로 보게 만들기.
  - 엔화 지출 후 영수증 분실 없이 실시간으로 더치페이 정산을 끝내기.
- **사용자 가치**: 3단계 여행 생성으로 1분 만에 일정표 뼈대를 잡고, 영수증은 사진만 찍으면 원화로 자동 계산되어 정산 스트레스 제로.

#### [보조 페르소나 1 (Secondary)] "자유로운 동행 탐험가" - 이준호 (25세, 대학생)

- **행동 특성**: 친구가 짜온 계획에 무임승차하길 선호하지만 가고 싶은 맛집 1~2곳은 확실한 P형 여행자.
- **핵심 니즈**:
  - 앱 설치나 복잡한 회원가입 절차 없이 친구의 일정을 카카오톡에서 바로 열람.
  - 내 휴대폰에서 가고 싶은 카페 하나를 일정에 간편하게 추천/추가.
- **사용자 가치**: 카톡 링크 클릭 시 웹/앱에서 0초 만에 일정이 열리며, 원터치로 장소 추가 제안 가능.

#### [보조 페르소나 2 (Secondary)] "감성 아카이빙 기록가" - 박서연 (32세, 프리랜서 디자이너)

- **행동 특성**: 여행지의 티켓, 카페 영수증, 골목길 풍경의 감성을 수집하고 인스타그램에 공유하길 즐김.
- **핵심 니즈**:
  - 여행 후 흩어진 사진과 지출 내역을 정리하는 데 드는 수일간의 시간 단축.
  - 나만의 여행 기록을 감각적인 그래픽으로 소장.
- **사용자 가치**: 여행 완료 당일 자정에 여행의 모든 궤적과 소비가 담긴 '여행 영수증(Trip Receipt)' 카드가 1초 만에 자동 생성되어 원클릭 인스타 공유 가능.

### 4.2 핵심 사용자 여정 (Core User Journey, CUJ)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        핵심 사용자 여정 (CUJ 4단계)                    │
├────────────────────┬────────────────────┬──────────────────────────────┤
│ CUJ-1: 무마찰 기획 │ CUJ-2: 초대와 협업 │ CUJ-3: 현장 가이드 & 정산    │
│ (설치 후 60초)     │ (바이럴 루프)      │ (오프라인 & 다중 통화 OCR)   │
├────────────────────┼────────────────────┼──────────────────────────────┤
│ 1. 앱 실행         │ 1. [초대 링크] 복사│ 1. 홈 [오늘의 일정] 자동 진입│
│ 2. 게스트 즉시 진입│ 2. 카카오톡 전송   │ 2. 구글맵 마커-동선 길안내   │
│ 3. 국가/도시/일자  │ 3. 동행자 웹 즉시  │ 3. 엔화 영수증 사진 찰칵     │
│ 4. 타임라인 자동생성│    열람 및 앱 유입 │ 4. OCR 원화 자동 정산 완료   │
└────────────────────┴────────────────────┴──────────────────────────────┘
                                   │
                                   ▼ CUJ-4: 여행 완료 및 바이럴 출판
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 여행 종료 익일 [여행 완료 축하] 브리핑 카드 노출                     │
│ 2. 9:16 감성 여행 영수증 카드 1초 렌더링 → 인스타그램 스토리 공유      │
│ 3. 웹 추천 일정 공개 발행 (`https://tripprint.me/p/{shareId}`)         │
└────────────────────────────────────────────────────────────────────────┘
```

1. **CUJ-1 [무마찰 계획 수립]**: 사용자가 앱 설치 후 첫 화면에서 [로그인 없이 둘러보기]를 탭하여 3초 만에 목적지(예: 도쿄)와 일정을 선택하고 DAY별 타임라인 스케줄러로 진입합니다.
2. **CUJ-2 [동행자 초대 및 유입]**: 작성자가 [동행자 초대]를 누르면 고유 토큰이 포함된 카카오톡 링크가 생성되고, 동행자는 앱 미설치 상태에서도 웹 브라우저에서 즉시 일정을 확인한 뒤 앱 설치로 이어집니다.
3. **CUJ-3 [현장 길안내 및 무오차 정산]**: 여행지 현장에서 홈 화면이 [오늘의 여정]으로 자동 전환되어 다음 장소와 구글맵 동선을 보여주며, 식당에서 결제한 영수증을 카메라로 찍으면 OCR이 엔화 금액을 인식하여 1/N 정산표를 즉시 산출합니다.
4. **CUJ-4 [발자국 영수증 출판 및 소셜 확산]**: 여행 종료일 다음 날, 그동안 방문한 장소 수와 지출 총액, 대표 사진이 담긴 '감성 여행 영수증 카드'가 생성되어 인스타그램 스토리에 공유됩니다.

## 5. 범위 및 기능 요구사항

### 5.1 포함 범위 (1단계 - Android MVP 및 10K 달성 범위)

- [x] **무마찰 게스트 모드 및 소셜 인증**: 로그인 없는 즉시 사용, Google One-Tap 로그인, 이메일 가입, 게스트-회원 원활한 데이터 승계.
- [x] **4대 글로벌 메인 허브**:
  - 홈 대시보드 (`SCR-HOME-01`): D-Day 카운트다운, 실시간 오늘 일정 브리핑, AI 코치 '하루' 문맥 팁.
  - 내 여행 워크스페이스 (`SCR-WORK-01`): 3단계 신규 여행 생성, 상태별 필터(예정/진행중/완료/보관함).
  - 커뮤니티 탐색 (`SCR-COMM-01`): 8개 주요 도시 가이드, 공개된 추천 여행 일정 탐색.
  - 마이페이지 (`SCR-MYPG-01`): 프로필 관리, 이용약관, 90일 탈퇴 유예 및 복구.
- [x] **여행 상세 5대 핵심 허브**:
  - 1. 일정 허브 (`TAB-TRIP-01`): DAY별 타임라인, Google Places 자동완성 장소 검색, 드래그앤드롭 순서 변경.
  - 2. 지도 허브 (`TAB-TRIP-02`): Google Maps 네이티브 핀 렌더링, 순차 이동 폴리라인(Polyline), 장소 카드 캐러셀.
  - 3. 비용 허브 (`TAB-TRIP-03`): 정수 센트(Cent) 다중 통화 환율 계산기, 2단계 영수증 OCR 스캐너, 1/N 정산표.
  - 4. 체크리스트 허브 (`TAB-TRIP-04`): 개인/공용 준비물 분류, 템플릿 로드, 준비율 프로그레스 바.
  - 5. 멤버/공유 허브 (`TAB-TRIP-05`): 권한별 멤버 관리(방장/편집자/뷰어), 만료 초대 링크 발급, 비공개 메모 마스킹 웹 일정 발행, 9:16 여행 영수증 이미지 발행.
- [x] **오프라인-퍼스트 지원**: 비행기 모드 캐시 읽기, 네트워크 복구 시 백그라운드 지연 동기화.

### 5.2 제외 범위 (향후 2단계 로드맵)

## 6. 상세 기능 요구사항 및 수용 기준

### FR-1: 무마찰 게스트 온보딩 및 첫 여행 생성

- **설명**: 사용자가 회원가입이나 로그인 없이 즉시 앱을 둘러보고 60초 안에 첫 여행 일정을 생성할 수 있도록 지원합니다.
- **사용자 스토리**: _처음 앱을 설치한 여행자로서, 복잡한 본인 인증 없이 바로 내 여행 목적지와 날짜를 넣어 일정표를 만들고 싶다._
- **수용 기준 (Acceptance Criteria)**:
  - [ ] **AC 1:** 앱 최초 실행 시 [로그인 없이 둘러보기] 버튼을 최상단 또는 명확한 CTA로 제공해야 하며, 클릭 즉시 메인 화면으로 1초 이내에 진입해야 합니다.
  - [ ] **AC 2:** 게스트 상태에서 생성된 여행 데이터는 기기 로컬 스토리지(MMKV/SQLite)에 안전하게 격리 저장되어야 하며, 앱 재부팅 후에도 유지되어야 합니다.
  - [ ] **AC 3:** 게스트 사용자가 추후 Google 또는 이메일 계정을 연동할 경우, 로컬에 저장된 모든 여행·일정·가계부 데이터가 유실 없이 원격 서버 DB로 100% 자동 마이그레이션되어야 합니다.
  - [ ] **AC 4:** 여행 생성 모달에서 국가/도시 미선택 시 [완료] 버튼이 비활성화되어야 하며, 시작일이 종료일보다 미래일 경우 인라인 에러 문구(`TP-TRIP-VAL-001`)를 표시해야 합니다.

### FR-2: DAY별 일정 타임라인 및 Google Places 장소 검색

- **설명**: DAY별로 방문할 장소를 Google Places 검색을 통해 등록하고, 방문 순서를 자유롭게 편집할 수 있습니다.
- **사용자 스토리**: _일정을 계획하는 총무로서, 현지 장소명을 구글 검색으로 정확하게 찾아 타임라인에 넣고 드래그로 순서를 바꾸고 싶다._
- **수용 기준 (Acceptance Criteria)**:
  - [ ] **AC 1:** 검색창에 키워드 입력 시 300ms 디바운스를 거쳐 Google Places 자동완성 API를 호출하고, 장소명/주소/카테고리가 포함된 리스트를 표시해야 합니다.
  - [ ] **AC 2:** 장소 선택 시 구글 플레이스 ID, 위도/경도 좌표, 영문/현지 장소명이 누락 없이 데이터 객체에 바인딩되어야 합니다.
  - [ ] **AC 3:** 장소 카드의 드래그 핸들을 조작하여 순서를 변경하면 `sort_order` 정수값이 즉시 재계산되며, 재실행 시에도 변경된 순서가 유지되어야 합니다.
  - [ ] **AC 4:** 동행자가 동일한 DAY의 일정을 동시에 수정하여 서버 버전 충돌이 발생할 경우 `TP-TRIP-CON-001` 에러 토스트를 노출하고 최신 데이터로 안전하게 화면을 갱신해야 합니다.

### FR-3: Google Maps 동선 시각화 및 마커-캐러셀 인터랙션

- **설명**: 해당 DAY의 모든 방문 장소를 지도상에 번호 핀으로 렌더링하고 방문 순서대로 폴리라인으로 연결합니다.
- **사용자 스토리**: _현장 이동 중인 여행자로서, 다음 목적지까지의 동선이 꼬이지 않았는지 지도에서 한눈에 보고 길찾기를 실행하고 싶다._
- **수용 기준 (Acceptance Criteria)**:
  - [ ] **AC 1:** 지도 진입 시 해당 DAY의 모든 마커 좌표를 포함하는 최적의 줌 레벨(`fitToCoordinates`)로 지도가 자동 중앙 정렬되어야 합니다.
  - [ ] **AC 2:** 하단 장소 캐러셀을 좌우로 넘기면 지도의 카메라 중심점이 해당 마커 위치로 부드럽게 팬(Pan) 이동해야 합니다.
  - [ ] **AC 3:** 장소 카드의 [길찾기] 버튼 탭 시 Google Maps 네이티브 앱 또는 웹 길찾기 URL로 위경도 좌표 파라미터를 넘겨 즉시 실행해야 합니다.

- **설명**: 해외 현지 통화(엔화, 달러 등)를 지원하며, 영수증 사진을 찍어 금액과 상호를 자동 파싱한 뒤 1/N 정산표를 계산합니다.
- **사용자 스토리**: _경비를 관리하는 총무로서, 엔화 영수증 사진을 찍어 자동으로 입력하고 원화 환산액과 동행자별 더치페이 금액을 확인하고 싶다._
- **수용 기준 (Acceptance Criteria)**:
  - [ ] **AC 1:** 모든 금액은 부동소수점 오차 방지를 위해 `amount_in_cents` (정수 센트/원) 단위로 저장 및 계산되어야 합니다.
  - [ ] **AC 2:** 영수증 촬영 후 [분석] 실행 시 3초 이내에 상호명, 결제 일시, 통화 기호, 최종 합계 금액이 추출되어 검증 확인 화면에 자동 채워져야 합니다.
  - [ ] **AC 3:** OCR 인식 실패 시 임의의 0원 저장이나 크래시 없이 수동 입력 모드로 전환되며 사용자에게 "금액을 직접 확인해 주세요" 안내를 제공해야 합니다.
  - [ ] **AC 4:** 참여 멤버를 선택하고 [더치페이 정산] 탭 시, 멤버 간 최소 송금 횟수를 보장하는 최적화된 1/N 송금액 목록이 계산되어야 합니다.

## 7. 비기능 요구사항

### 7.1 성능 (Performance)

- **앱 시작 시간 (Cold Start)**: 보급형 안드로이드 기기(Galaxy A34 등) 기준 앱 아이콘 클릭부터 홈 대시보드 인터랙션 가능 시점까지 **1.5초 이내** 완료.
- **화면 전환 및 프레임 레이트**: 모든 탭 이동 및 모달 노출 시간 **200ms 이하**, 타임라인 스크롤 시 **60fps(프레임 드랍 1% 미만)** 보장.
- **API 레이턴시**: Cloudflare Workers 기반 P95 응답 시간 **300ms 이내** (OCR 처리 및 이미지 업로드 제외).

### 7.2 보안 및 규정 준수 (Security & Compliance)

- **전송 및 저장 보안**: 모든 통신 구간 TLS 1.3 암호화 강제, 인증 토큰은 Android Keystore 연동 SecureStore 보관.
- **데이터 격리 (Row Level Security)**: D1 및 Supabase 데이터베이스에서 타인의 비공개 여행 데이터에 대한 SQL 직접 접근 원천 차단.
- **개인정보 보호 및 탈퇴 유예**: 회원 탈퇴 시 90일 유예 기간을 부여하며, 90일 이내 재로그인 시 1클릭 복구 지원. 90일 경과 시 개인 식별 데이터 영구 파기.

### 7.3 분석 및 로깅 (Analytics & Logging)

- **표준 에러 코드 체계 강제**: 모든 에러는 사전에 정의된 규약(`TP-{PAGE}-{CATEGORY}-{NNN}`)을 따르며, 모호한 500 에러를 사용자 화면에 절대 노출하지 않음.
- **핵심 퍼널 로깅**: `first_open`, `trip_create_step1`, `trip_create_success`, `invite_link_copy`, `receipt_scan_success`, `receipt_card_share` 이벤트를 GA4 및 Mixpanel에 일관된 네이밍으로 기록.

### 7.4 접근성 및 UI 표준 (Accessibility - WCAG 2.1 AA)

- **색상 대비**: 모든 본문 텍스트와 배경 간 명도 대비는 **4.5:1 이상** 준수.
- **터치 타겟**: 모든 클릭 가능 요소는 패딩 포함 최소 **48 x 48dp** 터치 영역 확보.
- **시스템 폰트 200% 대응**: 사용자 OS 글꼴 크기가 200%로 설정되어도 텍스트 잘림 없이 유연하게 줄바꿈 레이아웃 유지.

## 10. 프로젝트 개발 및 거버넌스 원칙 (Rule of Truth)

1. **단일 진실 공급원 (Single Source of Truth) 원칙**:
   - 모든 화면 구현과 데이터 구조는 본 문서(`TripPrint_통합_PRD_및_시스템기획서.md`), `DB_객체사전.txt`, `오류코드_계약.md`를 절대 기준으로 삼습니다.
   - 문서에 명시되지 않은 임의의 팝업, 가짜 로그인/더미 데이터 삽입은 절대 금지합니다.
2. **사전 계약 우선 개발 (Contract-First)**:
   - 클라이언트 화면 개발 전 API 입출력 및 로컬 스토리지 키 규격을 선확정하고 개발에 착수합니다.
3. **사용자 중심 에러 안내 원칙**:
   - 시스템 내부 예외(`NullPointerException`, `HTTP 500`)를 화면에 절대 노출하지 않으며, "어떤 문제가 발생했는지"와 "사용자가 취할 수 있는 다음 행동"을 쉬운 말로 제공합니다.
4. **엄격한 수용 기준(AC) 기반 완료 판정**:
   - 단순 코드 작성 완료가 아닌, 6절의 수용 기준(Given-When-Then) 체크리스트를 100% 충족했을 때에만 기능 개발 완료로 판정합니다.
