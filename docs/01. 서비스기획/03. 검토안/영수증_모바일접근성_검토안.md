- 버전: v0.1 / 작성·검토일: 2026-10-26 / 상태: 개발·디자인 인계용 검토안
- 사용자 방향: 국제 접근성 기준을 고려하고 모바일 환경을 우선한다.
- 적용 범위: 영수증 등록·확인·원본 보기, 메뉴 입력, 날짜/일정 연결, 관련 오류·확인 상태. 앱 전체 재설계는 아님.
- 구현 상태: 문서 작성만 완료. 앱·공통 토큰·HTML 시안 변경 및 실제 화면 캡처 검수는 미실행.

## 1. 국제 기준과 프로젝트 선택의 구분

WCAG 2.2 AA를 웹 접근성 목표로 삼고, 네이티브는 해당 원칙과 Android·Apple 플랫폼 지침을 함께 검수한다. WCAG 웹 기준을 네이티브 단위에 기계적으로 대입하거나, 일부 검사만으로 국제표준 전체 적합성을 선언하지 않는다. 폰트 16이나 여백 8의 배수는 국제표준의 일률적 요구가 아니라 제품 디자인 선택이다.

| 항목                   | 외부 기준                                                                                                           | 이번 인수 기준                                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 텍스트 대비            | WCAG 1.4.3: 일반 4.5:1, 큰 글자 3:1, 일부 예외                                                                      | 현행 프로젝트의 더 엄격한 모든 정보 글자 4.5:1 유지. 비활성·placeholder도 현행 자체 기준 적용 |

웹 CSS px, Android dp/sp, Apple pt, 물리 화면 픽셀을 같은 단위로 쓰지 않는다. React Native 논리 단위의 숫자뿐 아니라 실제 측정 영역과 시스템 글자 확대 결과를 확인한다. 플랫폼 지침은 국제표준 인증서가 아니다.

Apple 버튼의 44pt는 공식 검색 자료로 확인한 일반 권장값이며 이번 도구에서 본문 전체 열람은 제한됐다. 실제 프로젝트 인수 값은 기존 48을 사용한다. 숫자 하나로 모든 iOS 컨트롤의 절대 최소를 주장하지 않는다.

## 3. 모바일 우선 배치 계약

- 기준 폭은 현행 390, 우선 검수 폭은 320·360·390·430이다. 웹은 CSS px, 네이티브는 사용 가능한 논리 폭으로 기록한다. 사진·메뉴·입력 폼은 모바일에서 한 열로 배치한다.
- 입력 순서는 결제 정보 → 날짜·방문 연결 → 메뉴 → 합계/원본 보관 확인 → 저장으로 검토한다. 원본 보기는 편집 입력을 잃지 않고 왕복한다. 세부 화면 전환은 기존 236~238 경로를 우선 재사용한다.
- 메뉴 한 행은 별도 묶음으로 표시한다. 이름은 전체 폭, 수량·단가·금액은 좁은 폭/큰 글꼴에서 각각 다음 줄로 배치한다. 가로 표에 다섯 열을 억지로 넣지 않는다.
- 메뉴 카드 안쪽 16, 필드 라벨과 입력 사이 8, 필드 그룹 사이 12, 카드 사이 12, 다음 구역까지 24를 적용안으로 둔다. 모두 기존 토큰에서 선택한 값이며 국제표준의 필수 간격은 아니다.
- 삭제·메뉴 추가·재시도·원본 보기의 실제 터치 영역을 48×48 이상 확보한다. 보이지 않는 확장 영역이 다른 조작 영역과 겹치지 않아야 한다. 아이콘만 쓸 때도 대상 메뉴를 포함한 접근성 이름을 준다.
- 긴 상호·메뉴·오류는 줄바꿈하고 높이를 늘린다. 글자 축소·말줄임·고정 높이로 핵심 정보나 수정 행동을 숨기지 않는다. 금액과 통화도 줄바꿈 뒤 의미가 유지돼야 한다.
- 한 화면에서 주요 행동은 저장 등 하나를 우선한다. 저장 중 중복 실행을 막고 상태를 알린다. 고정 하단 행동을 사용한다면 키보드·안전 영역을 반영하고 마지막 입력·오류·초점을 가리지 않는다.
- 화면 회전·키보드 열림·접근성 글꼴 변경 시 입력을 유지한다. 좁은 가로 화면도 세로 스크롤로 완료할 수 있어야 한다.
- 모바일 최대 콘텐츠 폭 640과 Ledger의 1024 이상 확장 규칙을 유지한다. 큰 화면 두 열은 보조이며 확대 글자에서 한 열로 돌아간다. 큰 화면을 축소한 모양으로 모바일을 만들지 않는다.
- 미입력, 인식 중, 0개 품목, 부분 인식, 오류, 저장 중, 충돌, 완료 상태의 안내와 다음 행동을 모두 설계한다. 로딩/오류를 색이나 애니메이션만으로 전달하지 않는다.

## 4. 접근성 동작 계약

입력마다 지속적인 라벨과 오류 연결을 제공한다. ‘이름’만 반복하지 않고 대상 메뉴를 구분한다. 메뉴 추가 후 새 이름 입력, 삭제 후 인접 메뉴 또는 메뉴 추가 버튼으로 초점을 옮긴다. 저장 오류는 요약과 해당 입력에 접근 가능하게 한다.

TalkBack·VoiceOver에서 읽기 순서, 선택·비활성·저장 상태, 원본 보기의 열기·닫기와 복귀 초점을 확인한다. 웹은 키보드만으로 모든 행동을 수행하고, 초점이 보이며 고정 영역에 가려지지 않아야 한다. OCR 완료·오류·저장 결과는 보조기술로 알리되 대기 중 반복 알림으로 방해하지 않는다.

글자 200% 검사는 320 재배치 검사와 별도로 수행한다. 시스템의 더 큰 접근성 글꼴도 확인하고 최대 배율 제한으로 결함을 숨기지 않는다. 웹 사용자 텍스트 간격 재정의는 별도 검사이며, 네이티브에서는 시스템 글꼴/확대·화면 읽기 설정으로 검수한다.
