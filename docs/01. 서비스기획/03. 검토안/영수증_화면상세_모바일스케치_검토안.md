## 1. 화면 구성과 공통 규칙

S0는 기존 여행 선택 맥락, S1은 236 등록, S2는 인식 상태, S3·S5·S5M·S6은 **237 확인 화면의 연속 구역**이다. S4는 238을 참조한 원본 확대 보완안, S7은 확인 화면 위의 중복 비교, S8은 같은 확인 화면의 저장 상태, S9는 기존 기록 상세다. 스케치의 화면 선택기는 검토 도구이며 제품에 추가하는 메뉴가 아니다.

2026-10-26 구현 대조: S4 원본 확대와 S7 후보 비교는 확인 폼 안에서 열고 접는다. 독립 라우트를 추가하지 않아 입력과 기존 이탈 보호를 유지한다. 원본은 2배 확대와 스크롤을 제공하며 핀치 확대는 제공하지 않는다. 공통 헤더·GNB 규격은 바꾸지 않는다. 실기기 초점·확대 조작 인수는 개발 기록의 미검증 범위를 따른다.

모바일은 한 열이다. 확인 화면의 순서는 결제 정보·날짜 → 방문 연결 → 메뉴 → 합계·원본 보관·저장이다. 입력을 확인하기 위해 매 구역을 별도 페이지로 쪼개지 않는다. 스케치는 신규 경로를 표현하며 수정 모드의 차이는 아래에 명시한다.

공통 ScreenHeader의 한 행 뒤로가기·제목을 따른다. 제목 26/36·700, 뒤로가기 아이콘 24·터치48, 좌우20, 세로 여백6, 실제 기본 행60 이상. 긴 제목은 남은 폭에서 줄바꿈하고 높이를 늘린다. 작성·상세에서는 기존 GNB 숨김 정책을 유지하며 스케치에 새 탭을 넣지 않는다. 현재 `/trips/:id`와 `/diary/:id`는 GNB를 숨기며 영수증 독립 라우트는 없다. 236은 ReceiptCapture, 237은 PlanEditor의 모달 상태다. `/record/:id`는 메모·사진 편집이므로 영수증 등록 경로로 단정하지 않는다. 실제 화면 통합 시 기존 navigation 정책을 다시 대조한다.

본문16/26·400, 보조14/22, Ledger 구역 제목20/28, 카드 제목18/26·600, 버튼16/24·600. 카드 안쪽16, 그룹12, 구역24, 라벨과 입력8, 최소 조작48×48, 주요 행동 최소52. Pretendard와 현행 Ledger 색을 사용한다. 색·선택만으로 상태를 구분하지 않는다. 안전 영역은 실제 기기에서 한 번만 적용하고, 스케치는 가상 기기 노치·상태표시줄을 그리지 않는다.

모든 입력은 화면 생존 중 유지한다. 원본/후보 보기 왕복은 값·스크롤·초점을 보존한다. 영속 자동 저장으로 안내하지 않는다. 수정 모드는 동일 영수증·지출 ID와 원본·보관 선택을 유지하며 사진 교체는 제공하지 않는다. 금액·날짜·통화·메뉴 변경 후 확인이 필요한 상태는 다시 확인한다.

## 3. 화면별 상태·행동 명세

### S0 여행 선택·권한 확인

- 목적·입력: 현재 여행 또는 완료 여행을 선택한다. 제목·기간·여행 상태·사용자 역할을 서버 확인 후 표시한다.
- 정상: 선택한 여행과 ‘이 여행에 기록하기’. COMPLETED도 진입 가능. 뷰어는 기록 조회만 가능하다.
- 빈 상태: 여행이 없으면 ‘등록할 여행이 없어요.’, 기존 여행 만들기/돌아가기. 여행 생성은 별도 기존 흐름이다.
- 오류: 조회 실패는 재시도·돌아가기, 로그인 필요는 로그인 복귀, ARCHIVED는 권한 있는 보관 해제 경로. 뷰어에게 해제/수정 행동을 주지 않는다.
- 처리 중: 여행을 확인 중이며 진입 버튼 잠금. **이 화면은 저장하지 않으므로 저장 중은 해당 없음.**
- 복귀: 이전 여행 목록/기록. 로그인 후 선택과 권한 재검증. 검증 D06·P03.

### S1 영수증 등록 — 236

- 목적·행동: 실제 카메라 또는 앨범으로 한 장 선택. 원본 업로드 성공 후 S2. 사진 없는 사용자는 기존 비용 직접 입력으로 나갈 수 있으며 메뉴 영수증 저장과 구분한다.
- 정상: 선택 사진 미리보기와 ‘이 사진으로 계속’, 사진 다시 선택. 자동 업로드 구현을 선택한다면 별도 계속 버튼과 중복 실행되지 않게 한다.
- 빈 상태: 사진 없음 안내, 촬영·앨범 행동. 예시 영수증으로 실제 선택을 대신하지 않는다.
- 오류: 권한 거절은 설정·앨범 대체, 업로드 실패는 재시도·다른 사진. 사용 가능한 행동만 표시한다.
- 처리 중: ‘사진을 올리고 있어요’, 사진 변경과 중복 실행 잠금. 업로드는 일정·지출 확정 저장이 아니다.
- 복귀: 최초 선택 취소는 S0, 사진 재선택 취소는 기존 입력 S3로 돌아간다. 검증 Q02·F07.

### S2 영수증 인식 상태 / E2 — 713

- 정상: 인식 성공은 내용을 확정하지 않고 S3로 이동한다. 부분 인식은 해당 빈 필드와 함께 S3로 이동한다.
- 빈 상태: 읽힌 항목 없음. 원본 확인·직접 입력·다른 사진을 제공한다.
- 오류: ‘영수증을 읽지 못했어요.’와 재시도·다른 사진·직접 입력. 제한 초과는 반복 호출 대신 가능한 재시도 안내·수동 입력.
- 처리 중: ‘영수증을 읽고 있어요’. 실제 진행률을 모르면 퍼센트 표시 금지. 저장 중이 아닌 인식 중이다.
- 복귀·취소: 입력이 있으면 X, 늦은 응답은 닫힌 화면·다른 계정에 적용하지 않는다. 검증 F06·Q03.

### S3·S5·S5M·S6 영수증 확인 — 237

- 정상: 위 입력 순서와 제약을 적용. 같은 DAY 방문 후보와 새 장소 선택, 메뉴 편집, 총액 차이 확인, 원본 보관 선택, ‘영수증 저장’ 제공. 수정은 제목 ‘영수증 수정’, 행동 ‘변경 저장’이다.
- 빈 상태: 필드 전체 빈 상태는 수동 입력으로 표시. 메뉴 0개와 일정 후보 0개를 별도로 안내하고 직접 입력·새 장소로 복구한다. 미확인 값에 예시를 저장값처럼 넣지 않는다.
- 오류: 필드 오류는 같은 폼 안에 표시하고 입력 보존. 총액 차이는 E4로 확인, 실제 미지원 통화는 저장 제한. 오류 요약에서 해당 필드로 이동한다.
- 저장 중: 같은 폼을 유지한 채 입력·메뉴 조작·저장 잠금, ‘저장하고 있어요’ 상태. 완료를 미리 보여주지 않는다. 키보드·초점·안전 영역을 고려해 스크롤로 마지막 항목에 접근한다.
- 결과: 후보 검사는 S7/E7, 저장 성공 확인 후 S9. 새 일정·메뉴·지출의 일부만 성공으로 표시하지 않는다. 검증 M01~M06·D01~D05·F08.

### S4 원본 보기 — 238 참조 보완안

- 현재 차이: 폼 안 원본 contain 표시는 있으나 독립 확대·이동 화면은 확인되지 않았다. 이 절은 신규 보완 명세이며 기존 구현 완료가 아니다.
- 정상: 원본 전체를 contain으로 보여주고 확대/축소·스크롤 지원. 사진 비율을 고정 크롭하지 않는다. ‘입력으로 돌아가기’는 입력과 초점을 보존한다.
- 빈 상태: ‘원본 사진을 보관하지 않은 기록이에요.’, 기록으로 돌아가기. 없는 원본 다운로드 버튼을 표시하지 않는다.
- 오류: 조회 실패 시 재시도·돌아가기. 권한 오류이면 이전 원본 캐시를 계속 노출하지 않는다.
- 처리 중: 원본 불러오는 중. **저장 동작 없음.** 스케치의 회색 영역은 원본 위치 표식이며 실제 영수증이 아니다.
- 검증: P01·P03·A03. 원본 읽기 순서와 돌아가기 초점 확인.

### S7 유사 결제 비교 / E7 동일 원본 중복

- 정상: 같은 여행의 후보를 카드로 표시. 날짜·상호·통화·총액·기록 종류·비교 이유를 보여주고 원본 입력과 비교한다. ‘기존 기록 보기’, ‘내용으로 돌아가기’, ‘별도 결제로 계속’ 제공.
- 빈 상태: 후보 없음은 별도 페이지를 띄우지 않고 저장으로 진행. 스케치에서는 빈 상태 설명용으로만 표시한다.
- 오류: 비교 조회 실패 시 입력 유지·재시도·내용으로 돌아가기. 비교를 건너뛰어 조용히 확정하지 않는다.
- 처리 중: 후보 확인 중, 확정 잠금. 별도 결제 선택 후 저장 중은 S8 상태로 전환한다.
- 확정 중복 E7: 동일 원본은 기존 기록 보기/등록 취소만 제공한다. 별도 결제 행동은 없음. 수정 대상 자기 자신·연결 지출은 후보에서 제외한다.
- 검증: F01~F04. 후보 왕복은 입력 보존, 실제 이탈은 X.

### S8 저장 결과 확인 / E5·E6

- 정상: 성공 응답과 실제 저장 대상 확인 후 S9. 장식용 성공 화면을 추가하지 않는다.
- 빈 상태: 조회할 확정 결과가 아직 없음은 성공/실패로 단정하지 않는다. 요청 확인 상태를 유지한다.
- 오류: E5는 ‘저장 결과를 확인하지 못했어요.’, 같은 요청 재확인. E6는 ‘동행자가 내용을 바꿨어요.’, 최신 내용 비교 후 S3에서 다시 확인한다. 입력 오류는 해당 필드, 권한 오류는 E0로 이동한다.
- 저장 중: 동일 요청만 처리. 신규 ID로 재등록·연속 저장 차단. 화면을 나갔다고 서버 작업 취소를 보장하지 않는다.
- 검증: F01·F05·Q03. 재접속 시 불확실 요청 복구 방식은 개발 계약에서 확정하며 새 오프라인 큐를 약속하지 않는다.

### S9 영수증 기록 상세

- 정상: 저장된 날짜·장소·메뉴·지출·원본 보관 여부. 신규 저장 직후에만 완료 안내. 기존 기록 열기는 저장 성공 안내를 반복하지 않는다. 수정·다음 등록·여행 기록 보기 제공.
- 빈 상태: 기록이 삭제됐거나 존재하지 않으면 ‘기록을 찾을 수 없어요.’와 여행 기록으로 돌아가기. 조회 중 빈 기록으로 단정하지 않는다.
- 오류: 조회 실패 재시도, 권한 오류는 돌아가기. 삭제 실패는 원래 기록 유지·재시도. 원본 정리 실패는 내용 저장 여부와 구분한다.
- 처리 중: 처음에는 불러오는 중, 삭제 요청이면 삭제 중 잠금. 상세 화면에서 새 영수증 저장은 하지 않음.
- 삭제 확인: ‘영수증과 연결된 지출이 삭제돼요. 장소 일정과 보관 사진은 남아요.’ → 취소/삭제. 보관 사진은 영수증 기록을 삭제해 참조를 해제한 뒤 기존 사진 삭제 흐름에서 삭제한다. 확정 영수증이 참조하는 사진만 먼저 삭제하는 행동은 제공하지 않는다. 새 삭제 범위를 추가하지 않는다. 검증 P04·P05·Q04.

## 4. 스케치 범위와 디자인 대조

2026-10-26 디자인 적용: 사용자 요청에 따라 기존 236·237 Ledger 시안의 흰 카드, 옅은 파란 입력 면, 원본 미리보기 카드와 붉은 주행동을 반영했다. `STITCH_CURRENT_SOURCE.json`의 237 모바일 원본 PNG·HTML과 현행 `ledgerTheme.ts`를 대조했다. 빈 상태·오류·처리 중에는 저장소의 하루 원본 이미지를 사용하며 재채색하지 않는다. 검토 도구의 TripPrint 로고는 화면 바깥에만 두고 앱 공통 헤더를 대체하지 않는다.

카드 반경16·안쪽16, 입력 반경12·최소48, 주행동 최소52, 모바일 좌우20, 제목26/36, 본문16/26·보조14/22를 유지한다. 원본 시안의 작은 글자, 프로필 사진, 인식 정확도, 결제수단, ‘나만 보기’ 문구는 복사하지 않는다. 승인된 데이터 범위와 공동 열람 정책을 따른다. 이번 시안은 디자인을 입힌 검토용 화면이며 실제 앱 적용은 아니다.

HTML은 문서용 독립 스케치다. 네트워크 호출·카메라·OCR·저장·로그인을 수행하지 않는다. 화면 내부 행동은 비활성 미리보기이며 상단 검토 도구만 화면·상태·폭·배율을 바꾼다. 정상/빈 상태/오류/처리 중을 나란히 보거나 단일 상태로 볼 수 있다. 저장하지 않는 화면은 처리 중을 조회·업로드·인식으로 표기한다.

정상 예시의 여행·상호·금액은 가상 검토 자료이며 화면 밖에 이를 명시한다. 원본 사진은 공간을 표시하는 도형만 사용한다. 이는 실제 서비스 캡처나 구매 증거가 아니다. GNB가 없는 작성·상세 맥락과 공통 헤더를 표시하며 실제 앱 컴포넌트 재사용 검증을 대신하지 않는다.

## 5. 개발 전 확인과 산출물 경계

- 승인된 정책은 구현 시 다시 추측하지 않는다. 미확정 사항은 공통 컴포넌트 적용 방식, 원본 정리 재처리, 결과 불확실 재진입 복구의 기술 계약이다.
- S3/S5/S5M/S6를 한 확인 화면으로 구현하고, S7/X/E4는 기존 시트/확인 패턴을 따른다. 데이터 모델 변경은 개발 단계에 DB 사전·API 계약과 함께 반영한다.
- 스케치에 보이는 새 메뉴 추가/삭제·중복 비교 등은 기획 범위이며 현재 앱에 이미 적용됐다고 안내하지 않는다.
- 기존 검수 M/D/F/P/Q/A를 재사용하고 50/51개 메뉴, 원본 미보관 수정, 확정 중복과 유사 후보 분리, 불확실 저장 후 재진입을 추가 확인한다.
- 스케치 검수 결과와 남은 차이는 아래 기록하며, 앱 테스트·빌드·배포는 이번 범위가 아니다.

## 6. 문서용 스케치 검수 기록

2026-10-26 문서용 HTML을 Edge에서 열어 검사했다. 14개 화면 묶음의 56개 상태를 폭 320·360·390·430과 글자 배율 100%·200%로 확인했다. 총 448개 배치 조건에서 화면 내부 가로 넘침, 제목 글자 크기 불일치, 48px 미만 행동 영역, 실행 오류가 없었으며 Pretendard 글꼴도 불러왔다. 검토 도구와 여러 화면을 나란히 놓은 바깥 보드의 가로 스크롤은 검사 대상 화면 내부와 구분했다.

영수증 확인 화면의 390px 상태별 배치, 320px·200% 배치와 중복 비교 화면은 캡처로 확인했다. 공통 제목·한 열 입력·카드 여백·선택 색·저장 중 잠금 표현을 대조했다. 읽기 전용 검토에서 발견한 수정 화면의 기존 장소 연결 기본값, 날짜 변경 뒤 미선택 상태, 상세의 원본 보관 여부와 삭제 진입을 보완했다. 삭제 확인·실패·처리 중은 별도 화면 묶음에 포함했다.

스케치의 원본 이미지는 도형이며 공통 확인 시트는 내용과 행동 순서를 설명하는 카드로 표시했다. 실제 앱의 키보드, 기기 안전 영역, 시스템 글자 확대, 화면 읽기 도구, 저장·권한·뒤로가기 동작은 검사하지 않았다. 앱 코드와 디자인 토큰은 변경하지 않았으며 실제 서비스 화면 인수는 개발 후 진행한다.
