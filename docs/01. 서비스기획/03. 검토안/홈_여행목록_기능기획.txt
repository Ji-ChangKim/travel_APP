여행 목록 중심 홈 · 기능기획 및 개발 계획
상태: 첨부 시안의 레이아웃·메뉴·출발일 분류는 사용자 지시 적용. 아래 보완 정책은 권장안으로 구분한다.
기준일: 2026-10-26
참조: 04_계획_여행목록.png, 디자인시스템.md, design-tokens.json, 헤더GNB_규격.md.
목업: 같은 폴더의 홈_여행목록_레이아웃목업.html. 예시 데이터이며 실제 앱과 구분한다.

1. 목적과 범위
다른 사용자 데이터 없이도 내 여행을 만들고 이어 쓸 수 있는 초기 MVP 홈이다.
추천 여행지·공개 피드·외부 통계에 의존하지 않는다. 화면 순서는 브랜드 헤더 → 하루의 팁 → 다가오는 여행 → 예정된 여행 → 작성 중인 일정 → 하단 홈/만들기/커뮤니티다.
브랜드 아이콘과 이름은 비활성 표시, 프로필만 클릭 가능하다. 실제 브랜드는 TripPrint를 유지한다.
사진이 없거나 아직 불러오지 못한 영역은 요청한 #FF00FF로 표시한다. 실제 예약 완료나 임의 여행 사진을 만들어 넣지 않는다.

2. 사용자 보완으로 확정된 분류
작성 중인 일정은 출발일이 없는 계획이다. 항공권·세부 일정 미입력은 분류 조건에서 제외한다.
출발일이 있는 저장 여행과 기기 초안을 함께 날짜순으로 정렬한다. 다가오는 여행은 오늘 이후 출발하는 가장 가까운 한 건이다. 해당 카드가 없으면 섹션 전체를 숨긴다.
예정된 여행은 다가오는 한 건을 제외한 나머지 날짜 확정 계획이다. 일정 건수가 0이어도 포함한다. 최대 3건, D-day 오름차순. 제목 옆 숫자는 표시한 3건이 아니라 후보 전체 개수다.
날짜가 있는 기기 초안은 기기 저장임을 표시하고 일정 보기 대신 이어서 계획으로 복원한다. 아직 서버 여행이 아니므로 친구 초대를 제공하지 않는다.
출발일 없는 기기 초안은 작성 중인 일정에 표시한다. 저장 성공 시 기존 생성 흐름이 해당 기기 초안을 제거한다. 서버 여행 ID와 초안 멱등 키는 다르므로 ID 일치만으로 중복을 판정하지 않는다. 초안 삭제 실패 시 같은 내용의 기기 초안이 남을 수 있으며 전체보기의 초안 삭제로 정리할 수 있다. 원격 생성 결과와 초안의 영구 매핑은 후속 보완 대상이다.
기존 tripLifecycle의 DRAFT는 7일 이상 남은 여행에도 사용되므로 작성 중 판별에 사용하지 않는다.

3. 추가 권장 정책과 이유
D-day는 각 여행의 현지 달력 날짜로 계산한다. DST와 시각 차이는 밀리초 시간이 아닌 날짜 차이로 처리한다. 같은 D-day는 시작일, ID 순으로 고정한다.
여행 중인 항목은 D-day가 음수인 다가오는 여행으로 섞지 않고 별도 여행 중 행으로 연결한다. 지난 여행·보관 여행은 전체보기에서 접근한다.
날짜 미정은 최근 기기 저장 순으로 표시한다. 현재 기기 초안 최대 5개 정책을 유지한다.
예정 여행이 0건이어도 전체보기는 남겨 지난 여행과 전체 여행 목록으로 이동할 수 있게 한다. 최초 방문에는 하루의 팁과 신규 계획 생성 안내를 제공한다.
동행 인원은 실제 멤버에서 본인을 제외한 수다. 친구 초대는 소유자에게만 제공하고 기존 동행 화면으로 이동한다. 누른 즉시 초대 링크를 만들거나 전송하지 않는다.
시안의 항공권 완료/숙소 예약 완료는 확인할 근거가 없다. 항공편 등록/숙소 일정 등록으로 표현한다. 예산·렌터카·가족여행 태그도 실제 필드가 없으면 생략한다.
전체보기에는 서버 여행뿐 아니라 날짜 있는 기기 초안의 나머지도 접근할 수 있어야 한다. 초기 구현은 전체보기 시트에 예정 여행 전부를 제공하고 전체 여행 관리 버튼으로 기존 목록을 연다.
서버 목록 실패와 초안 조회 실패는 구분한다. 오류를 여행 없음으로 바꾸지 않고 해당 조회의 재시도를 제공한다. 날짜가 없는 서버 여행 저장 지원은 현재 계약 밖이며 기기 초안을 활용한다.

4. 하루의 팁 운영 전략
초기 MVP는 검수한 상시 팁을 앱에 포함한다. 데이터와 네트워크가 없어도 한 문장을 표시한다. 앱 실행 세션의 첫 선택은 무작위, 이후 홈 재진입은 이전 팁과 다른 문구를 선택하며 화면 재렌더·스크롤만으로 바꾸지 않는다.
하루에 한 문장만 고정하면 접속마다 다양하게 보인다는 요구와 충돌하므로 오늘의 팁은 노출 영역의 이름이며 하루 고정 콘텐츠를 뜻하지 않는다.
확장 단계: 언어·국가·도시·월·여행 단계·유효기간으로 후보를 좁힌 뒤 최근 7개 노출 ID를 기기에 저장해 제외한다. 후보가 없으면 상시 팁으로 복귀한다. 계정 개인정보·실시간 위치는 수집할 필요가 없다.
계절 축제·운임·입국·결제 조건은 검수일·공식 출처·만료일이 필요하므로 초기 상시 팁에 넣지 않는다. 매번 생성형 AI가 사실을 만들어 내게 하지 않는다. KR/EN/JP 문구를 함께 검수한다.
초기 전달 문구: 숙소 주소 저장, 일정 사이 여유 시간, 지도 메모, 예약 확인서 보관, 영수증과 방문 기록 연결 등 앱 사용과 준비 행동 중심.

5. 상태와 접근성
정상: 실제 계정 자료만 표시. 비로그인: 팁·신규 생성, 생성 시 인증 후 복귀. 빈 상태: 다가오는 숨김·첫 계획 안내.
조회 중: 로딩 상태, 이전 계정 데이터 노출 금지. 오류: 메시지와 재시도. 일부 상세 실패: 기본 여행 카드 유지, 동행·예약 상태 추정 금지.
작은 화면 320/390/430px, 글자 200%, 긴 제목, 날짜 없음, 여행 0/1/5건, 서버+초안 중복을 확인한다.
공통 48 터치·기존 글꼴·색·안전 영역 유지. 사용자가 명시한 하단 3개 메뉴는 공통 GNB 계약으로 변경하며 중앙 버튼도 다른 두 메뉴와 같은 구조로 배치한다.
마젠타 위 흰 제목은 대비가 부족하므로 제목 뒤에 기존 진한 배경을 둔다. 이미지 외 영역을 마젠타로 바꾸지 않는다.

6. 개발 순서와 완료 기준
P0-1 목업: 시안의 영역 순서·카드 비율·3개 메뉴, 마젠타 이미지, 여행 있음/없음 전환. 실제 앱으로 오인하지 않게 표시.
P0-2 홈 모델: 서버·기기 초안 병합, 출발일 기반 분류, 초안·서버 구분, D-day 정렬, 최대 3건 및 전체 개수. 날짜·동률·경계·분류 단위 검사.
P0-3 앱 화면: 공통 헤더, 팁, 대형 카드, 목록, 작성 중 초안, 소유자 초대 연결. 사진은 권한 확인된 기존 사진만 사용하고 없으면 마젠타.
P0-4 탐색: 홈/만들기/커뮤니티 3개. 프로필 및 전체 여행 접근 유지. 뒤로가기·이탈 보호·로그인 복귀 확인.
P0-5 검증: npm run check, 헤더/GNB 검사, 홈 상태·여행 생성·초안 복원 브라우저 검사와 화면 캡처. 실기기 검증 별도.
보류: 예약 완료 인증, 자동 도시 통계, AI 실시간 팁, 공개 피드 기반 추천, 날짜 미정 서버 저장 스키마 변경.

7. 인계 및 출시 경계
문서·목업과 실제 앱 적용·검수 결과를 구분해 보고한다. 운영 배포·외부 초대 전송·기존 사용자 데이터 삭제는 이 작업에 포함하지 않는다.

2026-10-26 서버 전환 확정 사항
- 기존 기기 초안·고정 팁 정책을 서버 초안·발행 팁으로 변경한다.
- 여행/일정/동행/사진은 기존 회원 API, 초안은 /api/v1/plan-drafts, 팁은 /public/travel-tips를 사용한다.
- 출발일 기준 분류, 예정 최대 3개, 이미지 없는 영역의 마젠타 규격은 유지한다.
- 조회 실패를 빈 여행이나 예시 여행으로 대체하지 않는다. 저장 충돌 시 최신 계획을 다시 열도록 안내한다.
- 기기 초안은 전체보기에서 명시적으로 가져온 뒤 서버 확인된 항목만 기기에서 정리한다. 게스트 기록은 자동 이전하지 않는다.
- 서버에 발행 콘텐츠가 없으면 팁을 숨긴다. KR/EN/JP는 각각 ko/en/ja 콘텐츠를 조회한다.
- 적용 순서: 대상 DB 백업/마이그레이션 이력 확인 → 0010 적용 → API 배포 → 앱 배포 → 실제 계정 저장/재조회/다른 기기/오류 복구 검수.
- 이전 API로 되돌릴 때 새 테이블은 보존한다. 사용자 초안이 있는 테이블을 복구 목적으로 삭제하지 않는다.
- 이번 작업은 로컬 구현과 검증이다. 기존 배포 보류 지시에 따라 원격 DB와 서버는 변경하지 않는다.

최종 가져오기 정책: 이전 앱 탭의 동시 수정을 보호하기 위해 서버 가져오기 성공 후에도 기기 원본은 삭제하지 않는다. 홈 목록의 원본은 서버 데이터이며 기기 원본은 복구용으로만 보존한다. 앞선 가져오기 후 기기 삭제 설명을 대체한다.
