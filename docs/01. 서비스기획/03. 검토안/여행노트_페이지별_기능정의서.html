0. 이번 작업의 확정 범위
- 여행 노트 HTML 시안의 우측 상단 프로필 제거. 하단 MY를 계정 단일 진입점으로 사용한다.
- 실제 앱 HomeHeader·DB·API는 이번에 변경하지 않는다. 기능 정의 후 아래 단계로 개발한다.
- 사용자 확정: 로고·브랜드명·하루 보존, 모바일 우선, 한·영·일, 실제 서버 데이터, 영수증으로 방문 일정·메뉴 추가.
- 새 홈 디자인의 세부 정책은 제안 상태다. 기존 승인된 RCP-D01~D14 영수증 정책은 유지한다.
- “기존 처리 재사용”은 소스 연결을 확인했다는 뜻이다. 운영 서버·실기기에서 정상임을 새로 인증한 결과가 아니다.
- 기존 Page01~Page21 ID를 보존한다. 하위 단계 전체는 부록에 기존 ID로 추적하며 독립 페이지로 부풀리지 않는다.

1. 개발 진행 순서와 종료 조건
단계1 / 정의 대조: 이 문서의 페이지·권한·데이터·예외를 기존 구현과 대조한다. 미결정 정책은 H01~H04로 기록한다.
  산출물: 페이지별 차이표, 실제 API/모델 대응표, 미결정 사항. 종료: 각 CTA의 목적지·저장 대상·실패 복구가 정해짐.
단계2 / 공통 탐색: 실제 앱 홈의 상단 프로필 제거, MY 단일 진입, 뒤로가기/인증 복귀 유지.
  산출물: 공통 컴포넌트·규격 문서·회귀 검사. 종료: 홈에서 MY 접근, 상세 직접 링크 복귀, 미저장 이탈 보호 통과.
단계3 / 홈·내 여행: 서버 조회로 상태별 홈을 구성하고 작성 중인 초안을 구분한다. 예시 여행/통계는 넣지 않는다.
  종료: 처음/준비/진행/완료/빈/조회 중/오류 상태와 계정 전환에서 실제 데이터가 일치함.
단계4 / 생성·일정: 날짜·목적지·초안·생성·DAY 편집을 연결한다. 데이터 계약 변경 시 DB_객체사전.txt도 갱신한다.
  종료: 생성→상세→수정→재조회, 충돌·중복 요청·이탈 보호 검증.
단계5 / 영수증: 촬영/선택→인식→사용자 확인→방문/메뉴/비용 연결→재조회.
  종료: 여행 중/후, 날짜 변경, 중복, 부분 인식, 업로드 실패, 응답 유실 시 중복 저장 없이 복구.
단계6 / 공유·기록·계정: 공개 사본·동행 초대·개인 기록을 구분하고 기존 기능의 시각 규격을 순차 적용.
  종료: 공개받은 사용자·공유하는 사용자·계획하는 사용자 3개 여정이 권한별로 연결됨.
단계7 / 통합 인수: npm run check + 변경 영역별 기능 검사 + test:headers:web + 실화면 캡처 대조.
  웹: 320/390/430, 큰 글꼴, 긴 제목, KR/EN/JP, 키보드·초점·빈/오류/저장 중.
  기기: Android/iOS 권한·카메라·공유·안전 영역·뒤로가기·통신 중단. 미실행은 미검증으로 기록.
  배포는 별도 사용자 지시 후 진행. 단계 통과마다 변경 파일·검사 근거·남은 차이를 인계한다.

2. 공통 데이터 계약 / 아래 D번호는 기능 정의 참조키이며 새 API가 아니다
D01 여행 목록: GET /api/v1/trips → PersistedTrip[]. 계정별 쿼리 키. 시작/종료일·timezone·status를 보존한다.
D02 여행 원본: GET /api/v1/trips/:id/workspace → WorkspaceSnapshot. 서버에서 멤버십 검사, 버전 포함.
D03 초안: GET /api/v1/plan-drafts, PUT/DELETE /api/v1/plan-drafts/:id. 서버 revision, 현재 클라이언트 조회 최대5. 초안 한도 초과 시 덮어쓰기 금지.
D04 팁: GET /public/travel-tips?language=... → 실제 발행 팁. 빈 결과 숨김, 실패 재시도. 고정 예시로 대체하지 않는다.
D05 여행 변경: POST /api/v1/trips/:id/commands. If-Match=trip:id:version, Idempotency-Key. 명령 성공 후 해당 여행/목록 재조회.
D06 공개 자료: GET /public/community 및 /public/community/:postId, 회원 피드는 /api/v1/community. 비공개 원본과 분리.
D07 사진: GET /api/v1/trips/:tripId/media/:mediaId/url → 짧은 유효기간의 권한 있는 URL. 만료 시 새로 요청.
인증/업로드/OCR/프로필/탈퇴의 상세 URL·필드·오류 코드는 해당 서비스 소스와 스키마를 단계1에서 고정한다.
이 문서에 쓰지 않은 엔드포인트나 상태 코드를 새 서버 계약으로 간주하지 않는다.

공통 읽기: 진입/인증복원 → 계정·여행ID 확인 → 조회 → 응답 스키마 검증 → 화면. 계정/조건 변경 시 늦은 응답 무시.
공통 쓰기: 입력 → 로컬 검증 → 권한·서버 검증 → 실제 저장 → 응답 확인 → 관련 캐시 갱신·재조회 → 완료 안내.
오프라인: 서버 저장 완료로 표시하지 않는다. 별도 검증된 대기열이 없으면 자동 오프라인 동기화를 약속하지 않는다.
개인정보: 개인 메모·영수증 원본·위치·메뉴는 공개 사본에 자동 포함하지 않는다. 기존 승인 공개 정책을 따른다.
권한: 비회원=허용된 공개 읽기, 회원=자신/초대 여행, owner/editor/viewer는 서버 응답을 기준으로 허용 행동 구분.

3. 공통 예외와 서버 오류 / 제품 처리 기준, 모든 API가 이 코드를 이미 반환한다는 뜻은 아님
E01 401/세션 만료: 로그인 안내, 허용 목적 보존, 안전한 재인증. 일반 네트워크 오류와 구분.
E02 403/권한 상실: 변경 잠금, 원본 재조회/목록 복귀. 클라이언트 버튼 숨김만으로 보안을 대신하지 않음.
E03 404/삭제·공개 중단·없는 대상: 찾을 수 없음 안내와 안전한 복귀. 비공개 존재 여부 상세 노출 금지.
E04 400/422/입력 검증: 해당 필드·원인·고칠 행동. 입력 보존, 사용자 원문을 임의 변경하지 않음.
E05 409/412/버전 충돌: 최신 원본 확인 후 재편집. 다른 사람 수정을 자동 덮어쓰지 않음.
E06 429/쿼터: 재시도 제한과 가능한 다음 행동. Retry-After가 있으면 존중, 무한 자동 재시도 금지.
E07 5xx/오프라인/타임아웃(조회): 오류 영역과 재시도. 실패를 빈 배열·0건·예시 데이터로 바꾸지 않음.
E08 저장 응답 유실/부분 성공: 결과 재조회 후 같은 의도의 멱등 요청 재시도. 성공 여부 불명확 상태에서 새 키로 중복 생성 금지.
기기 예외: 카메라·앨범·위치·공유 권한 거절은 서버 오류와 구분. 취소는 오류 팝업을 남발하지 않음.

4. 공통 UI/UX·팝업 계약
본문 최소16, 보조14, 터치48, LINE Seed KR/EN/JP, 현재 로고 원본. 헤더/GNB는 공통 규격 재사용.
상태: 로딩/정상/빈/오류/저장 중/완료. 색만으로 의미 전달 금지. 숫자는 실제 조회 완료 후 표시.
팝업: 열기 전 초점 기억 → 제목/첫 입력 초점 → 배경 조작 차단 → 닫기/Escape/시스템 뒤로가기 → 호출 버튼 초점 복귀.
편집 팝업: 입력 변경 후 닫기는 계속 작성/버리기 확인. 전송 중 닫기 허용 여부는 해당 서비스의 취소·재조회 계약에 맞춤.
파괴 작업: 무엇이 삭제되는지 명시, 취소가 기본 대안. 자동 삭제·암묵적 동의 금지.
단일 화면에 주 CTA 하나를 우선하되 상황별로 달라짐. +는 생성, MY는 계정. 홈 상단 프로필은 제거.
검토 HTML은 예시·입력 미리보기만 제공하며 실제 저장/OCR/권한 검증의 증거가 아님.

5. 홈 상태 정책 제안 / 앱 반영 전 차이 검토 필요
H01 대표 여행 우선: 실제 진행 여행 → 가장 가까운 예정 여행 → 출발일 없는 초안 → 최근 완료 여행 → 처음 방문.
진행 판정은 여행 현지 날짜의 시작일≤오늘≤종료일. ARCHIVED는 대표에서 제외. 완료 상태/날짜 모순은 기존 도메인 정책과 조정 후 확정.
복수 후보는 시작일, 종료일, ID로 안정 정렬하고 여행 전환을 제공한다. 상세 일정 수가 아니라 출발일 유무로 미정 여행을 분리한다.
H02 날짜 미정: 초안 저장까지 허용하는 안. 최종 여행 생성에서 날짜 필수 여부는 기존 스키마와 맞춰 확정해야 함.
H03 영수증 진입: 단일 대표 여행이면 해당 여행으로, 복수/대상 불명확이면 선택 시트. 기존 비용 영역 경유와 새 직접 확인 흐름의 차이 검증 필요.
H04 여행 후 숫자: 실제 방문/메뉴 집계 정의 필요. 하나의 방문에 여러 영수증이 있어도 방문 수 중복 합산 금지. 없는 기록은 예시12건 등으로 대체 금지.
기존 승인 정책과 충돌하는 H항목은 적용하지 않고 영향·대안을 정리한다. 확정된 정책은 다시 승인받지 않는다.

정상은 자동 진행. 실패 시 다시 확인, 업데이트 필요 시 설치 경로 열기. 알 수 없는 외부 링크는 허용 경로 검사 후 안내한다.

5. UI/UX

시작 동안 GNB 없음. 가짜 진행률 대신 실제 대기 상태. 재시도 중 중복 실행을 막고 오류에는 다음 행동을 제공한다.

6. 예외·서버 에러

E01 인증 만료와 E07 통신 실패를 구분한다. 네트워크 실패를 로그아웃으로 단정하지 않는다. 복원 중 다른 계정 로그인 결과를 덮어쓰지 않는다.

Page02 · 로그인

/login / P0 · 기존 처리 재사용

1. 기능

실제 활성화된 Google·이메일 인증, 가입, 게스트/공개 열람 진입. 회원 저장과 게스트 기기 기록 범위를 구분한다.

2. 동작

보호 기능에서 진입하면 복귀 목적 보관 → 인증 성공 → 프로필 확인 → 원래 목적지. 게스트를 회원 서버 저장 성공으로 처리하지 않는다.

3. 데이터 흐름

이메일·비밀번호 또는 OAuth 시작 요청 → 기존 인증 서비스 → 세션·프로필 → 허용된 복귀 값. 비밀번호는 문서·로그·일반 기기 저장소에 남기지 않는다.

4. 팝업·CTA·Action

Google 로그인, 이메일 로그인·가입, 둘러보기, 언어 변경. 가입/로그인 폼은 같은 입력을 보존하며 오류 필드로 초점을 보낸다.

5. UI/UX

GNB 숨김, 입력 라벨 상시 표시. 비밀번호 붙여넣기 허용. 요청 중 버튼 잠금과 진행 상태. KR/EN/JP 안내 및 기존 언어 선택 유지.

8. 영수증·편집 하위 기능 개발 계약
Page09_02~03 일정 편집/복사/이동/삭제: 여행ID·DAY·일정ID·버전 → 폼 검증 → D05 → 해당 DAY 재조회. 삭제 영향 확인, 409 충돌 원본 확인, 입력 이탈 보호.
Page09_04~05 항공/장소: 조회 성공 후보와 직접 입력 구분. 공급자 실패는 수동 대안, 출처 보존. 선택 전 저장하지 않음.
Page09_06 지도: 실제 좌표만 표시. 좌표 없음과 지도 공급자 실패 구분. 이동시간을 임의 값으로 채우지 않음.
Page09_07~09 비용/사진: 통화별 합계, 서로 다른 통화 임의 합산 금지. 실제 저장된 비용만 집계. 업로드와 명령 실패 단계 분리, 사진 삭제 영향 확인.
Page09_10 영수증 입력: 권한 확인 → 촬영/사진 선택 → 파일 조건 검증 → 기존 업로드/OCR. 취소·권한 거절·지원하지 않는 형식/용량·업로드 실패를 구분. 처리 중 중복 제출 잠금.
Page09_11~12 영수증 확인/메뉴: 원본·추출값 병기, 상호·결제일·통화·총액·메뉴 수정. 인식 값은 확인 전 확정 사실로 표시하지 않음. 메뉴 추가/삭제·합계 차이 설명·잘못된 값 필드 오류.
Page09_13 날짜/중복/보관: 업로드일과 결제일 구분, 현지 날짜 확인. 기존 방문 연결 또는 새 실제 방문을 명시 선택. 원래 계획 자동 덮어쓰기 금지. 동일 방문 다중 영수증과 동일 영수증 중복 비용을 구분.
Page09_14 실패/재시도: 인식 실패는 직접 보완 또는 재인식, 저장 실패는 확인 폼 유지. 응답 유실은 E08. 가짜 OCR 결과와 성공 안내 금지.
Page09_15 삭제: 원본 사진 삭제/영수증·지출·방문 연결 해제를 구분해 영향 표시. 서버 실패 시 삭제 완료로 숨기지 않음.
Page09_16 준비물: 본인 역할 확인 → 항목 추가/완료 변경 → D05 → 체크 상태 재조회. 보기 권한 변경 금지, 실패한 체크를 성공으로 표시하지 않음.
Page09_17 동행: owner가 허용된 초대/권한/참여 해제 수행, 권한 서버 재검사. 초대 취소 후 토큰 재사용 불가, 공개 링크와 구분.
Page09_18~20 여행 정보/기간/도시: 변경 영향(삭제 DAY·연결 일정·비용)을 확인. 참조 중인 도시/날짜를 원본 기록 손실 없이 처리. 충돌 시 재조회.
Page09_21~24 공개: 공개 대상 선택 → 미리보기 → 명시적 확인 → 공개 사본 저장 → 링크 공유. 사본 저장 실패와 시스템 공유 취소를 구분한다. 공개 중단이 다른 사용자의 독립 사본을 삭제하지 않음.
위 하위 기능은 공통 팝업·UI·E01~E08과 해당 부모 페이지의 6개 정의를 상속한다.
핵심 영수증의 필드·중복·수정·보관 정책은 RCP-D01~D14가 최종 근거이며 문구로 “방문 인증 완료”를 임의 보장하지 않는다.
