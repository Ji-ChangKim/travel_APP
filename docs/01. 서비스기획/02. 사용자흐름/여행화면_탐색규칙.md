## 확인한 원인

홈은 저장 상태로 배지를 표시하면서 날짜로 안내 문구와 정렬을 계산했다. 저장 상태가 PLANNED이고 종료일이 지난 여행에서 ‘여행 예정’과 ‘지난 여행’ 안내가 함께 나올 수 있었다. 홈·목록·상세의 기간 기호와 열기 버튼 문구도 달랐다. 서버에서 날짜만 보고 자동 완료하는 로직은 확인되지 않았다. 서버의 저장 상태·권한 검사와 클라이언트의 날짜 표시를 혼용한 문제가 핵심이었다.

상세 라우트는 이미 루트 Stack에 있었지만 GlobalNavigation을 Stack 밖에서 거의 모든 경로에 렌더링했다. 탭 내부 상세의 push 설정보다 루트 전역 메뉴의 표시 범위를 고쳐야 했다. 일부 모달은 페이지 내부 레이어였고, 확인 창과 메뉴마다 중앙 카드·우측 팝업·하단 패널을 따로 만들었다.

## 공통 표시 기준

공유 도메인 `packages/domain/src/tripLifecycle.ts`가 여행지의 오늘 날짜로 정확히 네 단계를 판단한다. 기존 수동 저장 상태는 날짜 판별에 사용하지 않는다. 잘못된 시간대는 UTC로 복구한다.

| 조건                            | 화면 단계             | 주 행동       |
| ------------------------------- | --------------------- | ------------- |
| 날짜 미정 또는 출발까지8일 이상 | DRAFT / 준비 중       | 계획 계속하기 |
| 출발까지1~7일                   | PLANNED / 임박/예정   | 계획 계속하기 |
| 시작일≤오늘≤종료일              | IN_PROGRESS / 여행 중 | 계획 계속하기 |
| 종료일 이후                     | COMPLETED / 여행 완료 | 기록 보러가기 |

D-7을 임박에 포함하며 D-Day는 여행 중을 우선한다. 부분·잘못된 날짜·역전된 기간은 날짜 미정으로 표시한다. 표시 입력의 복구 규칙이며 API의 필수 기간 계약을 완화하지 않는다.

모바일 `tripPresentation.ts`가 같은 단계에서 뱃지·안내·버튼·기간을 만든다. 보관 여부는 별도 속성/필터다. 네 단계별 필터에서는 보관을 제외하고 전체/보관에서 찾는다. 저장된 조기 완료 값도 날짜 단계를 앞당기지 않는다.

날짜가 지난 원본 PLANNED 여행도 기존 권한으로 다이어리를 읽는다. ‘기록 보러가기’는 `/diary/{id}`, 나머지는 `/trips/{id}`로 연결한다. 날짜 경과로 원본 status·권한·공개를 바꾸지 않는다. 공개할 기록의 정리 완료는 기존 소유자·명시적 원본 COMPLETED·내용 선택 확인을 유지한다.

홈은 현재/가까운 여행 한 건의 실제 다음 일정 브리핑과 여행 팁/추천을 제공한다. 계정·여행별 기존 스냅샷을 읽고 여행지의 지난 시각을 제외한다. 조회 실패와 빈 기록은 구분한다. 홈 팝업 내비게이션과 내 여행의 홈 이동 버튼, 홈 도구의 하단 탭 중복 경로는 제거했다.

기간은 `YYYY-MM-DD – YYYY-MM-DD`, 날짜 미정은 ‘날짜 미정’으로 표시한다. 기존 전경 분 경계·앱 복귀 갱신과 배경 정리를 유지한다.

## 내비게이션과 시트

전역 메뉴는 `/`, `/plans`, `/footprints`, `/community`, `/my`에서만 표시한다. `/trips/{id}`, `/diary/{id}`, `/new-trip`, 인증·가져오기·여행지 상세에는 표시하지 않는다. 최상위 화면에서 연 전체 편집 패널에도 전역 메뉴를 남기지 않는다. 상세는 기존 상단 뒤로가기와 페이지 행동만 사용하며 작성 이탈·저장 잠금은 유지한다. SafeAreaView와 기존 페이지 행동 영역을 보존해 하단 시스템 영역을 두 번 더하지 않는다.

ActionSheet는 React Native Modal 기반의 공통 바텀시트다. 아래 고정·흰 표면·둥근 위 모서리·55% 어두운 배경·화면 높이 제한·내부 스크롤·하단 안전 영역을 적용했다. 삭제 확인, 작성 이탈, 항공편 건너뛰기, 여행 더보기와 권한 안내를 연결했다. 전체 입력 화면과 OS 선택기는 전체 화면 모달을 유지한다. 상단 제목을 중복 표시하지 않는다.

모달 등록·우선순위·닫기 전환·배경 읽기 차단·웹 Tab 순환과 Escape·초점 복원은 기존 AppModal 계층을 재사용한다. Android 뒤로는 onRequestClose로 같은 닫기 행동에 연결한다. 취소·바깥 영역·뒤로는 저장 명령을 보내지 않는다. 저장 중 닫기 제한은 각 기존 호출자가 유지한다. iOS·Android 실기기 동작은 브라우저 검사로 대신 인증하지 않는다.
