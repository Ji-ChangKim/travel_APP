## 여행 계획 만들기

기본 정보 화면은 상단 뒤로가기·제목·오른쪽 다음, 나의 여행 주제, 여행지 선택, 여행 날짜 순서다. 별도 취소와 하단 다음은 제거했다. 뒤로가기와 전역 이동의 작성 내용 보호는 유지한다.

주제 입력의 안내는 ‘여행의 타이틀을 생성해주세요.’다. 주제를 비우면 서버와 기기 게스트의 공통 생성 모델에서 실제 닉네임과 나라명으로 `{닉네임}의 {나라} 여행`을 만든다. 예를 들어 `Guest_A4A1AS의 일본 여행`이다. 닉네임이나 나라를 예시 값으로 채우지 않는다.

나라 선택은 ‘직접 입력하기’ 입력란 하나로 검색·입력을 처리한다. ‘이름으로 검색’과 모드 전환 버튼은 제거했다. 이름·별칭·국가 코드와 한글 초성으로 검색하며 입력 중에는 선택한 대륙을 넘어 모든 국가를 찾는다. 목록 탐색은 대륙 → 지역 → 나라 순서이며 아시아 → 동남아 → 베트남, 유럽 → 동유럽 → 폴란드처럼 표시한다. 기존 국가 선택 정책은 유지한다.

대륙·지역은 [UN M49 분류](https://unstats.un.org/unsd/methodology/m49/)를 여행지 탐색용으로 정리했다. 홍콩·대만·괌 등 기존 카탈로그의 여행 지역을 누락하지 않는다. 정치적 지위 판정 용도로 사용하지 않는다.

도시는 선택 항목이다. 목록에 없으면 같은 입력란에 이름을 입력하거나 도시 없이 진행한다. 저장값은 빈 문자열이며 나라명이나 임의 도시로 대체하지 않는다. 여행 허브와 주요 여행 목록의 위치 표시는 도시가 없으면 나라를 사용한다.

날짜 저장·전송은 `YYYY-MM-DD`다. 기본 정보 화면의 출발·도착 요약은 같은 해면 `MM-DD`, 서로 다른 해면 양쪽 모두 `YY-MM-DD`로 표시한다. 예: `12-30 → 12-31`, `26-12-31 → 27-01-02`. 시간처럼 보이는 콜론은 제거했다.

## 항공편 목록과 항공권 입력

항공편 목록은 출발 항공편과 도착 항공편 두 빈 슬롯으로 시작한다. 빈 슬롯은 예시 운항편이 아니다. ‘출발 항공편 추가하기’, ‘도착 항공편 추가하기’로 각 입력 페이지를 연다. ‘추가 항공권 등록’으로 여행 중 다른 구간을 등록한다. 전체 목록은 최대 30편이다. 출발·도착 슬롯은 각각 하나이며 기존 슬롯 수정은 다른 항공편을 덮어쓰지 않는다.

항공권 입력 화면 상단은 뒤로가기 아이콘과 오른쪽 완료다. 출발편은 여행 출발일, 도착편은 여행 도착일을 기본 출발일로 사용하며 여행 기간 안에서 변경할 수 있다. 추가편은 실제 탑승 날짜를 선택한다. 항공사 코드를 입력 → 조회된 항공사 선택 → 번호 3~4자리 입력 → 조회하기 → 구간 선택 → 완료 순서다. 항공사 선택 전에는 번호 입력을 잠근다. IATA 코드에는 7C처럼 숫자도 포함되므로 영문·숫자 두 자리를 허용한다. 실제 운항 번호의 앞 0과 ZE781A 같은 접미사는 보존한다.

항공사 이름과 코드는 [IATA 공개 회원 목록](https://www.iata.org/en/about/members/airline-list/)의 2026-10-15 조회에서 두 자리 코드가 있는 364행을 추출했다. 실제 한국공항공사 공개 운항 응답에서 확인한 21개 코드를 한국어 이름과 비회원 항공사 보완에 사용했다. 원문 페이지의 설명·이미지·로고는 복사하지 않았다. 이 목록은 항공사 선택용이며 현재 운항이나 항공권 예약 확인을 보증하지 않는다. 모든 비회원·신규 항공사가 포함된 전 세계 코드 DB로 안내하지 않는다.

조회 결과와 목록에는 편명, 출발 공항 → 도착 공항, 출발·도착 예정시각, 출발·도착 터미널을 표시한다. 제공되지 않은 항목은 ‘항공권 확인’ 또는 ‘정보 없음’으로 남긴다. 조회 당시 실제시각·게이트·기종·등록번호는 생성 목록에 늘어놓지 않는다. 기종·등록번호가 공급자에 있으면 기존 항공편 상세 계약으로 보존한다.

조회만으로 목록을 바꾸지 않는다. 조회 결과가 하나면 임시 선택해 완료를 활성화하고, 여러 구간이면 사용자가 고를 때까지 완료를 잠근다. 완료하면 해당 슬롯에 반영한 뒤 목록으로 돌아간다. 입력 변경이나 재조회 시작 시 이전 임시 선택을 해제하고 늦은 응답은 취소한다. 입력 페이지의 뒤로가기는 미완료 수정만 버리고 기존 목록을 보존한다. 별도 직접 입력하기와 취소 버튼은 없다. 번호 입력에는 숫자 키패드를 사용한다.

항공편이 없을 때 ‘건너뛰기’를 누르면 ‘추후 항공편을 입력할 수 있습니다.’와 확인 버튼 하나를 표시한다. 확인 후 기존 여행 생성·재시도 경로로 저장하고 여행 화면으로 이동한다. 건너뛰기는 입력값 초기화 버튼이 아니다. 등록한 편이 있으면 ‘여행 만들기’로 저장하며 비어 있는 출발/도착 슬롯을 강제로 채우게 하지 않는다.

## 저장 계약과 호환성

새 생성 입력 `flights[]`는 항공편 상세에 출발일 `date`, 출발시각 `time`, 역할 `role`을 더한 배열이다. 출발·도착 역할 중복, 여행 기간 밖 출발일, 30편 초과, 기존 단일 `flight`와 새 `flights`의 동시 입력은 거부한다. 도시는 생략 또는 빈 문자열을 허용한다. 기존 단일 `flight` 입력은 구형 클라이언트를 위해 유지한다.

각 항공편은 출발일의 DAY에 TRANSPORT 일정으로 저장한다. 시간은 일정 timeSlot, 나머지는 flight 상세에 보관한다. 생성 전용 date/time/role은 상세에 복사하지 않으며 생성 배열을 여행 속성에 중복 보관하지 않는다. Cloudflare D1의 trips.snapshot과 기기 게스트 JSON의 기존 저장소를 사용한다. 새 SQL 테이블·물리 컬럼·마이그레이션은 없다. 새 앱을 원격 서버에 연결하려면 새 생성 계약을 받는 API도 배포해야 한다.

## 조회 서비스에서 남은 범위

현재 키가 등록된 한국공항공사 API로는 국내선과 일부 한국 출발편을 조회한다. 해외 출발 귀국편, 인천 국제선 전체, 먼 미래 날짜와 터미널을 모두 제공하지 않는다. 항공사 목록을 넓혀도 운항 데이터 범위가 넓어지는 것은 아니다. 조회되지 않은 항공권을 가짜 데이터로 확정하거나 수동 입력으로 조회 성공처럼 처리하지 않는다.

전 세계 출발편·귀국편과 터미널 조회를 제품의 필수 조건으로 삼으면 해당 범위를 제공하는 추가 항공 데이터 서비스 계정·키가 필요하다. 기존 선택형 AeroDataBox 어댑터는 유지하며 추가 키 없이 유료 공급자로 자동 전환하지 않는다. 화면 개편 완료와 전 세계 조회 서비스 인수는 구분한다.

첫 전체 화면 검사에서는 80/91이 통과했다. 실패 항목에는 현재 개인 목록으로 연결되는 ‘내 여행’을 공개 홈 진입으로 사용하던 예전 검사, 저장/재시도 버튼을 동시에 고르던 선택자, 이전 화면에 남아 있는 동일 제목까지 찾던 선택자가 있었다. 공개 홈은 실제 홈 탭으로 진입하고, 저장 버튼과 화면 제목은 해당 화면의 대상으로 좁혀 검사를 수정했다. 기능 검증 조건과 제한 시간은 낮추지 않았다. 초반 집중 검사의 저장 직후 새로고침은 저장 완료·이동을 기다린 뒤 실행하도록 바로잡았다.

두 번째 전체 검사는 90/91이 통과했다. 다이어리 화면에 없는 여행 설정 버튼을 기준으로 제목을 찾던 검사도 화면에 보이는 제목을 확인하도록 수정했다. 이후 공통 검수 폴더가 다른 빌드와 겹쳐 서버 시작에 실패한 실행은 기능 검사 결과로 세지 않았다. 전용 출력 폴더와 포트에서 최종 91/91 통과를 확인했다. 항공편 화면 검사는 응답 고정값과 실제 KAC 응답을 보관한 검수 데이터를 사용하며 전 세계 실시간 조회 성공을 뜻하지 않는다.

기획 자체 검토에서는 기본 정보의 필수 조건·제목 생성·나라/도시 선택, 날짜 표현, 상단 행동, 항공편 슬롯 분리, 완료 시점의 목록 반영, 미완료 수정 보존, 저장 재시도와 실제 DAY 배치를 확인했다. 화면·저장 흐름과 조회 서비스 인수는 별개다. 해외 출발편·먼 미래 일정·터미널까지 조회해야 하는 서비스 요건은 추가 계정·키와 실제 범위 검증이 남아 있어 전체 서비스 기획 승인은 보류한다.

원격 Worker 비밀 등록·배포, 서명 APK/AAB, Play 업로드, Android 실기기 검수는 수행하지 않았다. 생성한 JavaScript/Worker 번들을 설치·배포 완료로 보고하지 않는다.
