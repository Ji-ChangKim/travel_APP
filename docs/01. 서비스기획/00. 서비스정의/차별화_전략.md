# 차별화 전략

## 1. 목적과 문서 상태

이 문서는 TripPrint가 다른 여행 앱과 어떻게 다르게 쓰여야 하는지 정한다. 사용자가 어떤 상황에서 TripPrint를 고르는지, 그때 무엇을 얻는지, 이를 위해 무엇을 먼저 만들고 무엇을 만들지 않을지를 순서대로 정리한다.

- 상태: **검토안**이다. 4절의 포지셔닝과 8절의 제외 범위는 사용자 확정이 필요하다.
- 기준일: 2026-11-13. 경쟁 앱 정보는 공개 자료로 확인했으며 앱을 직접 설치해 비교하지 않았다.
- 연결 문서: [서비스 개요](서비스_개요.md), [정식 출시 계획](<../03. 작업계획/앱웹_정식출시_계획서.md>), [MVP 기능 규격](<../01. 기능정의/MVP_기능규격.md>)

## 4. 포지셔닝

**한 문장 정의(검토안):** 영수증 한 장으로 실제 다녀온 곳·먹은 것·쓴 돈이 정리되고, 그중 고른 것만 다른 여행자와 나누는 여행 기록 앱.

- **주 사용자:** 여행 중이나 다녀온 뒤 "어디서 무엇을 먹고 얼마를 썼는지" 남기고 싶은 자유여행자. 동행과 경비를 나누는 2~4인 여행이 우선이다.
- **사용자가 TripPrint를 고르는 순간:** 계획은 다른 곳에서 대충 세웠거나 세우지 않았다. 손에 영수증과 사진이 남아 있다. 정리하기 귀찮지만 남기고 싶다.
- **경쟁 앱과의 관계:** 일정 추천·예약으로 경쟁하지 않는다. 계획은 가볍게 만들 수 있으면 충분하고, 기록의 정확함과 편함으로 차별화한다.

## 5. 차별화의 세 축

### 5.1 영수증 한 장 → 방문·메뉴·지출이 한 번에

사용자는 영수증을 찍거나 고른다. 앱은 상호·결제 시각·총액·품목을 읽고 어느 날짜 어느 일정인지 제안한다. 사용자가 확인하면 실제 방문 일정, 메뉴 기록, 가계부 지출이 함께 저장된다. 읽지 못한 값은 사용자가 고칠 수 있고 원래 계획은 바뀌지 않는다.

수용 기준(초안):

- 영수증 1장을 등록하는 데 확인 화면 1개, 저장 버튼 1번이면 끝난다.
- 결제일·현지 시각으로 날짜를 제안하고, 같은 장소의 기존 일정이 있으면 그 일정에 연결을 먼저 제안한다.
- 같은 영수증을 다시 올리면 중복으로 안내하고 지출을 두 번 더하지 않는다.
- 인식 실패·부분 인식에서도 사진은 보존되고 직접 입력으로 이어진다.

### 5.2 계획과 실제를 나란히

같은 DAY에서 ‘계획했던 곳’과 ‘실제로 간 곳’, ‘예상 비용’과 ‘실제 지출’을 함께 보여 준다. 여행이 끝나면 별도 정리 없이 여행 기록이 완성된다.

수용 기준(초안):

- 지난 여행을 열면 실제 방문이 있는 일정과 계획만 있었던 일정이 구분돼 보인다.
- 예상 대비 실제 지출 합계를 날짜·분류별로 보여 준다.
- 영수증이 없는 방문도 사진·메모로 실제 기록에 추가할 수 있다.

### 5.3 실제 기록에서 나온 공유

공개 일정에는 ‘영수증 근거가 있는 방문’과 ‘계획만 있는 일정’을 구분해 표시한다. 다른 사람은 실제로 다녀온 동선과 메뉴·가격을 참고해 자기 여행으로 담는다.

- 영수증은 결제 사실을 보여 줄 뿐 본인 방문이나 원본의 진위를 보장하지 않는다. 표시는 ‘영수증 기록 있음’처럼 사실만 쓰고 ‘방문 인증’이라고 쓰지 않는다.
- 영수증 원본·카드 정보·개인 메모는 공개하지 않는다. 메뉴명·가격 공개 여부는 사용자가 고른다.

## 6. 대표 사용자 흐름

| 시점      | 사용자 행동                                        | 앱의 결과                                                |
| --------- | -------------------------------------------------- | -------------------------------------------------------- |
| 출발 전   | 목적지·기간만 골라 여행을 만든다(선택: 장소 몇 곳) | DAY가 만들어지고 바로 기록할 준비가 된다                 |
| 여행 중   | 식사 후 영수증을 찍는다                            | 방문 일정·메뉴·지출이 저장되고 동행 가계부에 반영된다    |
| 다녀온 뒤 | 남은 영수증 사진을 한꺼번에 고른다                 | 날짜별로 자동 정리된 확인 목록을 보고 한 번에 저장한다   |
| 정리 후   | 공개할 일정·사진·메뉴를 고른다                     | 미리보기 후 커뮤니티에 공개, 언제든 철회 가능            |
| 다음 여행 | 커뮤니티에서 같은 도시의 실제 기록을 본다          | 마음에 드는 일정을 내 여행으로 담고 원본은 그대로 남는다 |

‘다녀온 뒤 한꺼번에 등록’은 현재 구현 범위가 확인되지 않았다. 6절의 흐름 중 가장 먼저 검증할 대상이다.

## 7. 현재 부족한 점

### 7.1 차별화를 막는 문제

1. **영수증 인식 실사용 검증 없음:** 실제 영수증 표본(국가·언어·상태별)으로 정확도·실패 처리·비용을 확인하지 않았다.
2. **대표 경험이 흩어져 있음:** 영수증 등록이 일정 추가·가계부·사진 메뉴 등 여러 곳에 있어 처음 쓰는 사람이 핵심을 알기 어렵다. 홈·여행 상세에서 ‘영수증으로 기록하기’가 첫 행동으로 보이지 않는다.
3. **게스트 제약:** 게스트는 기록이 이 기기에만 저장되고 장소 검색이 막혀 있다. 기록 앱에서 기록 유실 위험은 치명적이다.
4. **커뮤니티 초기 콘텐츠 없음:** 공개 피드가 비어 있으면 ‘실제 기록 담기’의 가치를 보여 줄 수 없다.
5. **통화 범위:** KRW·JPY·USD만 저장할 수 있다. 대만·베트남·태국 등 주요 근거리 여행지 영수증은 읽어도 저장하지 못한다.

### 7.2 기본기

여행 삭제 없음, iOS 미지원(후속 계획), 정산 송금액 계산 미확인, 오프라인 조회 미확인, 웹 E2E 검사 다수가 개편 이전 기준이다.

## 8. 하지 않을 것(검토안)

- AI 일정 자동 생성으로 트리플·Somewhere와 정면 경쟁하지 않는다.
- 항공·숙소·액티비티 예약과 장소 평점·리뷰 데이터베이스를 직접 만들지 않는다. 장소 정보는 지도 공급자 링크로 대신한다.
- ‘방문 인증’ 배지, 좋아요·댓글·팔로우는 1.0 범위에 넣지 않는다.

## 11. 결정이 필요한 사항

1. 4절의 한 문장 정의와 주 사용자를 확정할지.
2. 8절의 제외 범위(AI 일정·예약·리뷰 직접 구축 안 함)에 동의하는지.
3. 통화 확대 우선순위(예: TWD·VND·THB·CNY·SGD).
4. 커뮤니티 초기 콘텐츠를 운영팀이 직접 만들지, 초대 사용자에게 맡길지.
5. 게스트 서버 저장을 0.3에서 할지, 회원 유도로 대체할지.
