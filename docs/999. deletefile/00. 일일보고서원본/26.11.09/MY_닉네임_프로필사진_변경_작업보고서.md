# MY 닉네임·프로필 사진 변경 작업 보고서

## 요청과 적용 범위

Google 회원이 MY에서 선택적으로 닉네임과 사진을 바꾸도록 구현했다. 로그인 직후에는 추가 입력 없이 시작한다. 게스트는 Google 로그인 안내를 확인하며 서버 프로필을 만들지 않는다. 홈 레퍼런스에 대한 후속 질문에는 정보 구성안을 제안했으며 홈 레이아웃은 변경하지 않았다.

닉네임은 영어·숫자·한글·히라가나·가타카나, 공백 포함 1~10자다. 앞뒤 공백은 거부하며 중간 공백은 총 2개까지 허용한다. 영어 대소문자를 구분하지 않고 중복을 검사한다. 마지막 성공 변경 후 정확히 30일이 지나야 다시 바꾼다. 같은 값 저장은 변경 기회를 쓰지 않는다. 미설정 ‘여행자’는 기본 표시이며 고유 닉네임 예약이 아니다.

사진은 닉네임의 변경 간격과 무관하게 교체한다. 실제 PNG로 변환한 뒤 `tripprint-staging-private/User/profile/pfImg_{유저ID}.png`에 해당하는 고정 객체 키를 사용한다. 같은 회원이면 덮어써 현재 객체 한 개만 유지한다. 비공개 본인 조회로 표시한다.

## 화면 대조

참조 문서는 [디자인 시스템](<../../02. 디자인/00. 공통규격/디자인시스템.md>), [헤더·GNB](<../../02. 디자인/00. 공통규격/헤더GNB_규격.md>), [MY 변경 규격](<../../02. 디자인/01. 화면설계/MY_프로필변경_규격.md>)이다. 기존 공통 제목·설정 행동·하단 4탭·LINE Seed·버튼·입력·팝업을 재사용했다. 별도 색상·공통 치수 변경은 없다.

Chrome 실제 캡처 `nickname-confirm.png`, `photo-reloaded.png`, `my-320-font200.png`, `nickname-320-font200.png`를 확인했다. 기본·변경 후·중복 오류·작은 폭·큰 글꼴에서 내용 줄바꿈과 세로 스크롤을 유지한다. 큰 글꼴의 GNB 라벨은 공통 줄바꿈·높이 확장 정책을 따른다. 여행 화면의 기존 별도 변경은 이번 범위에서 되돌리지 않았다.

## 검토 기록

- 쟁점 ID / 대상: PROFILE-01 / 공통 검증·새 API·MY. 최초 검토(0회): 기존 가입 프로필 제거 정책과 선택 변경 지시를 구분했다. 새 계약에 해당하는 MY만 변경하고 과거 소개·생일·완료 요청은 열지 않았다.
- 쟁점 ID / 대상: PROFILE-02 / 사진·인증·정리. 최초 검토(0회): 회원 전환 뒤 늦은 응답, 사진 미리보기 재사용, 과거 개인정보 정리와 새 선택 자료 충돌을 확인했다. 회원 ID·세션 차수 확인, 고정 경로 소유권 검사, 새 이름 보존으로 조치했다.
- 쟁점 ID / 대상: PROFILE-03 / `cloudAuth.ts` 인증 DB 갱신. 최초 검토(0회): 선택 닉네임이 기본 ‘여행자’로 바뀌는 증상을 재현했다(`login-name-before.log`). 공급자 이름을 갱신에서 제외한 뒤 같은 조건의 5개 검사와 API 전체 179개가 통과했다(`login-name-after.log`, `foundation-final4.log`). 실제 외부 Google OAuth 검사로 확대 해석하지 않는다.
- 검증 실행과 실제 화면 대조는 주 에이전트가 수행했다. 별도 검토 담당의 완료 의견으로 대체하지 않았다.

## 홈 정보 구성 검토안

홈은 여행을 시작하고 기존 여행으로 돌아오는 화면으로 제안한다. 첨부한 레퍼런스의 인사말·원형 도시·빠른 도구 구성을 참고하며 공통 TripPrint 헤더와 하단 4탭은 유지한다. 다음은 제안이며 확정된 새 화면 규격이 아니다.

| 순서 | 정보·행동                                       | 필요한 데이터                                                           |
| ---- | ----------------------------------------------- | ----------------------------------------------------------------------- |
| 1    | 닉네임 인사·여행 D-Day 또는 여행 일차           | 프로필 이름, 여행 날짜·상태                                             |
| 2    | 진행 중·가장 가까운 예정 여행 한 개·이어서 열기 | 여행 ID, 도시, 제목, 기간, 작성 상태                                    |
| 3    | 검색·도시 원형 바로가기                         | 도시 ID, 이름, 국가, 대표 이미지. 집계 전에는 인기 순위로 표시하지 않음 |
| 4    | 새 여행·영수증 등록·지출 기록·준비물            | 대상 여행과 실제 연결할 화면. 저장·재조회 검수가 끝난 기능부터 노출     |
| 5    | 다른 여행자의 공개 일정·방문 기록               | 공개 게시물 ID, 유형, 도시·기간, 대표 이미지                            |

여행이 없으면 도시 탐색을 위에 두고, 여행이 있으면 내 여행을 우선한다. 여행 중에는 오늘 일정·영수증 등록을 앞에 배치하는 안이다. 기존 도시 자료·여행 날짜·상태·공개 목록을 활용할 수 있으나 오늘 일정 요약·영수증 상태의 홈 연결은 별도 검수가 필요하다. 실시간 인기·날씨·환율은 이번 기본안에 추가하지 않는다.

## 남은 검수와 반영 순서

실제 Google OAuth, Android·iOS의 카메라 권한·실기기 촬영, 원격 R2 업로드·재조회는 미검증이다. 로컬 저장 성공을 원격 저장 성공으로 보고하지 않는다. 웹에서 사진 선택·변환·서버 저장·재조회는 확인했으며 촬영 버튼의 기기 동작은 별도 설치본 검수가 필요하다.

원격 배포·DB 변경·커밋·푸시는 수행하지 않았다. 반영 시 대상 DB·백업을 확인하고 `0016_member_profile_names.sql` → API → 앱 순서로 적용한다. 복구 시 새 테이블·사진을 즉시 삭제하지 않고 보존하며 이전 개인정보 정리 코드가 새 자료를 지우지 않는지 확인한다.

게스트 여행 기록의 서버 저장·재조회는 기존 후속 과제로 남아 있다. 이번 Google 회원 프로필 변경으로 완료 처리하지 않는다. 홈 정보 구성은 인사말 → 대표 여행 → 도시 탐색 → 빠른 실행 → 공개 여행 제안이며 확정·구현 전 단계다.
