1. 읽는 기준

‘기존’은 저장소에서 구현·등록을 확인했다는 뜻이다. 운영 환경의 공급자 설정이나 Play 설치본에서 성공했다는 뜻으로 쓰지 않는다. ‘보완’은 현행 계약을 유지하며 연결·예외·검증을 보태는 작업, ‘신규’는 구현과 데이터 계약을 별도 확정할 작업이다.
아래 기술 목록은 초기 제안의 기준이다. 후속 요청에 따라 앱 기능과 staging API·웹, D1 migration0007을 반영했다. APK/AAB 생성과 Play 제출은 하지 않았다. APK는 설치 파일, SDK는 앱에 넣는 개발 도구, API는 서버나 외부 서비스의 통신 계약이다. 세 항목을 구분한다.
우선순위는 P0 저장·지도·권한 등 기능 신뢰, P1 핵심 화면 개편, P2 재사용·공유 유입 기능이다. 100만 다운로드 목표를 위해 모든 SDK를 추가하는 방식은 채택하지 않는다.
후속 실제 반영:공통 최소 터치48·중앙 확인·선택 상태, 발견 서버 필터, 원문/기간 보호, 공개 단계와 기록 단건, G11 계정 유예/복구를 적용했다. 새 SDK는 추가하지 않았다. 계정 예약 정리는 staging cron으로 연결했고 production 반영은 별도다. 공개 전 Google 사진 미리보기, Play 실기기 인수, 운영값과 보존/삭제 정책은 남아 있다.

2. 채택할 기본 기술

앱 | 기존 재사용 | Expo ~57.0.26, React 19.2.3, React Native 0.86.3, Expo Router. 실제 설치 버전은 lockfile과 빌드 결과로 고정한다. 개편을 이유로 프레임워크를 교체하지 않는다.
입력·상태 | 기존 재사용 | React Hook Form, Zod, React Query, Zustand. 입력 검증·서버 응답 검증·저장 중 잠금·충돌 복구를 기존 구조에 연결한다. 서버/공유 검증 패키지와 앱의 Zod 주 버전이 다르므로 임의 일괄 업그레이드는 별도 검토한다.
UI | 기존 재사용 | Pretendard 로컬 폰트, 디자인 토큰, 기존 헤더/버튼/모달, react-native-svg, Reanimated, Gesture Handler, Safe Area. 큰 글자·화면 읽기·동작 줄이기·배경 복귀를 화면마다 확인한다. 신규 UI 라이브러리 설치는 현재 필수 항목이 아니다.
지도 | 기존 재사용·P0 검증 | react-native-maps 1.27.2 + Google Maps SDK for Android. 마커·선택 DAY·지도 복귀를 유지한다. 현행 Polyline은 장소를 잇는 선이며 도로 경로·예상 이동 시간·최적 경로 API가 아니다.
현재 위치 | 기존 재사용·P0 검증 | expo-location. 사용자가 현재 위치를 누를 때 전경 위치를 요청한다. 지도 열기에 GPS 권한을 강제하지 않는다. 정확도 낮음·서비스 꺼짐·거부·설정 복귀·취소 뒤 늦은 응답을 검증한다. 상시 위치 수집은 범위 밖이다.
사진·영수증 | 기존 재사용·P0 검증 | expo-image-picker, image-manipulator, file-system. 실제 촬영/선택→압축→권한 확인→파일 업로드→원본 여행 연결→재조회까지 확인한다. OCR 결과는 확인 전 초안으로 유지한다.
항공권 | 기존 재사용·P0 보완 | 서버 항공편 조회와 이동 일정의 flight 필드. 조회 가능한 공항·편명·날짜 범위는 실제 공급자 응답으로 확인한다. 조회 실패·지난 편명은 직접 입력으로 등록할 수 있어야 한다. 항공권 사진/PDF 자동 파싱·메일 연동은 설치된 문서 선택 패키지만으로 지원된다고 안내하지 않는다.
인증·링크 | 기존 재사용·P0 검증 | Secure Store, Linking, Web Browser, 서버 인증·소셜 핸드오프. 로그인·온보딩 뒤 원래 여행/공개 링크 복귀와 역할 재검사를 확인한다. 설치 전 링크를 설치 후까지 복원하는 계약은 P2에서 별도 설계한다.
시작·업데이트 | 기존 재사용 | expo-video, 정적 로고, 시작 정책 API, tripprint-play-update 네이티브 모듈. BI 영상은 미제작이므로 흰 바탕 중앙 로고를 기본 대체 화면으로 유지한다. 원격 정책 운영값과 Play 업데이트는 실제 채널에서 확인한다.
서버 | 기존 재사용 | Cloudflare Workers + Hono + better-auth. D1을 현행 저장소, R2를 비공개 사진 저장소로 사용한다. Supabase 패키지·이전 문서가 남아 있어도 현행 주 저장소를 Supabase로 설명하지 않는다.
OCR | 기존 재사용·환경 확인 | 코드에서 AI 바인딩이 있으면 Workers AI를 우선 사용한다. 없을 때 GOOGLE_VISION_API_KEY 경로를 사용한다. 두 공급자를 매번 동시에 호출하지 않는다. staging 바인딩과 production 필수 키 선언의 차이는 배포 전에 정리할 항목이다.
품질·운영 | 기존 재사용·보완 | npm run check, 모델/권한/클라우드/웹 흐름 테스트, 요청 ID와 공급자 오류 구분. 저장 실패율·지연·중복·사진/OCR 비용을 관찰한다. 신규 분석 SDK는 개인정보·동의·보관·운영비를 정한 뒤 도입한다.

3. 외부 API·설정과 담당 구분

A. Android 지도 — P0 / 모바일·릴리스 담당
서비스: Google Maps SDK for Android.
키 이름: GOOGLE_MAPS_ANDROID_API_KEY. 현재 GitHub Actions Secret을 빌드에 주입하고 mapsBuildConfig.cjs가 네이티브 설정을 만든다. 키 원문을 문서나 로그에 남기지 않는다.
제한: com.tripprint.app + 사용할 서명 인증서 SHA-1 + Maps SDK for Android로 제한한다. 직접 설치 APK의 테스트/업로드 인증서와 Play 앱 서명 인증서는 다를 수 있다. 최종 제한은 Play 설치본의 앱 서명 인증서까지 대조한다.
확인: SDK 활성화·결제 계정·정확한 프로젝트·키 주입·서명 제한·Play Services 환경. Places 서버 키를 등록하는 것만으로 네이티브 지도가 설정되지는 않는다.
네이티브 지도 키·권한·모듈 변경은 새 Android 빌드가 필요하다.

B. 장소 검색·상세·사진 — P0 / 서버·운영 담당
서비스: Places API (New)의 Text Search, Place Details, Place Photos. 지도 SDK와 별도 기능이다.
키 이름: GOOGLE_PLACES_API_KEY. 서버 Worker Secret으로만 사용하고 앱·웹 번들에 넣지 않는다. 사용자에게는 이미 등록했다고 답변을 받았으나 이번 준비 작업에서 라이브 키의 활성 API·과금·제한 상태를 재확인하지 않았다.
확인: API 제한·최소 FieldMask·요청 시간 제한·호출량 제한·한도 소진 응답·오류 시 재시도·동일 장소 중복 요청 억제. Cloudflare Worker의 송신 IP를 고정 IP라고 가정해 IP 제한을 입력하지 않는다. 서버 사용에 맞는 제한 방법을 운영 구성과 함께 확인한다.
현행 검색 응답은 장소 ID·이름·주소·출처를 제공한다. 검색 결과에 좌표·영업시간·평점·전화·사진이 모두 들어온다고 가정하지 않는다. 검색 카드 사진과 지도 좌표가 필요하면 기존 상세/사진 흐름을 대조하고 필요한 필드·응답 계약·비용을 보완한다.
사진은 실제 Google 장소와 연결된 원본만 사용한다. 미등록·사진 없음·403·429·느린 응답에는 대체 이미지와 복구 행동을 둔다. 라이선스와 공급자 정책에 필요한 출처 표시는 유지하되 기존 화면의 긴 링크 나열을 간결한 사진 정보 UI로 정리한다. 새 이미지 복제·영구 캐시를 정책 확인 없이 추가하지 않는다.
무료 사용을 보장하지 않는다. 호출 제한·월 한도·서비스 중단 시 복구 UX를 운영값으로 정하고 비용 알림과 함께 관리한다. 숫자 목표는 이번 문서에서 임의 확정하지 않는다.

C. 항공편 — P0 / 서버·기획 담당
현행 기본: KAC 공공데이터 어댑터, KAC_FLIGHT_SERVICE_KEY, FLIGHT_LOOKUP_PROVIDER=kac.
대체 어댑터: aerodatabox를 명시적으로 선택한 경우만 사용한다. 실패했다고 유료 공급자를 자동 호출하지 않는다. 외국 출발편·지난 여행·과거 운항 정보 지원을 전체 보장하지 않는다. 직접 입력으로 일정 저장이 가능해야 한다.

D. 영수증 — P0 / 서버·운영 담당
Workers AI 바인딩 또는 명시적으로 설정한 Google Vision 경로를 사용한다. 앱에 OCR 비밀 키를 넣지 않는다. 원본 R2 접근 권한·파일 크기·인식 시간 제한·재시도·중복 지출 방지를 확인한다. 거래 통화가 불명확하거나 미지원이면 사용자가 확인할 수 있게 한다. 현재 실제 저장 통화는 KRW/JPY/USD다.

E. 로그인·저장소 — P0 / 서버·운영 담당
인증에 AUTH_SECRET, AUTH_BASE_URL, 소셜 공급자의 클라이언트 ID/Secret·등록된 콜백 주소를 대조한다. DB(D1)·MEDIA(R2)·AI 바인딩은 대상 환경별로 확인한다. staging은 코드상 wherego-staging / tripprint-staging-private이다. 이름 확인을 운영 접근·복구 검증으로 대체하지 않는다.
원본 여행과 공개 사본의 접근 정책을 분리한다. 로그인만 했다고 타인의 여행·사진·영수증 원본을 읽거나 변경할 수 없어야 한다.

workspace 명령은 {operation,input}으로 보낸다.
DAY 소개: day.plan / planTitle 최대200자, planConcept 최대2,000자.
장소 작성·수정: schedule.save / planContent.description 최대4,000자, 선택 그룹·선택/대체 구분. schedule.delete, schedule.reorder.
항공권 수동 등록: schedule.save의 TRANSPORT 일정에 flight 연결.
개인 메모: memo 최대300자. 공개 설명과 구분하며 공개 사본에 섞지 않는다.
지출: expense.save, expense.delete. 금액은 통화 규칙을 검증한 문자열로 저장하고 예상/실제를 구분한다. 통화가 다른 금액을 그대로 더하지 않는다.
여행 정보·기간: trip.update, trip.period. 기간 변경 시 DAY ID와 연결 기록을 보존하는 기존 계약을 회귀 확인한다.
사진: media.register, media.delete. 파일 업로드와 메타데이터 연결 성공을 각각 확인하고 중단된 업로드 정리도 검증한다.
영수증 확인: receipt.confirm, receipt.update, receipt.delete. OCR 초안과 실제 비용 저장을 구분한다.
초대·권한: invite.create, invite.revoke, member.role, member.remove. 쓰기 전 현재 역할을 다시 확인한다.
공개: community.publish(kind=plan|record), community.withdraw. 선택 scheduleIds/photoIds/includeCosts로 공개 사본을 만들며 개인 메모·동행 개인정보·영수증 원본을 무단 포함하지 않는다. 본문 body 최대2,000자는 별도 필드다. 긴 여행 원문은 DAY·장소 설명으로 구조화해 보존한다.

저장 공통 조건
Idempotency-Key(UUID)와 If-Match("trip:<tripUUID>:<version>")를 유지한다. 성공 응답이 유실되면 같은 키·본문·버전으로 재시도해 중복 생성을 막는다. 충돌409에서는 최신 원본을 다시 읽고 작성 중 내용을 보존한다. 성공 문구만 확인하지 않고 재실행·다른 세션에서 읽은 값과 공개 사본까지 비교한다.
화면 이동·DAY 전환·검색어 변경·로그아웃 후 늦은 응답을 적용하지 않는다. 삭제·공유·제출 연타를 잠그고 재시도 가능한 실패를 구분한다. 전체 네트워크 장애를 ‘결과 없음’으로 바꾸지 않는다.

5. 제안했지만 신규 계약이 필요한 항목

P2 공개 계획을 내 여행에 담기: 현행 목록/상세/공개 API만으로 구현 완료되지 않는다. 인증·복제 대상 선택·새 여행/DAY/일정 ID 발급·소유권·출처·철회 이후 동작·중복 요청·기존 여행에 합칠지 여부를 확정한다. 개인 메모·동행자·영수증·비공개 사진은 복제 대상에서 제외한다. API 경로·본문·응답은 미확정이며 시안 버튼으로 구현된 것처럼 안내하지 않는다.
P2 저장한 장소: 현재 여행 일정과 별도의 저장함을 만들려면 소유권·중복·삭제·Google 표시 데이터 처리·기기/서버 동기화 계약을 추가한다. 신규 DB/도메인 변경과 DB_DICTIONARY.txt 갱신을 함께 진행한다.
P1/P2 발견 필터: 공개 계획/기록의 도시·일수·검색·페이징을 현행 응답과 대조한다. 서버에 없는 필터는 화면 문구만 추가하지 않고 검증·정렬·빈 결과 계약까지 보완한다.
P2 공유→설치→원래 계획 복귀, 측정 이벤트: 설치 전후 링크 유지·로그인 복귀·비공개/철회·동의·보관 범위를 먼저 정한다. 분석 SDK·원격 푸시·광고 SDK는 이번 기본 필수 목록에 넣지 않는다.
보류: Routes/경로 최적화, 환율·자동 정산, 예약 판매, 이메일 예약 자동 가져오기, AI 일정 자동 작성, 상시 이동 추적, 완전한 오프라인 쓰기. 현행 기능과 구분해 별도 비용·데이터 계약을 검토한다.

6. 필요한 APK·AAB와 도구

직접 설치 검수 APK | 필요할 때 생성 | staging 연결의 release APK. UI·촬영·권한·앱 복귀 확인용. 현행 CI는 업로드 키가 없으면 테스트 서명을 사용하므로 ‘release 빌드’와 ‘Play와 같은 서명’을 혼동하지 않는다. 테스트 서명 인증서도 지도 제한에 맞춰야 한다.
Google Play 내부 테스트 AAB | 최종 검수에 필요 | Play 등록용 번들. AAB 자체를 휴대폰에 설치하지 않는다. 업로드 키로 서명하고 Play가 배포한 설치본에서 지도·로그인·업데이트·링크를 최종 확인한다. 직접 APK에서 통과한 결과만으로 이 항목을 대체하지 않는다.
개발용 APK/dev client | 선택 | 네이티브 모듈·권한 개발에 필요할 때 사용한다. Expo Go만으로 최종 Google 지도/업데이트 검수를 끝내지 않는다.
경쟁 앱 설치본 | 비교 조사 선택 | 공식 Play의 Wanderlog·TripIt·Polarsteps·Tripadvisor·Trip.com을 같은 과제로 비교한다. 제3자 APK 다운로드는 필요하지 않다. 기존 역기획은 공개 등록 자료·스크린샷 조사이며 해당 앱 로그인 후 실기기 과제 수행 결과는 아니다.
도구 | 현행 | Node .nvmrc=22.17.0, npm lockfile, JDK17, Android SDK, Gradle, GitHub Actions. 로컬 네이티브 점검 시 Android Studio·adb를 사용한다. 최종 Play 설치본은 USB 연결 없이 테스터가 검수할 수 있으나 실행 증거·기기/앱 버전·서명 조건을 남긴다.
휴대폰 보조 앱 | 선택 | Google Play/Play Services 환경과 외부 지도·인증 브라우저를 확인한다. Places API나 Cloudflare를 쓰려고 별도 공급자 APK를 설치할 필요는 없다.

현재 빌드 기준
현행 승인 경로는 .github/workflows/play-internal.yml의 Android Play Internal이다. main에서 artifact_type=apk|aab, submit_play 기본false, release_status=draft|completed를 선택한다. Expo prebuild 뒤 Gradle assembleRelease/bundleRelease를 실행한다. EAS 빌드 서비스는 이 경로에 필요하지 않다.
package.json의 build:apk/build:play-internal 계열 별칭과 eas.json은 EAS 경로를 남겨 두고 있어 현행 CI 문서와 다르다. 이 별칭을 현재 GitHub 빌드 명령으로 안내하지 않는다. 후속 정리 후보이며 이번에는 실행·수정하지 않았다.
서명 준비: ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS, ANDROID_KEY_PASSWORD. Play 자동 제출을 선택할 때 GOOGLE_PLAY_SERVICE_ACCOUNT_JSON과 내부 트랙 권한도 필요하다. 비밀 값은 사용자 화면·문서·로그에 출력하지 않는다.
현재 ver.text는 versionCode9 / versionName0.1.0이다. 이번에 올리거나 빌드하지 않는다. 실제 다음 업로드 전 Play에 이미 사용한 최고 버전을 확인해 재사용을 막는다.
산출물 인계에는 소스 커밋·API 리비전·환경·패키지명·버전·파일 SHA-256·서명 인증서 지문·검증 보고서를 기록한다. 서명 비밀 키는 인계 문서에 넣지 않는다.

7. 고객 과제별 인수 기준

항공권 입력: 조회 성공과 실패→직접 입력을 각각 등록한다. 재접속 후 날짜·시각·편명·공항을 비교한다. 영수증 OCR을 항공권 자동 인식이라고 안내하지 않는다.
일정 입력: 검색한 실제 장소를 올바른 DAY에 추가한다. 시간·순서·좌표/주소·Google Place ID·사용자 설명을 저장하고 다시 읽는다. 기간 축소·DAY 전환·충돌 뒤 연결 ID를 비교한다.
여행 계획 추가: 여행 제목·도시·기간→DAY 소개→장소 설명/팁을 일반 편집 화면으로 작성한다. 긴 원문·선택/대체 장소·개인 메모가 각 필드에 보존되는지 확인한다.
영수증 촬영: 권한 거부·사진 선택 취소·업로드 실패·OCR 실패·품목 합계 차이·통화 미지정을 확인한다. 사용자가 확정한 한 건만 실제 지출이 된다. 원본 사진 보관 선택도 다시 읽는다.
여행 경비 요약: 수동 지출과 영수증 지출의 예상/실제·통화별 합계를 대조한다. 재시도·수정·삭제 후 중복·잔존 금액이 없어야 한다.
커뮤니티 노출: 공개 일정·사진·비용 선택→실제 미리보기→확정→비로그인 공개 링크를 비교한다. 선택 해제한 항목과 개인 메모가 나오면 실패다. 읽기 화면은 편집/추가 권한과 구분한다. 철회 후 접근도 확인한다.
내 여행기록: 완료 여행을 재실행해 장소·사진·비용·기록으로 읽는다. 공개 철회와 개인 원본 삭제를 구분하며 동행 역할별 접근을 대조한다.

각 과제는 입력값·저장 응답·재조회값·공개값·원본 보존을 연결한 증거를 남긴다. 검수 계정과 구분된 데이터로 실제 서버 등록을 확인하되 이번 문서 작성에서 새 데이터는 등록하지 않았다.
공통 환경: 작은 화면, 글자200%, 긴 제목, 빈 목록, 키보드, 느린 네트워크, 권한 거부, TalkBack, 동작 줄이기, 배경 복귀. 화면 캡처와 실제 터치 동작을 함께 확인한다.
품질 검사: npm run check와 관련 auth/release/foundation/cloud/workspace 테스트를 변경 범위에 맞게 실행한다. 현행 CI도 이 검사 후 빌드한다. 기존 시안 검사 결과는 APP_REDESIGN_REVIEW.txt 12절에 있으며 신규 앱 기능/서버 인수 결과로 사용하지 않는다.

8. 디자인 컴펌과 착수 순서

사용자 요청에 따라 UI 경력10년 차 팀장 관점의 별도 AI 검토 역할에 같은 시안·현행 규격·캡처·브랜드 자산을 전달했다. 실제 사람 팀장이나 외부 조직의 승인으로 표현하지 않는다. 요청 문구는 ‘필요 시 APP 아이콘과 하루 캐릭터를 활용한 APP 디자인을 요청할 것’이다.
검토 원문: UI_LEAD_REVIEW.txt. 판정은 ‘개편 방향 조건부 승인 / 현 시안 일괄 개발 착수·출시 디자인 확정 보류’다. 공개 읽기와 개인 장소 추가의 혼동, 선택 공유와 미리보기 불일치, 홈 다음 일정 누락, 정상 지도·사진·동행·공개 확정 화면 부재를 수정 조건으로 받았다. 공식 아이콘의 선 굵기·표지 모서리와 하루 배치도 재검토한다. 사용자 최종 승인은 별도로 남아 있다.
착수 순서: UI 필수 수정→독립 재검토→사용자 검토→P0 기능/운영 설정 확인→P1 화면별 계약·구현→저장/공개 회귀→Play 산출물 생성 전 준비 검토. 공개 계획 담기 등 P2는 승인한 범위만 착수한다.
앱 아이콘과 하루는 기존 원본·라이선스·매니페스트를 우선 사용한다. 하루는 첫 여행·빈 화면·오류 복구에 쓰고 일정·비용·공개 개인정보 판단을 가리는 장식으로 늘리지 않는다. 앱 런처 아이콘 교체와 화면 안 아이콘 재사용은 별도 변경으로 관리한다.
