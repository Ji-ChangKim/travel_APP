TripPrint 화면 설계와 디자인 적용 가이드
기준일: 2026-10-19 / 대상: 전체 페이지 개편 제작본 / 상태: 사용자 최종 검토 전

1. 적용 범위와 기준 문서

누가 화면을 제작하더라도 제목·문구·버튼·입력·이미지·예외·팝업이 같은 원칙으로 동작하도록 정한다. 화면106개의 구체적인 기능·발생 조건·저장/이동 결과는 PAGE_FUNCTION_SPEC.txt, 번호/상위 관계는 pages/PAGE_MANIFEST.json이다. 현재 가이드는 디자인과 앱 적용 요구사항이며 전체 앱 반영 완료 선언이 아니다.
값의 원본은 design-tokens.json이다. 현행 브랜드/글꼴은 DESIGN.md, 헤더는 SCREEN_HEADER_SPEC.md, 공개 계획은 COMMUNITY_PLAN_SCREEN_SPEC.md, 일정은 ../1.uiux/ITINERARY_SCHEDULE_SCREEN_SPEC.md를 따른다. 개편 제작본의 차이는 PAGE_DESIGN_SYSTEM.txt에서 관리한다. 팝업 수치는 POPUP_SPEC.txt가 상세 원본이다.
사용자의 최신 지시를 먼저 적용하고 바뀐 문서에 적용 화면과 차이를 남긴다. 과거 스케치나 ui_design_system.md의 이전 색을 다시 적용하지 않는다. 같은 규칙을 여러 파일에서 서로 다르게 고치지 않는다. 기술적 제약이나 현행 API와 충돌하면 PAGE_FUNCTION_SPEC.txt의 보완 항목에 기록하고 실제 제공 범위를 먼저 맞춘다.

2. 화면 구조와 탐색

정보 구조
홈100은 한 여행의 다음 행동 브리핑, 내 여행200은 전체 여행 찾기, 발견300은 선택 공개된 계획/기록 탐색, 발자국400은 다녀온 여행 기록, MY500은 계정/공개 관리다. 홈에 전체 여행 카드와 바텀탭 경로를 반복하지 않는다.
전역 하단 메뉴는 최상위 영역에서만 표시한다. 개인 여행 상세는 일정·지도·비용을 고정된 세 작업으로 두고 나머지는801 여행 관리에 둔다. 일정 화면 하단에는 일정 추가 하나만 둔다. 지도·카메라·앨범 행동을 같은 바에 중복해서 넣지 않는다. 보기 권한에는 쓰기 바를 표시하지 않는다.
발견은 실제 공개 탐색 탭 이름이다. 명칭과 메뉴 순서는 전역 탐색에서 통일한다. API의 community 식별자는 유지한다.

헤더
최상위는 왼쪽 제목, 뒤로가기 없음. 홈은 기존 로고다. 일반 하위 화면은 최소56의 이동 바와 아래26/36 제목을 분리한다. 개인 여행 상세는 이동 바의 뒤로/더보기와 본문 첫 실제 여행명을 구분한다. 공개 계획·기록·공개 장소 상세만 뒤로가기 옆 실제 여행/장소명을 사용하는 기존 허용 규격을 따른다.
좌우 여백20과 본문 기준선을 맞춘다. 이동 바 아래8, 제목 아래4, 제목 뒤 본문 여백20은 현행 헤더 규격을 따른다. 뒤로/우측 아이콘24, 터치48×48 이상. 최상위 안전 영역을 헤더에서 또 더하지 않는다. 넓은 화면의 실제 앱 본문/헤더 최대너비640을 따른다.
긴 제목은 전체 줄바꿈한다. 고정 높이·임의 말줄임·글자 축소·확대 제한으로 맞추지 않는다. 확대된 텍스트 행동이 높이를 더 요구하면 바가 자연스럽게 늘어난다. 제목을 작게 바꿔 상단바에 끼워 넣지 않는다.

번호와 복귀
000 공통,100 홈/시작,200 내 여행 원본,300 공개 읽기,400 기록/선택 공유,500 계정,600 인증/시작,700 예외,800 팝업이다. Num_페이지명은 고정 식별자로 기존 번호를 다시 매기지 않는다. 새 하위 화면·예외·팝업은 parent와 실제 진입/복귀 위치를 함께 등록한다.
화면을 닫으면 원래 여행·DAY·스크롤·입력 맥락과 열었던 버튼 초점으로 돌아간다. 시트 안에서 다른 목적지를 선택한 경우에는 시트를 닫은 뒤 목적 화면을 연다. 여러 팝업을 겹쳐 뒤로가기가 어떤 작업을 취소하는지 모르게 만들지 않는다.

3. 색·글꼴·여백과 크기

색 역할
화면 #FFF9F3, 카드 #FFFFFF, 본문/제목 #203247, 보조 #596574, 링크 #A43E31, 주요 버튼 #FF6B57/#203247, 식별 경계 #8A7B70이다. 눌림은 #A43E31/#FFFFFF, 비활성은 #EEE8E2/#596574, 위험은 #9E3438/#FFFFFF를 사용한다. 이 값은 원본 토큰을 읽는 기준표이며 수정은 토큰과 같은 작업에서만 한다.
밝은 코랄을 작은 글자색으로 쓰지 않는다. 선택·완료·오류는 색과 텍스트/형태/접근성 상태를 함께 전달한다. DAY 채움·밑줄, 준비물 체크, 오류 아이콘과 문구는 서로 다른 의미다. 카드 장식 경계와 컨트롤 식별 경계를 혼동하지 않는다.

글꼴
본문은 로컬 Pretendard다. 제목26/36·700, 섹션22/30·700, 장소/카드18/26·600, 본문16/26·400, 보조/주소/날짜14/22·400, 버튼16/24·600, 시간/금액16/24·600. 하단 메뉴만13/20·600을 허용한다. 로고는 기존 원본을 쓰고 본문 폰트로 다시 그리지 않는다.
작성자가 적은 설명은 문단/줄바꿈을 보존한다. 원문을 보기 좋게 만들겠다고 요약하거나 가격·평점·영업 상태를 고치지 않는다. 긴 원문은 상세에서 읽는다. 사용자 글자 배율200%에서 제목은52/72이며 본문도 배율을 따른다. 표기 숫자는 날짜/통화 형식을 지키고 필요하면 고정폭 숫자를 사용한다.

간격과 모양
화면 좌우20, 카드 안16, 같은 묶음12, 섹션24. 카드 모서리16, 여행 표지20, 버튼/입력12, 팝업24다. 부모/자식이 각각 같은 패딩을 더해 이중 여백을 만들지 않는다. 간격을 맞추려고 빈 텍스트나 공백 문자를 넣지 않는다.
작은 화면은 정보 순서와 세로 배치를 조정한다. 글자를 줄이거나 사진 위로 겹치지 않는다. 시간·번호와 카드가 좁은 열에 끼면 위아래로 배치한다. 가로 스크롤은 DAY처럼 의도한 단일 컨트롤에만 허용하며 본문 전체가 옆으로 밀리지 않게 한다.

4. 버튼과 선택 컴포넌트

규격
주요 버튼 최소높이52, 일반 버튼48, 입력48, 헤더/아이콘/칩 최소 터치48×48다. 고정 최대높이를 두지 않아 큰 글자에서 늘어난다. 아이콘은24이며 원본 매니페스트의 선2·명시된 예외2.5를 유지한다. 버튼 글자16/24·600, 모서리12, 초점선2다. 터치 영역은 그림 크기와 별도로 확보한다.
주요 코랄 행동은 화면당 하나 이하로 둔다. 카드 전체의 열기와 버튼을 같은 위치에서 경쟁시키지 않는다. 보조 행동은 경계/링크/일반 버튼을 사용한다. 삭제·철회는 위험색과 실제 결과 동사를 사용한다. 비활성은 투명도를 일괄 낮추지 않고 지정 배경/전경을 사용한다.

상태와 문구
기본→눌림→처리 중→성공/실패를 구분한다. 처리 중에는 동일 동작과 관련 입력을 잠그고 busy/disabled를 전달한다. 버튼 너비가 스피너나 문구 때문에 흔들리지 않게 한다. 길어진 문구를 자르지 않는다. 요청이 끝나면 실패에서도 다시 사용할 수 있어야 한다.
라벨은 행동/결과를 설명한다: ‘장소 검색’, ‘일정 저장’, ‘공개 중단’, ‘계속 작성’. ‘확인’ 하나로 저장·삭제·이동을 모두 표현하지 않는다. 작동하지 않는 기능을 활성 버튼으로 보여주지 않는다. 필수 입력 미완료라면 가까운 안내로 필요한 다음 행동을 설명한다.

선택 규칙
DAY는 현재 읽는 날짜 탐색이다. 미선택 흰 배경/네이비, 선택 네이비/흰 글자·밑줄·selected/pressed 상태다. 체크나 체크용 빈 공간을 넣지 않는다. 글꼴 크기/굵기·테두리 두께·패딩을 전후 동일하게 해 모든 DAY의 위치와 크기를 유지한다.
공개 항목과 준비물은 다중 선택/완료이므로 체크를 사용한다. 체크 공간을 미리 확보하고 행 전체 라벨을 누를 수 있게 한다. 단일 역할/통화 선택과 다중 체크를 혼용하지 않는다. 아이콘만 바뀌는 선택은 화면 읽기에 이름과 상태를 제공한다.

5. 입력과 저장 피드백

라벨은 플레이스홀더와 별도로 표시한다. 선택 항목에는 ‘선택’을 붙이고 필수값을 추측하게 하지 않는다. 입력 아래에 단위·허용 범위·공개 범위를 필요한 만큼만 안내한다. 주소와 장소명, 공개 설명과 개인 메모는 다른 라벨로 구분한다.
형식/범위/필수 오류는 해당 입력 바로 아래에 표시한다. 첫 오류로 이동/초점을 안내하고 입력값은 유지한다. 키보드로 저장 버튼이나 오류가 가려지면 스크롤할 수 있게 한다. 화면 전체를 팝업으로 가려 입력칸을 찾게 하지 않는다.
닉네임2~20은 공백 포함 UTF-8 바이트다. 화면 문구와 실제 계산을 일치시키며 기존 이름 유지 예외를 보존한다. 생년월일은 선택이며 생일을 비웠다는 이유로 온보딩을 막지 않는다.
공개 설명은 DAY 소개와 장소 설명에서 작성한다. 개인 메모 바로 근처에 공개 제외를 알린다. 원문4000자와 공유 소개2000자를 같은 필드로 취급하지 않는다. 입력 제한의 상세 값/의미는 PAGE_FUNCTION_SPEC.txt와 검증 스키마를 따른다.
저장 버튼은 성공 응답 전 완료로 바꾸지 않는다. 정상 저장은 원래 화면 복귀와 반영 결과로 알리고 매번 중앙 성공 팝업을 열지 않는다. 응답 유실은 같은 요청 재시도 정책을 사용한다. 충돌은 내 입력/최신 자료를 비교할 경로를 제공한다.

6. 팝업을 여는 판단 규칙

중앙 확인을 연다
저장 전 실제 변경이 있는 이탈, 특정 일정 삭제, 공개 확정/중단, 로그아웃, 계정 탈퇴, 동행 참여 해제, 작성자 차단처럼 한 번 결정하면 결과가 달라지는 행동이다. 해당 버튼을 누르기 전에 매 진입마다 열지 않는다.802/803/805~808/810/819가 해당하며 기간 축소804는 연결 영향 확인 단계다.
제목은 무엇이 바뀌는지 묻고 본문은 대상·범위·되돌릴 수 있는지·남는 내용을 알린다. 확정은 실제 결과 동사, 취소는 유지할 행동을 쓴다. 실제 서버 영향과 다른 연쇄 삭제/복구 가능성을 문구로 약속하지 않는다.

하단 시트를 연다
현재 맥락의 관리 목록, 통화/시각/권한/사진 방법 선택, 초대, 출처, 짧은 신고 입력이다.801/809/811~818이 해당한다. 날짜/시간은 운영체제 선택기를 우선하고 시안의 HTML 선택을 새 OS 규격으로 강제하지 않는다.
선택만으로 저장하는 항목인지 폼 초안에 반영하는 항목인지 구분한다. 통화/날짜/시각은 원래 폼으로 돌아가고 최종 저장은 폼에서 한다. 권한 변경/초대는 실제 성공을 확인해야 한다.

상세 화면을 연다
장소 설명·팁, 긴 공개 읽기, 영수증 원본처럼 읽기/확대가 중심이면 전체 상세를 사용한다.221/222/311/238이 해당한다. 작은 중앙 창에 장문을 넣거나 카드 높이가 매번 늘어나는 인라인 펼침으로 바꾸지 않는다.

팝업을 열지 않는다
일반 검색0건·빈 일정·필수값/형식 오류·단순 저장 성공·사진 한 장 실패·평범한 DAY 전환이다. 해당 영역에서 설명과 다음 행동을 제공한다. 위치/카메라 권한 요청은 사용자가 그 기능을 선택한 때 필요한 OS 절차로 진행한다. 공통 팝업처럼 꾸민 가짜 권한 허용 화면을 만들지 않는다.
연결 장애가 일부 자료만 막으면 해당 영역에서 복구하고 이미 읽은 내용은 유지한다. 전체 진행이 불가능한 정책/인증 문제만 원래 맥락의 전용 상태로 안내한다. 위치 설정 복귀820은 위치 성공 확인이 아니라 재확인/우회 행동이다.

팝업20개의 정확한 발생 조건·확정/취소 결과·실패 동작은 PAGE_FUNCTION_SPEC.txt의5절을 원본으로 관리한다. 여러 곳에 다른 조건표를 복제하지 않는다.

7. 팝업의 공통 규격

중앙 확인: 양옆20, 최대너비350, 상하20 확보, 가용 높이를 넘지 않는다. 하단 시트: 화면 너비에 맞추되 최대640, 최대높이90%, 위 모서리24. 안전 영역은 하단 한 번만 적용한다. 제목/본문이 길면 본문 내부를 스크롤하고 행동에 접근할 수 있게 한다.
안쪽20, 제목26/36·700, 본문16/26, 보조14/22. 제목과 닫기 사이8, 제목 뒤 본문16, 버튼 간8. 주요 버튼52 이상, 일반48 이상, 닫기48×48 이상. 좁은 반쪽 버튼 둘 대신 세로로 배치해320px/200%에서도 라벨을 읽게 한다.
배경 네이비40% 가림, 배경 입력·읽기·스크롤은 잠근다. dialog/aria-modal 또는 플랫폼 동등 의미, 제목/설명 연결을 제공한다. 최초 초점은 닫기/취소처럼 안전한 행동, Tab/Shift+Tab은 팝업 안에서 순환한다. 닫으면 실제 열었던 버튼으로 돌아간다. 검토 도구 목록의 같은 이름 버튼으로 보내지 않는다.
Escape/Android 뒤로는 최상위 팝업 한 겹만 닫는다. 바깥 탭으로 저장·삭제·탈퇴를 확정하지 않는다. 바깥 탭 닫기를 허용하는 단순 선택에서도 초안을 확정하지 않는다. 처리 중 취소/닫기를 허용하는지는 작업 취소 계약과 맞춘다.
열기200ms·닫기150ms·배경150ms. 장소 상세는 오른쪽에서200ms 진입, 오른쪽으로150ms 종료한다. 동작 줄이기·화면 읽기·접근성 상태 확인 전·백그라운드에는 즉시 전환한다. 전환을 보이게 하려고 고정 대기시간을 추가하지 않는다.

8. 사진·아이콘·하루와 대체 표시

브랜드
기존 앱 아이콘·가로 로고·하루 원본을 재사용하고 종횡비·색·형태를 유지한다. 하루는 첫 시작·빈 화면·오류/복구·로딩의 보조다. 정보가 많은 일정/비용 화면에 반복 장식으로 넣지 않는다. 큰 글자/작은 화면에서는 행동과 본문이 먼저 보이도록 크기를 조정한다. 장식 캐릭터는 화면 읽기에서 제외한다.
아이콘은 기존53개 매니페스트와 앱의 플랫폼 뒤로/닫기/더보기를 쓴다. 모양이 비슷하다는 이유로 이모지나 임의 선 굵기의 아이콘을 섞지 않는다. 새 의미가 필요하면 기존 체계에 맞춘 원본과 이름/용도를 등록한다.

일반 사진과 표지
사용자가 공개를 허용한 실제 일반 사진을 우선한다. 없으면 검증된 도시 표지와 그 출처, 도시 표지도 없으면 공통 아이보리/흰 카드·기존 여행/장소 아이콘·실제 제목을 표시한다. 임의 관광 사진을 사용자 촬영 사진이나 해당 장소 사진으로 표시하지 않는다. 영수증은 표지로 사용하지 않는다.
장소 썸네일은88×88, 일반 여행 표지 모서리20을 따른다. 썸네일 안에서 비율을 유지하며 허용된 범위로 채우고, 사진을 세로로 늘이거나 중요한 글자를 겹치지 않는다. 출처가 요구하는 크롭/변경 규칙을 먼저 확인한다.

Google 장소 사진
응답의 실제 place ID·사진·제공자/저작자 정보를 연결한다. 카드의 작은 Google Maps 표기와 원본 접근, 상세 정보813을 기존 표시 계약에 맞춰 유지한다. 길게 반복되던 저작자 줄을 카드 설명 본문에 다시 넣지 않는다. 필요한 제공자 표시는 단순한 장식으로 취급해 삭제하지 않는다.
사진 없음: 같은 크기 아이콘 슬롯. 불러오는 중: 같은 크기 대기 슬롯. 통신/이미지 실패: 같은 크기 실패 슬롯과 재시도. 제공자 한도/일시 제한: 재시도 시점을 무리하게 반복하지 않고 원문 읽기를 유지한다. 권한이 사라진 사진 주소를 계속 재사용하지 않는다.
다른 장소의 사진·도시 대표 사진으로 조용히 바꾸지 않는다. 제작본 기본 슬롯과 실제 앱의 사진 조회 지원 상태를 구분한다. 외부 사진 키/인증/오류 코드는 고객 화면 문구에 넣지 않는다.

가이드와 영수증
도시 가이드는 해당 도시의 실제 자료명·저작자·라이선스·변경·원본을812에서 읽는다. 사진의 CC 조건을 도시 소개 텍스트에 일괄 적용하지 않는다. 사진 실패에도 본문/출처를 유지한다.
영수증 원본은 실제 권한 있는 파일을 읽는다. 로딩/실패를 가짜 영수증 그림으로 대체하지 않는다. 제작본의 종이 예시는 검토 도구 밖의 실제 서비스 증빙으로 쓰지 않는다. 원본이 없으면 원본 없음과 직접 금액 확인 행동을 제공한다.

시작 영상
tripprint_bi.mp4는 아직 제작되지 않았다. 영상이 없거나 손상·재생/첫 프레임 실패면 흰 배경 중앙 기존 로고 이미지를 표시한다. 다른 관광 영상이나 광고로 대체하지 않는다. 시작 점검/인증 복귀가 끝나면 한 번만 이동하고 배경에서 영상/타이머를 계속 실행하지 않는다.

지도
정상 앱은 실제 지도와 허용된 좌표/핀을 표시한다. 좌표가 없으면 임의 핀을 만들지 않는다. 지도 실패723은 장소 목록으로 우회한다. 디자인 제작본의 위치 도식은 도로 지도 대체 서비스가 아니며 실제 길찾기/소요 시간으로 안내하지 않는다.

9. 데이터가 없거나 실패했을 때

조회 성공0건일 때만 빈 화면이다. 기존 제목·DAY·검색어·필터를 유지하고 ‘무엇을 하면 되는지’ 한 문장과 첫 행동을 제공한다. 첫 여행701, 첫 일정702, 검색703, 완료 여행704, 지출721은 다른 원인과 행동을 쓴다. 차트를 채우려고 가짜 통계/후기/일정을 만들지 않는다.

처음 읽는 중에는 동일 정보 영역의 대기 상태를 사용한다. 이미 읽은 자료를 갱신할 때는 기존 내용을 보존하고 갱신 상태만 표시한다. 실패 원인은 사용자 말로 짧게 설명하고 다시 시도/직접 입력/목록/이전 화면 중 실제 가능한 복구를 제공한다.

일시 오류를 전체 화면 차단으로 확대하지 않는다. 단, 개인정보/권한이 사라진 원본은 보존한 캐시라도 계속 노출하지 않는다. 토큰/키/스택/API·DB 설정 설명은 제품 화면에 표시하지 않는다.

10. 아직 디자인이 없는 기능의 처리

미디어가 없는 경우와 UI 설계 자체가 없는 경우를 구분한다. 미디어는8절 대체 규칙을 쓰고, UI 설계가 없으면 아래 순서로 처리한다.
첫째, 같은 사용자 목적의 기존 화면/컴포넌트를 찾는다. 이름/데이터만 다른 동일 책임이면 기존 헤더·필드·버튼·상태·팝업 규격을 재사용하고 화면 번호/parent를 등록한다. 실제 동작과 다른 화면을 억지로 재사용하지 않는다.
둘째, 화면 틀은 같지만 새 상태가 필요하면 정상·빈 상태·오류·로딩·처리 중·권한 없음·긴 문구·큰 글자를 함께 설계한다. 새 화면의 기능/진입/복귀/저장/취소를 먼저 적고 최소 동작을 검토한다. 공통 규칙을 화면 하나 때문에 임의로 바꾸지 않는다.
셋째, 저장 영향/권한/삭제 범위가 새롭다면 기능 정의의 미확정 항목으로 남기고 계약부터 맞춘다. ‘디자인 없음’ 또는 ‘개발 준비 중’을 고객 화면에 노출하지 않는다. 동작이 준비되지 않은 신규 진입은 숨기고 이미 지원하는 읽기/직접 입력/기존 화면으로 안내한다. 기존에 작동하던 기능을 임의로 제거하지 않는다.
넷째, 고유한 새 패턴이 필요하면 기존 토큰으로 시안을 만들고 해당 번호/범위만 검토한다. 사용자 최신 지시·UI 검토 결과·남은 차이를 문서에 기록한다. 구조 스케치를 완성 디자인이나 실제 저장된 화면으로 제시하지 않는다.
다섯째, 정상/빈/실패 상태와 접근성·뒤로가기까지 제작한 후 실제 캡처를 문서와 대조한다. 화면만 추가하고 예외·팝업을 후속 미정으로 방치하지 않는다.

11. 문구와 공개 범위

고객은 개발 상태가 아니라 여행을 정리한다. 제목은 지금 다루는 여행/장소/작업, 설명은 얻는 결과/다음 행동, 오류는 수정/복구 방법을 쓴다. ‘검수용 날짜’, ‘API 설정 필요’, ‘제공자 키 없음’은 서비스 본문에 넣지 않는다. 예시 날짜/금액은 디자인 검토 도구에서만 구분한다.
공개 범위는 선택 직전과 확인 단계에서 짧고 구체적으로 알린다. 링크를 가진 누구나 읽는 내용, 공개에서 빠지는 메모·예약·동행·영수증, 원본이 남는 점은 이용자 선택에 필요하므로 숨기지 않는다.
여행 제목을 공유 헤더로 사용하고 DAY 제목/소개는 그 DAY와 함께 바뀐다. 장소 설명은 해당 일정에서 작성한 원문이다. 작성자 설명의 영업/가격/평점을 실제 실시간 확인값으로 단정하지 않는다. 새로운 홍보 문구나 검수 설명을 원문에 덧붙이지 않는다.
버튼과 문구는 연결된 기능을 실제로 제공할 때만 사용한다. 계획 복제·경로 최적화·항공 변경 알림·자동 오프라인 동기화 등 미지원 기능을 작동하는 것처럼 쓰지 않는다.
