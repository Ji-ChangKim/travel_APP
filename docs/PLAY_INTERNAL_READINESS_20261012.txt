1. 이번 배포의 테스트 목표

- Google Play 내부 테스트에서 설치한 앱이 Metro 개발 서버 없이 실행되는지 확인한다.
- 방문자는 계정 생성 없이 공개 발자국을 읽는다. 게스트는 Google 인증 없이 기기 계정을 발급받아 여행·사진을 로컬 저장하고 공개 발자국을 읽는다.
- 회원은 가입/로그인 → 국가·도시·기간·항공편 → 일정 → 영수증·지도 장소 → 나의 발자국 → 커뮤니티 공개/조회 흐름을 완료한다.
- 회원 저장 결과는 재실행과 다른 기기에서도 같은 계정에 복원되어야 한다. 게스트 기록은 같은 기기에서만 복원하며 다른 기기 동기화 대상이 아니다.
- 비밀번호·세션·비공개 사진·영수증·다른 계정 데이터의 보호를 확인한다.
- 사용자 확인: Google 북마크 요구사항은 장소별 공유 링크가 아니라 Google 계정 저장 목록의 직접 동기화다.

2. 요구사항별 판정

[수정 완료 / 실기기 인수 필요] 미가입 방문자 공개 발자국 탐색
  공개 API와 커뮤니티 화면은 있었지만 AuthGate가 로그인으로 돌려보내고 하단 메뉴도 모두 비활성화했다.
  로그인 화면에 "로그인 없이 여행 발자국 둘러보기"를 추가하고 공개 홈·커뮤니티 탭을 허용했다.
  공개 탐색에서 익명 계정·세션 토큰을 생성하거나 개인 여행 API를 호출하지 않는다.
  홈 미리보기의 로그인 전 영구 로딩을 수정했다.
  개인 여행·다이어리·프로필 경로의 로그인 요구는 유지한다.
  신고/차단 요청 시 로그인하고, 가입 설정까지 마친 뒤 공개 목록으로 복귀한다.

[추가 구현 / 원격 적용 및 실기기 인수 필요] 기기별 게스트
  Google 인증 없이 최초 시작 시 DB에 익명 회원을 등록하고 Quest-[A-Z0-9]{6}을 발급한다.
  DB에는 계정 관리 정보를 저장한다. 여행·DAY·항공편·일정·지출·준비물·사진·영수증은 기기에 저장한다.
  최초 발급 뒤 서버 연결이 끊겨도 같은 기기 기록을 재실행·편집할 수 있다.
  회원을 포함한 모든 닉네임에 고유 인덱스를 적용하며 가입·프로필 수정에서도 중복을 거부한다.
  게스트 영수증은 사진 선택 후 직접 입력한다. 커뮤니티 게시·동행 공유는 회원 가입이 필요하다.
  닉네임으로 다른 기기의 여행을 복원하지 않는다. 회원 전환 시 기기 여행을 자동 업로드하지 않는다.

[기존 구현 / 자동 검증 / 실기기 인수 필요] 회원 여행 생성
  국가·도시 선택, 출발일/도착일, DAY 생성, 선택 항공편 등록이 구현되어 있다.
  항공편은 사용자가 입력한 편명·공항·시각을 첫 이동 일정으로 저장한다. 실시간 운항 조회는 아니다.
  항공편 없이도 생성하고 DAY2/DAY3 등에 일정·영수증을 저장하는 흐름이 있다.

[기존 구현 / 공급자 실기기 인수 필요] Google 지도 검색·장소별 공유
  인증된 장소 검색, Google 장소 ID 선택, Google Maps 열기, 단일 장소 공유 링크 해석이 구현되어 있다.
  저장 목록 링크는 단일 장소 공유로 처리하지 않는다.
  장소 검색 자동 테스트는 공급자 응답을 격리한다. 실제 staging의 Places 키·결제·쿼터와 Android 검색 결과는 따로 검증한다.

[미완료 / 외부 서비스 제약] Google 계정 저장 목록 직접 동기화
  Google 로그인만으로 저장 목록을 읽을 수는 없다.
  Data Portability API의 saved.collections는 저장 링크·장소·컬렉션의 복사본을 제공한다.
  일반 로그인과 Data Portability 권한을 같은 OAuth 요청에 섞을 수 없으므로 별도의 동의 흐름이 필요하다.
  2026-10-12 확인한 Google 공식 지원 국가에 대한민국은 포함되어 있지 않다.
  지원 국가의 적격 계정에서도 앱 검증·API 활성화·별도 동의·비동기 내보내기·복사본 수신·중복 처리·접근 철회가 필요하다.
  API는 실시간 양방향 동기화가 아니라 복사본 이전이다. 내보내기에 수시간 또는 수일이 걸릴 수 있다.
  따라서 한국 계정용 직접 동기화는 현재 내부 테스트의 통과 항목으로 표시할 수 없다.
  Google Takeout 파일 가져오기나 장소별 공유는 대안이지만 사용자가 요청한 직접 동기화와 동일하지 않다. 이번에 파일 가져오기로 임의 대체하지 않았다.
  근거:
    https://developers.google.com/data-portability/schema-reference/save
    https://developers.google.com/data-portability/user-guide/configure-oauth
    https://support.google.com/accounts/answer/14452558?hl=en

[기존 구현 / 자동 검증 / 실기기 인수 필요] 영수증 촬영 후 일정
  카메라/사진 선택 → 비공개 업로드 → 인식 후보 → 사용자 확인 → 일정·지출 원자 저장이 있다.
  큰 PNG 압축, DAY3 등록, 사진 보관/정보만 저장, 중복 확정 방지, 실패 후 재시도 흐름이 있다.
  현재 사진 구조화 인식은 Worker AI 바인딩을 사용한다. 이전 Vision-only 설명과 구분한다.
  로컬 자동 테스트 성공이 실제 촬영 사진의 인식 정확도를 보장하지 않는다.

[기존 구현 / 자동 검증 / 실기기 인수 필요] 나의 발자국·커뮤니티 저장
  완료 여행의 날짜별 다이어리와 선택한 일정·사진·비용의 커뮤니티 공개/철회가 있다.
  비공개 메모·영수증 원본은 공개 게시물에 포함되지 않는다.
  실제 D1·R2 런타임에서 저장 재시도, 버전 충돌, 멤버 권한, 선택 공개, 공개 철회를 검증한다.
  실제 staging 공개 피드는 점검 시 HTTP 200, 게시물 0개였다. 가짜 게시물은 추가하지 않았다.
  공개 피드 인수에는 실제 테스트 계정 A가 기록을 게시하고 게스트/B가 조회하는 준비가 필요하다.

[기존 구현 / 자동 검증 / 실제 Google 인증 인수 필요] 회원 가입
  이메일·비밀번호·닉네임 가입과 프로필 설정, 재로그인·세션 복원이 있다.
  Google 로그인은 staging 제공자 조회에서 활성화되어 있다. 실제 계정 선택·동의·앱 복귀는 미검증이다.

[일부 검증 / 추가 보완 필요] 계정 보안
  확인 범위: 회원별 비밀번호 해시, 서버 서명 토큰, 만료·로그아웃 철회, 인증 요청 제한,
  PKCE 검증자·일회용 코드·재사용/만료 거부, 멤버 권한, 비공개 R2, 공개 철회, 계정 전환 캐시 제거.
  추가한 검증: 동일 비밀번호의 서로 다른 해시, 서명 없는 DB 원문 토큰 거부, 변조 토큰 거부, 서버에서 만료된 세션 거부.
  미완료: 이메일 소유 확인 메일, 비밀번호 재설정/계정 복구, 회원 탈퇴 및 관련 데이터 삭제 흐름.
  현재 emailAndPassword에는 확인 메일 발송과 requireEmailVerification 설정이 없다.
  위 미완료 항목까지 포함한 계정 보안 전체 완료로 판정하지 않는다.

3. 실제 빌드·배포 상태

- Android package: com.tripprint.app
- EAS play-internal은 store 배포용 AAB 프로필이다.
- 기본 GitHub Android Play Internal은 Expo 계정 없이 Linux Gradle로 APK/AAB를 만든다.
- 2026-10-07 성공 실행 #2 확인:
  https://github.com/Ji-ChangKim/travel_APP/actions/runs/37604959612
  커밋: 935272bd03beeb647ece87663af283aaeed888b1
  산출물: tripprint-apk-1002 (APK). AAB와 Play 제출 단계는 실행되지 않았다.
- 이번 수정본은 위 APK에 포함되지 않는다. 새 커밋으로 새 AAB를 빌드해야 한다.
- 업로드 서명 Secrets 4개 등록 여부, Play API 서비스 계정 권한, 기존 최고 versionCode는 이번 세션에서 확인되지 않았다.
- 이번 작업에서 Play 업로드·내부 테스트 출시·실기기 설치는 실행하지 않았다.
- 로컬 Hermes 번들은 Android JS/자산 생성 검증이며 설치 가능한 APK/AAB가 아니다.

6. 내부 테스트 실행 및 합격 조건

1) 새 API와 0006 DB 마이그레이션을 적용하고 이번 수정본을 반영한 커밋과 새 versionCode로 Android Play Internal을 실행한다.
   artifact_type=aab, submit_play=false이면 서명된 AAB 다운로드 후 콘솔에 직접 업로드한다.
   자동 제출 자격이 있으면 submit_play=true, release_status=draft로 먼저 등록한다.
   내부 테스터 목록·참여 링크·출시 여부는 Play Console에서 확인한다.
2) 새 설치와 이전 버전 업데이트 모두에서 앱을 열고 크래시·흰 화면·네트워크 오류 복구를 확인한다.
3) 방문자: 공개 발자국 진입 → 일정·선택 사진 조회 → 재실행 → 홈 미리보기. 다른 사용자의 개인 여행을 볼 수 없어야 한다.
   게스트: Google 화면 없이 시작 → 고유 Quest 닉네임 → 여행·일정·사진·직접 입력 영수증 저장 → 통신 끊고 재실행·편집.
   다른 기기에는 이 여행이 없어야 한다. 회원과 같은 닉네임 변경은 거부하고 회원 전환 시 자동 업로드하지 않아야 한다.
4) A: 이메일 가입 및 Google 신규/기존 로그인 → 프로필 설정 → 종료·재실행 후 로그인 복원.
5) A: 국가/도시·기간·항공편 → 여행 생성 → 지도 검색/장소 공유 → DAY2 일정 → 영수증 촬영·확정.
6) 앱 재실행과 A의 다른 기기에서 여행·일정·금액을 대조한다. 응답 유실 재시도에도 중복이 없어야 한다.
7) A: 여행 완료 → 나의 발자국 → 일정·사진 선택 공개.
8) 게스트/B: 같은 공개 기록 조회. 비공개 메모·영수증·성별·생일·계정 토큰이 없어야 한다.
9) A: 공개 철회 → 게스트/B 새로고침. 철회한 게시물과 사진을 다시 읽을 수 없어야 한다.
10) A 로그아웃 → B 로그인. A의 개인 여행·캐시·사진을 B에게 표시하면 실패다.
11) Google 취소·잘못된 비밀번호·만료 세션·카메라 거절·업로드 실패·네트워크 끊김 뒤 재시도를 확인한다.
12) Google 저장 목록 직접 동기화는 별도 미완료 항목으로 남긴다. 단일 장소 공유 성공으로 대체 합격시키지 않는다.

현재 판정: 지원하는 기능의 내부 테스트 준비를 보완했으나, Google 계정 저장 목록 직접 동기화와 계정 복구/탈퇴는 미완료이며 최신 AAB의 Play 출시·실기기 인수는 남아 있다.
