TripPrint 홈·여행 허브 디자인 수정 기록
작성일: 2026-10-06 (Asia/Seoul)
기준: 사용자가 첨부한 Trip Hub / 일정 추가 / 영수증 인식 / 지도 화면 시안

1. 기존 구현이 시안과 달라진 이유
- 시안의 날짜 선택·장소 타임라인·사진·지출이라는 핵심 정보 구조를 구현 기준으로 고정하지 않았다.
- 색상과 둥근 카드 위주로 적용하면서 긴 설명, 중복 제목, 큰 버튼을 반복했다.
- 여행 상세에서 실제 첫 일정보다 소개·설정·작업 버튼이 먼저 공간을 차지했다.
- 모든 일정에 사진 촬영·사진 추가·수정·삭제를 항상 펼쳐 읽기 흐름을 끊었다.
- 첫 방문 홈과 여행 중 허브의 목적을 충분히 구분하지 않았다.

2. 변경한 사용자 경험
- 첫 방문: 여행 시작 버튼을 첫 화면에 배치. 가상 일정 사용 예시와 반복 소개 제거.
- 도시 선택: 도시를 누르면 즉시 여행 만들기 또는 로그인으로 이동. 인증 후 목적지 유지.
- 재방문: 여행 중인 실제 여행을 우선 제공. 완료·보관 여행은 재개 목록과 구분.
- 여행 허브: 공통 소개 제목을 제거하고 실제 여행 제목·장소·기간·상태를 짧게 표시.
- 설정: 제목 옆 설정 아이콘에서 필요할 때 펼침.
- 작업 영역: 큰 버튼 나열을 밑줄 탭으로 변경.
- 날짜: DAY와 실제 현지 월·일을 같은 버튼에 표시. 사라진 선택 날짜는 첫 날짜로 복구.
- 일정: 경로선과 장소 카드로 타임라인 구성. 저장된 주소·메모·여행 사진·실제 지출을 같은 장소에서 조회.
- 일정 관리: 해당 장소에서 사진 추가·촬영·수정·삭제를 펼침. 기존 권한·삭제 보호 유지.
- 추가 행동: 일정 추가·영수증 촬영·앨범 선택을 화면 하단에 고정.
- 하루: 첫 여행 안내와 기존 로딩·오류 상태에 실제 브랜드 자산 사용.

3. 변경 파일

- HomeTripList.tsx: 실제 여행 상태별 우선순위 및 목록/재개 카드.
- homeStyles.ts: 흰 바탕, 글자 위계, 충분한 터치 영역과 소형 화면 배치.
- WorkspaceScreen.tsx: 실제 여행 헤더, 설정 아이콘, 작업 탭, 날짜/타임라인/하단 행동 연결.
- TripTimeline.tsx: DAY 선택, 밑줄 탭, 장소·실제 사진·지출과 일정 관리 펼침.
- TripHubActions.tsx: 하단 고정 일정 추가·촬영·앨범 선택과 처리 중 중복 실행 차단.
- tripHubStyles.ts: 여행 허브 배경·헤더·본문 위계.
- tests/web/workspace.spec.ts: 도시 선택 한 번으로 인증과 여행 생성까지 이어지는 흐름 검증.
- scripts/build-page-gallery.mjs: 수정 홈·재방문·여행 허브·조회 오류의 비교 페이지 생성.
- apps/mobile/public/release.json: test-1-trip-hub 식별자.
- 이 보고서: 설계 차이·수정 범위·검증 결과·미반영 범위.
- outputs/TripPrint-pages: 실제 웹 앱을 촬영한 PNG, manifest, HTML 갤러리 (기존 미추적 출력 유지).
- .release/capture-home-redesign.mjs, .release/playwright.home.config.mjs: 격리된 내부 캡처/검증 도구. 서비스 번들에 포함하지 않음.

4. 이번 범위의 한계
- 전체 첨부 시안과 픽셀 단위 일치가 완료된 상태로 선언하지 않는다.
- 지도 내 동선 화면, 빠른 장소 추가, 영수증 촬영→사진 미리보기→검토→한 번의 등록 흐름 전체는 이번 홈·허브 수정에서 구현하지 않았다.
- 영수증은 기존 촬영 안내와 두 확인 선택이 있는 구현을 유지한다. 별도 UX 수정이 필요하다.
- 없는 날씨·이동 거리·환율·후기·인기 순위는 화면에 만들어 넣지 않았다.
- DB 테이블·서버 API·도메인 객체 변경 없음. 화면의 펼침 상태는 저장하지 않는다.
- English 전체 지원과 설치 APK 갱신을 완료한 것으로 표시하지 않는다.
- 캡처의 인증·여행·지출 데이터는 HTTP 경계에서 격리한 검증 자료다. 실제 서비스 계정이나 여행 데이터를 생성하지 않는다.
