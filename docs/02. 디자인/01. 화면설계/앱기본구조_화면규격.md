# 앱 기본 구조 화면 규격

## 목적과 적용 범위

페이지별 행동·예외·수용 기준과 타이틀·GNB 배정 기준은 [앱 기본 구조 페이지별 기능 정의서](<../../01. 서비스기획/01. 기능정의/앱기본구조_페이지별기능정의서.md>)를 참조한다. 홈은 브랜드, 내 여행·커뮤니티·MY는 공통 제목 헤더를 사용한다. 커뮤니티의 두 주소는 같은 화면과 검색 구성을 사용하며, 기존 공통 치수·GNB 구성은 유지한다.

앱을 열고 이용 방식을 선택한 뒤 홈·커뮤니티·MY를 오가고, 설정과 계정 관리를 마치는 흐름을 먼저 완성한다. 여행 생성·일정 편집 화면과 게스트 서버 저장은 후속 작업이다. 기존 기능의 진입점은 유지하며 아직 제공하지 않는 자동 생성·환율·방문 인증을 안내하지 않는다.

로그인 직후에는 **추가 입력 없이 기본 프로필을 표시**한다. 2026-11-09 후속 지시에 따라 Google 회원의 MY에서만 선택적으로 닉네임·사진을 바꾼다. 소개·성별·생일·여행 스타일은 입력받지 않는다. 세부 기준은 [MY 프로필 변경 규격](MY_프로필변경_규격.md)을 따른다. 게스트 서버 저장은 별도 필수 과제지만 구현 전에는 기기 기록을 서버에 보관한다고 안내하지 않는다.

## 공통 디자인과 이동

- 기준은 [디자인 시스템](<../00. 공통규격/디자인시스템.md>), [단일 토큰](<../00. 공통규격/design-tokens.json>), [헤더·GNB](<../00. 공통규격/헤더GNB_규격.md>)다. 문서의 예전 수치와 토큰이 다르면 실제 토큰 값을 따른다.
- 공통 헤더·GNB 구현과 토큰은 변경하지 않는다. 화면 여백 20, 최대 폭 640, 카드 내부 여백 16, 최소 터치 영역 48을 적용한다. LINE Seed와 공통 버튼·카드·모달을 재사용한다.
- 루트 이동은 홈(`/`)·내 여행(`/plans`)·커뮤니티(`/footprints`)·MY(`/my`)의 기존 4탭을 유지한다. `/community`는 공개 목록의 호환 경로다. `/account`는 MY 아래 계정 관리 화면이다.
- 시작·로그인·기본 프로필 확인에는 GNB를 표시하지 않는다. 설정과 계정 관리는 기존 하위 화면 헤더를 사용한다. 작은 화면과 큰 글꼴에서 줄바꿈·높이 확장을 허용하며 공통 헤더를 축소하지 않는다.

홈의 추천 자료는 공식 여행 정보를 참고한 가이드로 설명한다. 도시를 선택해 여행 만들기로 이동하는 버튼을 ‘코스 전체 담기’로 표시하지 않는다. 경비 기록 진입을 실시간 환율 계산이라고 표시하지 않는다.

## MY와 설정

MY의 기본 이름은 비어 있을 때 ‘여행자’다. 회원 여부만으로 Google 계정이라고 표시하지 않는다. 서버가 확인한 Google 회원만 Google 계정으로 표시하고 나머지 회원은 회원 계정으로 안내한다. 과거 소개·여행 스타일·편집 폼을 표시하지 않는다.

설정은 현재 이용 방식 → 언어 → 앱 버전 → 계정 관리·로그아웃 순서로 읽히게 한다. 버전은 앱 설정에서 읽는다. 로그아웃 확인에는 서버 기록 또는 기기 기록의 실제 보관 범위를 설명한다. 약관·개인정보 문서는 현재 앱에 실제 페이지가 없으므로 작동하지 않는 링크를 만들지 않는다. 게시할 문서와 주소를 준비하는 작업은 별도로 남긴다.

## 계정 관리와 삭제

회원 계정은 본인 계정 정보 → 삭제 사전 확인 → 필요한 소유권 이전 → 삭제 내용 확인 → 명시적 삭제 요청 순서로 처리한다. 게스트에는 서버 회원 삭제 행동을 표시하지 않는다.

- `GET /api/v1/account`로 본인 계정 종류·비공개 이메일을 확인한다.
- `GET /api/v1/account/deletion-preview`로 삭제할 개인 여행·나갈 공유 여행·소유권 이전 대상을 구분한다. 조회 실패 시 삭제 버튼을 열지 않고 재시도를 제공한다.
- 다른 참여자가 있는 본인 소유 여행은 현재 참여자 중 새 소유자를 사용자가 직접 선택한다. `POST /api/v1/account/owned-trips/:tripId/transfer` 전 확인창을 표시하고 성공 후 다시 조회한다. 자동 선정하지 않는다.
- `DELETE /api/v1/account`에는 현재 정책 버전과 명시 확인을 전송한다. 최근 인증이 필요하면 계정 관리 목적지로 다시 로그인한다.
- 신규 삭제에는 90일 복구 유예를 안내하지 않는다. HTTP 202는 ‘삭제 요청을 접수했어요’로 표시한다. 실제 자료 삭제 완료로 표현하지 않는다.
- 삭제 중에는 중복 요청·뒤로가기를 막는다. 실패 또는 응답 유실이면 성공으로 처리하지 않고 계정 상태 확인·재인증을 안내한다. 늦은 응답이 새 계정의 화면이나 세션을 변경하지 않게 한다.

## 실제 화면 검수 기준

실행 → 게스트 또는 회원 → 홈 → 커뮤니티 → 공개 상세 → 목록 복귀 → MY → 설정 → 로그아웃 → 로그인 복귀를 확인한다. 기본 프로필 직접 링크에서도 입력 API가 호출되지 않아야 한다.

320·390·430px, 큰 글꼴, 긴 제목, 빈 목록, 조회 오류·재시도를 확인한다. 헤더·GNB·뒤로가기 회귀 검사와 실제 캡처를 함께 남긴다. 로컬 계정·대체 공급자 응답을 쓴 검사를 실제 Google 인증으로 보고하지 않는다. 실제 계정 삭제는 격리된 검수 계정에서만 확인한다.
