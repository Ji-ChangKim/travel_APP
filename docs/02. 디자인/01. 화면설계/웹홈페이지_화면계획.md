# TripPoint 웹 홈페이지 화면 계획

웹 홈 `/home`은 로그인 전에는 계획 만들기와 공개 일정 탐색을 안내하고, 로그인 후에는 하던 여행 작업을 다시 열게 한다. 여행의 편집·영수증 확인·공개 설정은 각각의 작업 화면에서 처리한다.

이 문서는 웹 홈 `/home`의 구성·문구·버튼·이동을 구체화한 검토안이다. [웹사이트 전체 계획](<../../01. 서비스기획/03. 작업계획/웹사이트_초기구성_계획서.md>)의 하위 계획이며, 화면을 구현하거나 공통 탐색 규격을 변경한 것은 아니다. 로그인 전 공개 일정 열람은 앞선 권장안을 이번 화면 계획의 가정으로 사용한다. 웹 게스트 계정과 비회원 여행 저장은 제공하지 않는다.

소개 랜딩 `/`과 서비스 홈 `/home`을 나누는 사용자 지시를 반영한다. 랜딩의 사진·애니메이션·서비스 이야기는 [웹 랜딩 규격](웹랜딩_화면규격.md)에서 관리한다. 홈은 여행 작업을 빠르게 여는 역할에 집중한다. 이번 범위는 홈의 화면·기능 설계까지이며 실제 `/home` 화면·로그인·DB 연결은 구현하지 않는다. 앱의 홈 `/`·4탭은 바꾸지 않는다.

## 1. 홈의 역할과 공통 기준

홈에서 끝내야 할 일은 세 가지다. 새 여행의 입력 화면을 열고, 접근 가능한 내 여행을 다시 열고, 다른 사람의 공개 일정을 찾아보게 한다. 홈 버튼을 눌렀다는 이유로 여행·비용·공개 게시물을 생성하지 않는다.

현행 [홈 규격](홈온보딩_화면규격.md), [로그인 규격](로그인_프로필생성_규격.md), [디자인 시스템](<../00. 공통규격/디자인시스템.md>), [디자인 토큰](<../00. 공통규격/design-tokens.json>), [헤더·GNB](<../00. 공통규격/헤더GNB_규격.md>)를 따른다. 웹만의 차이는 본문·로그인 진입 정책에 한정한다. 기존 앱 홈과 게스트 선택은 변경하지 않는다.

| 공통 요소      | 적용안                                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 상단           | `HomeHeader`의 `travel-home` 유형. 기존 브랜드 표시, 우측 행동 없음. 브랜드는 표시 요소이며 새 홈 링크 버튼으로 만들지 않음 |
| 하단 메뉴      | 홈 → 내 여행 → 커뮤니티 → MY의 4개 `GlobalNavigation` 유지. 홈에서 홈 선택                                                  |
| 로그인 전 메뉴 | 내 여행·MY는 로그인 후 해당 화면으로 이동. 커뮤니티는 공개 목록 열람                                                        |
| 로그인 화면    | 공통 뒤로가기 헤더와 Google 로그인. 웹에는 게스트 시작 버튼 없음. GNB 숨김                                                  |
| 홈의 주 버튼   | 상태별 한 개. 나머지는 보조 버튼·텍스트 링크로 위계 구분                                                                    |
| 브랜드         | 요청서에서는 TripPoint. 승인 전 로고·하루·TripPrint 자산과 인증 식별자 교체 없음                                            |

데스크톱 전용 상단 메뉴를 새로 추가하거나 하단 메뉴를 없애지 않는다. 그 변경이 필요하면 별도 공통 탐색 규격 작업으로 다룬다. 이번 계획의 모든 홈 행동은 본문에서 제공한다.

## 2. 로그인 전 서비스 진입

랜딩의 긴 소개를 홈에서 반복하지 않는다. 로그인 상태를 확인한 뒤 비회원에게는 짧은 안내와 실제 로그인 진입점을 제공하는 계획이다. 로그인하지 않아도 허용된 공개 일정은 열람할 수 있다. 게스트 계정·비회원 여행 저장은 없다.

| 영역·행동           | 다음 화면                                    | 취소·실패                           |
| ------------------- | -------------------------------------------- | ----------------------------------- |
| 여행 계획 만들기    | 생성 목적을 보존해 /login, 성공 후 /new-trip | 취소하면 /home, 여행 자동 생성 없음 |
| 로그인              | /login, 성공 후 /home의 같은 서버 여행 조회  | 재시도 또는 /home 복귀              |
| 공개 일정 둘러보기  | /footprints의 실제 공개 피드                 | 목록 오류는 해당 화면에서 재시도    |
| 서비스 소개         | 랜딩 /                                       | 로그인 상태·여행 변경 없음          |
| 정책·도움말·앱 안내 | 실제 콘텐츠가 준비된 목적지만 표시           | 없는 페이지의 버튼은 만들지 않음    |

소개 사진·장식 애니메이션은 랜딩에 둔다. 홈은 장소·URL 검색창을 넣지 않고 여행 편집기에서 검색한다. 로그인 확인 중에는 개인 자료와 비회원 안내가 번갈아 나타나지 않게 한다.

## 3. 로그인 후 화면 구성

로그인 후에는 긴 소개 영역을 없애고 **인사·이어갈 작업 → 내 여행 → 빠른 작업 → 공개 일정 → 푸터** 순서로 보여준다. 공개 일정 영역은 개인 여행 아래에 두며, 추천 때문에 기존 작업이 아래로 밀리지 않게 한다.

| 순서 | 영역        | 표시할 내용                                                                                      | 행동                                                            |
| ---- | ----------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| 1    | 인사        | 선택 닉네임이 있으면 ‘OO님, 여행을 이어서 준비해 볼까요?’. 없으면 ‘여행을 이어서 준비해 볼까요?’ | 닉네임·사진을 입력하라는 가입 절차 없음                         |
| 2    | 이어갈 작업 | 초안 또는 대표 여행 1개, 지역·기간/날짜 미정·권한                                                | ‘이어서 만들기’·‘이어서 계획하기’·‘여행 보기’ 중 하나           |
| 3    | 내 여행     | 접근 가능한 저장 여행 최대 3개, 소유/함께하는 여행 구분                                          | 각 카드 ‘일정 열기’, ‘내 여행 전체 보기’, 보조 ‘새 여행 만들기’ |
| 4    | 빠른 작업   | 영수증·가계부·준비물의 실제 진입점                                                               | ‘영수증 등록’, ‘가계부 보기’, ‘준비물 확인’                     |
| 5    | 공개 일정   | 로그인 전과 같은 공개 게시물 최대 3개                                                            | ‘일정 보기’, ‘공개 일정 전체 보기’                              |
| 6    | 푸터        | 정책·도움말·문의·앱 안내                                                                         | 로그인 전과 같은 목적지                                         |
| 공통 | 상단·하단   | 기존 브랜드 헤더와 4탭                                                                           | 공통 규격 유지                                                  |

### 대표 작업 선택 규칙

‘최근 편집’ 시각이 현재 응답에 없는데 임의로 최근 편집했다고 표시하지 않는다. 첫 홈에서는 아래 순서로 대표 작업을 고른다. 이는 이번 웹 계획의 구체화이며 앱의 기존 홈 우선순위를 바꾸는 지시가 아니다.

대표 저장 여행 후보에서 `ARCHIVED`는 제외한다. 저장 여행의 `DRAFT`는 생성 초안과 같은 상태로 추정하지 않고, 전용 재개 계약이 확인되기 전에는 내 여행에서 확인하게 한다. 날짜 미정 여행은 실제 날짜가 있는 진행·예정 분류에서 먼저 제외한다. 완료 여부는 서버의 명시적 완료 상태를 따르며 날짜가 지났다는 이유로 완료 처리하지 않는다. 미래 날짜라도 완료 처리됐다면 완료 영역으로 분류한다. 날짜가 지났지만 미완료인 여행은 진행·예정 후보에 넣지 않는다.

홈의 일반 여행 카드에서도 보관 여행과 재개 계약이 확인되지 않은 저장 DRAFT는 제외한다. 해당 기록이 있다는 사실은 빈 상태 판정에 반영하고, 내 여행의 기존 관리 경로에서 확인하게 한다.

| 우선순위 | 조건                                            | 표시와 주 버튼                                                                  |
| -------- | ----------------------------------------------- | ------------------------------------------------------------------------------- |
| 1        | 서버에서 확인한 작성 중 여행 생성 초안이 있음   | 최신 `savedAt` 초안 → ‘이어서 만들기’                                           |
| 2        | 여행지 현지 날짜 기준으로 진행 중인 여행이 있음 | 출발일이 빠른 여행 → 편집 가능하면 ‘이어서 계획하기’, 열람 전용이면 ‘여행 보기’ |
| 3        | 예정 여행이 있음                                | 출발일이 가장 가까운 여행 → 같은 권한별 버튼                                    |
| 4        | 날짜 미정의 저장 여행이 있음                    | 제목·ID의 고정 순서로 대표 선택 → 같은 권한별 버튼                              |
| 5        | 완료 여행만 있음                                | 종료일이 가장 최근인 여행 → ‘여행 기록 보기’                                    |
| 6        | 초안과 여행 모두 없음                           | 빈 상태 → ‘새 여행 만들기’                                                      |

저장 여행은 있지만 대표 후보가 없으면 ‘내 여행을 확인해 보세요.’와 주 버튼 ‘내 여행 전체 보기’, 보조 ‘새 여행 만들기’를 제공한다. 보관·미완료·DRAFT 여행을 임의로 수정하거나 ‘첫 여행’ 상태로 표시하지 않는다.

동일한 날짜·시각이면 ID를 마지막 정렬 기준으로 삼아 새로고침 때 카드가 흔들리지 않게 한다. 기록이 실제 서버에 저장된 시각만 표시한다. 브라우저에만 있는 입력을 서버 초안이라고 보여주지 않는다. 대표 여행은 ‘내 여행’의 3개 카드에서는 중복 제외하고, 나머지가 없으면 해당 카드 영역을 생략하되 전체 보기 링크는 유지한다.

### 여행이 없는 회원

제목은 ‘첫 여행을 만들어 보세요’, 설명은 ‘여행지와 기간을 정한 뒤 가고 싶은 장소를 추가해 보세요.’로 한다. 주 버튼은 ‘새 여행 만들기’, 보조는 ‘공개 일정 둘러보기’다. 초안은 있지만 생성된 여행이 없는 회원은 빈 상태가 아니라 ‘이어서 만들기’를 보여준다.

앱에서 사용하던 여행이 보이지 않는 경우를 위해 도움말에 ‘앱과 같은 Google 계정인지 확인해 주세요. 앱의 기기 기록은 앱에서 가져오기를 마친 뒤 확인할 수 있어요.’를 둔다. 홈에서 자동 가져오기나 계정 자동 합치기를 제안하지 않는다.

### 로그인 후 버튼 정의

| 버튼                     | 조건과 동작                                 | 목적지·결과                                                   |
| ------------------------ | ------------------------------------------- | ------------------------------------------------------------- |
| 이어서 만들기            | 회원 본인의 서버 초안 ID·현재 revision 확인 | `/new-trip`의 기존 `resume` 흐름. 기존 단계·입력 복원         |
| 이어서 계획하기          | 대표 저장 여행의 편집 권한 확인             | `/trips/:id` 일정 영역. 별도 사본 생성 없음                   |
| 여행 보기·여행 기록 보기 | 저장 여행의 현재 접근 권한 확인             | 같은 여행의 읽기 가능한 상세. 열람자를 편집자로 안내하지 않음 |
| 새 여행 만들기           | 빈 생성 화면 열기                           | `/new-trip`. 기존 초안을 덮어쓰지 않음                        |
| 일정 열기                | 누른 카드의 ID로 이동                       | `/trips/:id`. 카드 전체를 같은 목적지의 한 링크로 취급        |
| 내 여행 전체 보기        | 개인·참여 여행 목록 열기                    | `/plans`. 홈 목록에 없던 여행도 여기서 조회                   |
| 영수증 등록              | 편집 가능한 여행을 선택                     | 해당 여행의 사진·영수증 영역 → 파일 선택 → 영수증 확인        |
| 가계부 보기              | 열람 가능한 여행을 선택                     | 해당 여행의 가계부. 쓰기는 별도 권한 판정                     |
| 준비물 확인              | 열람 가능한 여행을 선택                     | 해당 여행의 준비물. 열람자는 읽기만 허용                      |
| 공개 일정 보기·전체 보기 | 공개 자료만 열기                            | `/community/:postId` 또는 `/footprints`                       |

여행 삭제·초안 삭제·공개 전환·초대·로그아웃은 홈의 빠른 작업에 넣지 않는다. 여행 관리·여행 더보기·MY의 정해진 위치에서 처리한다. 홈페이지가 관리 버튼으로 가득 차지 않게 한다.

## 4. 여행 선택창의 동작

빠른 작업은 대표 여행에 조용히 적용하지 않는다. ‘영수증 등록’, ‘가계부 보기’, ‘준비물 확인’별로 접근 가능한 여행을 확인한다. 후보가 1개라도 선택할 여행 이름과 다음 행동을 보여주고 사용자가 눌러 이동한다.

| 선택창 상태                | 표시                                                                      | 다음 행동                                                                |
| -------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 불러오는 중                | ‘여행을 불러오고 있어요.’                                                 | 선택·중복 실행 잠금                                                      |
| 후보 있음                  | 제목·지역·기간·열람/편집 권한. 대표 여행은 표시만 하고 자동 확정하지 않음 | ‘이 여행에 등록’ 또는 ‘이 여행 보기’                                     |
| 영수증 편집 가능 여행 없음 | ‘영수증을 등록할 수 있는 여행이 없어요.’                                  | ‘새 여행 만들기’, ‘닫기’. 열람 여행이 있으면 편집 권한이 필요하다는 안내 |
| 가계부·준비물 대상 없음    | ‘확인할 여행이 없어요.’                                                   | ‘새 여행 만들기’, ‘닫기’                                                 |
| 목록 조회 실패             | ‘여행을 불러오지 못했어요.’                                               | ‘다시 불러오기’, ‘닫기’                                                  |
| 선택 직후 권한 상실        | ‘이 여행에서는 기록을 추가할 수 없어요.’                                  | 최신 후보 다시 조회·다른 여행 선택                                       |

‘닫기’·Escape·공통 닫기 동작은 같은 취소로 처리한다. 입력·파일 업로드를 시작하지 않고 홈의 원래 버튼으로 초점을 돌린다. 선택창을 닫지 않은 채 배경 카드로 이동하지 않는다. 파일 선택을 취소하면 여행의 영수증 화면에 남으며 비용·방문·업로드 성공을 만들지 않는다.

## 5. 공개 일정 카드와 푸터

공개 카드는 지역·여행 제목·계획/기록 구분·일수·공개 작성자명·허용된 표지만 보여준다. 원본 영수증·품목·실제 여행 소유자 이메일·동행자·개인 메모는 가져오지 않는다. 홈에는 비용 요약·좋아요·인증 배지를 넣지 않는다.

현재 공개 상태가 유효한 게시물만 최신 공개순으로 최대 3개 표시한다. 유효한 사진이 없으면 공통 대체 표현을 사용한다. 이용자가 사진을 올린 것처럼 임의 여행 사진을 끼워 넣지 않는다. 본인 차단·운영 숨김·철회는 공통 피드 정책에 따라 반영한다.

‘내 여행으로 담기’는 공개 상세에만 둔다. 사용자가 일정을 읽은 뒤 출발일과 가져올 범위를 확인하게 한다. 홈의 카드 클릭이나 로그인 성공만으로 사본을 생성하지 않는다. 홈으로 돌아오면 공개 영역의 스크롤 위치를 복원하고 게시물 상태는 재확인한다.

| 푸터 링크         | 목적지안                        | 이용 조건                                                 |
| ----------------- | ------------------------------- | --------------------------------------------------------- |
| 이용약관          | `/terms`                        | 로그인 없이 열람                                          |
| 개인정보처리방침  | `/privacy`                      | 로그인 없이 열람                                          |
| 커뮤니티 운영정책 | 운영정책 페이지, 경로 확정 필요 | 공개 기준·신고·처리 안내                                  |

위 경로는 전체 계획의 인계안이다. 정책·도움말 콘텐츠와 실제 연결을 먼저 준비한 뒤 링크를 표시한다. 문의가 실제 전송되지 않는데 ‘접수 완료’를 보여주지 않는다. 홈에서는 외부 앱 스토어로 자동 이동하거나 설치를 강제하지 않는다.

## 6. 페이지 이동 흐름

| 흐름                | 이동 순서                                                                                                     | 완료·복귀 기준                                               |
| ------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 비회원 새 계획      | 홈 → 여행 계획 만들기 → 로그인 → Google 인증 → 여행 만들기                                                    | 목적지·기간을 정하고 별도 생성 버튼을 눌러야 여행 저장       |
| 기존 앱 회원 로그인 | 홈 → 로그인 → Google 인증 → 회원 홈 → 여행·초안 조회                                                          | 추가 프로필 입력 없음. 같은 계정의 서버 여행 표시            |
| 회원 새 계획        | 홈 → 새 여행 만들기 → 목적지 → 기간 → 세부 일정 만들기                                                        | 저장 성공 후 새 여행 상세. 취소 시 홈으로 복귀 가능          |
| 초안 재개           | 홈 → 이어서 만들기 → 기존 생성 단계                                                                           | 기존 초안 ID로 재개. 새 초안 자동 생성 없음                  |
| 기존 여행 열기      | 홈 → 카드 또는 대표 버튼 → 여행 상세                                                                          | 여행별 일정·권한 확인. 뒤로가기는 원래 홈                    |
| 공개 일정 활용      | 홈 → 공개 상세 → 내 여행으로 담기 → 필요 시 로그인 → 같은 상세의 가져오기 확인 → 출발일 선택 → 새 비공개 여행 | 로그인 후 홈으로 새지 않음. 출발일 확인 전 복사 없음         |
| 영수증 기록         | 홈 → 영수증 등록 → 대상 여행 선택 → 사진·영수증 → 파일 선택 → 내용 확인 → 저장                                | 재조회로 결과 확인. 홈 복귀 시 여행 정보 갱신                |
| 가계부·준비물       | 홈 → 빠른 작업 → 대상 여행 선택 → 해당 여행 영역                                                              | 취소 시 홈, 상세 뒤로가기의 실제 출발점 보존                 |
| 하단 내 여행·MY     | 비로그인 홈 → 메뉴 → 로그인 → 해당 메뉴                                                                       | 로그인 취소 시 홈. 보호된 메뉴로 돌아가 로그인 반복하지 않음 |
| 도움말·정책         | 홈 → 문서                                                                                                     | 같은 탭 열람, 뒤로가기 시 홈의 읽던 위치 복귀                |

로그인 복귀는 허용한 내부 목적지·대상 ID·행동만 보존한다. 임의 외부 URL로 복귀하지 않는다. 각 탭에서 이번 로그인을 시작한 행동을 하나의 유효한 목적으로 묶는다. 같은 탭의 초대·공유 확인 화면에서 계속 로그인했다면 그 흐름으로 복귀한다. 사용자가 이를 취소하고 홈에서 다시 시작했다면 이전 대기 목적을 폐기하고 새 홈 행동을 따른다.

| 이번 로그인을 시작한 위치·행동 | 성공 후 우선 목적지                             |
| ------------------------------ | ----------------------------------------------- |
| 홈의 여행 계획 만들기          | 새 여행 입력                                    |
| 홈의 로그인                    | 회원 홈                                         |
| 하단 내 여행·MY                | 선택한 메뉴                                     |
| 공개 상세의 내 여행으로 담기   | 같은 게시물의 가져오기 확인                     |
| 유효한 초대 확인 화면에서 계속 | 해당 초대의 참여 확인                           |
| 취소·만료한 대기 목적만 남음   | 대기 목적 폐기. 유효한 새 행동이 없으면 회원 홈 |

두 탭에서 서로 다른 목적을 시작했다면 각 탭의 출발점을 유지한다. 현행 `authReturnPath`에는 초대·공유 대기를 우선하는 처리가 있으므로, 취소한 목적 정리와 로그인 시도별 귀속을 공통 인증 흐름에 연결하는 선행 작업이 필요하다. 이번 계획만으로 해당 동작이 구현됐다고 판단하지 않는다. 기존 앱의 유효한 초대·공유 흐름은 회귀 검사로 보존한다.

인증 중 새로고침이나 기본 프로필 조회 실패가 나도 성공을 추정하지 않는다. 로그인 취소·실패는 다시 시도하거나 출발 화면으로 돌아갈 수 있게 한다. 취소한 목적은 폐기하고 이전 계정의 비공개 응답·초안·미리보기를 다음 계정에 적용하지 않는다.

## 8. 반응형 배치와 규격 대조

색상·글꼴·버튼 반경·간격은 현행 토큰에서 가져온다. 헤더 최대 폭·GNB 높이를 본문 최대 폭에 맞춰 덮어쓰지 않는다. 주 버튼은 하나만 강조하고 카드 안의 같은 목적지 링크를 중복 초점으로 만들지 않는다. 사진 비율은 해당 공통 카드 규격을 재사용하며 별도 값은 화면 시안 단계에서 명시한다.

Tab 이동은 시각적 순서와 일치해야 한다. 선택창을 닫으면 호출 버튼으로 초점을 복구하고, 비활성·오류 상태는 색상 외 문구로도 구분한다. 화면이 작아도 로그인·복귀·오류 설명을 잘라내지 않는다. 기존 하루 캐릭터는 빈 상태 등에 승인된 자산만 사용한다.

규격 대조 결과, 공통 헤더·4탭·색상·글꼴·기본 치수는 유지한다. 웹의 비회원 본문·회원 대표 작업·빠른 작업 선택창을 추가하는 계획이며 앱 홈에는 소급 적용하지 않는다. 이미지 선택·최종 줄바꿈·정확한 카드 높이는 시안에서 확정한다. 이번 문서는 완성 디자인이나 실제 화면 캡처가 아니다.

개발 전 확인할 항목은 로그인 시도별 복귀와 취소된 초대·공유 대기 정리, 생성 초안 재개, 빠른 작업의 여행 영역 진입·홈 복귀, 공개 피드의 회원 차단 적용, 실제 푸터 문서·앱 안내 주소다. 경로 문자열이나 쿼리 파라미터는 공통 라우팅 계약과 대조한다. 이 계획의 논리적 목적지만으로 아직 없는 경로를 연결하지 않는다.

## 11. 첫 홈페이지의 완료 범위

첫 구현은 상태 판정 → 로그인 전 본문 → 회원·빈 상태·초안 → 버튼과 복귀 → 여행 선택창 → 실제 공개 카드·푸터 → 오류·키보드·화면 검수 순서로 진행한다.

완료 조건은 로그인 전·후 각 버튼이 정해진 목적지에 도착하고, 취소·실패·빈 상태에서도 다음 행동을 할 수 있는 것이다. 실제 저장·지도 검색·영수증 인식의 성공 여부는 각 작업 화면의 완료 기준을 따른다. 홈페이지를 만든 것만으로 서비스 전체가 동작한다고 안내하지 않는다.
