# 시작·로그인 예외 처리 규격

상태: 사용자 지시 반영·로컬 구현 / 작성일: 2026-11-04 / 범위: BI → 로그인 선택 → 인증·회원 설정·원래 목적지 이동.

사용자는 앱을 열고 Google 또는 게스트로 시작한다. 앱이 복구할 수 있는 문제는 코드에서 처리한다. 사용자의 재시도·업데이트·로그인 선택이 있어야 진행할 수 있는 실패는 중앙 팝업으로 알린다. 다시 시도하면 실패한 단계만 확인하고, 취소하면 가능한 시작 방법을 다시 고를 수 있다.

## 처리 구분

‘코드 처리’는 화면을 막는 새 팝업 없이 복원·검증·중복 차단·안전한 복귀를 수행하는 경우다. 기다림과 Google 이용 가능 여부는 해당 버튼 주변에서 짧게 안내한다. ‘팝업’도 먼저 코드에서 실패를 판정하며, 팝업 표시만으로 인증·버전·기록 검증을 대신하지 않는다.

## 팝업 구성과 중앙 배치

기존 `AppModal`의 계층·초점 이동·배경 읽기 차단·뒤로가기 처리를 재사용한다. 새 `CenteredNoticeModal`은 이번 진입 안내에만 사용한다. 공통 헤더·GNB의 크기·위치·이동 규칙은 변경하지 않는다.

- 앱 표시 영역 전체의 가로·세로 중앙에 카드를 둔다. 위·아래 안전 영역 중 큰 값과 최소 20을 양쪽에 같은 여백으로 적용한다. 좌우도 같은 방식으로 계산한다.
- 카드 너비는 화면 가용 너비를 따르며 최대 384다. 높이는 화면에서 대칭 여백을 뺀 값 이하로 제한하고, 내용이 길면 카드 내부를 스크롤한다. 글자를 줄이거나 버튼을 숨겨 맞추지 않는다.
- 원본 브랜드 심볼 80·원본 비율, 흰 카드·반경 12, 안쪽 여백 24, 항목 간격 16을 사용한다. 제목은 공통 headlineSmall 18/26·Bold, 설명·버전은 14/22다. 버튼은 기존 DesignButton과 최소 터치 영역 규칙을 따른다.
- 중앙 배치·딤 배경·카드 형식은 첨부 이미지와 HTML을 참고했다. 외부 로고·폰트·스크립트는 실행하거나 가져오지 않는다. 원본 브랜드, LINE Seed, 공통 모달 딤과 대비를 확보한 버튼 문구색을 유지한다.
- 팝업이 열리면 배경 조작과 읽기를 막고 최상위 팝업 안에서 키보드 초점을 순환한다. 닫을 수 있는 안내는 닫기·Escape·기기 뒤로가기로 같은 동작을 수행한다.
- 필수 업데이트·설치 가능 여부 미확인·시작 점검 실패는 배경 클릭이나 Escape로 통과하지 않는다. 선택 업데이트만 ‘현재 버전으로 시작’과 닫기 동작을 같은 선택으로 연결한다. Android 필수 업데이트의 앱 닫기는 앱 종료이며 진입 우회가 아니다.

## 언어와 버전 표시

제목·설명 문장·현재 버전 라벨·최신 버전 라벨·버튼 라벨을 각각 번역 키와 실제 Text로 구성한다. 문구 전체를 이미지로 만들거나 한국어 줄바꿈 위치를 고정하지 않는다. 한·영·일을 등록하고 긴 번역과 글자 200%에서 카드 내부 줄바꿈·스크롤을 확인한다.

현재 버전은 네이티브에서 확인한 이름 또는 실제 Expo 앱 버전을 쓴다. 현행 정책 API에는 최신 버전의 표시 이름이 없으므로 비교 영역 오른쪽에는 번역한 ‘최신 버전’만 표시한다. 시안의 v1.1.0을 실제 값처럼 넣거나 내부 versionCode를 사용자 버전 이름으로 바꾸지 않는다. 최신 표시 이름을 추가하려면 별도 데이터 계약 변경이 필요하다.

## 출시 전 Google Play 버튼

사용자 최신 지시에 따라 이번에는 `클릭 시 이동`과 `{ action: 'google-play-store' }`만 콘솔에 기록한다. URL 열기·즉시 업데이트 실행·외부 앱 실행·설치 완료 처리·팝업 닫기·버전 통과는 수행하지 않는다. 토큰·계정·기기 식별자는 기록하지 않는다.

루트와 Android 직접 링크의 버튼을 같은 로그 함수에 연결했다. 과거 규격의 ‘누르면 공식 스토어 이동·복귀 후 재확인’은 출시 전에는 보류한다. 선택 업데이트의 현재 버전 사용과 설치 불가의 다시 확인은 기존처럼 실제 동작한다. 필수 업데이트 팝업은 버튼을 눌러도 유지된다.

출시 단계에서는 스토어 주소·설치 경로·업데이트 취소와 복귀를 별도 승인된 범위에서 검증하고 실제 이동을 다시 연결해야 한다. 이번 클릭 로그는 그 기능의 통과 증거가 아니다. 검수용 업데이트 UI 경로는 로컬 빌드에만 임시 생성한 뒤 제거하며 제품 소스에 테스트 분기를 남기지 않는다.
