# 일일 보고서 문서 사이트 규격

## 목적과 범위

사용자는 HTML 문서 사이트에서 날짜·요일별로 어떤 작업을 했고 어디를 어떻게 개선했는지 확인한다. 기존 여행 앱 화면과 분리한 개발 기록 사이트이며 앱 헤더·하단 GNB는 변경하지 않는다. 진입 파일은 `docs/998. 일일 업무 보고서/index.html`이다. HTML 파일을 직접 열어도 동작하도록 화면·데이터·동작을 한 파일에 포함한다.

등록된 날짜의 통합 Markdown 보고서를 원본으로 사용한다. `npm run reports:build`가 날짜 폴더의 보고서를 읽어 HTML을 다시 만든다. 원본이 없는 날짜에 예시 작업이나 통과 수치를 만들지 않는다. 날짜는 UTC 정오 기준으로 계산해 요일과 주간 이동이 기기 시간대 때문에 바뀌지 않게 한다.

## 디자인 기준과 구조

색상·글꼴은 [공통 디자인 시스템](<../00. 공통규격/디자인시스템.md>)과 [토큰](<../00. 공통규격/design-tokens.json>)을 따른다. 네이비 본문·코럴 강조·밝은 배경·LINE Seed를 사용한다. 문서 탐색용 왼쪽 메뉴와 상단 도구는 이 사이트의 구성요소이며 여행 앱의 공통 헤더·GNB 규격을 바꾸는 작업이 아니다. 별도 디자인 시스템이나 외부 글꼴·이미지 의존성은 추가하지 않는다.

- 데스크톱: 왼쪽 고정 탐색 → 상단 검색·일지 등록 → 주간 날짜 선택 → 날짜별 본문과 검증 보조 영역.
- 모바일: 메뉴 열기·닫기, 주간 날짜 영역의 가로 스크롤, 한 열 본문. 문서 전체에 가로 넘침을 만들지 않는다.
- 본문: 작업 요약 → 개선 전후 → 전체 문서 전환. 별도 메뉴로 검증·남은 작업도 확인한다.
- 접근성: 최소 48px 터치 영역, 읽기 대비 4.5:1·주요 컨트롤 3:1, 보이는 키보드 초점, 의미 있는 제목·라벨, 동작 감소 설정, 큰 글꼴 줄바꿈·높이 확장.
- 상태: 선택한 날짜·메뉴·필터를 명확히 표시하고 검색 결과 없음과 날짜의 기록 없음을 구분한다. 인쇄에서는 선택한 일지의 전체 내용을 출력한다.

## 실제 동작과 데이터

| 기능          | 사용자 행동과 결과                                   | 실패·보관 기준                                                                    |
| ------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------- |
| 날짜·요일     | 주 이동·이번 주·날짜 선택으로 일지 확인              | 등록 자료가 없으면 빈 화면과 등록된 날짜 복귀 제공                                |
| 검색          | 제목·날짜·작업 본문에서 검색하고 해당 일지로 이동    | 빈 결과에 검색어 수정·초기화 제공                                                 |
| 문서 열람     | 요약·개선 전후·전체 원문·검증·남은 작업 확인         | 기존 로컬 검수와 실제 서비스·실기기 검수를 구분                                   |
| 일지 등록     | 날짜·제목·오늘 작업·개선 전후·다음 작업 입력 후 저장 | 이 브라우저의 localStorage에만 저장. 저장 실패를 성공 처리하지 않음               |
| 수정·삭제     | 직접 등록한 일지만 수정·삭제                         | 원본 Markdown에서 온 기록은 화면에서 덮어쓰지 않음. 삭제 전 확인                  |
| 백업·가져오기 | JSON으로 일지 보관·가져오기                          | 버전·날짜·필수 문자열·크기 검사. 중복 날짜는 보존하고 건너뜀. 임의 HTML 실행 금지 |
| 내려받기·인쇄 | 선택 일지의 Markdown 내려받기·인쇄/PDF               | 다운로드·인쇄 실제 브라우저 동작. 서버 업로드·공유 저장으로 표시하지 않음         |

사이트 템플릿·스타일·동작은 `docs/02. 디자인/02. 리소스/00. 일일보고서사이트/`의 `daily-report-site.html`, `daily-report-site.css`, `daily-report-site.js`에서 관리한다. 생성·미리보기 도구는 `scripts/design/`에 둔다. 생성 HTML에 직접 수정한 내용은 다시 생성하면 사라지므로 원본 Markdown·템플릿·도구를 수정한다. 비공개 설정·키·계정 원문을 보고서나 백업에 넣지 않는다.

## 검수와 완료 조건

원문과 날짜·요일·검사 수치·상태를 대조한다. 데스크톱·작은 화면·큰 글꼴, 날짜·메뉴 전환, 검색·빈 결과, 등록·재조회·수정·삭제, 백업·잘못된 가져오기, 인쇄를 실제 브라우저에서 확인한다. `npm run check`와 문서 연결·서식을 검사하고 캡처·검수 기록은 `outputs/daily-report-site/`에 남긴다. 외부 서비스 게시·운영 배포·앱 기능 변경은 포함하지 않는다.

## 페이지별 TC 차트

문서 사이트의 ‘페이지별 TC’는 TripPrint 앱의 페이지별 테스트 케이스(TC)를 관리한다. 검수자는 페이지와 항목을 고른 뒤 아래 세 단계에서 성공 또는 실패 체크박스를 선택한다.

| 단계                  | 확인할 범위                                                    |
| --------------------- | -------------------------------------------------------------- |
| 개발 완료             | 정의한 동작이 구현됐고 개발 단계에서 기대 결과를 확인했는지    |
| Android Studio 테스트 | Android 에뮬레이터에서 같은 TC를 실행해 기대 결과를 확인했는지 |
| 내부 빌드 테스트      | 내부 배포 설치본을 실제 기기에서 실행해 기대 결과를 확인했는지 |

한 단계의 성공·실패는 동시에 선택하지 않는다. 선택한 체크를 해제하면 미검증으로 돌아간다. 세 단계는 독립적이며 개발 성공을 선택해도 에뮬레이터·실기기 결과를 자동으로 바꾸지 않는다. 기존 웹 자동 검사·코드 존재·빌드 생성만으로 실제 기기 성공을 채우지 않는다. 초기 결과는 모두 미검증이다.

페이지별 진행 차트와 단계별 성공·실패·미검증 수를 보여준다. 페이지·TC 검색·결과 필터를 제공하고, TC 상세에서 사전 조건·조작 순서·기대 결과와 단계별 검수자·빌드·기기·메모·기록 이력을 확인한다. 체크는 수동 기록이며 실제 테스트를 자동 실행하는 기능이 아니다. 세 단계 모두 성공해야 해당 TC를 전체 성공으로 센다.

TC 정의 원본은 `docs/03. 개발/04. 검증/페이지별_TC_목록.json`, 파일로 보관하는 결과 원본은 보고서 루트의 `tc-results.json`이다. 생성 HTML에는 두 자료를 포함한다. 화면에서 바꾼 결과는 `tripprint.tc-results.v1` 브라우저 저장소에 보관하며 원본 파일을 자동으로 덮어쓰지 않는다. 검수 결과 전용 JSON 내려받기·가져오기와 인쇄를 제공한다. 가져오기는 형식·TC ID·단계·상태·시각·길이를 확인한 뒤 기존 같은 항목을 바꾸는 범위를 안내하고 사용자가 적용한다. 실패하면 기존 값을 보존한다.

`tc-results.json`의 `schemaVersion`은 1, `catalogRevision`은 목록의 개정 값이다. `results`는 TC ID → `development`/`emulator`/`device` → `{status, updatedAt, tester, build, device, note}` 구조다. 상태는 `unverified`/`pass`/`fail`만 허용한다. `history`에는 TC ID·단계·상태·기록 시각과 당시 메모를 남긴다. 개인정보·토큰·실제 영수증 원문은 적지 않는다. 앱 DB나 공통 도메인 객체는 변경하지 않는다.

모바일에서는 체크 차트 안에서만 가로 스크롤한다. 성공·실패는 색상과 텍스트·체크를 함께 사용하고 각 체크의 터치 영역을 48px 이상 확보한다. 실제 체크·상호 배타·해제·저장 후 새로고침·단계 독립·메모·이력·필터·파일 복원·잘못된 파일·저장 실패·큰 글꼴·인쇄를 검수한다.
