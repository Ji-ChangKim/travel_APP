# 간단 시작 화면 규격

## 2026-11-04 예외 안내·출시 전 Play 버튼

사용자가 추가한 업데이트 팝업 시안에 따라, 시작을 막는 실패와 업데이트 선택을 중앙 팝업으로 표시한다. 정상 점검·자동 복구·Google 이용 가능 여부는 코드와 기존 화면 안 안내로 처리한다. 제목·설명·버전·행동을 각각 번역하며 화면 크기·큰 글자에도 카드 중심을 유지한다. Google Play 버튼은 출시 전 ‘클릭 시 이동’ 로그만 기록하고 실제 이동·설치 완료·필수 정책 통과를 수행하지 않는다. 이 지시는 아래 과거 스토어 이동 설명보다 우선한다. 상세 분류와 UI 값은 [시작·로그인 예외 처리 규격](시작_로그인_예외처리규격.md)을 따른다.

## 2026-11-04 BI 배경·중앙 배치 추가

사용자가 추가한 HTML에서는 배경색과 로고 위치만 참조한다. BI 배경은 위 `#FFF9F6` → 아래 `#FFF0EC`의 세로 그라데이션으로 변경한다. `design-tokens.json`의 `startup.bi`에 한정하며 공통 canvas·로그인 완료 배경·헤더·GNB는 유지한다. 첨부 HTML의 외부 이미지·글꼴·82vh 높이·별도 확대 연출은 가져오지 않는다. 원본 TripPrint 심볼과 기존 160 너비·비율을 유지한다.

BI의 장식 심볼은 앱 표시 영역 전체를 채운 레이어의 가로·세로 중앙에 배치한다. 안전 영역 안쪽의 중앙이나 화면 높이 일부를 기준으로 삼지 않는다. 화면 크기·가로세로 비율·창 크기가 달라져도 flex 중앙 정렬을 적용한다. 이미지 실패 시 브랜드 글자도 같은 중앙에 둔다. 시작 오류·업데이트 안내는 별도 안전 영역 레이어에서 제공한다.

로그인으로 넘어갈 때 이동용 심볼도 앱 표시 영역 전체의 중앙에서 출발한다. 로그인 버튼과 최종 상단 로고는 기존처럼 안전 영역 안에 둔다. 이동 중 BI 배경은 640ms 심볼 이동에 맞춰 사라지고 로그인 canvas로 이어진다. 직접 로그인 진입·움직임 줄이기에서는 최종 로그인 배치를 즉시 표시한다.

OS 기본 스플래시는 그라데이션 대신 위쪽 색 `#FFF9F6`을 사용하고 React BI에서 그라데이션을 표시한다. OS 스플래시 설정은 새 네이티브 빌드에 반영되며 웹 캡처로 설치본 반영을 판정하지 않는다. 실제 OS 표시 영역과 안전 영역은 설치본에서 별도로 확인한다.

## 2026-11-04 실제 앱 적용

사용자가 승인한 목업의 BI/CI → 로그인 연출을 앱 코드에 적용했다. 아래 ‘앱 적용 전’ 설명은 목업 제작 당시의 기록이며, 현재 구현과 검증 범위는 이 절과 [적용 검수 기록](<../../05. 검수/02. 검수보고/2026-11-04_BICI_로그인연출_적용검수.md>)을 따른다.

일반 실행은 원본 심볼을 가운데 표시하면서 실제 세션·공통 데이터·업데이트를 확인한다. 정상 상태에서는 중간 로딩 화면을 표시하지 않는다. 비로그인·기기 게스트는 `/welcome`으로 이동해 로고 이동과 버튼별 등장을 한 번 재생한다. 기존 회원은 설정 완료 여부와 원래 목적지에 따라 홈·회원 설정·초대·공유로 이동한다. 직접 링크·인증 복귀에서는 시작 연출을 반복하지 않는다.

중앙 160 너비 심볼을 상단 132 너비의 실제 배치로 이동한다. 이동 640ms, 영문 로고·Google·게스트·버전의 등장 순서는 목업과 같다. 전경에서만 진행하고 배경에서는 멈춘 뒤 남은 시간을 이어간다. 움직임 줄이기·화면 읽기에서는 즉시 완료하며, 도중 화면 크기나 글자 배율이 바뀌면 최종 배치로 정리한다. 버튼은 연출·인증 복원이 끝나야 사용할 수 있다.

실제 Google 버튼과 버전 표시도 반영했다. 초기 화면은 소개 문구 없이 원본 로고·두 버튼·앱 버전으로 구성한다. 게스트 버튼은 기존 공통 DesignButton을 재사용하므로 목업의 코럴 경계와 달리 공통 컴포넌트의 테두리를 유지한다. 헤더·GNB 수치는 바꾸지 않았다. 공통 페이지 등장 효과는 전용 연출이 있는 `/welcome`에만 중복 적용하지 않는다.

공통 데이터 확인 실패는 중앙 브랜드를 유지한 화면 아래에서 재시도한다. 필수·선택 업데이트 안내와 실제 인증 실패 복구는 유지한다. 시작 점검 요청을 BI와 병렬로 실행하는 것은 이번 사용자 승인 흐름에 맞춘 변경이다. 과거의 ‘BI 동안 점검 없음’과 ‘별도 01 로딩 화면’ 설명은 이전 동작이다.

로컬 앱 웹 빌드·검사와 Android·iOS 설치본, 실제 Google 계정 인증은 별도로 구분한다. 이번에는 배포나 DB 변경을 하지 않는다.

## 2026-11-04 스케치 구체화 · 앱 적용 전 목업

Google 가이드 추가 반영: Google 버튼은 [Google 로그인 버튼 규격](<../00. 공통규격/Google로그인_버튼규격.md>)을 우선한다. 문구는 `Google 계정으로 계속`, 밝은 테마의 공식 글자·경계색과 Google Sans Medium 14/20을 적용한다. 한글은 Noto Sans KR Medium으로 보완한다. 공통 LINE Seed·네이비 글자·반경 12는 게스트 버튼에 유지한다. 이 예외는 목업과 디자인 규격에 반영했으며 실제 앱의 버튼은 후속 적용 대상이다.

전환 연출 추가 지시: 중앙의 BI/CI 심볼이 로그인 상단의 심볼 자리로 연속해서 올라간다. 영문 로고가 이어 나타나고, Google·게스트 버튼은 각자 최종 위치보다 24 아래에서 위로 올라오며 나타난다. 화면 전체를 밀거나 사라지는 효과로 바꾸지 않는다. G를 포함한 버튼 내부 디자인은 그대로 유지한다.

목업 타이밍은 BI/CI 1초 표시 후 심볼 이동 640ms다. 심볼 이동 시작을 기준으로 영문 로고는 200ms 뒤, Google 버튼은 280ms 뒤, 게스트 버튼은 360ms 뒤에 각각 420ms 동안 나타난다. 버전은 440ms 뒤부터 320ms 동안 나타난다. 버튼은 연출을 마친 뒤 조작할 수 있다. 움직임 줄이기는 대기와 이동 없이 로그인 화면을 표시한다. 재생 중 다시 누르거나 화면을 선택하면 이전 연출을 취소한다. 이는 이번 시작 목업의 전용 연출이며 공통 헤더·GNB·앱 화면 전환은 변경하지 않는다.

사용자가 첨부한 손그림과 이번 지시에 따라 BI/CI 다음에 간단한 로그인 선택 화면이 바로 나타나는 목업을 만든다. 사용자가 보는 중간 로딩 화면은 두지 않는다. 앱의 실제 시작 분기·인증·업데이트 동작은 이번 목업 작업에서 변경하지 않는다.

첫 로그인 선택 화면에는 상단 브랜드 심볼·영문 로고, Google 계정으로 계속, 게스트로 시작하기, 하단 버전만 표시한다. 아래 2026-10-27 설명의 ‘나만의 여행 기록’, 소개 두 줄, 저장 시점 안내는 이번 간단 목업에서는 생략한다. 헤더·GNB 생략은 기존 첫 시작 화면의 예외를 따르며, 목적이 있는 `/login`과 다른 화면의 공통 규격은 바꾸지 않는다.

## 화면의 역할

앱을 처음 열면 브랜드를 보고 시작 방법을 고른다. Google로 로그인하거나, 게스트로 둘러보고 계획을 입력한다. 계획 저장에 필요한 회원 로그인 정책은 그대로 유지한다.

이번 요청의 ‘홈’은 로그인 전 첫 화면인 `/welcome`에 적용한다. 이미 로그인한 회원은 기존 홈으로 들어간다. 앱 안의 여행 목록 홈과 저장·초대에서 여는 `/login`은 유지한다.

## 기다림과 오류

인증 복원 중에는 버튼을 잠근다. Google 이용 여부를 확인하는 동안 Google 버튼은 로딩 표시를 하며, 게스트 버튼은 별도로 사용할 수 있다. 요청 중 연속 누르기는 잠근다.

Google을 쓸 수 없거나 조회에 실패하면 Google 버튼을 비활성화하고 다시 확인할 수 있게 한다. 안내는 ‘Google 로그인을 지금 이용할 수 없어요. 다시 확인하거나 게스트로 시작해 주세요.’다. 서버 설정·API·인증 공급자 같은 개발 설명은 보여주지 않는다.

게스트 발급이나 로그인 시작에 실패하면 오류 안내와 재시도할 버튼을 남긴다. 이때 ‘다른 방법으로 로그인’으로 기존 로그인 화면에 갈 수 있다. 실패를 가짜 계정으로 대체하지 않는다. 일반 상태에는 로고와 두 시작 버튼, 안내만 표시한다.
