# 로그인과 기본 프로필 화면 규격

- 적용 경로: `apps/mobile/src/app/login.tsx`, `welcome.tsx`, `profile-setup.tsx`.
- 공통 기준: [앱 기본 구조](앱기본구조_화면규격.md), [디자인 시스템](<../00. 공통규격/디자인시스템.md>), [헤더·GNB](<../00. 공통규격/헤더GNB_규격.md>).

## 로그인 선택

브랜드 → 현재 인증 상태 → Google 계정으로 계속 → 게스트로 시작하기 순서로 배치한다. 카카오·네이버 신규 가입이나 이메일 가입을 새 선택지로 표시하지 않는다. 기존 계정 호환 처리는 서버 정책을 따른다.

시작 선택 화면은 기존 웰컴 표현을 사용한다. 하위 화면에서 로그인으로 이동했을 때는 공통 `ScreenHeader`와 실제 복귀 목적지를 사용한다. GNB는 숨긴다. 브랜드 원본·시작 모션·공통 버튼·최소 터치 영역 48을 유지한다. 색상·글꼴·치수는 토큰을 사용하며 별도 팔레트를 만들지 않는다.

Google 공급자 상태를 확인하기 전에는 성공을 추정하지 않는다. 로그인 중 연속 누르기를 막고, 취소·실패 후 다시 시도하거나 게스트로 시작하도록 안내한다. 로그인 성공만으로 여행을 생성하거나 게스트 기록 전체를 서버로 전송하지 않는다.

## 기본 프로필 확인

사용자는 추가 개인정보를 입력하지 않는다. 서버의 기본 프로필을 확인해 현재 계정에 반영한 다음 원래 목적지 또는 홈으로 이동한다. 기본 이름은 ‘여행자’이며 실제 확인한 계정 종류만 표시한다. 서버가 생년월일·성별·소개를 반환하지 않아도 계정 복원이 가능해야 한다.

`/profile-setup`은 예전 링크 호환용 경로다. 닉네임·사진·소개·여행 스타일 입력이나 프로필 완료 요청을 하지 않는다. 인증 확인 → 기본 프로필 확인 → 원래 목적지 이동만 처리한다. 게스트는 기기 프로필로 이어가고, 미인증이면 복귀 정보를 보존한 로그인으로 이동한다.

프로필 조회 실패에는 계정 확인 안내와 ‘다시 시도’, ‘로그인 화면으로’를 제공한다. 확인하지 못한 계정을 성공 처리하거나 다른 계정의 응답을 반영하지 않는다.

## 복귀와 실제 검수

복귀 경로는 `authReturn`이 허용한 내부 목적지만 사용한다. 로그인 취소·새로고침·외부 인증 복귀에도 작성 중인 입력과 목적지를 보존한다. 확인 중 계정이 바뀌면 이전 응답을 적용하지 않는다.

Google 회원은 시작 후 MY에서 선택적으로 닉네임·사진을 바꾼다. [MY 프로필 변경 규격](MY_프로필변경_규격.md)을 따르며 가입·로그인의 필수 단계로 넣지 않는다. 게스트는 로그인 안내를 제공한다. 작은 화면·큰 글꼴·긴 오류 안내, 공급자 조회 실패·재시도, 회원 재로그인, 기기 게스트 재선택을 검사한다. 실제 Google 인증과 로컬 세션 검수를 구분한다.
