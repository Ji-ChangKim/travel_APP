# TripPrint 여행계획 작성·공유 화면

기준일: 2026-10-16. 기존 앱의 일정 작성 흐름과 디자인을 유지한다. 로컬 시안의 메모리 저장 결과를 서버 저장 검증으로 사용하지 않는다.

## 디자인 기준

[디자인 시스템](<../00. 공통규격/디자인시스템.md>), [공통 토큰](<../00. 공통규격/design-tokens.json>), [헤더 규격](<../00. 공통규격/헤더GNB_규격.md>), [일정 화면 규격](여행일정_화면규격.md)과 `docs/99. 아카이브/01. 이전디자인/00. 이전캡처/detail-일정-390-100.png`, `../00. 공통규격/schedule-editor-390-100.png`를 참조한다.

공유 화면도 기존 TripTimeline의 방문 번호·시간·연결선과 흰 장소 카드를 사용한다. 제목 26/36, 장소 제목 18/26, 본문 16/26, 보조 설명 14/22를 유지한다. 사용자의 요청에 따라 공유 상세에서만 뒤로가기 옆에 여행 제목을 배치한다. 다른 화면의 헤더 기본 동작은 유지한다.

Google 장소 사진은 88×88 썸네일로 표시한다. 반복되던 저작자·원본 텍스트 줄은 제거하고 썸네일을 누르면 Google 원본을 연다. 작은 Google Maps 표기는 유지한다. [Google Places 표시 정책](https://developers.google.com/maps/documentation/places/web-service/policies)의 썸네일 예외에 따라 큰 사진과 전체 저작자 정보에 접근할 수 있게 한다. 사진 없음·통신 오류·이미지 실패는 구분하고 재시도 기능을 유지한다.

2026-10-19:공개 전 미리보기도 같은 PlacePhoto와 Google 대표 사진 선택 함수를 사용한다. 현재 멤버가 저장한 장소는 인증된 여행별 사진 경로로 조회한다. 공개본 생성이나 다른 게시물의 사진을 빌려오는 우회는 하지 않는다. 정상/대기/없음/실패의88×88 슬롯·Google Maps 표기·원본 열기·재시도를 공유한다. 외부 대표 사진은 Google의 현재 응답에 따라 바뀔 수 있으므로 사진 URL을 게시 사본에 고정 저장하지 않는다.

## 작성한 내용이 공유되는 경로

| 작성 위치                                        | 저장 항목                            | 공유 화면                                        |
| ------------------------------------------------ | ------------------------------------ | ------------------------------------------------ |
| 여행 생성·여행 정보 수정                         | trip.title                           | 상단 여행 제목. 공유 제목을 따로 쓰지 않는다.    |
| 일정 → DAY 선택 → 이날 여행계획 정리             | day.planTitle, day.planConcept       | 선택한 DAY의 제목·소개. DAY 전환 시 함께 바뀐다. |
| 일정 추가·수정 → 계획 설명·추천 메뉴·팁          | schedule.planContent.description     | 해당 장소의 설명·팁 보기에서 원문 전체를 읽는다. |
| 같은 선택지 묶음·선택지 안내·선택 후보/대체 장소 | choiceGroup, choiceLabel, choiceKind | 저장한 후보·대체 관계를 표시한다.                |
| 일정 메모                                        | schedule.memo                        | 공개하지 않는다.                                 |
| 여행계획 공유하기 → 일정 선택 → 확인하고 게시    | community.publish(kind=plan)         | 선택 일정과 연결된 DAY의 공개 사본을 저장한다.   |

선택 입력인 계획 소개는 기존 게시 입력 body다. 개인 여행에 새 전체 소개 필드를 추가하지 않는다. 오사카 원문은 DAY 소개와 장소 설명으로 나누어 저장하고, 원문에 없던 검수 안내나 소개 글은 게시 본문에 추가하지 않는다.

공유 후 개인 계획을 수정해도 기존 공개 사본은 자동 변경하지 않는다. 공개 업데이트는 다시 확인하고 게시해야 한다. 계획 공유로 여행을 완료 처리하거나 가짜 지출·항공편을 만들지 않는다.

## 검증 범위

모델 테스트는 원문·선택지·비공개 정보 제외·여행 제목 사용을 검증한다. 화면 테스트는 기존 작성 폼, 저장 후 재조회, 공개 선택과 DAY 전환, 작은 사진과 오류 복구를 확인한다. 실제 staging 앱에서 작성·저장·공유한 결과와 API·DB 대조 증거는 outputs/community-osaka/actual-*에 기록한다. Android 설치본 반영에는 이후 빌드가 필요하며 이번 작업에서 APK/AAB를 만들지 않는다.

## 장소 설명 상세 전환 · 2026-10-17

장소 설명·팁 보기는 카드 안에서 펼치지 않고 전체 읽기 화면을 연다. 오른쪽 화면 밖에서 현재 너비만큼 이동해200ms에 도착하며, 뒤로가기는150ms 동안 오른쪽으로 닫힌다. 개인 일정·공개 계획·공개 선택 미리보기가 같은 컴포넌트를 사용한다. 장소명은 공통26/36 제목과 뒤로가기, 원문 설명은16/26 본문으로 표시한다. 저장된 주소·선택지 안내가 있으면14/22로 표시한다.

동작 줄이기·화면 읽기·백그라운드·접근성 확인 전에는 즉시 전환한다. Android 뒤로와 웹 Escape는 상세만 닫는다. 배경 입력·읽기를 막고 돌아온 뒤 선택 DAY·목록 스크롤·열기 버튼의 초점을 유지한다. 상세는 읽기 전용이며 비공개 메모를 받거나 API·DB를 수정하지 않는다. 공통 AppModal에 선택형 오른쪽 진입 옵션만 추가하며 다른 모달의 기본 전환은 유지한다.

## DAY 선택과 배치 유지 · 2026-10-17

DAY 버튼에는 체크와 체크용 빈 공간을 넣지 않는다. 미선택은 흰 배경·네이비 글자, 선택은 네이비 배경·흰 글자와 밑줄로 표시한다. 선택 상태는 화면 읽기에도 전달한다. 개인 일정·일정 작성·공개 계획·공개 미리보기 모두 같은 방식이다. 선택 전후 글꼴 크기·굵기·테두리 두께·안쪽 여백을 유지해 버튼 너비·높이와 이웃 DAY 위치가 바뀌지 않게 한다. 글꼴100/200%·너비320/390px에서 크기와 글자 중앙 배치를 비교한다. DAY는 한 줄 가로 탐색을 유지한다. 체크리스트와 기존 다중 선택에는 이 규칙을 적용하지 않는다.
