# TripPrint 화면 헤더 규격

바로가기: [리소스 실제 저장 경로](<../02. 리소스/리소스_저장경로.md>) · [H01~H08 시각 규격판](<../01. 화면설계/00. 헤더시안/index.html>). 상황별 유형 선택과 폰트 크기·행간·굵기 표준은 이 문서의 ‘헤더 상황별 시안·폰트 규격’에서 확인한다.

## 페이지 작업에서 지켜야 할 공통 규칙

2026-10-22 사용자 지시:
1. 헤더 구조 개선: 상단 뒤로가기 화살표와 우측 액션, 그리고 그 아래로 떨어져 나오던 2단 분리 헤더 구조를 개선하여, 상단 단일 행(Row)에 뒤로가기와 페이지 타이틀, 우측 액션이 단정하게 배치되는 단일 행 헤더(`inlineTitle: true` 기본값)로 통합함.
2. 긴 헤더 타이틀 짤림 방지: 상하 패딩과 경계 상자 여유(`paddingVertical: 2`) 및 유연한 텍스트 바운딩을 적용하여 긴 페이지명에서도 글자가 잘리지 않고 안정적으로 표현되도록 개선.
3. GNB 스크롤 연동 및 유지: 사용자가 화면을 아래로 스크롤할 때 GNB가 부드럽게 화면 아래로 내려가고(숨김), 위로 스크롤할 때 즉시 다시 올라오도록 애니메이션 연동. 경로 정규화를 통해 화면 이동 시 GNB가 의도치 않게 사라지는 문제 차단.
4. 앱 전체 배경색(BG) 통일: 구버전 베이지 캔버스(`#FFF9F3`)를 제거하고 모던 쿨 소프트 캔버스인 `#F8F9FF`로 앱 전반(토큰, 모달, 서브 페이지, 카드 서페이스)을 완전히 일체화. WCAG AA 대비 100% 통과(75/75).

2026-10-21 사용자 지시: 헤더와 하단 GNB의 디자인·크기·동작은 앱 공통 규칙으로 유지한다. 개별 페이지의 시안이나 구현에 맞춰 수치를 바꾸지 않는다. 새 시안에 다른 헤더·GNB가 있더라도 이 문서와 공통 토큰을 우선한다.

페이지는 정의된 헤더 유형을 선택하고 제목·실제 행동·복귀 경로·잠금 상태를 연결한다. 아이콘·폰트·색·여백·터치 영역·선택 표시·전환은 공통 컴포넌트가 결정한다. GNB의 순서·개수·표시 여부·선택 상태도 공통 정책으로 결정하며 페이지별 복제나 스타일 덮어쓰기를 금지한다.

작은 화면·큰 글꼴·긴 제목·안전 영역에서는 승인된 반응 규칙에 따라 줄바꿈하거나 필요한 높이를 확보한다. 규격 유지는 높이를 무조건 고정하거나 글자를 잘라내는 뜻이 아니다. 사용자가 공통 규격 변경을 명시적으로 요청하면 별도 공통 규격 작업에서 문서·토큰·구현·검증을 함께 변경한다. 개발 적용 규칙은 프로젝트 `AGENTS.md` 8항을 따른다.

## 공통 규격 우회 차단 · 2026-10-21

이번 보완은 기존 화면의 모양을 유지하면서 페이지가 헤더·GNB를 다시 조립하거나 장식하는 경로를 닫는다. 이전의 헤더 JSX 전달 설명보다 이 계약을 우선한다.

- 공통 브랜드 헤더는 `apps/mobile/src/components/HomeHeader.tsx`, 배치는 같은 폴더의 `homeHeaderStyles.ts`에서 관리한다. 홈과 공개 발자국은 승인된 유형만 선택한다. 공개 발자국의 기존 바탕·구분선은 `navigation.brandFeed` 토큰으로 보존한다.
- `CommunityFeedViewProps`는 `headerVariant: 'public-brand'`만 선택할 수 있다. 임의의 `header: ReactNode`는 받지 않는다.
- `ScreenHeader`는 우측 JSX 대신 `actions`의 이름·의미 아이콘·콜백·잠금·펼침 상태만 받는다. `HeaderActions`가 버튼과 간격을 만든다. 페이지가 아이콘 크기·색·글꼴·배치를 전달할 수 없다. 텍스트 행동의 폼 잠금도 유지한다.
- `ScreenTitle`은 내용과 남은 너비를 사용하는 `grow`만 받으며 style·글자 축소·줄 수 제한을 받지 않는다. 기존 26/36·700·왼쪽 정렬은 유지한다.
- `screenNavigationPolicy.json`에 모든 화면의 파일·경로·헤더 유형·인증 전 제목·GNB 표시를 등록한다. 성공 후 실제 여행 제목을 이 파일의 일반 제목으로 대체하지 않는다.
- MY 인증 대기는 H02의 `MY`를 유지한다. 인증 복구 오류는 `RecoveryHeader`가 진입 화면의 유형을 사용한다. 여행 상세는 인증 전 실제 제목을 추정하지 않고 H04 이동 바를 유지하며, 재시도·공개 목록 복귀는 기존 동작을 따른다. 시작 BI의 헤더 생략은 유지한다.

`npm run check:navigation`은 별칭·재내보내기를 추적해 공통 속성 외 전달, JSX spread, 페이지 장식 래퍼, 헤더 스타일·컴포넌트 복제, 네이티브 탐색 덮어쓰기, GNB 중복과 신규 라우트 정책 누락을 검사한다. 규칙 자체의 차단 테스트도 실행하며 `npm run check`에 포함된다. 기존 CI·배포 검사의 check 단계에서도 적용된다.

정적 검사는 등록된 경계와 소스 패턴을 검사한다. 모든 배치를 수학적으로 보장하는 검사가 아니므로 새 화면의 캡처·줄바꿈·터치·복귀 검수는 계속 필요하다. 본문 카드와 구역 제목은 허용 목록으로 구분하며 공통 헤더의 예외로 사용하지 않는다. 정책·허용 목록 변경은 공통 규격 변경으로 검토한다.

구현과 검증 결과는 [헤더·GNB 규격 고정 보완](<../../05. 검수/02. 검수보고/2026-10-21_헤더GNB_규격보호검수.md>)에 기록한다.

## 화면별 배치

최상위 화면은 뒤로가기 없이 영역을 식별한다. 내 여행은 제목 옆 검색·계정 행동을 제공하고, 발자국은 승인된 브랜드 헤더를 유지한다. 새 여행 만들기는 본문과 GNB 중앙 행동으로 제공한다. 홈은 기존 TripPrint 심볼과 워드마크를 유지하며 같은 최소 높이와 좌우 20 기준선을 따른다. 브랜드 로고는 화면 제목의 글꼴 규격과 구분한다.

여행 만들기·항공권 입력·일정 작성·나라/도시 선택·여행지 가이드·다이어리·초대·장소 가져오기·이전 기록·인증 입력은 이동 바 아래에 26/36 제목을 둔다. 기본 간격은 이동 바 아래 8, 제목 아래 4다. 제목 아래 본문 여백은 20이다. 여행 상세는 이동 바에 뒤로가기와 더보기만 두고 실제 여행명을 본문 첫 제목으로 표시한다. `여행 상세`를 작은 제목으로 중복하지 않는다.

프로필 편집과 바텀시트의 제목도 `ScreenTitle`을 사용한다. 시트 안쪽에 이미 20 여백이 있으면 `ScreenHeader inset={false}`로 중복 여백을 막는다. 시트의 제목과 내용은 사용자가 끝까지 스크롤할 수 있어야 한다. 본문 섹션·카드·달력의 제목은 화면 제목과 별도 위계이므로 26으로 일괄 확대하지 않는다.

## 큰 글자와 긴 제목

기본 이동 바 높이는 56이지만 확대된 텍스트 행동이 더 많은 높이를 요구하면 자연스럽게 늘어난다. 고정 높이로 글자를 자르지 않는다. 아이콘만 있는 이동 바는 글자 확대 때문에 높이를 바꾸지 않는다. 최소 높이56과 별개로 48 터치 영역에 위아래6을 더한 실제 행은60 이상이다.

제목은 사용자의 글자 배율을 그대로 따른다. 200%에서는 52/72다. `numberOfLines`, 말줄임, `adjustsFontSizeToFit`, 최대 배율 제한, 고정 제목 높이를 사용하지 않는다. 실제 가용 너비에서만 줄바꿈하고 전체 제목을 왼쪽 정렬로 읽게 한다. 글자 확대 여부만 보고 제목을 다른 행으로 이동하거나 빈 컨트롤 행을 만들지 않는다. 우측 액션과 제목이 겹치지 않도록 제목은 줄바꿈하고 액션은 최소 터치 영역을 유지한다.

상태 표시줄 안전 영역은 최상위 `SafeAreaView`에서 한 번 처리한다. 헤더에 기기 상단 높이를 다시 더하지 않는다. 헤더 뒤 본문은 `ScrollView`로 이동할 수 있어야 한다.

## 헤더·GNB 통합 동작과 시각 규칙 · 2026-10-21

사용자 요청에 따라 UI·문구·아이콘 이름·색·상태·애니메이션·예외를 함께 정의한다. 아래의 ‘규칙’은 제작과 검수에 사용할 계약이며, ‘현재 구현’은 2026-10-21 로컬 소스 대조 결과다. 문서 작성으로 앱 반영이나 실제 화면 검수가 완료됐다고 판단하지 않는다. 화면별 최신 승인 예외는 보존하고, 차이는 마지막 표에서 관리한다.

### 1. 영역의 역할과 제목 결정

헤더는 현재 화면·대상·작업을 식별하고 이전 화면으로 돌아가는 영역이다. 타이틀은 헤더 안의 제목이며 기본적으로 클릭 행동을 갖지 않는다. GNB는 앱의 주요 영역을 바꾸는 공통 탐색이다. 검색·정렬·저장은 해당 화면의 행동이며 GNB 메뉴로 추가하지 않는다.

여행 제목은 개인 화면의 저장 원본과 공개 화면의 공개 사본에서 각각 읽는다. 비공개 원본을 공개 화면에 대신 노출하지 않는다. DAY 전환은 DAY 소개·일정·관련 내용만 바꾸며 여행 타이틀은 유지한다. 로딩에는 `공유된 여행` 같은 일반 화면명을 사용해도 되지만 존재하지 않는 여행명을 만들지 않는다. 조회 실패에는 다시 불러오기와 목록 복귀를 제공한다.

개인 여행 상세의 현재 승인은 이동 바 아래 첫 제목이며, 공개 상세는 한 줄 헤더 제목을 사용한다. 두 방식을 섞어 같은 제목을 반복하지 않는다. 두 화면을 모두 `← 여행명`으로 통일할 경우 적용 범위를 명시한 변경과 시각 검수가 필요하다.

### 5. 색상과 적용 범위

### 6. 애니메이션 규칙

| 대상                | 진입                    | 종료·복귀                | 표현                                               |
| ------------------- | ----------------------- | ------------------------ | -------------------------------------------------- |
| 일반 페이지·주요 탭 | 200ms                   | 별도 복귀 연출 중첩 없음 | 페이지 fade, `Easing.out(Easing.cubic)`            |
| 중앙 확인 팝업      | 200ms                   | 150ms                    | fade, 배경 가림은 150ms                            |
| 목록·더보기 시트    | 200ms                   | 150ms                    | fade와 아래쪽 오프셋 16 → 0, 배경 가림 150ms       |
| 장소 설명·팁 상세   | 200ms                   | 150ms                    | 오른쪽에서 왼쪽으로 진입, 오른쪽으로 복귀          |
| GNB 선택·헤더 눌림  | 즉시                    | 손을 떼면 즉시           | 상태색·아이콘만 전환, 위치·폭·높이 애니메이션 없음 |
| 연속 탭·반복 렌더   | 새 작업에 필요한 전환만 | 이전 전환 중단           | 같은 화면을 다시 그릴 때 진입 연출 반복 금지       |

사용자가 동작 줄이기를 켰거나 화면 읽기를 사용 중이거나, 접근성 설정이 아직 확인되지 않았거나 앱이 백그라운드면 전환은 0ms로 최종 상태에 정착한다. GNB는 접근성 설정과 관계없이 눌림 축소를 사용하지 않는다. 전경 복귀 시 지난 애니메이션과 밀린 이동을 다시 재생하지 않는다.

연출 완료를 기다리려고 임의의 타이머로 저장·인증·뒤로가기를 늦추지 않는다. 화면 종료·대상 변경·계정 전환 뒤 이전 요청이나 애니메이션 완료가 새 화면을 덮어쓰지 않아야 한다. 페이지와 네이티브 라우터의 전환을 중복 실행하지 않는다.

5초 자동 순환은 별도 캐러셀에만 적용한다. 헤더·GNB·DAY를 자동으로 바꾸지 않는다. 캐러셀은 화면 비활성·백그라운드·팝업·사용자 조작 중 자동 이동을 멈추고, 재개할 때 밀린 이동을 즉시 실행하지 않는다.

### 7. 이동·저장·복귀 계약

- 주요 탭 이동은 같은 탭 화면을 쌓지 않는다. 다시 누르기만으로 검색·필터·스크롤을 초기화하지 않는다. 상태 복원은 구현과 브라우저/기기 검수에서 별도 확인한다.
- 여행 만들기는 한 번의 조작으로 작성 흐름 하나만 연다. 로그인 필요 시 요청한 작성 흐름으로 복귀하며 임의의 다른 여행을 열지 않는다.
- 뒤로가기와 닫기는 자동 저장을 뜻하지 않는다. 변경이 있으면 계속 작성/내용 버리고 이동을 구분한다. 서버 저장 실패 시 입력은 보존한다.
- 저장 중에는 저장·닫기·중복 실행을 막는다. 제목·로고·GNB를 눌러 이 잠금을 우회하지 못하게 한다.
- 기기 뒤로가기와 화면 왼쪽 복귀는 같은 작성 보호를 사용한다. 팝업이 열려 있으면 팝업 한 겹부터 닫는다.
- 상세에서 돌아오면 진입 목록·선택 DAY·검색 조건·스크롤·초점을 복원한다. 직접 링크로 이전 화면이 없으면 개인 상세는 내 여행, 공개 상세는 발자국으로 복귀하는 기준을 사용한다.
- 공개 범위·권한에 없는 헤더 행동은 제공하지 않는다. 선택 중인 여행이나 계정이 바뀌면 이전 데이터와 요청 수명을 정리한다.
