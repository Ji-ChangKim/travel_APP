TripPrint 전체 페이지 디자인 시스템
기준일: 2026-10-19 / 제작본: page-design-1 / 상태: 전체 디자인 제작·최종 검토 전

1. 범위와 기준
사용자의 지시에 따라 UI 독립 검토에서 나온 필수 수정부터 전체 페이지를 제작한다. 큰 페이지→작은 페이지→예외 화면→팝업 순서로 분류하고 Num_페이지명을 고정 식별자로 쓴다. 실제 앱·API 배포·DB 변경·Android 빌드와는 별도다.
현행 디자인시스템.md·design-tokens.json 3.0.3·헤더GNB_규격.md·공개여행계획_화면규격.md·여행일정_화면규격.md·SCREEN_REVIEW.txt를 대조했다. UI_LEAD_REVIEW.txt의 필수 수정 조건을 제작 범위에 포함한다.
기존 승인 브랜드와 수치는 유지한다. 이번 디자인에는 제안한 하단 메뉴 이름/순서(홈·내 여행·발견·발자국·MY)를 적용한다. 제품 앱의 내비게이션을 이미 바꿨다는 뜻은 아니다. 개인 여행 상세는 현행대로 이동 바와 여행 제목을 분리하고, 공개 여행계획과 공개 장소 상세는 뒤로가기 옆 제목을 사용한다.

2. 원본 파일과 번호
공통 렌더러: review/index.html·review/review.css·review/review.js, catalog.mjs·model.mjs·components.mjs·screens.mjs·states.mjs·design-system.mjs.
전체 번호 원본: review/catalog.mjs. 제작 목록: pages/PAGE_MANIFEST.json, 한글 목록: pages/PAGE_INDEX.txt. 각 화면은 pages/Num_페이지명.html로 직접 열 수 있다. 같은 제목이라도 개인 읽기·공개 읽기·검색 후보는 번호를 나눈다.
000 디자인 시스템 / 100 홈·여행 시작 / 200 내 여행·원본 관리 / 300 발견·공개 읽기 / 400 발자국·선택 공유 / 500 MY·계정 / 600 시작·인증 / 700 예외 / 800 팝업.
번호는 화면의 정체성이며 추가할 때 기존 번호를 다시 매기지 않는다. 큰 페이지와 하위 화면은 parent로 연결한다. 예외와 팝업도 발생한 페이지를 parent로 기록한다. 실제 라우트와 디자인 식별자는 구분한다.
재생성: node docs/02. 디자인/01. 화면설계/02. 시안렌더러/prepare-pages.mjs. 생성 뒤 해당 파일에만 Prettier를 적용한다. 서버: node docs/02. 디자인/01. 화면설계/02. 시안렌더러/serve.mjs, 기본 주소 http://127.0.0.1:8837/ . 서버는 허용 목록의 파일과 기존 공개 장소 사진 읽기만 제공한다.
캡처는 outputs/page-design/captures/Num_페이지명.png로 같은 번호를 사용한다. 전체 화면의 기본390/100%와 작은 화면·큰 글자·긴 제목 검수 결과를 별도 기록한다. HTML은 전체 스크롤 내용을 포함하며 PNG 한 장은 해당 화면의 첫 뷰포트다.

3. 색·글꼴·여백
원본: design-tokens.json. 생성한 brand-data.mjs는 원본 목록·값·해시를 포함한다. 제품 토큰을 새 시안에 맞춰 몰래 바꾸지 않는다.
화면 #FFF9F3 / 카드 #FFFFFF / 본문 #203247 / 보조 #596574 / 주요 배경 #FF6B57 / 링크 #A43E31 / 경계 #8A7B70.
위험 행동 #9E3438·흰 글자 / 비활성 #EEE8E2·#596574. 밝은 코랄 위 작은 흰 글자는 사용하지 않는다. 선택·오류·완료는 색과 상태 텍스트·접근성 속성을 함께 쓴다.
Pretendard 제목26/36·700, 섹션22/30·700, 장소18/26·600, 본문16/26·400, 보조14/22·400, 버튼16/24·600, 하단 메뉴만13/20·600. 로고는 원본 자산이다.
좌우20, 카드 안16, 같은 묶음12, 섹션 사이24. 일반 카드 모서리16, 여행 표지20, 버튼·입력12, 팝업24. 작은 화면에서 글자 크기를 줄여 맞추지 않는다.
버튼·입력은 최소48×48 터치, 주요 버튼 최소52, 입력 최소48. 아이콘24·원본 선2, 원본 예외2.5. 기존 매니페스트53개를 사용한다. 원본에 없는 뒤로/닫기/더보기는 앱의 기존 플랫폼 아이콘 역할로 구분하며 임의 SVG 체계를 추가하지 않는다.

4. 컴포넌트와 상태
헤더: 최상위는 제목 왼쪽·뒤로 없음, 홈은 로고. 하위는 이동 바56·터치48와 제목26/36. 공개 읽기 제목은 실제 여행명이다. 긴 제목은 전체 줄바꿈한다.
버튼: 기본·눌림·비활성·처리 중·초점·위험·링크를 구분한다. 주요 코랄 행동은 화면당 하나 이하. 처리 중에는 실제 disabled와 busy를 사용하고 중복 제출을 막는다.
DAY: 같은 패딩·굵기·테두리·너비 규칙을 유지하고 미선택 흰색/네이비, 선택 네이비/흰색·밑줄·눌림 상태로 표시한다. 체크와 빈 아이콘 칸을 두지 않는다. 가로로 넘기는 DAY 목록은 의도한 단일 스크롤이며 본문 전체 가로 넘침과 구분한다.
입력: 표시 라벨을 실제 입력과 연결하고 필수·선택·오류를 구분한다. 날짜와 시각은 운영체제 선택기를 쓴다. 큰 글자·키보드에서도 입력과 저장이 겹치지 않게 스크롤한다. 작성 중 입력은 여행·DAY·장소별로 구분한다.
장소 카드: 방문 번호·등록 시각/시간 미정·장소명·주소/선택 관계·88×88 사진·설명/팁 행동. 원문 장문은 카드에서 펼치지 않고 우→좌 상세로 읽는다. 큰 글자에서는 번호/카드와 사진/장소명을 세로로 바꿔 좁은 열을 없앤다.
현재/다음 여행: 상태 판별 결과 하나로 뱃지·안내·버튼·필터를 정한다. 출발8일 이상/미정=준비 중, 출발1~7일=여행 예정, 시작일~종료일=여행 중, 종료일 이후=여행 완료. 시작일 당일은 여행 중 우선. 서버의 정리 완료·기록 공개 조건과 날짜 표시를 구분한다.

5. 필수 수정의 적용
홈은 한 여행의 DAY·다음 장소·등록 시각(없으면 미정)과 예약 확인을 먼저 보여준다. 전체 여행 카드를 반복하지 않는다. 현재 예시 날짜는 외부 검토 안내에서 구분한다.
여행 만들기는 나라/도시·기간을 나누고 나라 변경 시 도시를 초기화한다. 현행 생성 API는 기간 필수다. 날짜를 나중에 정하면 기간 확정 화면으로 이어지며 ‘날짜 없이 서버 생성 완료’를 만들지 않는다. 임시 여행 저장 계약은 신규 범위로 별도 승인한다.
개인 장소 설명은 내 일정 읽기/수정, 공개 설명은 읽기만, 검색 후보는 일정 추가로 연결한다. 미지원 공개 계획 복제는 주요 행동에서 제거한다.
DAY 소개는 day.planTitle/planConcept, 장소 설명·팁은 schedule.planContent.description 한 필드, 개인 메모는 schedule.memo다. 팁 때문에 새 DB 컬럼을 만들지 않는다. 선택지 묶음과 선택/대체 관계도 보존한다.
공개 선택은 일정별 체크를 사용하고 선택0건은 미리보기/확정 불가다. 같은 투영으로 미리보기와 공개 사본을 만든다. 원본 수정이 게시 사본에 자동 반영되지 않는다. 개인 메모·동행·예약·영수증 원본/품목은 제외한다.
항공 조회와 수동 입력·숙소 STAY 입력, 사진과 영수증, 지출 실제/예상·통화별 합계, 동행·준비물·설정·공개 관리 진입을 각각 제공한다. 영수증 원본을 확인 폼과 다른 화면에서 대조한다.
오사카 DAY 소개와19개 장소의 원문·선택지 문구는 기존 공개 결과에서 그대로 읽는다. 작성자 계정·인증·비공개 필드는 예시에 포함하지 않는다. 원문의 평점/영업 문구는 작성자가 제공한 설명이며 실시간 Google 정보로 새로 검증한 값이 아니다.

6. 이미지·하루·지도
런처/Play 아이콘·가로 로고·하루 empty/error/loading은 기존 apps/mobile/assets/brand 원본을 재사용한다. 캐릭터는 세로 비율을 보존하고 첫 시작·빈 화면·복구 안내에서만 보조로 쓴다. 320/200%에서는 크기를 줄여 행동을 먼저 읽게 한다. 장식은 화면 읽기에서 제외한다.
여행지 표지는 기존 osaka.jpg와 실제 credits.json의 원본/저작자/라이선스/변경 표시를 연결한다. 이 사진을 Google 장소 사진이라고 표기하지 않는다.
장소 사진은 기본 대체 슬롯으로 표시한다. 외부 검토 도구의 ‘실제 Google 사진 조회’를 켜면 원문 공개 장소의 기존 API를 읽기 전용으로 조회한다. 서버 키·URL·이미지를 파일로 보관하지 않는다. 제공자 정보·원본은 실제 응답에서 표시하며 이미지 없음·오류·소진을 구분한다. 일반 사진·Google 장소 사진·도시 가이드 사진의 출처를 섞지 않는다.
지도 제작본은 장소 상대 위치 도식이다. 도로 지도나 Google 타일을 모방하지 않는다. 정상 핀 선택·카드·동일 DAY·목록 복귀의 배치를 확인한다. 실제 Google 타일·좌표·권한·설정 복귀·Play 서명 제한은 앱 구현 인수에서 별도 확인한다.
카메라/앨범·인증·설정·앱 업데이트·삭제는 디자인의 실행 범위와 외부 처리 범위를 검토 도구에서 구분한다. 제품 화면에 개발 준비·키·API 설정 문구를 노출하지 않는다.

7. 예외와 팝업
예외는 700번대의 독립 화면으로 관리한다. 여행/일정/검색0건, 오프라인·조회·저장·충돌, 위치 권한/정확도/서비스, 카메라·OCR·통화·합계 차이, 사진·공개 철회·권한·초대·세션·지도·항공 조회 실패를 구분한다.
빈 화면은 하루·짧은 제안·첫 행동, 실패는 원인·작성값 보존 여부·다시 시도/우회 행동을 제공한다. 실패를0건이나 성공으로 바꾸지 않는다. 완전한 오프라인 쓰기를 약속하지 않는다.
팝업의 배치·최소/최대·본문 스크롤·행동 위계·초점·닫기 규칙은 POPUP_SPEC.txt에서 통일한다. 원문 읽기는 큰 상세, 확인은 중앙, 선택/목록은 하단 시트를 사용한다.

8. 제작 검증과 남은 경계
전체 기본 화면, 320/390/430×글자100/200%, 긴 제목·긴 본문·예외·팝업을 검사한다. 캡처를 직접 열어 제목·행동·아이콘·브랜드·여백을 대조한다. 자동 검사만으로 컴펌을 완료하지 않는다.
실제 검증 결과와 독립 재검토는 PAGE_DESIGN_QA.txt에 기록한다. 디자인의 로컬 동작·레이아웃 결과와 서버 저장/공개/Android 인수 결과를 구분한다.
실제 API 필드·권한·공급자·APK/AAB 준비 목록은 REDESIGN_TECH_API_BUILD.txt를 따른다. 화면 제작 중 앱의 저장 계약·DB/도메인·버전코드는 변경하지 않는다.

2026-10-19 실제 앱 반영 규격
Google Android 공식 접근성 기준에 맞춰 최소 터치48dp를 적용했다. 주요 버튼52, 제목26/36·본문16/26·보조14/22와 기존 브랜드 색은 유지한다. 위험한 최종 확정은 #9E3438/흰색, 확인창을 여는 보조 위험 행동은 연한 위험 배경/진한 위험 글자로 구분한다. 중앙 확인은 손잡이 없이 fade, 목록 시트는 손잡이와 slide를 사용하며 접근성/백그라운드 즉시 전환 규칙은 공통 모달에 따른다.
발견 명칭과 홈/내 여행/발견/발자국/MY 순서를 실제 전역 탐색에 적용했다. 공개의 선택·미리보기·확정은 실제 폼의 연속 단계이며 별도 블로그 본문 작성으로 바꾸지 않는다. DAY/장소 설명은 여행 원본에서 작성한다.
폭400 미만 또는 글꼴 배율1.3 초과에서는 7열 달력을 강제로 줄이지 않고 시작/종료일의 플랫폼 날짜 선택기를 쓴다. 실제 여행은 기간을 정한 뒤 생성하며 항공편은 선택이다.
기간 축소는 입력 아래에 최신 영향과 차단 이유를 보여준다. 기록이 있는 날짜의 자동 이동/삭제 확인은 제공하지 않는다. 실제 앱 검수와 남은 차이는 ../qa/REDESIGN_IMPLEMENTATION.txt를 따른다. 과거 3.0.2 제작본 캡처는 현재 3.0.3 설치본 검수 증거가 아니다.
