## 1. 디자인 철학 및 핵심 원칙

### 1.1 탈(脫) AI 디자인 선언

TripPrint는 흔한 생성형 AI 템플릿의 양산형 느낌(거대한 캐릭터 일러스트 땜질, 상투적인 "하루가 도와드릴게요!" 챗봇 문구, 검은색 투박한 텍스트 배경 박스, 의미 없는 풀위드 버튼 적층)을 완전히 배제합니다. 사용자가 여행을 떠나기 전 설레는 공항의 공기, 현지 식당에서 받은 영수증을 모으는 손맛, 여행지의 날씨와 이동 동선을 직관적으로 기록하는 **"진짜 실물 여행 노트"**의 감성을 디지털 화면으로 구현합니다.

### 1.2 보존해야 할 2대 핵심 자산

1. **브랜드명 `TripPrint`**: '여행의 발자국을 활자처럼 인쇄하여 남긴다'는 정체성을 담은 공식 타이포 브랜드 로고.
2. **마스코트 `Haru (하루)`**: 화면 중앙을 거대하게 가로막는 장식 요소가 아니라, 사용자가 필요한 순간에 똑똑하게 나타나 팩트를 짚어주는 든든한 여행 메이트.

### 1.3 3대 실물 메타포 (Physical Metaphor)

1. **보딩패스 티켓 (Boarding Pass Ticket)**:
   - D-Day 카운트다운, 도시 코드(ICN, NRT, FUK, CDG 등), 출입국 날짜를 비행기 탑승권 형태로 시각화.
   - 중앙의 **점선 절취선(Perforation)**과 좌우의 **반원 펀칭 노치(Ticket Notch)**를 통해 실제 티켓을 쥐고 있는 듯한 질감을 전달.
2. **라이브 영수증 (Live Receipt)**:
   - 여행 중 지출 등록 시 현지 식당/카페 영수증 형태의 톱니 테두리, 일시, 상호명, 품목, 통화 기호를 깔끔하게 표기.
   - 불필요한 장식 없이 여행 경비의 실제 지출 내역을 한눈에 검증.
3. **하루의 인증 도장 (Haru Verified Stamp)**:
   - 영수증 스캔 인증 및 일정 완료 시 '여권 입국 도장'처럼 찍히는 마이크로 브랜딩 스탬프.

### 2.3 간격 및 여백 시스템 (Spacing & Layout)

- **기본 배수**: `4px` 및 `8px` 그리드 기반.
- **여백 스케일**:
  - `space-1` (4px): 아이콘과 라벨 사이, 미세 뱃지 패딩
  - `space-2` (8px): 칩 내부 여백, 리스트 아이템 내부 요소 간격
  - `space-3` (12px): 카드 내부 텍스트 행 간격, 퀵 액션 아이콘 간격
  - `space-4` (16px): 일반 카드 패딩, 타임라인 노드 간격
  - `space-5` (20px): 화면 좌우 기본 거터(Screen Horizontal Gutter), 티켓 내부 패딩
  - `space-6` (24px): 섹션과 섹션 사이의 구분 간격
  - `space-8` (32px): 페이지 상하단 주요 여백

### 2.4 모서리 곡률 (Border Radii)

- `radius-sm` (`6px`): 작은 뱃지, 태그 칩
- `radius-md` (`10px`): 입력 필드, 드롭다운 메뉴
- `radius-lg` (`16px`): 일반 콘텐츠 카드, 영수증 카드, 퀵 액션 카드
- `radius-xl` (`20px`): 보딩패스 티켓 상단 모듈, 주요 모달 팝업
- `radius-full` (`9999px`): 원형 액션 버튼, 필터 캡슐 칩

## 3. 실물 메타포 컴포넌트 상세 규격

### 3.1 보딩패스 티켓 모듈 (`BoardingPassCard`)

여행이 예정되어 있거나 진행 중일 때 최상단에서 여행의 기대감과 현황을 한눈에 보여주는 대표 컴포넌트입니다.

```text
┌───────────────────────────────────────────────┐  ▲
│  [D-Day 뱃지: D-14]          [상태: 출발 준비] │  │
│                                               │  │ Ticket Body
│  ICN ──────────✈────────── NRT                │  │ (Dark Navy #203247
│  SEOUL                     TOKYO              │  │  or Linear Scrim)
│  2026.11.10 - 2026.11.15                      │  │
├─( ) - - - - - - - - - - - - - - - - - - - ( )─┤  ▼
│  노치(Notch)       절취선(Perforation)   노치 │  ▲ Ticket Stub
│  동행 2명 · 환율 100￥ = 910원    [일정 열기 >]│  ▼ (#162536)
└───────────────────────────────────────────────┘
```

1. **상단 바디 (Main Body)**:
   - 배경: 고해상도 여행지 이미지 위에 선형 그라데이션 스크림(`linear-gradient(180deg, rgba(32,50,71,0.2) 0%, rgba(17,30,46,0.95) 100%)`)을 적용하여 텍스트 가독성을 100% 보장.
   - 공항 코드 및 도시명: 영문 3자리 IATA 코드(32px Bold)와 국문 도시명을 병기.
   - 출발-도착 사이 비행기 아이콘 연결선.
2. **절취선 및 노치 (Perforation & Notch)**:
   - 양측 노치: 반원 형태의 음각 펀칭 (`width: 16px, height: 16px, border-radius: 8px, background: canvas`).
   - 중앙 점선: `border-top: 1.5px dashed rgba(255, 255, 255, 0.45)`.
3. **하단 부표 (Ticket Stub)**:
   - 동행 인원, 환율 정보, 빠른 작업공간 이동 버튼을 담은 요약 영역.

### 3.2 2열 퀵 액션 그리드 (`QuickActionGrid`)

가장 자주 쓰이는 핵심 여행 행동을 화면 좌우 2열 대칭 카드로 배치하여 한 번의 탭으로 진입할 수 있도록 합니다.

```text
┌───────────────────────┐ ┌───────────────────────┐
│ 🧾 영수증 등록        │ │ ✈️ 새 여행 만들기    │
│                       │ │                       │
│ 지출 내역을 사진 찍고 │ │ 항공권·도시 등록하고 │
│ 바로 일정에 매핑      │ │ 새 티켓 발권하기    │
└───────────────────────┘ └───────────────────────┘
```

- **카드 1 (`ReceiptCaptureCard`)**:
  - 아이콘: `receipt-scan-outline`
  - 타이틀: "영수증 등록"
  - 설명: "지출을 찍고 바로 일정에 매핑"
  - 테두리: `#FF6B57` (코랄 포인트 라인)
- **카드 2 (`NewTripCard`)**:
  - 아이콘: `flight-outline`
  - 타이틀: "새 여행 만들기"
  - 설명: "항공권·도시 등록하고 티켓 발권"
  - 테두리: `#203247` (네이비 포인트 라인)

### 3.3 하루 마이크로 뱃지 & 인증 스탬프 (`HaruModules`)

AI의 존재감을 과시하지 않고, 사용자의 기록을 검증해주는 따뜻한 조력자로 `Haru`를 포지셔닝합니다.

1. **하루의 팩트 팁 (`HaruDailyTip`)**:
   - 위치: 홈 하단 및 일정 화면 상단.
   - 형태: `[💡 하루의 여행 팩트 팁]` 마이크로 뱃지와 1~2줄의 현지 실용 정보.
   - 문구 원칙: 챗봇형 어투("제가 추천해드릴게요~") 금지, 사실 위주의 간결한 팁("도쿄 메트로는 24시간권 사용 시 3회 탑승부터 이득이에요.") 제공.
2. **하루의 인증 도장 (`HaruVerifiedStamp`)**:
   - 위치: 영수증 스캔 완료 항목, 방문 완료 장소 카드 우측 상단.
   - 형태: 원형 또는 사각 라운드 테두리의 잉크 스탬프 메타포 (`HARU VERIFIED · 2026.11.10`).
   - 색상: 앤틱 에메랄드 그린 (`#10B981`) 또는 레트로 코랄 (`#FF6B57`).

## 4. 공통 레이아웃 및 내비게이션 모듈 규격

### 4.1 상단 헤더 규격 (`HeaderModule`)

헤더는 사용자의 시야를 방해하지 않고 현재 화면의 맥락만을 제공해야 합니다.

1. **홈 헤더 (`HomeHeader`)**:
   - 좌측: `TripPrint` 공식 워드마크 (높이 22px).
   - 우측: 시스템 알림 아이콘(`bell-outline`, 24px) 1종만 배치.
   - **금지 사항**: 우측 상단 프로필/계정 아바타 버튼은 완전 제거 (하단 GNB의 `MY` 탭으로 계정 관리 일원화).
2. **서브페이지 헤더 (`ScreenHeader`)**:
   - 좌측: 뒤로가기 버튼 (`chevron-back`, 최소 터치 영역 48×48px).
   - 중앙: 화면 타이틀 (18px SemiBold, 말줄임 처리 적용).
   - 우측: 화면별 컨텍스트 액션 (예: '완료', '저장', '필터' 등 최대 1개).

### 4.2 하단 글로벌 내비게이션 (`GlobalNavigation`)

- **탭 구성 (고정 4대 목적지)**:
  1. `홈 (Home)`: 여행 현황 보딩패스, 2열 퀵 액션, 하루 팁
  2. `내 여행 (My Trips)`: 준비 중/진행 중/다녀온 여행 티켓 아카이브
  3. `커뮤니티 (Community)`: 실시간 여행자 영수증 및 추천 루트 피드
  4. `MY (My Page)`: 프로필, 저장된 티켓/영수증 통계, 설정, 언어 변경
- **규격**:
  - 높이: 56px (기기별 SafeAreaBottom 추가).
  - 배경: `#FFFFFF` (상단 1px `border-subtle` 라인).
  - 활성 탭: 코랄 포인트 컬러(`#FF6B57`) + Filled 아이콘 + 굵은 라벨.
  - 비활성 탭: 슬레이트 그레이(`#64748B`) + Outline 아이콘.

## 5. 폼 및 인터랙션 컨트롤 규격

### 5.1 버튼 모듈 (`DesignButton`)

- **높이 규격**:
  - Primary / Secondary: **52px** 고정 (모바일 엄지손가락 터치 최적화).
  - Small / Compact: **38px** (모달 내부 서브 버튼).
- **스타일 변형**:
  - `primary`: 배경 `#FF6B57`, 글자 `#FFFFFF` (주요 확인/저장/등록).
  - `secondary`: 배경 `#203247`, 글자 `#FFFFFF` (보조 행동, 티켓 관리).
  - `quiet`: 배경 투명, 글자 `#64748B`, 테두리 `#E2E8F0` (취소, 목록 보기).
  - `disabled`: 배경 `#F1F4F9`, 글자 `#94A3B8` (비활성 상태).

### 5.2 입력 필드 모듈 (`DesignInput`)

- **높이**: 48px ~ 52px.
- **모서리**: `radius-md` (10px).
- **상태별 표현**:
  - Default: 배경 `#F8F9FA`, 테두리 `#E2E8F0`, 글자 `#203247`.
  - Focus: 배경 `#FFFFFF`, 테두리 1.5px `#203247`, 가벼운 외곽 그림자.
  - Error: 배경 `#FEF2F2`, 테두리 1.5px `#EF4444`, 하단 에러 텍스트 표시.

## 6. 모바일 반응형 및 접근성 보장 기준

1. **최소 터치 영역 48×48px 준수**:
   - 아이콘 크기가 24px이더라도, 부모 터치 컨테이너의 히트 슬롭(Hit Slop)이나 패딩을 통해 최소 48px 이상의 터치 타겟을 무조건 확보합니다.
2. **WCAG 2.1 AA 명도 대비 4.5:1 만족**:
   - 밝은 코랄(`#FF6B57`) 위에 흰색 글씨를 작게 배치하는 것을 금지하며, 흰색 바탕 위의 텍스트는 최소 `#203247` 또는 `#475569` 이상의 짙은 톤을 적용합니다.
3. **시스템 글꼴 확대 대응 (Dynamic Type)**:
   - 고정 높이 컨테이너 안에 텍스트를 가두지 않고, 사용자가 폰트 크기를 키웠을 때 컨테이너 높이가 유연하게 늘어나거나 줄바꿈(wrap)되도록 설계합니다.
4. **오류 피드백의 즉각성**:
   - 폼 입력 오류나 네트워크 지연 시 토스트 팝업이나 인라인 텍스트로 명확한 원인과 복구 행동("다시 시도")을 제공합니다.
