## 검토 원칙

기능 테스트 통과와 기획 승인을 구분한다. 화면 캡처만으로 실기기·접근성·사용성 검증을 완료했다고 판단하지 않는다. 원본은 390px 폭의 전체 화면이며, 현재 앱의 844px 캡처와 전체 이미지 길이를 그대로 비교해 일치율을 만들지 않는다.

색상·아이콘·번호 레일·실제 자료 표시, 기존 항공편·영수증·권한·저장 복구는 유지한다. 장소 검색 공급자 없이 평점·사진·이동 시간을 채우는 방식은 승인하지 않는다. 승인 범위가 제한된 항목은 결과에도 명시한다.

## 반복 검토 기록

1. 기획 1차: 위 문제를 확인하고 승인 보류. 고정한 조건에 맞춰 수정한다.
2. 개발 1차: 이탈 확인, 시간 충돌, 비용 삭제·날짜 정책, 선택형 지도·링크 입력, 유형별 입력과 새 여행 구분을 반영했다.
3. 기획 2차: 새 여행을 덮어 올리는 이동에서는 버린 폼이 남을 수 있는 점을 발견했다. 확인 시 폼 자체를 지우도록 수정하고 새 여행에서 돌아오는 경로를 검사했다. 저장 응답 대기 중 전역 이동도 별도 검사했다.
4. 검수 환경 점검: 이전 staging 빌드의 Metro 캐시가 로컬 검수 주소를 덮는 문제를 확인했다. 캐시 초기화·주소 확인을 포함한 `npm run test:schedule:web`로 실행 순서를 고정했다. 환경이 섞인 검사의 43/48 결과를 최종 통과 근거로 사용하지 않는다.
5. 기획 3차: 지도보다 삽입 순서를 먼저 보여주고, 위치 후보는 선택 후 접으며 전체 목록과 지도는 선택해 펼치도록 정리했다. 체류·비용 정보를 한 줄에 묶어 터치 영역을 줄이지 않고 카드 높이를 줄였다.
6. 최종 검토: 전체 브라우저 49/49, 모델·인증 74/74, API 70/70, 로컬 Workers·D1·R2 11/11, 릴리스 39/39 통과. 마지막 웹 위치 버튼 문구 수정 뒤 관련 브라우저 3/3과 `npm run check`를 추가 통과했다. 최신 캡처에서 앞뒤 방문·지도 선택·카드 정보 위계를 확인하고 승인 기준 8개에 대해 기획 승인했다.

검토는 이 작업의 구현 단계와 기획 재검토 단계를 나눠 기준표·실행 결과·실제 렌더링을 대조하는 방식으로 진행했다. 참고 화면과 다른 데이터 때문에 사진·평점·예약·이동 시간이 없는 부분을 가짜 자료로 채우지 않았다.

원본과 다른 부분도 인수 범위에 기록한다. 기존 여행 허브와 전역 메뉴는 서비스의 다른 기능에 접근하기 위해 유지했다. 원본의 작은 글자를 그대로 줄이지 않고 읽기 크기와 터치 영역을 유지했다. 장소 사진은 실제 등록한 자료가 있을 때 표시하며, 자동 경로가 없는 현재 버전에서는 삽입 순서를 먼저 보고 지도는 선택해서 펼친다. 이 차이를 원본과 완전히 같다고 표현하지 않는다.

승인 범위는 위에 고정한 일정 계획 MVP다. 앱 내부 장소 검색·자동 경로·환율·추천 기능 전체를 승인한 것으로 확대하지 않는다. 서명 APK/AAB, 실기기 설치·업데이트·키보드·글자 확대·접근성, 잔여 의존성 보안 검토와 원격 배포 인수는 별도 출시 조건으로 유지한다.
