언어 선택 · 화면 규격
기준일: 2026-10-26
상태: 사용자 요청에 따른 앱 구현 기준
적용 범위: 로그인 선택, MY, 앱 고정 문구·버튼·접근성 이름·상태·입력 안내

1. 언어 선택
- 선택 항목: 한국어 · KR / English · EN / 日本語 · JP. 내부 언어 코드는 ko / en / ja다.
- 처음 사용하는 기기는 한국어로 시작한다. 지원하지 않거나 손상된 저장값도 한국어로 복구한다.
- 로그인 화면과 MY에서 같은 공통 언어 선택 버튼을 제공한다. 버튼과 선택 시트는 기존 DesignButton·ActionSheet를 사용한다.
- 선택한 언어는 이 기기에 저장한다. 다음 실행과 로그아웃 후에도 유지한다. 다른 기기·계정으로 동기화하지 않는다.
- 저장에 실패하면 기존 언어를 유지하고 같은 시트에서 재시도할 수 있다. 저장 중 선택과 닫기를 잠근다.

2. 번역과 원문 경계
- 앱이 작성한 고정 문구를 호출 지점에서 번역한다. AppText가 임의의 텍스트를 자동 번역하지 않는다.
- 여행 제목·상호·메뉴·개인 메모·닉네임·사용자 게시물과 외부 제공 콘텐츠는 원문을 보존한다. 도시·국가명 등 기존 저장 데이터도 언어 변경으로 덮어쓰지 않는다.
- 언어 변경은 여행의 통화·금액·날짜·시간대·권한을 변경하지 않는다. 날짜 입력과 저장은 기존 ISO 규격을 유지한다. 표시용 월·요일은 언어에 맞춘다.
- 영수증의 사용자 확인·중복 판단·공개 제외·원본 보관 정책은 기존 정책을 따른다. 언어 설정으로 OCR 지원 범위를 확대하지 않는다.
- 폼의 오류 연결 이름은 원래 값으로 유지한다. 표시 이름과 접근성 이름만 번역한다. 영수증 품목의 순번도 같은 원칙을 따른다.

3. 기존 디자인과 차이
- 디자인시스템.md, design-tokens.json, 헤더GNB_규격.md를 유지한다. 헤더·GNB 순서, 선택 표시, 색·높이·여백·글자 토큰을 바꾸지 않는다.
- 추가된 UI는 로그인과 MY의 언어 버튼, 공통 선택 시트뿐이다. 긴 영문·일문은 기존 줄바꿈·높이 확장·스크롤 규칙을 따른다. 글자를 임의 축소하지 않는다.
- 기존 Pretendard를 유지하고 지원하지 않는 일본어 글자는 웹에서 고딕 계열·sans-serif 대체 글꼴을 사용하고 네이티브에서는 OS 대체 글꼴을 사용한다. 일본어 글리프·행간·스크린리더 발음은 Android/iOS 실기기에서 별도 확인한다.
- 웹 문서 언어와 텍스트의 접근성 언어를 설정한다. iOS 날짜 선택기에 선택 언어를 전달한다. Android의 기본 날짜·시간 선택기, 키보드, 사진/공유 화면은 OS 언어 설정의 영향을 받는다.

4. 검증과 유지 관리
- 검사: npm run check, npm run test:auth, npm run test:headers:web.
- 다국어 UI 검사: npm run test:localization:web. 로컬 번들을 새로 만들고 13개 흐름을 검사한다.
- 320·390·430px에서 KR/EN/JP를 확인한다. 영수증은 200% 글자, 입력값 보존, 저장 결과, 원문 유지, 재실행, 저장 실패와 재시도를 확인한다.
- 번역 사전은 messages.json에서 한국어 원문을 키로 EN/JA 두 값을 관리한다. 변수는 {name} 형태로 보존하며 임의의 사용자 문자열을 사전 키로 사용하지 않는다.
- UI 문구 변경 시 사전·접근성 이름·필드 연결·관련 UI 검사를 함께 갱신한다. 웹 통과를 실기기 인수 완료로 기록하지 않는다.

2026-10-26 승인 변경: KR/EN/JP마다 LINE Seed 공식 파일을 앱에 포함한다. 기존 Pretendard 유지 정책을 대체한다. 웹은 세 언어 글꼴을 순서대로 대체하고 네이티브의 혼합 언어 중 해당 파일에 없는 문자는 OS 대체를 사용한다. 언어 전환 시 입력 원문과 선택 상태는 유지한다. Regular 400, 기존 600·700 강조 역할은 Bold 700으로 연결한다. 글꼴 로딩 실패 시 기존 시스템 글꼴 복구를 유지한다.
