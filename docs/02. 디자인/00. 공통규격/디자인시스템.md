## 행동과 탐색 위계 · 2026-10-16

코랄 주요 버튼은 한 화면에 하나 이하로 둔다. 홈에 이어갈 여행이 있으면 여행 보기가 주요 행동이며 새 여행 만들기는 보조 행동이다. 내 여행 목록에서는 첫 번째로 보이는 여행 카드의 열기만 주요 행동이다. 나머지 카드는 작은 보조 링크를 사용하고 새 여행 만들기는 헤더 오른쪽의 48px + 아이콘으로 제공한다. 빈 목록에서는 헤더의 + 버튼으로 시작한다. 목적지가 있는 화면의 보조 탐색을 주요 버튼과 같은 크기·색으로 반복하지 않는다.

여행 상세는 일정·지도·비용 세 항목을 한 줄에 고정한다. 더보기는 공통 헤더 오른쪽의 ⋯ 아이콘으로 제공한다. 가로로 밀어야 보이는 작업 탭을 사용하지 않는다. 사진·영수증, 준비물, 동행, 발자국 공유와 소유자의 여행 정보·기간 변경은 상단 더보기 메뉴에서 연다. 동행 바로가기와 인원 소개를 중복해서 배치하지 않는다. 역할·공개 관리의 기존 권한은 유지한다.

여행 상세에서는 글로벌 하단 내비게이션을 숨긴다. 일정 추가는 일정 화면 하단 가운데의 주요 버튼 하나로 제공한다. 이 바에는 지도·카메라·앨범 버튼을 함께 두지 않는다. 지도·비용·부가 영역과 보기 전용에서는 일정 추가 바를 숨긴다. 지도는 상단 영역 선택으로, 영수증 촬영·앨범은 사진·영수증 영역으로 접근한다. 화면이 실제 일정에 제공하는 높이를 브라우저에서 측정한다. 빈 날짜에는 추천 코스 불러오기와 장소 검색으로 추가 두 개의 보조 가이드 카드를 표시한다. 코스는 기존 도시 가이드의 장소를 미리 보고 선택한 날짜의 작성 화면으로 이어진다. 시간·위치는 추정하지 않으며 저장 전에 취소하면 여행은 바뀌지 않는다. 추천이 없는 도시는 검색으로 이어간다.

화면 제목은 ScreenTitle의 26/36px·굵기 700·왼쪽 정렬을 유지한다. ScreenHeader의 이동 바는 기본 최소 56px, 좌우 여백 20px, 뒤로가기 터치 영역 48px, 같은 24px 화살표를 사용한다. 이동 바와 큰 화면 제목은 역할을 분리한다. 최상위 화면에는 뒤로가기를 두지 않는다. 큰 글꼴은 실제 너비에 따라 자연스럽게 줄바꿈하고 빈 행이나 말줄임을 만들지 않는다. 상세 규격과 검수 절차는 [화면 헤더 규격](헤더GNB_규격.md)을 따른다.

여행 기간은 travelDateRange 함수와 format.dateRangeSeparator 토큰을 사용해 YYYY-MM-DD – YYYY-MM-DD로 통일한다. 저장한 날짜와 시간대는 바꾸지 않는다. 홈·목록·발자국·다이어리·커뮤니티·공개 미리보기도 같은 구분 기호를 사용한다.

필터와 여행 스타일은 최소 높이 48px의 chip 변형을 사용한다. 선택은 옅은 코랄·네이비 테두리·체크와 selected 속성으로 전달한다. 아이콘 버튼과 달력 날짜도 같은 초점·눌림·비활성 규칙을 따른다. 달력의 양 끝은 테두리와 selected 속성으로 표시하고 기간 안쪽은 연한 배경으로 이어준다.

기존 화면의 colors.primary·accent는 네이비와 흰 글자 조합을 보존하는 호환 이름이다. 새 주요 행동은 colors.actionPrimary·actionForeground를 사용한다. 일정 테마는 같은 JSON의 action 전경을 읽는다. 작은 링크에 actionPrimary를 쓰지 않는다.

## 세 화면 적용

홈은 실제 여행 사진이나 노트 표지, 여행명·기간·계속하기 행동으로 구성한다. 첫 여행은 원본 하루와 코랄 버튼으로 시작한다. 긴 제목을 작은 글자로 축소하지 않는다.

공동 일정은 실제 멤버 수, 배경을 채우는 DAY 선택, 네이비 시간, 장소 카드, 진한 링크로 구성한다. 큰 글꼴에서는 시간과 카드가 위아래로 배치되어 좁은 열에 글자가 끼지 않는다. 동행 관리는 더보기에서 연다.

발자국은 완료 여행만 표시한다. 일반 사진을 표지로 사용하고 영수증은 제외한다. 원본 기록은 나와 동행자가 읽는다는 기존 권한을 안내한다. 커뮤니티에는 사용자가 직접 고른 내용만 공개하는 기존 흐름을 유지한다.

하단 메뉴는 홈·내 여행·발자국·커뮤니티·MY다. 새 여행은 홈과 내 여행의 생성 버튼에서 시작한다. 일정 작성 중 메뉴를 옮길 때 기존 이탈 확인을 유지한다.

## 추가 네 화면 적용

여행 만들기는 두 단계의 현재 위치를 안내하고 첫 단계에 원본 하루를 작게 배치한다. 제목·여행지·달력은 흰 카드로 묶는다. 항공편 선택과 입력의 뒤로가기·완료·조회도 공통 버튼을 사용한다. 웹 날짜 입력은 Pretendard와 사용자 글자 배율을 적용하며 모바일 시스템 날짜 선택기는 운영체제의 표시 설정을 따른다.

내 여행 목록은 실제 상태별 건수와 검색 결과를 구분한다. 첫 번째 여행 카드의 열기만 주요 행동으로 두고 다른 카드 열기는 보조 링크로 표시한다. 새 여행 만들기는 헤더의 + 아이콘으로 제공한다. 목록의 검색 입력은 공통 글꼴·초점 테두리를 사용한다. 목록 응답에 없는 사진·동행 인원을 만들지 않는다.

커뮤니티는 공개된 사진·작성자·날짜·여행 정보·본문·일정 순서로 구성한다. 사진 위에 작은 글자를 겹치지 않는다. 사진 조회·다운로드 실패에는 다시 불러오기를 제공하고 공개 권한 검사에 실패한 주소를 계속 표시하지 않는다. 신고·차단·추가 읽기도 공통 상태를 사용한다.

MY는 프로필 카드·실제 여행 통계·앱 정보로 구성한다. 닉네임과 설명은 줄바꿈하고, 여행 스타일은 체크가 있는 선택 칩으로 표시한다. 프로필 수정·닫기·저장·로그아웃은 같은 버튼 체계를 따른다. 저장 중 입력 잠금과 작성 내용 이탈 확인은 기존 흐름을 유지한다.

## 여행 상세 네 영역 적용

지도는 22px 영역 제목·18px 장소명·14px 주소와 안내로 구성한다. 긴 장소명을 줄바꿈하고 방문 번호·선택 상태·위치 수정 행동을 구분한다. 웹의 상대 위치 도식은 번호의 축소 비율과 사용자 글자 배율을 함께 반영한다. 모바일 지도 핀은 일반 코랄/네이비, 선택 네이비/흰색을 사용한다. 연결선은 실제 도로 경로를 뜻하지 않는다는 안내와 기존 외부 지도 열기를 유지한다.

비용은 실제 지출과 예상 비용을 각각 흰 카드에 표시하고 KRW·JPY·USD를 따로 합산한다. 소수 금액은 정수 센트로 계산하고 1센트와 0도 소수 두 자리로 표시한다. 항목은 비용 구분·출처·제목·통화와 금액·연결한 일정으로 나눈다. 입력의 통화·실제/예상·일정 연결은 공통 선택 상태를 사용한다.

체크리스트는 준비한 개수와 전체 개수, 완료 막대를 표시한다. 각 준비물은 공통 버튼의 checkbox 변형으로 checked 속성과 체크를 함께 제공한다. 저장이 확정되기 전에 임의로 완료 처리하지 않는다. 동행자는 닉네임 첫 글자·실제 역할·나 표시를 사용하고 역할 변경과 참여 해제는 기존 권한에 따라 제공한다. 초대 내역의 역할·만료일·상태는 14px 이상으로 표시한다.

빈 지도·비용·준비물에는 원본 하루와 다음 행동을 안내한다. 보기 전용 여행에는 입력할 수 있다고 안내하지 않는다. 세 핵심 탭·날짜 선택·상단 더보기는 같은 선택·초점·눌림 토큰을 따른다. 저장 중에는 실제 입력과 관리 행동을 잠그고 처리 안내를 표시한다.

## 제작 전 접근성 기준 · WCAG 2.2 AA

새 화면을 작업하기 전에 `npm run check:design`으로 의미별 전경·배경 조합을 확인한다. `npm run check`도 이 검사를 먼저 실행하며 기준 미달이면 실패한다. 저장된 대비 수치를 믿지 않고 현재 토큰을 다시 계산하고, 4.499처럼 기준에 못 미치는 값을 반올림해 통과시키지 않는다.

WCAG의 일반 글자는 4.5:1, 큰 글자는 3:1이 최소 기준이다. TripPrint는 본문·보조 문구·버튼·입력값·플레이스홀더를 크기와 관계없이 4.5:1 이상으로 제작한다. WCAG에서 제외되는 비활성 컨트롤의 글자도 같은 4.5:1을 유지한다. 로고와 장식용 브랜드 코랄을 정보 전달용 글자에 재사용하지 않는다. [W3C · Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

컨트롤을 식별하는 경계·아이콘과 직접 만든 초점 표시는 인접 배경 대비 3:1 이상을 확인한다. 선택·오류·완료는 색만으로 구분하지 않고 체크·텍스트·접근성 상태를 함께 제공한다. 장식용 카드 구분선에 컨트롤 식별 경계 기준을 일괄 적용하지 않는다. [W3C · Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

키보드로 이동·실행·닫기가 가능해야 하고 초점이 보여야 한다. 프로젝트 공통 규격은 2px 초점선과 48px 터치 영역이다. 입력 라벨과 오류를 연결하고 시트를 닫으면 열었던 버튼으로 초점을 돌려준다. [W3C · Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)

320px 폭과 글자 200%에서 주요 내용과 기능을 확인한다. 사진 위 글자·배경 이미지·화면 읽기 순서·iOS/Android 보조기기는 수동 검수도 거친다. 색상 검사나 브라우저 일부 검사만으로 전체 WCAG AA 적합성을 선언하지 않는다.

## 검증과 범위

토큰의 contrastChecks는 지정 전경·배경의 sRGB 계산이다. 프로젝트의 모든 정보 전달용 글자 4.5:1, 식별 경계 3:1을 기준으로 반올림 전 값을 비교한다. 브라우저 검수는 표시된 본문·입력값·플레이스홀더의 단색 배경, 실제 색·크기·불투명도를 읽고 360·390·430px 및 큰 글꼴을 확인한다.

사진·그래디언트와 기기별 렌더링까지 포함한 전체 앱 접근성 인증을 뜻하지 않는다. 인증·저장·공개 선택의 API·DB 계약은 바꾸지 않는다.

DAY 탐색은 현재 보고 있는 날짜를 선택하는 기능이다. 체크와 체크용 빈 공간을 없애고, 미선택은 흰 배경·네이비 글자·기존 테두리, 선택은 네이비 배경·흰 글자로 표시한다. 선택 글자의 밑줄과 접근성 선택 상태를 함께 제공한다. 글꼴 크기·굵기·테두리 두께·안쪽 여백은 선택 전후에 같게 유지한다. 개인 일정의 전체/DAY, 일정 작성의 DAY, 공유 계획의 DAY에 같은 규칙을 적용한다. 한 줄 가로 탐색을 유지하고 화면 너비가 부족하면 가로로 이동한다.

여행 스타일 등 기존 체크 선택 버튼은 체크 공간을 미리 확보해 크기를 유지한다. 일반 행동 버튼에는 선택 공간을 추가하지 않는다. DAY 선택 방식은 체크리스트의 완료·다중 선택과 구분한다.

2026-10-19 후속 코드 정리는 제목·색·폰트·여백·버튼·선택·모달 규격을 유지한다. 큰 화면의 표현은 영역별 함수와 *View, 요청 수명은 컨트롤러와 작업별 행동 훅, 명령 본문과 초안 생성은 workspaceScreenActions가 맡는다. 프로필·타임라인의 기존 스타일 값은 별도 스타일 모듈로 옮긴다. 실제 검수와 변경 범위는 [큰 화면 분리·회원 검수 기록](<../../05. 검수/02. 검수보고/대형화면함수_분리검수.txt>)을 따른다. 새 시안이나 신규 디자인 토큰을 적용하는 작업이 아니다.
