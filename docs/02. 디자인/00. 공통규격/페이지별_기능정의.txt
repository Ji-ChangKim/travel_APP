TripPrint 페이지별 기능 정의
기준일: 2026-10-19 / 대상: page-design-1의106개 화면 / 상태: 디자인 제작본의 개발·검수 계약

1. 문서의 역할

페이지마다 이용 목적, 제공 기능, 입력과 동작, 저장·이동 결과, 예외와 완료 조건을 정의한다. 화면 번호와 파일명은 pages/PAGE_MANIFEST.json, 디자인은 pages/Num_페이지명.html을 따른다. 시안에서 버튼이 이동한다는 사실과 실제 앱에서 기능을 완성했다는 사실은 구분한다.
아래 ‘동작’과 ‘완료’는 앱에 적용할 요구사항이다. 현재 전체 개편 제작본은 브라우저 메모리에서 일부 입력·선택·읽기를 확인하는 단계다. 실제 기능의 인수 증거는 서버 재조회·권한 검사·설치본 검증을 별도로 남긴다. 현재까지 실행한 검사는 PAGE_DESIGN_QA.txt를 따른다.
공통 디자인 규칙과 디자인이 없는 경우의 처리 순서는 디자인_적용가이드.txt, 수치 원본은 design-tokens.json, 팝업 상세 수치는 POPUP_SPEC.txt다. 기존 앱 기능·통신 계약은 REDESIGN_TECH_API_BUILD.txt와 ../DB_DICTIONARY.txt를 함께 확인한다. 이 문서만으로 DB나 API를 추가·변경하지 않는다.

2. 서비스와 공통 기능 계약

여행계획: 여행 제목·나라·도시·기간·DAY별 소개·순서·장소·시각·예약을 정리하는 개인/동행 원본이다. 장소 설명·팁은 그 일정에서 작성한다. 커뮤니티 게시글을 먼저 쓴 뒤 일정처럼 꾸미는 구조를 사용하지 않는다.
발자국: 다녀온 여행 원본과 연결된 장소·사진·비용·메모를 다시 읽고 보완하는 개인 기록 영역이다. 여행 종료와 공개는 별개다.
발견/커뮤니티: 이용자가 선택해 공개한 여행계획·여행기록을 읽는 영역이다. 원본의 비공개 내용이나 별도 블로그 본문을 자동 노출하지 않는다. ‘발견’은 개편 제작본의 메뉴 이름이며 현행 앱의 ‘커뮤니티’와 같은 공개 탐색 영역을 뜻한다.

C01 식별·복귀: tripId·실제 dayId·scheduleId를 유지한다. 상위/하위 이동, 상세 닫기, 로그인 복귀에서 여행·선택DAY·목록 위치를 보존한다. 서로 다른 여행의 초안을 재사용하지 않는다. 화면 번호는 디자인 식별자이며 API ID나 실제 앱 라우트가 아니다.
C02 권한: 로그인 여부·현재 여행의 소유자/편집/보기 권한을 화면 진입과 쓰기 요청에서 확인한다. 공개 읽기는 선택된 공개 사본만 읽는다. 보기는 수정 버튼을 숨기는 것에 더해 서버에서도 쓰기를 거부한다. 초대·권한·공개 관리의 소유자 제한은 기존 서버 정책을 따른다.
C03 입력: 라벨·필수/선택·오류를 연결한다. 오류는 해당 입력 아래에 이유와 수정 방법을 표시하고 입력값을 유지한다. 공백·날짜·금액·허용 범위는 공유 검증 스키마와 맞춘다. 저장 중 버튼과 연관 입력을 잠그며 연타를 중복 요청으로 보내지 않는다.
C04 저장: 서버 성공 응답 뒤에 목록·상세·합계를 갱신한다. 저장 실패를 성공이나 빈 목록으로 바꾸지 않는다. workspace 쓰기의 Idempotency-Key와 If-Match를 유지하고, 응답 유실의 같은 요청은 같은 키·본문으로 재시도한다. 다른 내용은 새로운 요청으로 보낸다. 충돌은708, 세션 만료는720으로 처리한다.
C05 이탈: 저장 전 실제 변경이 있을 때만802를 연다. 변경 없는 뒤로가기는 즉시 돌아간다. 제출 처리 중에는 중복 이동·제출을 막고, 완료 후 원래 목적지로 한 번만 이동한다. 앱 종료·기기 변경까지 초안이 남는다는 약속은 저장 계약이 있을 때만 한다.
C06 비동기: 요청 시작 시 여행·DAY·검색어·폼·인증 맥락을 묶는다. 화면 종료·폼 변경·로그아웃·다른 요청 뒤 늦게 온 응답은 현재 화면에 적용하지 않는다. 설정 복귀는 권한과 서비스를 다시 확인하고 사용자가 재시도하도록 한다.
C07 상태: 날짜 미정 또는 출발8일 이상 전=준비 중, 출발1~7일 전=여행 예정, 시작일~종료일=여행 중, 종료일 다음 날부터=여행 완료. 시작일 당일은 여행 중이 우선이다. 뱃지·문구·버튼·필터는 같은 판별 결과를 사용한다. 날짜로 계산한 표시와 서버의 기록 공개 가능 상태를 혼동하지 않는다. 표시 기준 날짜/시간대는 현행 공통 날짜 모듈과 같아야 한다.
C08 공개: community.publish(kind=plan|record)는 선택한 일정·일반 사진·명시적으로 선택한 통화별 합계를 공개 사본으로 만든다. plan은 일정1개 이상, record는 현행 서버의 완료 조건을 충족해야 한다. 개인 메모·동행 개인정보·예약번호·영수증 원본/품목은 제외한다. 원본 수정은 기존 공개 사본을 자동 갱신하지 않는다. 미리보기와 확정 요청은 같은 선택을 사용한다.
C09 지도·위치: 지도 표시와 GPS 요청을 분리한다. 현재 위치는 사용자가 눌렀을 때만 전경 권한을 요청한다. 지도 타일·장소 검색·장소 사진은 서로 다른 조회다. 연결선은 실제 도로 경로나 소요 시간으로 표현하지 않는다. 제작본의 상대 위치 도식은 Google 지도 구현 완료를 뜻하지 않는다.
C10 금액·이미지: KRW·JPY·USD는 현행 통화별 정밀도 검증을 사용하고 정수 최소 단위로 계산한다. 다른 통화를 환율 없이 합치지 않는다. 이미지 없음·통신 실패·이미지 디코딩 실패·공개 권한 만료를 구분한다. 영수증/OCR 초안은 확인 전 실제 지출에 합산하지 않는다.
C11 인수: 쓰기 성공→목록/상세 재조회→앱 재실행 또는 새 세션 재조회→허용/금지 역할 확인을 실제 환경에서 검사한다. 공개 기능은 익명 읽기와 비공개 필드 제외도 확인한다. 캡처·로컬 클릭만으로 저장 인수를 완료하지 않는다.

입력 제한의 현재 기준
여행 이름 최대50자, 일정/지출 제목1~100자, 주소 최대200자, 개인 메모 최대300자, DAY 제목 최대200자·소개 최대2000자, 장소 계획 설명 최대4000자, 선택 그룹1~80자·안내 최대200자, 머무를 시간1~1440분이다. 공유 소개 body 최대2000자는 별도 선택 필드이며 전체 원문을 넣는 칸이 아니다. 현행 planContent와 DAY 제한은 JavaScript 문자열 길이 기준이며 닉네임의 바이트 제한과 다르다. 실제 스키마 변경 시 이 문서도 함께 갱신한다.
신규/변경 닉네임은 공백 포함 UTF-8 2~20바이트, 기존 본인 이름은 그대로 유지할 수 있다. 생년월일은 선택이며 생일 없이 온보딩을 완료한다. 입력한 생일만 실제 날짜·1900-01-01~오늘 범위로 검증한다.

3. 큰 페이지와 하위 페이지

000_디자인시스템
목적·기능: 제작/검수 담당자가 색·글꼴·여백·컴포넌트·아이콘·하루·상태·전환을 비교한다. 고객 앱 메뉴에는 넣지 않는다.
동작·완료: 컴포넌트의 기본·선택·비활성·오류·처리 중 예를 확인하고 실제 값은 토큰 원본과 대조한다. 숫자와 예시가 다르면 토큰을 임의로 바꾸지 않고 예시를 수정한다.

100_홈
목적·기능: 현재 진행 중인 여행 또는 가장 가까운 여행1개의 다음 일정과 예약 확인을 먼저 보여준다. 여행 팁/도시 가이드/공개 계획 탐색을 보조로 제공한다.
입력·동작: 계획 계속하기→210, 항공·예약→230, 새 여행→110, 가이드→313. 시간 미정은 그대로 표시하고 다음 장소가 없으면 일정 추가 행동으로 연결한다.
데이터·예외·완료: 본인 여행과 실제 일정에서 요약을 계산한다. 여행 없음701, 인증 필요722, 조회 실패706. 과거 여행을 ‘다가오는 여행’으로 표시하지 않으며 종료 여행의 주 행동은 기록 확인이다. 전체 여행 아카이브는200이 맡는다.

110_여행만들기
2026-10-21 V11 우선 계약: 구매한 항공권을 가진 이용자는 여행 날짜→국가·도시→선택 제목을 정한 뒤 다음 화면에서 항공권을 입력하고 실제 여행을 생성한다. 아래 ‘항공권은 나중에 추가’는 필수가 아니라 선택 경로다. 여행 생성과 항공권의 DAY 배치는 하나의 기존 생성 명령으로 저장하며 210에서 DAY별 추가·수정·삭제·순서 변경 후 재조회한다. 공통 헤더·GNB 규격은 바꾸지 않는다.
목적·기능: 여행 이름·나라·도시·기간을 정하는 첫 단계다. 항공권은 나중에 추가한다.
입력·동작: 나라111·도시112·기간113을 열고 돌아와 초안을 유지한다. 나라 변경은 이전 도시를 비운다. 다음→114에서 입력값을 확인한다.
데이터·예외·완료: 제목/여행지/기간은 기존 생성 검증을 따른다. 날짜 나중에 선택은 기간을 이어 정하는 경로이며 현행 API에 날짜 없는 여행을 생성하지 않는다. 미저장 이탈802. 실제 생성은114에서 한 번 수행한다.

111_나라선택
목적·기능: 나라 이름으로 찾고 한 나라를 고른다.
입력·동작: 목록 선택→열었던110/216으로 복귀. 실제로 나라를 바꿨을 때만 도시 선택을 초기화한다. 취소하면 이전 선택을 유지한다.
데이터·예외·완료: 선택한 국가 값과 화면 라벨을 구분한다. 검색0건은 검색 수정 안내를 표시한다. 제작본의 네 나라 목록을 전체 지원 국가 목록으로 간주하지 않는다.

112_도시선택
목적·기능: 선택 국가의 도시를 검색하거나 이름을 직접 입력한다.
입력·동작: 나라를 먼저 정하고, 도시 선택/직접 입력 확정 뒤110/216으로 돌아간다. 입력 중 뒤로가기는 확정값을 임의로 바꾸지 않는다.
데이터·예외·완료: 다른 나라의 도시 후보가 남지 않아야 한다. 도시 이름과 실제 좌표를 동일시하지 않는다. 검색 실패와 후보0건을 구분하고 직접 입력을 제공한다.

113_여행기간선택
목적·기능: 여행 시작·종료일을 정한다.815 달력과 같은 초안을 사용한다.
입력·동작: 두 날짜를 선택하고 시작일≤종료일을 검사한 뒤110으로 복귀한다. 취소는 생성 원본이나 DAY를 만들지 않는다.
데이터·예외·완료: 실제 달력 날짜와 현행 최대 기간 제한을 따른다. 미정이면 미정 표시와 기간 선택 행동을 유지한다. 날짜 확정 전 생성 성공을 표시하지 않는다.

114_여행시작확인
목적·기능: 이름·나라·도시·기간·일수를 입력값 그대로 확인하고 여행을 만든다.
입력·동작: 기본 정보 수정→110. 생성 누름→잠금→성공 응답의 tripId로210을 연다.
데이터·예외·완료: 생성 실패는 초안을 보존하고 재시도를 제공한다. 고정 오사카 예시를 실제 입력 대신 보내지 않는다. 재조회한 여행과 DAY 개수가 확인 화면의 기간과 같아야 한다.

200_내여행
목적·기능: 소유/참여 여행 전체를 검색·상태 필터·정렬로 찾는 아카이브다.
입력·동작: 제목/나라/도시 검색, 상태별 실제 건수와 필터, 여행 열기→210, 헤더+→110. 홈으로 가는 중복 링크는 두지 않는다.
데이터·예외·완료: 목록과 필터가 C07의 같은 상태를 읽는다. 검색0건·여행0건·불러오기실패706·로그인필요722를 구분한다. 여러 카드의 주요 버튼을 반복하지 않는다.

210_여행상세_일정
목적·기능: 여행의 DAY 소개·일정·시각·순서를 읽고 관리한다. 일정/지도/비용 세 작업과801 더보기를 제공한다.
입력·동작: DAY 변경은 소개와 장소를 함께 바꾼다. 장소 설명221, 소개224, 순서226, 추가220/223으로 연결한다. 뒤로가기는 들어온 목록 맥락으로 복귀한다.
데이터·예외·완료: 실제 DAY ID와 일정 ID 유지. 시간 미정·선택 후보·대체 장소를 구분한다. 일정0건702, 연결705, 권한718. 보기 권한에는 추가·수정 바를 제공하지 않는다.

211_여행상세_지도
목적·기능: 선택 DAY 장소의 위치와 방문 순서를 확인한다.
입력·동작: DAY 변경→해당 날짜의 핀/카드, 핀 선택→같은 장소 카드, 상세221, 목록210. 현재 위치는 사용자 동작 후225로 연결한다.

8. 보완 항목의 결정과 앱 적용 상태 (2026-10-19)

구현과 검증을 구분한다. 아래 ‘반영’은 실제 앱/서버 소스를 뜻한다. 106개 제작 화면 전부의 설치본 인수를 뜻하지 않는다. 최신 실행 결과와 남은 차이는 ../qa/REDESIGN_IMPLEMENTATION.txt에서 관리한다.

G01 생성/수정 연결 — 반영. 실제 여행 이름·국가·도시·기간 확인 뒤 생성한다. 항공편 없이 만들기는 추가 확인창 없이 실제 생성으로 이어진다. DAY 제목/소개와 장소 설명·팁은 원래 여행 편집에서 저장하며 공유 소개와 구분한다. 생성·저장 실패는 입력을 보존한다.
G02 검색/위치/사진/촬영 — 기존 실제 기능 유지, 환경별 인수 필요. 검색·지도·촬영은 실제 공급자/SDK/권한 경로를 사용한다. 시안의 예시로 대체하지 않는다. Play 설치본의 지도 키 제한·실기기 권한·OCR 정확도는 별도 인수다. 이번 웹 검증만으로 통과를 선언하지 않는다.
G03 순서/관리/계정 — 기존 명령/보호 재사용. 일정·지출·사진 삭제와 공유/철회는 고정 대상·역할·버전을 확인한다. 차단도 확인 뒤 실제 접수한다. 멤버·초대·신고·인증은 기존 서버 통합 검사로 확인한다. 탈퇴는 G11로 별도 관리한다.
G04 날짜 미정 생성 — 범위 확정. 실제 여행 저장에는 시작/종료일이 필요하다. 날짜 미정은 아직 저장하지 않은 입력 초안이며, 별도 임시 여행 생성 기능으로 안내하지 않는다.
G05 종료와 완료 — 기존 계약 유지. 달력의 여행 완료 표시는 종료일 다음 날부터다. 여행기록 공개는 서버 COMPLETED 정리 상태를 별도로 요구한다. 날짜가 지났다는 이유만으로 공개 조건을 우회하지 않는다.
G06 재공개 정책 — 기존 서버 계약 확인·앱 안내 반영. 여행당 공개본 한 개이며 재공개는 같은 postId/링크를 갱신한다. 계획↔기록 변경도 기존 공개본을 대체한다. 원본 수정은 자동 공개되지 않는다. 철회 뒤 다시 공개하면 새 공개 ID를 만들 수 있다. 기존 링크 갱신을 선택/미리보기/확정에서 안내한다.
G07 기록 공개 필드 — 반영. record 단건 상세를 실제 공개 투영으로 읽는다. 개인 메모와 계획 전용 설명을 개인 원본에서 끌어오지 않는다. 주소로 직접 들어와도 피드 첫 페이지에 의존하지 않는다. 앱의 신규 공개 제목은 여행 제목과 같으며 기존 record 제목 데이터는 보존한다.
G08 발견 필터 — 앱·API 반영. 도시/여행 이름 검색과 계획/기록, 1~3일/4일/5일 이상을 지원한다. D1에서 필터 후 20개씩 나눈다. 기간은 공개 DAY 수가 아닌 전체 여행 기간이다. 기본 목록 요청은 이전 계약과 호환된다. 미지원 저장소의 필터 요청은 거짓 성공으로 처리하지 않는다.
G09 기간 축소 — 정책 확정·누락 수정. 빠질 날짜에 DAY 소개·일정·지출·영수증이 있으면 축소를 막는다. 날짜별 DAY 소개·일정·연결 사진·지출·영수증 수를 폼 안에서 안내하고 다시 선택하게 한다. 서버도 같은 조건으로 거부한다. 자동 이동/삭제는 하지 않으며 비어 있는 날짜만 제거한다. 남는 날짜의 DAY ID는 유지한다. 804는 이 영향 안내의 디자인 분류이며 실제 앱에서는 불필요한 확인창 대신 기간 입력 아래에 표시한다.
G10 지출/사진 삭제 — 기존 실제 보호 연결 확인. expense.delete/media.delete의 대상·영향 확인을 중앙 확인 규격으로 표시한다. 사진은 대상 미리보기를 유지한다. 취소 시 명령 없음, 실패 시 원본 유지다. 일정 삭제의 연쇄 정책을 다른 삭제에 임의로 적용하지 않는다.
G11 회원가입/탈퇴 — 사용자 정책 확정·실제 구현. MY→513 계정 관리(/account)→808 확인에서만 요청한다. 탈퇴 즉시 모든 세션 철회, 여행/공개본에 ‘탈퇴 멤버’ 표시, 90일 유예 뒤 이메일·인증 연결·프로필·계정 명령 이력 제거다. 공동/혼자 여행과 사진·영수증·공개본은 계정과 분리해 보존한다. 소유권과 동행 역할은 바꾸지 않는다. 유예 중 새 로그인은 취소/복구, 기존 토큰 조회는 복구하지 않는다. 최근10분 이내 로그인 확인과 실제 서버 성공 후 기기 인증을 정리한다. 시간 단위 예약 작업이 만료 계정을100개씩 처리한다. 게스트의 기기 원본은 이 요청의 대상이 아니다. 게스트·Google 연결 방침은 유지하며 기존 이메일 회원도 보존한다. 계정 정보 삭제는 여행 원문 전체의 개인정보 삭제를 뜻하지 않는다. 약관/개인정보처리방침 URL, 여행 내 개인정보 삭제 요청 경로와 보존 정책의 Google Play 적합성은 출시 전 확정 항목이다.
G12 필수 운영값 — 운영 확정 필요. 최소 지원 정책은 설정되지 않았으며 강제 업데이트 운영값을 임의로 활성화하지 않는다. 기존 위치·조회 제한을 유지한다. 지도/Places 키 제한·공급자 비용 한도·Play 링크는 운영 인수 항목이다.
G13 비공개 값 보존 — 기존 계약 유지·회귀 검사. 공개는 선택 사본이며 개인 메모·예약 정보·동행·영수증 원본/품목을 제외한다. 기기 저장/기존 닉네임/인증 복귀는 기존 회귀 검사 범위를 유지한다. 실제 재설치·프로세스 종료·TalkBack은 Play 설치본에서 별도 확인한다.
G14 선택 후보 묶음 — 실제 저장 누락 수정. 후보 묶음만 수정한 경우에도 schedule.save에 planContent를 보낸다. 묶음 해제 시 숨겨진 choiceLabel/choiceKind를 함께 제거한다. 변경하지 않은 기존 폼은 필드를 생략해 원본을 유지한다. DAY/장소 원문은 공백과 개행을 보존한다.

적용 순서: 원문/기간 보호 → 공개 선택·미리보기·범위 확인 → 발견 검색/기록 단건 → 생성/문구 → 공통 터치·확인창. 기존 데이터와 공개 링크는 보존한다.
