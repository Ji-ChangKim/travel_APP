TripPrint Windows 네이티브 한글 경로 오류 해결
작업일: 2026-10-12

1. 원인
원본 프로젝트의 한글 경로가 CMake PCH 헤더에 Windows 코드 페이지 바이트로 기록됐다.
clang++가 WorkletsPCH.h의 경로를 해석하지 못해 arm64-v8a를 포함한 C++ 컴파일이 실패했다.
헤더 파일 자체가 없는 오류가 아니다. android.overridePathCheck=true는 사전 검사만 우회한다.
앞선 subst 가상 드라이브 실험에서는 Expo 자동 연결이 실제 한글 경로로 돌아가 해결되지 않았다.

2. 변경 내역
- 원본 J:/개인 프로젝트/App/travel_APP을 보존했다. 기존 staged/unstaged 파일을 수정·이동하지 않았다.
- 현재 소스의 빌드 복사본을 실제 영문 경로 J:/travel_APP에 만들었다.
  Git 이력, node_modules, 기존 Android 프로젝트·빌드 캐시, outputs, 서명 파일과 비밀 환경 파일은 복사하지 않았다.
- 같은 package-lock.json으로 npm ci를 실행해 1055개 패키지를 새 경로에 설치했다.
  Expo/React Native/Worklets 버전을 변경하거나 패키지 소스를 수정하지 않았다.
- Node 24.19.0으로 apps/mobile에서 Expo Android prebuild를 새로 실행했다.
- Expo가 자동 변경한 모바일 package.json 실행 스크립트는 원본 값으로 복구했다.
  원본과 복사본의 package-lock.json 및 모바일 package.json SHA-256 일치를 확인했다.
- 새 Android 프로젝트의 local.properties에 기존 SDK 경로를 연결했다.
- 새 Android 프로젝트의 .gradle/config.properties 및 .idea/gradle.xml에 기존 JDK 21을 연결했다.
- 기존 TripPrint Run 설정을 새 Android 프로젝트의 .run/TripPrint.run.xml에 복사했다.
- 새 .env.mvp에는 EAS preview의 공개 staging 설정 4개만 기록했다. 비밀 키는 복사하지 않았다.
- 이번 작업이 시작했던 이전 Metro 프로세스를 중단하고 새 폴더에서 개발 서버를 실행했다.
  CI 모드를 사용하지 않아 새로고침 기능을 사용할 수 있다.
- Metro가 ::1에만 수신하던 localhost 해석을 프로세스 옵션 --dns-result-order=ipv4first로 조정했다.
  Windows의 전역 네트워크·보안 설정은 변경하지 않았다.
- 앱 소스, DB 모델, 원본 의존성 및 Git 설정은 이번 수정으로 변경하지 않았다.

3. 확인된 검증
- npm ci: 성공, 1055개 패키지 설치.
- Expo prebuild --platform android --no-install: 성공.
- 새 복사본의 npm run check: 성공. TypeScript / ESLint / Prettier 모두 통과.
- 새 복사본의 npm run mvp:check: 성공.
- 자동 연결 root 및 Worklets sourceDir: J:/travel_APP 아래 실제 영문 경로 확인.
- 새 PCH 헤더: #include "J:/travel_APP/node_modules/react-native-worklets/android/src/main/cpp/WorkletsPCH.h"
- 아래 두 Worklets C++ 작업: BUILD SUCCESSFUL in 1m 56s, 40개 작업(5개 실행, 35개 재사용).
  :react-native-worklets:buildCMakeDebug[arm64-v8a]
  :react-native-worklets:buildCMakeDebug[x86_64]
- ARM64 libworklets.so 27,535,120바이트 및 x86_64 libworklets.so 26,598,032바이트 생성 확인.
  사용자가 전달한 PCH/헤더 경로 오류는 두 아키텍처에서 재현되지 않았다.

4. Android Studio 사용 경로

SDK: C:/Users/Jichang/AppData/Local/Android/Sdk
Gradle JDK: C:/Program Files/Android/openjdk/jdk-21.0.8
Gradle Sync 완료 후 TripPrint 앱 모듈을 선택하고 기기를 지정해 Run한다.
원본 한글 경로의 Android 프로젝트를 계속 열면 기존 오류가 발생할 수 있다.
개발 서버를 다시 시작할 때는 J:/travel_APP/apps/mobile에서 공개 .env.mvp를 불러 앱을 실행한다.
예: node --dns-result-order=ipv4first --env-file=../../.env.mvp ../../node_modules/expo/bin/cli start --dev-client --localhost
이번 실행에는 설치된 Node 24.19.0을 사용했다.
에뮬레이터에 연결할 경우 앱 설치 후 Expo CLI의 a 키로 실행한다.

주의: J:/travel_APP은 이번 소스의 빌드 복사본이다.
.git이 없으며 원본과 자동 동기화되지 않는다. Android Studio에서 복사본을 편집해도 원본은 바뀌지 않는다.
원본에 추가 수정하면 복사본도 해당 변경을 반영한 뒤 새 빌드를 검증해야 한다.
이번 복사본을 원본의 최신 상태로 영구 간주하지 않는다.

7. 최종 변경 범위
원본 저장소에는 이 해결 보고서를 추가하고 이전 Android/최종 점검 문서에 후속 판정을 추가했다.
원본 앱 소스·DB·패키지 및 기존 staged/unstaged 작업은 보존했다.
새 빌드 복사본에 의존성·네이티브 프로젝트·로컬 SDK/JDK/Run/공개 환경 설정과 빌드 결과를 생성했다.
커밋·푸시·원격 배포·Play 제출은 수행하지 않았다.
