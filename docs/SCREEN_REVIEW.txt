1. 확인한 사실과 원인

P0 상태 불일치 — 캡처1 홈과 캡처2 내 여행, 캡처3 상세
기간2026-10-01~2026-10-03인 와카야마 여행에 여행 예정 뱃지, 지난 여행 안내가 함께 보인다.
2026-10-16 기준 기간은 지났다. 저장 status=PLANNED를 뱃지에 직접 쓰고 날짜 기반 departureReminder를 별도로 조합하는 구현이 원인이다.
원본 v3는 ALL/DRAFT/PLANNED/IN_PROGRESS/COMPLETED/ARCHIVED 필터를 같은 배열에서 계산하도록 정의하지만, 날짜가 지난 미완료 여행의 표시 단계와 문구/필터를 묶는 규칙은 없다.
자동 저장 상태 전이가 없다는 사실만으로 서버의 완료 처리가 실패했다고 단정하지 않는다. 날짜 표시와 사용자의 완료 확정은 구분해야 한다.

P1 정보 구조 중복 — 캡처1 홈 메뉴/큰 카드, 캡처2 전체 목록
홈의 대표 카드가 전체 목록 카드와 같은 제목·기간·큰 표지·버튼을 반복한다. 홈 메뉴의 내 여행 계획, 본문 목록 버튼, 하단 내 여행이 같은 목적지로 분산된다.
홈은 지금 할 행동을 고르는 곳, 내 여행은 전체 여행을 검색·관리하는 곳으로 책임을 나눈다.

P1 빈 일정 첫 행동 — 캡처3
본문에는 외부 지도 가져오기만 가까이 보이지만 화면 하단에는 이미 일정 추가 버튼이 있다. 일정 추가 기능이 아예 없다는 지적은 캡처와 다르다.
문제는 빈 상태의 안내가 실제 첫 작성 행동과 떨어져 있고, 첫 일정에 무엇을 넣을지 선택할 시작점이 부족하다는 것이다.
가짜 인기 장소나 연결하지 않은 추천 템플릿을 안내하지 않는다. 실제 작성 폼으로 이어지는 작은 시작 제안을 제공한다.

추가 기획 검토 항목
- 캡처3의 멤버 인원 안내가 두 번 반복되고 상세 상단 정보가 큰 비중을 차지한다. 여행 제목·기간과 다음 행동의 위계를 우선 점검한다.
- 일정/지도/비용/사진·영수증/준비물/동행/발자국 탭이 한 줄에서 잘리는지 큰 글꼴로 확인한다.
- 지난 여행을 확인하는 행동과 완료 기록/공개 행동을 혼동시키지 않는다.
병행 작업의 상세 네 메뉴·더보기·중복 멤버 안내 제거·작성 화면 전역 메뉴 숨김을 보존했다. 폭360·390·430, 두 배 글꼴, 시트 배경 차단·키보드·초점 복원은 아래 브라우저 검사로 확인했다. TalkBack 실기기 인수는 이후 검수다.

2. 날짜·상태 표시 계약

기준 날짜는 여행 timezone의 현지 달력 날짜다. 잘못된 과거 시간대 값은 공통 도메인의 UTC 날짜 복구를 따른다.
우선순위:
ARCHIVED → 보관한 여행. COMPLETED → 완료한 여행. 두 상태는 날짜로 되돌리지 않는다.
나머지에서 endDate < today → PAST(지난 여행).
startDate <= today <= endDate → IN_PROGRESS(여행 중). 출발일과 마지막 날을 포함한다.
today < startDate → DRAFT는 준비 중, 그 외는 여행 예정.
PAST는 표시 전용 단계다. 서버/기기 저장 enum에 추가하지 않으며 자동 완료·발자국 생성·공개를 실행하지 않는다.
홈·목록 뱃지·필터/건수·정렬·상세의 상태·안내·열기 행동은 같은 공통 단계에서 계산한다.
전경의 현지 날짜 경계와 앱 복귀에 표시를 새로 계산하고 원본 여행·캐시는 수정하지 않는다.

3. 화면별 기대 동작

홈: 현재 여행 우선, 없으면 가장 가까운 다음 여행 한 건만 짧게 재개한다. 지난·완료·보관 여행을 다가오는 여행으로 강조하지 않는다.
지난 여행만 있어도 신규 사용자처럼 등록 여행이 없다고 안내하지 않는다. 다음 여행 준비와 탐색을 제공한다.
내 여행: 전체 검색·필터·건수·관리. 지난 여행 필터는 미완료 지난 여행을 찾고 완료/보관과 구분한다.
홈 메뉴: 초대·장소 가져오기 등 보조 행동. 중복된 전체 목록 항목을 제거하고 하단 내 여행을 전체 관리 진입점으로 둔다.
빈 일정: 보는 DAY의 첫 일정 직접 추가 또는 숙소/식사/관광으로 시작한다. 숙소15:00·식사12:00·관광09:00은 편집 가능한 예시다.
선택 DAY·초안 종류/제목/예시 시각만 전달한다. 주소·좌표·비용·추천 순위를 만들지 않는다. 저장 전 서버 명령 없음.
취소·다른 DAY 변경·계정/여행 변경은 기존 이탈/저장 보호를 유지한다. 보기 전용·보관 상태에는 작성 행동을 제공하지 않는다.
