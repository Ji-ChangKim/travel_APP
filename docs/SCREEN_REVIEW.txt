1. 확인한 사실과 원인

P0 상태 불일치 — 캡처1 홈과 캡처2 내 여행, 캡처3 상세
기간2026-10-01~2026-10-03인 와카야마 여행에 여행 예정 뱃지, 지난 여행 안내가 함께 보인다.
2026-10-16 기준 기간은 지났다. 저장 status=PLANNED를 뱃지에 직접 쓰고 날짜 기반 departureReminder를 별도로 조합하는 구현이 원인이다.
원본 v3는 ALL/DRAFT/PLANNED/IN_PROGRESS/COMPLETED/ARCHIVED 필터를 같은 배열에서 계산하도록 정의하지만, 날짜가 지난 미완료 여행의 표시 단계와 문구/필터를 묶는 규칙은 없다.
자동 저장 상태 전이가 없다는 사실만으로 서버의 완료 처리가 실패했다고 단정하지 않는다. 날짜 표시와 사용자의 완료 확정은 구분해야 한다.

P1 정보 구조 중복 — 캡처1 홈 메뉴/큰 카드, 캡처2 전체 목록
홈의 대표 카드가 전체 목록 카드와 같은 제목·기간·큰 표지·버튼을 반복한다. 홈 메뉴의 내 여행 계획, 본문 목록 버튼, 하단 내 여행이 같은 목적지로 분산된다.
홈은 지금 할 행동을 고르는 곳, 내 여행은 전체 여행을 검색·관리하는 곳으로 책임을 나눈다.

P1 빈 일정 첫 행동 — 캡처3
본문에는 외부 지도 가져오기만 가까이 보이지만 화면 하단에는 이미 일정 추가 버튼이 있다. 일정 추가 기능이 아예 없다는 지적은 캡처와 다르다.
문제는 빈 상태의 안내가 실제 첫 작성 행동과 떨어져 있고, 첫 일정에 무엇을 넣을지 선택할 시작점이 부족하다는 것이다.
가짜 인기 장소나 연결하지 않은 추천 템플릿을 안내하지 않는다. UI/UX 채팅에서 확정한 추천 코스·장소 검색 카드로 실제 작성 폼을 연다. 코스는 기존 도시 가이드의 장소를 고르는 흐름이며 자동 일괄 저장하지 않는다.

추가 기획 검토 항목
- 캡처3의 멤버 인원 안내가 두 번 반복되고 상세 상단 정보가 큰 비중을 차지한다. 여행 제목·기간과 다음 행동의 위계를 우선 점검한다.
- 일정/지도/비용/사진·영수증/준비물/동행/발자국 탭이 한 줄에서 잘리는지 큰 글꼴로 확인한다.
- 지난 여행을 확인하는 행동과 완료 기록/공개 행동을 혼동시키지 않는다.
병행 작업의 최신 기준은 상세 세 허브(일정·지도·비용)·상단 더보기·하단 단일 일정 추가, 목록 헤더의 새 여행 아이콘이다. 중복 멤버 안내 제거·작성 화면 전역 메뉴 숨김도 유지한다. 최종 화면·접근성 검증 결과는 아래에 기록한다. TalkBack 실기기 인수는 이후 검수다.

2. 날짜·상태 표시 계약 — 사용자 확정 4단계

기준 날짜는 여행 timezone의 현지 달력 날짜다. 누락·잘못된 시간대는 UTC로 복구한다.
준비 중(DRAFT): 날짜 미정 또는 출발까지8일 이상. 부분·잘못된 날짜·역전 기간도 미정으로 처리한다.
임박/예정(PLANNED): 출발까지1~7일. D-7 포함.
여행 중(IN_PROGRESS): 시작일≤today≤종료일. D-Day 겹침은 여행 중을 우선한다.
여행 완료(COMPLETED): 종료일 이후. 이전 지난 여행(PAST) 단계는 제거한다.
저장 상태로 날짜 단계를 앞당기거나 늦추지 않는다. 보관은 별도 속성/필터이며 홈 대표 여행에서 제외한다.
카드 뱃지·설명·버튼·필터/건수·상세·발자국·MY 통계는 공통 모듈을 따른다.
완료의 주 행동은 기록 보러가기→실제 다이어리, 나머지는 계획 계속하기→여행 상세다.
날짜가 지난 원본 PLANNED 여행도 비공개 기록을 읽을 수 있다. 원본 status·권한·공개 설정은 변경하지 않는다.
공개할 기록의 정리 완료 확인은 기존 원본 COMPLETED 계약을 사용하며 날짜 경과만으로 공개하지 않는다.
전경 날짜 경계·앱 복귀에는 기존 공유 훅으로 갱신하고 배경·마지막 화면 종료 시 타이머를 정리한다.
날짜 미정 표시는 순수 표시 입력의 복구 규칙이다. 생성 API의 필수 여행 기간 계약은 이번 범위에서 바꾸지 않는다.

3. 화면별 기대 동작

홈: 현재 여행 우선, 없으면 가장 가까운 다음 여행 한 건의 다음 일정 브리핑을 제공한다. 실제 저장 일정의 제목·DAY·날짜·시각을 읽고 지난 시각은 제외한다. 완료·보관 여행은 다음 여행에 넣지 않는다. 여행 팁·추천은 기존 탐색 영역을 유지한다.
지난 여행만 있어도 신규 사용자처럼 등록 여행이 없다고 안내하지 않는다. 다음 여행 준비와 탐색을 제공한다.
내 여행: 전체 아카이브의 검색·네 단계 필터·건수·보관을 제공한다. 상단 홈 이동 버튼은 제거하고 하단 홈 탭을 사용한다.
홈 메뉴: 팝업 내비게이션을 제거한다. 헤더는 브랜드·필요한 로그인만 표시한다. 접힌 여행 도구에는 초대·가져오기처럼 하단 탭과 겹치지 않는 행동만 남긴다.
빈 일정: 보는 DAY에서 추천 코스 불러오기 또는 장소 검색으로 추가한다. 일정 추가는 하단의 단일 주요 행동으로 둔다.
추천 코스: 같은 나라·도시의 기존 도시 가이드 장소를 미리 읽고 한 장소를 고르면 제목·설명만 작성 폼에 채운다. 지원하지 않는 도시에는 검색으로 이동할 방법을 제공한다.
선택 DAY ID를 작성 폼까지 유지한다. 검색·지도 링크·직접 입력은 기존 위치·입력 보호를 따른다. 주소·좌표·비용·최적 경로·추천 순위를 임의 생성하지 않으며 확인 후 저장 전까지 서버 명령이 없다.
취소·다른 DAY 변경·계정/여행 변경은 기존 이탈/저장 보호를 유지한다. 보기 전용·보관 상태에는 작성 행동을 제공하지 않는다.

4. 인수 시나리오

- 캡처와 같은 지난 PLANNED 여행: 홈의 다음 여행에서 제외, 목록 완료1·임박/예정0, 상세 여행 완료, 원래 status 유지.
- 출발 전날/당일/마지막 날/다음 날, 동일일 여행, Tokyo/Los Angeles 날짜 차이, 현지 자정·앱 복귀.
- 원본 조기 완료/보관 값을 보존하되 화면 단계는 날짜만 따르고 자동 저장·공개 없음.
- 홈에는 재개 요약 최대1건, 목록 카드 반복 없음, 메뉴 목록 중복 없음, 하단 내 여행은 검색/필터로 연결.
- DAY2 빈 화면에서 장소 검색 → DAY2 초안 → 취소 시 일정0건, 저장 시 한 건만 생성.
- 추천 코스 미리보기 취소는 저장 없음. 실제 가이드 장소 선택·작성·저장은 DAY2에 한 번 반영하고 재조회에서도 유지한다.
- 추천이 없는 도시의 검색 연결, 보기 전용의 작성 행동 숨김, 여러 카드에서 하나의 주요 행동을 확인한다.
- 보기 전용·저장 잠금·큰 글꼴·화면 읽기·배경 복귀에서도 기존 보호 유지.
